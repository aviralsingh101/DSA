The order

Study modules in this sequence. It is not the same as the module numbering, because the numbering groups by subject while the study order optimises for how quickly you regain the ability to see a problem's shape.

Why this order

Foundations and array patterns rebuild pattern recognition fastest, because they have the highest density of "signal in the statement → technique" mappings per hour spent. Dynamic programming is pulled forward ahead of advanced trees and graphs because it is by far the most common place experienced engineers fail an interview: the algorithms are memorable but state design is a skill that decays. Decompositions and flows come last: they are genuinely Google-hard, but they are low frequency, and they are much easier once segment trees and DSU are automatic.

Three ways to run this course

Interview in under 4 weeks — P0 only

Study only the P0 pages, in the order above. That is roughly 40 pages. Read Constraints → Complexity and Pattern Index on day one and again every weekend. Skip modules 09 and 12 entirely, and take only dp-foundations through string-dp from module 10.

Interview in 2–3 months — P0 then P1

Complete the P0 sweep first so you always have a working baseline, then do a second pass over the same module order picking up P1 pages. This is the right plan for a Google-style loop, where one round is usually a hard graph or DP problem rather than a pattern you can name in ten seconds.

Rebuilding CP rating — everything

Do all three tiers in module order. Module 11 (math) and module 06 (range queries) matter far more on Codeforces than in interviews, and modules 09 and 12 are where Div 1 problems live. Pair each module with a virtual contest rather than with more reading.

Weekly habits that actually fix pattern recognition

  1. Re-read the constraint table. Open Constraints → Complexity and cover the right-hand column. Given only n ≤ 20, say the intended complexity out loud before looking.
  2. Skim the pattern index, not the algorithms. Ten minutes on Pattern Index is worth an hour of re-reading implementations you already know.
  3. Do one unlabelled drill set. Mock Drills gives you three problems in 45 minutes with no topic hint. The failure mode you are training against only shows up when the label is missing.
  4. Write one template from memory. Pick a template from Java Toolkit, close the page, and type it out. Binary search, DSU, Dijkstra and the sliding-window skeleton should be muscle memory.
  5. Log every miss as a signal, not as a topic. When you fail a problem, write down the phrase in the statement you should have reacted to. That phrase is the reusable artefact; "I should revise DP" is not.
The trap for returning engineers

The tempting plan is to grind problems immediately, because reading feels slow. It does not work here: grinding trains recall of problems you have seen, and interviews test recognition of problems you have not. Front-load the recognition cards, then grind.
