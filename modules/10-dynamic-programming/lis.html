Longest Increasing Subsequence

Longest increasing subsequence is O(n²) prefix DP or O(n log n) patience sorting — same answer, different constraint.

Medium 24 min read Prerequisites: 1-D DP, Binary Search Basics LIS patience n log n P0

Why this exists

LIS is the first 1D DP whose transition is not O(1). dp[i] = 1 + max dp[j] over j < i with a[j] < a[i], else 1. That is O(n²), fine at n = 2000, dead at n = 1e5.

The O(n log n) upgrade keeps tails[len] = the smallest tail of any increasing subsequence of that length. A new value either extends the longest (append) or lowers a tail (binary-search replace). The length of tails is the LIS length. The array tails is not itself an LIS.

Variants (LDS, longest bitonic, longest chain of pairs, Russian-doll envelopes) are this page after a sort or a sign flip. Reconstruction needs a parent pointer; the n log n length algorithm does not give the sequence for free.

dp[i] is the LIS ending at i. The global answer is the max of those. Patience tails answers only the length, in n log n, by keeping one representative per length.

Recognise this pattern

Say yes when you see

  • Longest increasing / decreasing / non-decreasing subsequence (not subarray)
  • n ≤ 2000 → n² DP; n ≤ 1e5 → n log n tails
  • Box nesting, envelopes, chaining pairs after a sort
  • Longest bitonic = LIS + LDS meeting at i
  • You need the length, or the sequence, of a monotone subsequence

Not this pattern when

  • Contiguous → longest increasing subarray is a one-pass, not LIS
  • Any subset that sums to k → knapsack
  • Longest common subsequence of two strings → string DP, not this page
  • You must pick a contiguous window of indices → sliding window / Kadane

Ending-at-i, then tails

O(n²): for each i, scan j < i, take the max dp[j] among a[j] < a[i], then dp[i] = that max + 1 (or 1). Answer max(dp). parent[i] = the j that won, or -1.

O(n log n): tails starts empty. For each x, lower_bound the first tail ≥ x (strict LIS: first tail ≥ x, replace it; non-decreasing: first tail > x). If x is larger than every tail, append. The length of tails is the answer. Why tails works: an increasing subsequence of length k can always be rewritten to end as small as possible without hurting future extensions. Replacing a tail is that rewrite. You lose the actual sequence unless you also store a predecessor per index.

dp[i] = length of a longest strictly increasing subsequence that ends at i.

tails[k] = smallest tail of any IS of length k+1
lower_bound in Java

Collections.binarySearch on a List, or a manual lo/hi on an int[] used as a size-t prefix. Insertion point = -idx-1 on a miss. mid = lo + (hi-lo)/2.

tails is not an LIS

After [3, 1, 2] tails is [1, 2], which happens to be an LIS. After [1, 3, 2] tails ends as [1, 2], and [1, 2] is an LIS, but the replacements can mix values from different subsequences. Do not print tails.

n² or n log n?

Algorithm

  1. Decide length-only vs sequence, and n vs 2000.
  2. n²: dp[i]=1, for j < i if a[j] < a[i] and dp[j]+1 > dp[i], update and set parent.
  3. Answer is max(dp); reconstruct from the argmax via parent.
  4. n log n: int[] tails, size t = 0.
  5. For each x: lower_bound first index with tails[i] ≥ x (strict). Replace or append.
  6. Return t. Do not print tails as the sequence.
  7. Non-decreasing: lower_bound first tail > x (upper bound).

Java implementation

JavaLisRec.java
public class LisRec {
    
        static int lis(int[] a, int i) {
            int best = 1;
            for (int j = i + 1; j < a.length; j++) {
                if (a[j] > a[i]) {
                    best = Math.max(best, 1 + lis(a, j));
                }
            }
            return best;
        }
    
        static int lis(int[] a) {
            int ans = 0;
            for (int i = 0; i < a.length; i++) {
                ans = Math.max(ans, lis(a, i));
            }
            return ans;
        }
    
        public static void main(String[] args) {
            System.out.println(lis(new int[] {10, 9, 2, 5, 3, 7}));
        }
        // Input : [10, 9, 2, 5, 3, 7]
        // Output: 3
    }
JavaLisN2.java
public class LisN2 {
    
        static int lis(int[] a) {
            int n = a.length, ans = 1;
            int[] dp = new int[n];
            for (int i = 0; i < n; i++) {
                dp[i] = 1;
                for (int j = 0; j < i; j++) {
                    if (a[j] < a[i] && dp[j] + 1 > dp[i]) {
                        dp[i] = dp[j] + 1;
                    }
                }
                ans = Math.max(ans, dp[i]);
            }
            return ans;
        }
    
        public static void main(String[] args) {
            System.out.println(lis(new int[] {10, 9, 2, 5, 3, 7}));
        }
        // Input : [10, 9, 2, 5, 3, 7]
        // Output: 3
    }
JavaLisNlogN.java
public class LisNlogN {
    
        static int lowerBound(int[] t, int hi, int x) {
            int lo = 0;
            while (lo < hi) {
                int mid = lo + (hi - lo) / 2;
                if (t[mid] >= x) {
                    hi = mid;
                } else {
                    lo = mid + 1;
                }
            }
            return lo;
        }
    
        static int lis(int[] a) {
            int[] tails = new int[a.length];
            int t = 0;
            for (int x : a) {
                int i = lowerBound(tails, t, x);
                tails[i] = x;
                if (i == t) {
                    t++;
                }
            }
            return t;
        }
    
        public static void main(String[] args) {
            System.out.println(lis(new int[] {10, 9, 2, 5, 3, 7}));
        }
        // Input : [10, 9, 2, 5, 3, 7]
        // Output: 3
    }

Complexity

Time O(n²) or O(n log n) Space O(n)

Ending-at-i tries every pair (j, i):

T = Θ(n²)

Each of n values does one binary search on a tails array of size at most n:

T = Θ(n log n)

Edge cases and pitfalls

  • Printing tails as the LIS
    Tails mixes values from different subsequences after replacements.
    parent / predecessor per index, walk from the last append that grew the length.
  • Wrong bound for non-decreasing
    Using ≥ when equals are allowed. Equal values replace instead of extend.
    Strict: first tail ≥ x. Non-decreasing: first tail > x.
  • LIS vs subarray
    A one-pass "longest run of increases" on a problem that allows gaps.
    Subsequence may skip. If the problem says contiguous, it is not this page.
  • n² at n = 1e5
    10^10 operations. TLE, not WA.
    Tails or a Fenwick of max dp by compressed value.
  • Envelopes without a tie-break sort
    Same-width envelopes nest in the LIS of heights. They should not.
    Sort width ascending, height descending on ties, then LIS on height.
  • Empty array
    max of an empty dp, or tails length 0 vs 1.
    n == 0 → 0. n == 1 → 1.

Interview follow-ups

Why is tails increasing?

If tails[k] ≤ tails[k-1], the longer sequence would have a smaller-or-equal tail and would have replaced the shorter one. The construction maintains a strictly increasing tails.

How do I reconstruct with tails?

Store, for each index i, the length assigned and a predecessor index that had length-1 when you placed i. Then walk from any index that received the maximum length. Several extra arrays, still O(n log n).

Fenwick LIS?

Compress values. Fenwick stores max dp among values < a[i]. Query, then update a[i] with that max+1. Same n log n, and reconstruction is natural via parent.

Does LCS(a, sort(a)) equal LIS?

For strictly increasing, sort unique first or LCS can pick duplicates. It is O(n²) and a useful check, not an algorithm you submit at n = 1e5.

Hint for LC 354

Sort by width ascending. On equal width, height descending so two equal widths cannot form an increasing height pair in the later LIS. Then patience LIS on heights. n = 1e5, so n² dies.

Hint for AtCoder DP-Q Flowers

Weighted LIS: max sum of beauties with increasing heights. Fenwick or segtree on height: query max dp among height < h[i], add beauty[i], update. Compress heights. long.

Recap

  • dp[i] = LIS ending at i, O(n²), easy parent.
  • tails[k] = smallest tail of length k+1, O(n log n) length.
  • Do not print tails. Reconstruct with parent.
  • Strict vs non-decreasing is the bound (≥ vs >).
  • Envelopes: sort one axis, LIS the other, tie-break.
