DP Optimisations

When the naive transition is O(n) per state, convexity or monotonicity of the argmin lets you drop a log or a full factor of n.

Hard 28 min read Prerequisites: Knapsack Family, Interval DP CHT D&C opt Knuth P2

Why this exists

A huge family of DPs looks like dp[i] = min_{j < i} dp[j] + C(j, i), or the 2D form dp[i][j] = min_{i ≤ k < j} dp[i][k] + dp[k+1][j] + C(i, j). Naive is O(n²) or O(n³). When C satisfies a quadrangle inequality or the opt pointer is monotone, Knuth, divide-and-conquer optimisation, and Convex Hull Trick cut this to O(n²) or O(n log n).

You do not invent the inequality in an interview. You recognise the shape (layered DP on a line, MCM-like, or min of linear functions) and name the tool. The implementation is a hull of lines or a recursive split of the opt range.

P2 because the proofs are short if you already believe the quadrangle inequality, and because the hull must be maintained carefully (slopes monotone → deque; otherwise a Li Chao tree / multiset).

If the best j for i does not decrease as i grows (or the best k for [l,r] sits between the bests of the two smaller intervals), you may restrict the search window and the extra factor of n disappears.

Recognise this pattern

Say yes when you see

  • dp[i] = min_{j
  • Layered: dp[k][i] = min_{j
  • MCM-like dp[l][r] with monotone argmin (Knuth)
  • C(j,i) = b[j] * a[i] + extra(j) — lines of slope b[j]
  • CF / AtCoder problems tagged cht, d&c opt, knuth

Not this pattern when

  • C is an arbitrary table with no inequality → you cannot drop the inner loop
  • n ≤ 400 interval DP without QI → stay O(n³)
  • The min is over a data-structure query you already have (Fenwick of max) → that is enough
  • Online slopes that are not monotone and n is 1e5 → Li Chao, still this family but heavier

Three tools, one monotone idea

Knuth (interval): if opt[l][r] is the best k and opt[l][r-1] ≤ opt[l][r] ≤ opt[l+1][r], then when you fill by length you only walk k in that shrinking range. Total k-iterations become O(n²).

D&C opt (layered): for a fixed layer, the opt j as a function of i is monotone. To fill i in [L,R], compute the middle i, brute j in the allowed [jL, jR], then recurse left with jR = that opt and right with jL = that opt. O(n log n) per layer. CHT: dp[i] = min_j (m_j * x_i + b_j) with x increasing and m monotone. Keep a deque of lines, pop back while the new line makes a worse intersection, pop front while the next line is better at x_i. Amortised O(1) per query.

Name which monotonicity you have. Knuth: 2D opt nest. D&C: 1D opt monotone per layer. CHT: the choices are lines and the query x is sorted.

dp[i] = minj < i dp[j] + C(j, i)
Quadrangle inequality

C(a,c)+C(b,d) ≤ C(a,d)+C(b,c) for a≤b≤c≤d. Together with monotonicity of C, this is the usual sufficient condition for Knuth and for D&C opt. On a line with C = cost of a segment, convex costs often satisfy it.

When slopes are not sorted

Li Chao segment tree: each node stores one line, and you recurse on the half where the new line is better. O(n log X) or O(n log n) on compressed x. Heavier constant, no monotonicity needed.

Visual walkthrough

Tiny Knuth-style table: 4 points, C(l,r) = (r-l)^2, dp[l][r] min split cost + C

Rows l, columns r. We fill by gap. Target is [l,r]; from cells are the two children of the best k. opt pointers only move right as r grows.

Which optimisation?

Algorithm

  1. Write the naive rec and identify C(j, i) or C(l, r).
  2. Check QI / opt monotonicity (prove or trust the editorial).
  3. Knuth: store opt[l][r], loop k only in [opt[l][r-1], opt[l+1][r]].
  4. D&C: compute(layer, iLo, iHi, jLo, jHi): mid i, brute j, recurse.
  5. CHT: lines (m, b) into a deque; query at x_i from the front.
  6. Verify on a brute n=30 against the naive DP.
  7. Watch long for costs; mid = lo + (hi-lo)/2 on any binary search inside Li Chao.

Java implementation

JavaOptNaive.java
import java.util.Arrays;
    
    public class OptNaive {
    
        static long minCost(int[] a) {
            int n = a.length;
            long[] pref = new long[n + 1];
            for (int i = 0; i < n; i++) {
                pref[i + 1] = pref[i] + a[i];
            }
            long[] dp = new long[n + 1];
            Arrays.fill(dp, Long.MAX_VALUE / 4);
            dp[0] = 0;
            for (int i = 1; i <= n; i++) {
                for (int j = 0; j < i; j++) {
                    long d = pref[i] - pref[j];
                    dp[i] = Math.min(dp[i], dp[j] + d * d);
                }
            }
            return dp[n];
        }
    
        public static void main(String[] args) {
            System.out.println(minCost(new int[] {1, 3, 1, 3}));
        }
        // Input : [1, 3, 1, 3]
        // Output: 20
    }
JavaOptCht.java
import java.util.ArrayDeque;
    
    public class OptCht {
    
        static long minCost(int[] a) {
            int n = a.length;
            long[] pref = new long[n + 1];
            for (int i = 0; i < n; i++) {
                pref[i + 1] = pref[i] + a[i];
            }
            long[] dp = new long[n + 1];
            ArrayDeque<long[]> dq = new ArrayDeque<>(); // {m, b}
            dq.addLast(new long[] {0, 0});             // dp[0]=0, pref[0]=0
            for (int i = 1; i <= n; i++) {
                long x = pref[i];
                while (dq.size() >= 2) {
                    long[] p = dq.pollFirst();
                    long[] q = dq.peekFirst();
                    if (p[0] * x + p[1] <= q[0] * x + q[1]) {
                        dq.addFirst(p);
                        break;
                    }
                }
                long[] best = dq.peekFirst();
                dp[i] = best[0] * x + best[1] + x * x;
                long m = -2 * pref[i];
                long b = dp[i] + pref[i] * pref[i];
                while (dq.size() >= 2) {
                    long[] y = dq.pollLast();
                    long[] z = dq.peekLast();
                    // pop y if intersection(z,y) >= intersection(y, new)
                    if ((y[1] - z[1]) * (y[0] - m) >= (b - y[1]) * (z[0] - y[0])) {
                        continue;
                    }
                    dq.addLast(y);
                    break;
                }
                dq.addLast(new long[] {m, b});
            }
            return dp[n];
        }
    
        public static void main(String[] args) {
            System.out.println(minCost(new int[] {1, 3, 1, 3}));
        }
        // Input : [1, 3, 1, 3]
        // Output: 20
    }
JavaOptDc.java
public class OptDc {
    
        static long[] pref, dp0, dp1;
    
        static void compute(int iLo, int iHi, int jLo, int jHi) {
            if (iLo > iHi) {
                return;
            }
            int iMid = iLo + (iHi - iLo) / 2;
            int bestJ = jLo;
            long best = Long.MAX_VALUE / 4;
            int jMax = Math.min(jHi, iMid - 1);
            for (int j = jLo; j <= jMax; j++) {
                long d = pref[iMid] - pref[j];
                long val = dp0[j] + d * d;
                if (val < best) {
                    best = val;
                    bestJ = j;
                }
            }
            dp1[iMid] = best;
            compute(iLo, iMid - 1, jLo, bestJ);
            compute(iMid + 1, iHi, bestJ, jHi);
        }
    
        public static void main(String[] args) {
            int[] a = {1, 3, 1, 3};
            int n = a.length;
            pref = new long[n + 1];
            for (int i = 0; i < n; i++) {
                pref[i + 1] = pref[i] + a[i];
            }
            dp0 = new long[n + 1];
            dp1 = new long[n + 1];
            compute(1, n, 0, n);
            System.out.println(dp1[n]);
        }
        // Input : [1, 3, 1, 3], one layer
        // Output: 16
    }

Complexity

Time CHT O(n); D&C opt O(n log n) per layer; Knuth O(n²) Space O(n) or O(n²) for Knuth tables

D&C: each recursion level spends O(n) on the j-sweeps (they do not overlap more than a telescoping sum), and there are log n levels of mid-splits:

TD&C = Θ(n log n) per layer

Knuth: each (l,r) examines a disjoint k-range relative to its neighbours; the standard charging gives O(n²).

Edge cases and pitfalls

  • Applying Knuth without QI
    opt is not monotone; shrinking the k-range misses the real min. Silent WA.
    Prove QI or compare against naive on random tests of n=40.
  • CHT intersection overflow
    (b2-b1)/(m1-m2) computed with longs that wrap, or with doubles that mis-order equal slopes.
    Cross-multiply in a careful long (or __int128 in C++). Reject equal slopes by keeping the better intercept.
  • D&C iMid with empty j-range
    iMid == 0 or jMax < jLo. You write inf and recurse with inverted bounds.
    Guard jMax = min(jHi, iMid-1) and if jLo>jMax write inf, still recurse consistently.
  • Querying CHT with unsorted x
    Deque pops are irreversible; a later smaller x is broken.
    Sort queries, or use Li Chao / a multiset hull.
  • int costs
    (pref[i]-pref[j])^2 with pref = 1e5*1e9.
    long everywhere, including m*x + b.
  • Off-by-one on inclusive j
    j < i vs j ≤ i, empty segments, C(i,i) not defined.
    Match the naive rec exactly; empty prefix j=0 is a legal start.

Interview follow-ups

How do I check QI in five minutes?

For a segment cost on a line, convex / concave costs often work. Empirically: compute naive opt[i] on n=50 and assert opt[i] ≤ opt[i+1]. If it fails on random arrays, you do not have the structure. If it holds, you still want a proof for confidence, but CF will accept the code.

CHT vs D&C for the same rec?

If C(j,i) is a line in i, CHT is faster and simpler. If C is a black-box segment cost with monotone opt but not a line (e.g. a range-cost from a precomputed table), D&C still works and CHT does not.

Why does the D&C j-range not explode?

The mid's brute force of length J is charged once per level, and the left and right halves get complementary j-ranges that sum to J plus O(1). Across a level the j-sweeps telescope to O(n).

Can I combine Knuth with reconstruction?

Yes. Store opt[l][r] = best k. The last split is that k; recurse. Same as interval DP reconstruction, just with a smaller search during the fill.

Recap

  • Naive min-over-j is O(n) per state until you name a monotone opt or a line.
  • CHT: lines + sorted x → deque, O(n).
  • D&C opt: monotone opt[i] → mid split, O(n log n) per layer.
  • Knuth: nested opt on intervals → O(n²).
  • Prove or empirically check QI before shrinking a search range.
