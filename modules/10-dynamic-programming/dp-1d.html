Module 10 · Dynamic Programming

1-D DP

One index, two choices — take it or skip it — is house robber, frog jumps, decode ways, and most "best on a prefix" problems.

Easy 24 min read Prerequisites: DP Foundations 1D DP house robber prefix P0

Why this exists

Once the state is "best / ways using the first i elements", a surprising fraction of array DP collapses to one loop. The live question is only what the last decision was: did we take a[i], and what does that forbid?

House robber is the mascot: taking i forbids i-1, so dp[i] = max(dp[i-1], dp[i-2] + a[i]). Decode ways, delete-and-earn, and frog-jump costs are the same shape with a different combine. Learn the shape, not the story.

The space trick is automatic: two (or k) previous answers replace the array. That is why 1D DP is the first family after foundations — it is foundations with an array of weights attached.

Define dp[i] as the answer for the prefix a[0..i]. The transition looks only at a constant number of earlier prefixes plus a[i] itself.

Recognise this pattern

Say yes when you see

  • Best / ways / possibility on a prefix of an array
  • "Cannot pick two adjacent" / "jump at most k" / "last decision is local"
  • Delete-and-earn, house robber, decode ways, frog 1/2
  • A linear scan would work if you stored a few running answers
  • n = 1e5 rules out n², and the dependency is local

Not this pattern when

  • The answer for prefix i depends on an arbitrary earlier j → LIS / nested loops / n log n
  • Capacity / remaining budget is a second dimension → knapsack
  • A grid, not an array → grid DP
  • Subarrays as intervals [l,r] → interval DP

Constraint tell: n ≤ 10⁵ wants O(n) after you roll. Answers are long when values are 1e9. A window of k with a naive min is O(nk) and dies at k = n; then you need a monotonic deque (still 1D DP).

Take or skip, written as a prefix

Let dp[i] be the maximum money from houses 0..i. If you skip i you already have dp[i-1]. If you take i you cannot have taken i-1, so you add a[i] to dp[i-2]. The max of those two is optimal, because every plan decides i one way or the other.

Bases: dp[0] = a[0], dp[1] = max(a[0], a[1]). The loop runs i = 2 .. n-1. Rolling: keep prev2, prev1 and write cur = max(prev1, prev2 + a[i]). Decode ways is the counting twin: a valid last digit uses ways[i-1], a valid last pair uses ways[i-2]. Same indices, + instead of max, and a validity predicate on the characters.

dp[i] is the best answer that is allowed to use any subset of a[0..i] obeying the local constraint (no two adjacent, jump limit, …). After i = n-1 you have the full-array answer.

dp[i] = max(dp[i-1], dp[i-2] + a[i])
Circular house robber

If n and 0 are adjacent, you cannot take both. Run the linear DP twice, once on [0..n-2] and once on [1..n-1], and take the max. The empty / single-house cases are the only extra bases.

Window of k, O(n) with a deque

dp[i] = a[i] + min_{i-k ≤ j < i} dp[j]. A monotonic deque of increasing dp values with indices, popping the front when it leaves the window, makes each i O(1). That is still 1D DP; the deque is the data structure, not a new family.

Which 1D template?

Algorithm

  1. State: dp[i] = answer on prefix 0..i.
  2. Decision at i: skip (read i-1) or take (read i-2, or a window).
  3. Bases for i = 0 and i = 1, written out, not stuffed into the loop.
  4. Loop i = 2 .. n-1 and apply the formula.
  5. Roll to two (or k) running values if you do not need the table.
  6. Circular: run twice, drop the first house or the last.
  7. Reconstruct by comparing which branch produced dp[i].

Java implementation

JavaRobRec.java
public class RobRec {
    
        static int rob(int[] a, int i) {
            if (i >= a.length) {
                return 0;
            }
            return Math.max(rob(a, i + 1), a[i] + rob(a, i + 2));
        }
    
        public static void main(String[] args) {
            System.out.println(rob(new int[] {2, 7, 9, 3, 1}, 0));
        }
        // Input : [2, 7, 9, 3, 1]
        // Output: 12
    }
JavaRobMemo.java
import java.util.Arrays;
    
    public class RobMemo {
    
        static int rob(int[] a, int i, int[] memo) {
            if (i >= a.length) {
                return 0;
            }
            if (memo[i] != -1) {
                return memo[i];
            }
            return memo[i] = Math.max(rob(a, i + 1, memo), a[i] + rob(a, i + 2, memo));
        }
    
        public static void main(String[] args) {
            int[] a = {2, 7, 9, 3, 1};
            int[] memo = new int[a.length];
            Arrays.fill(memo, -1);
            System.out.println(rob(a, 0, memo));
        }
        // Input : [2, 7, 9, 3, 1]
        // Output: 12
    }
JavaRobTab.java
public class RobTab {
    
        static int rob(int[] a) {
            int n = a.length;
            if (n == 1) {
                return a[0];
            }
            int[] dp = new int[n];
            dp[0] = a[0];
            dp[1] = Math.max(a[0], a[1]);
            for (int i = 2; i < n; i++) {
                dp[i] = Math.max(dp[i - 1], dp[i - 2] + a[i]);
            }
            return dp[n - 1];
        }
    
        public static void main(String[] args) {
            System.out.println(rob(new int[] {2, 7, 9, 3, 1}));
        }
        // Input : [2, 7, 9, 3, 1]
        // Output: 12
    }
JavaRobRoll.java
public class RobRoll {
    
        static int rob(int[] a) {
            int prev2 = 0, prev1 = 0;
            for (int x : a) {
                int cur = Math.max(prev1, prev2 + x);
                prev2 = prev1;
                prev1 = cur;
            }
            return prev1;
        }
    
        public static void main(String[] args) {
            System.out.println(rob(new int[] {2, 7, 9, 3, 1}));
        }
        // Input : [2, 7, 9, 3, 1]
        // Output: 12
    }

Edge cases and pitfalls

  • Empty array / single house
    Reading dp[1] on n = 1.
    Guard n == 0 / n == 1 before the loop, or use the rolling form which starts at 0,0.
  • Circular without splitting
    Running linear DP on a ring. Taking both ends is legal in the table and illegal in the house.
    max(rob(0..n-2), rob(1..n-1)).
  • Mixing Kadane's reset into house robber
    cur = max(a[i], cur + a[i]) drops the prefix and can pick two adjacent houses after a skip of thinking.
    House robber never resets to "start here ignoring the constraint history". It only skips or takes.
  • Delete-and-earn without compressing
    Treating indices as the line. Deleting a value deletes every copy and the neighbours' values.
    cnt[v], then house-robber on v = 1..maxA.
  • int when a[i] is 1e4 and n is 100
    Usually fine; on CF with 1e9 values it overflows.
    long running totals whenever the statement's product n * maxA can exceed 2e9.
  • Off-by-one in decode ways on leading zeros
    "06" is not a valid pair, "0" is not a valid single. Counting them inflates the answer.
    A single digit is valid iff it is 1..9. A pair is valid iff 10..26.

Interview follow-ups

How is this different from Kadane?

Kadane's decision is "extend the current subarray or start a new one at i". House robber's decision is "take i (and skip i-1) or skip i". Both are 1D DP. The constraint is what changes the formula.

Can I reconstruct the subset in O(1) space?

Not from the two rolling integers alone. Keep the full dp[] (or a parent bit) if the subset is required. Rolling is for the value.

What if taking i forbids the previous k houses?

dp[i] = max(dp[i-1], dp[i-k-1] + a[i]). Still O(n). The "k" sits in the index, not in a new dimension.

Why does delete-and-earn become house robber?

Once you decide to take value v you must take all copies and you cannot take v-1. Adjacent values on the number line behave exactly like adjacent houses.

Hint for LC 213

Houses 0 and n-1 are adjacent. Any legal plan misses at least one of them. So the answer is max(linear on 0..n-2, linear on 1..n-1). n = 1 is just a[0].

Hint for AtCoder DP-C Vacation

dp[i][c] = max happiness on day i if you do activity c. Transition: max over c' != c of dp[i-1][c'] + a[i][c]. Three last-choices, still 1D in the day index. Roll the 3-array.

Recap

  • dp[i] is the answer on the prefix 0..i.
  • House robber: max(skip i-1, take i-2 + a[i]).
  • Circle = two linear runs.
  • Roll to two integers unless you must reconstruct.
  • Kadane is a different 1D rec (reset vs extend).
