Grid DP

A grid that only moves down and right is already a DAG — dp[r][c] reads the cell above and the cell to the left.

Easy 24 min read Prerequisites: DP Foundations, Topological Sort & DAG DP grid unique paths min path P0

Why this exists

Unique paths, minimum path sum, dungeon game, falling path, and cherry pickup all share one picture: a cell's answer is a combine of a constant number of incoming cells. Because you cannot move up or left (or you process layers so that you never need to), the dependency is a DAG and a double loop in row-major order is a topo scan.

This is the most visual DP. The table is the grid. The from cells are the legal predecessors. If you can fill a 3×3 unique-paths table by hand, you can write every problem on this page.

Obstacles are just cells you skip (leave at 0 ways / +inf cost). Space-opt rolls the previous row into one array. The hard variants add a second robot or a third dimension (remaining health, remaining cherries) — same grid, thicker state.

dp[r][c] = combine(dp[r-1][c], dp[r][c-1]) plus whatever the cell itself contributes. Row-major (or diagonal) order writes every from-cell first.

Recognise this pattern

Say yes when you see

  • Paths on a grid with only down/right (or 4-way with a decreasing rank)
  • Unique paths, min/max path sum, dungeon game, falling path sum
  • Obstacles that block a cell
  • Two tokens moving on the same grid (cherry pickup): add a dimension
  • R, C ≤ 200 so R*C*extra fits

Not this pattern when

  • 4-way movement with no decreasing rank and you want a shortest unweighted path → BFS
  • Weighted 4-way shortest path → Dijkstra, not a simple double loop
  • You must visit every cell → Hamiltonian, not grid DP
  • The "grid" is a matrix chain / interval → interval DP

One cell, two parents

Unique paths on an empty R×C grid: dp[0][*] = dp[*][0] = 1, then dp[r][c] = dp[r-1][c] + dp[r][c-1]. That is the dry run. With an obstacle, that cell is 0 and contributes nothing to its children.

Min path sum: dp[r][c] = a[r][c] + min(up, left), with the first row/col being prefix sums (only one parent). Dungeon game is the same DAG run backwards: you need enough health to enter a cell and still survive the later min-requirement. Rolling: dp[c] += dp[c-1] for unique paths (the old dp[c] is "up", dp[c-1] is "left" already updated). Order inside the row is left-to-right so left is new and up is old — the 0/1-knapsack direction trick in costume.

After processing (r, c), dp[r][c] is the aggregate (ways, min sum, min required health) over all legal paths from the start (or to the exit, if you ran backwards) that end at this cell.

dp[r][c] = dp[r-1][c] + dp[r][c-1]
First row and first column are prefix-only

They have one parent. Initialise them as a running sum / running product of ways (0 after the first obstacle). Forgetting this is the usual off-by-one.

Cherry pickup is not two independent paths

Two robots on the same grid share the cherries. State must remember both positions (and usually the step, or use r1+c1=r2+c2 to drop a coordinate). Adding two independent unique-path answers double-counts cells both visit.

Algorithm

  1. Confirm the move set is a DAG (down/right, or falling down a row).
  2. Allocate dp[R][C] (or one row).
  3. Base: start cell 1 (ways) or a[0][0] (cost). Fill first row and first col from their single parent.
  4. For r = 1..R-1, for c = 1..C-1: combine up and left (and the cell).
  5. Obstacles: write 0 / skip / +inf and do not feed children.
  6. Roll into one array of length C if you do not need the table.
  7. Read dp[R-1][C-1]. Backwards problems (dungeon) start at the exit.

Java implementation

JavaPathsRec.java
public class PathsRec {
    
        static int ways(int r, int c, int R, int C) {
            if (r >= R || c >= C) {
                return 0;
            }
            if (r == R - 1 && c == C - 1) {
                return 1;
            }
            return ways(r + 1, c, R, C) + ways(r, c + 1, R, C);
        }
    
        public static void main(String[] args) {
            System.out.println(ways(0, 0, 3, 3));
        }
        // Input : 3 x 3
        // Output: 6
    }
JavaPathsMemo.java
import java.util.Arrays;
    
    public class PathsMemo {
    
        static int ways(int r, int c, int R, int C, int[][] memo) {
            if (r >= R || c >= C) {
                return 0;
            }
            if (r == R - 1 && c == C - 1) {
                return 1;
            }
            if (memo[r][c] != -1) {
                return memo[r][c];
            }
            return memo[r][c] = ways(r + 1, c, R, C, memo) + ways(r, c + 1, R, C, memo);
        }
    
        public static void main(String[] args) {
            int[][] memo = new int[3][3];
            for (int[] row : memo) {
                Arrays.fill(row, -1);
            }
            System.out.println(ways(0, 0, 3, 3, memo));
        }
        // Input : 3 x 3
        // Output: 6
    }
JavaPathsTab.java
public class PathsTab {
    
        static int uniquePaths(int R, int C) {
            int[][] dp = new int[R][C];
            for (int r = 0; r < R; r++) {
                dp[r][0] = 1;
            }
            for (int c = 0; c < C; c++) {
                dp[0][c] = 1;
            }
            for (int r = 1; r < R; r++) {
                for (int c = 1; c < C; c++) {
                    dp[r][c] = dp[r - 1][c] + dp[r][c - 1];
                }
            }
            return dp[R - 1][C - 1];
        }
    
        public static void main(String[] args) {
            System.out.println(uniquePaths(3, 3));
        }
        // Input : 3 x 3
        // Output: 6
    }
JavaPathsRoll.java
import java.util.Arrays;
    
    public class PathsRoll {
    
        static int uniquePaths(int R, int C) {
            int[] dp = new int[C];
            Arrays.fill(dp, 1);
            for (int r = 1; r < R; r++) {
                for (int c = 1; c < C; c++) {
                    dp[c] += dp[c - 1];
                }
            }
            return dp[C - 1];
        }
    
        public static void main(String[] args) {
            System.out.println(uniquePaths(3, 3));
        }
        // Input : 3 x 3
        // Output: 6
    }

Complexity

Time O(R C) Space O(C) rolled; O(R C) table

One constant-time combine per cell:

T = Θ(R C)

Unique paths without obstacles is also a binomial C(R+C-2, R-1), computable in O(R) multiplications if you only need the empty-grid count.

Edge cases and pitfalls

  • Not initialising the first row/col
    Interior formula reads 0 from an unfilled border and the whole table stays 0.
    Set the start, then walk the first row using only left, first col using only up.
  • Obstacle on the start or the exit
    Returning 1 or a[0][0] anyway.
    If either is blocked, ways = 0 / min-path is impossible.
  • Rolling right-to-left for unique paths
    dp[c-1] would be the old row's left, not the new left. You mix two rows wrong.
    Left-to-right: old dp[c] is up, new dp[c-1] is left.
  • int overflow on ways
    C(38, 18) already exceeds int. LC 62 is within int; CF often is not.
    long, or the modulus.
  • Dungeon game run forwards
    Min health is not a min-sum. A deep negative late cell cannot be prepaid from an early surplus in the naive forwards rec.
    dp[r][c] = min health needed from here to the exit. Work from the exit backward.
  • Two independent min-path sums for two robots
    Shared cells counted twice.
    One state that holds both positions (or one position plus the step).

Interview follow-ups

When is the binomial enough?

Empty rectangle, only down/right, count of paths: C(R+C-2, R-1). Obstacles, min cost, or extra state kill the closed form. Use it as a check on the empty table.

Can I grid-DP a 4-way maze?

Only if you add a rank that strictly decreases (remaining health, remaining steps, a bitset of visited — the last is exponential). Plain 4-way shortest path is BFS/Dijkstra. A naive 4-way "dp[r][c] = min of four neighbours" is a cyclic system, not a DAG.

How does cherry pickup drop a coordinate?

After t steps, r+c = t for each robot. So r1+c1 = r2+c2, and c2 = r1+c1-r2. The state (t, r1, r2) or (r1, c1, r2) is enough. That is what keeps it O(n^3).

Rolling two rows vs one?

Falling path needs the previous row intact while you write the next (three parents in the same old row). Keep two rows, or write into a fresh array. Unique paths can overwrite in place left-to-right.

Hint for LC 174 Dungeon Game

dp[r][c] = min health you must have on entry to survive from here to the princess. From the exit, need max(1, 1 - a[R-1][C-1]). Then dp[r][c] = max(1, min(dp[r+1][c], dp[r][c+1]) - a[r][c]). Forwards min-sum is a different (wrong) problem.

Hint for LC 741 Cherry Pickup

Two paths of n-1 down/right steps. State (r1, c1, r2); c2 = r1+c1-r2. Add cell cherries once if the two sit on the same cell. Transition: 4 pairs of (down/right, down/right). Walk in increasing r1+c1.

Recap

  • Down/right grids are DAGs. Row-major is the topo order.
  • dp[r][c] combines up and left (plus the cell for costs).
  • Obstacles write 0 / +inf and contribute nothing.
  • Roll one row left-to-right for unique paths.
  • 4-way shortest path is BFS, not this page, unless a rank decreases.
dp[r][c] = up + left (or min + cell) | first row/col prefix | roll one row L-to-R
