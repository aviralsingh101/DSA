Knapsack Family

A second dimension that is a remaining budget — 0/1, unbounded, and bounded knapsack are the same table with three different loop directions.

Medium 26 min read Prerequisites: DP Foundations knapsack 0/1 unbounded P0

Why this exists

Knapsack is the first time a DP state needs two arguments: how many items you have considered, and how much capacity is left. That extra axis is the model for every "budget / weight / sum / volume" problem you will meet, including subset-sum, partition, coin change, and target-sum.

The family splits on whether each item may be used once (0/1), infinitely (unbounded), or up to c_i times (bounded). Those three are not three algorithms. They are three ways to iterate the same recurrence so that you do or do not reuse an item in one pass.

Pseudo-polynomial time O(nW) is the constraint tell. If W is 1e9 the table does not fit and you need meet-in-the-middle or a greedy/convex structure. If W is 1e4 and n is 100, this page is the intended solution.

dp[i][w] = best value using a prefix of i items and capacity exactly (or at most) w. 0/1 walks w downwards in the rolled array; unbounded walks w upwards.

Recognise this pattern

Say yes when you see

  • Items with a weight and a value, a capacity W, maximise value or test reachability
  • Subset-sum / partition-equal-subset / last-stone-weight II
  • Coin change: fewest coins or number of combinations
  • "Pick each at most once" vs "unlimited supply" in the statement
  • n * W fits in 1e7 .. 1e8

Not this pattern when

  • W is 1e9 and n is 40 → meet-in-the-middle, not a W-table
  • Items interact beyond a single budget (two capacities) → 3D knapsack or two rolls
  • Fractional items → greedy by value/weight, not DP
  • The "weight" is actually a time on a DAG → DAG DP, not knapsack

Constraint tell: n ≤ 100, W ≤ 10⁴ is the textbook signature. O(nW) time and O(W) extra after rolling. Values and ways need long. W = 1e9 is a hard no.

The 2D table and the roll direction

0/1: dp[i][w] = max(dp[i-1][w], dp[i-1][w-wt] + val) if w ≥ wt, else skip. Item i is considered once, against a table that does not yet contain it.

Rolling to long[] dp of size W+1: iterate items outside, and w from W down to wt so that dp[w-wt] is still the previous item's row. Unbounded flips that: w from wt up to W so you do reuse the current item. Subset-sum is the boolean special case (val = 1 or just OR). Coin-change fewest is unbounded min. Coin-change combinations is unbounded += with the coin loop outside so that {1,2} is counted once, not as 1-then-2 and 2-then-1.

After processing a prefix of items, dp[w] is the best value (or ways, or possibility) using capacity w and only those items, with the reuse rule of the family you chose.

0/1: w ↓    unbounded: w ↑
The direction is the algorithm

Ascending w on a 0/1 problem lets an item be taken many times in one pass. Descending w on unbounded forbids reuse and under-counts. Draw one row and mark whether dp[w-wt] is "old" or "new" before you pick the for-loop.

Bounded via binary splitting

c copies of weight wt become copies of 1, 2, 4, ... up to c, each a 0/1 item. That is O(n log C) 0/1 items and is usually simpler than a third nested loop over take-count.

Which knapsack loop?

Algorithm

  1. Identify the family: 0/1, unbounded, or bounded.
  2. State: dp[w] = best / ways / possible with capacity w (rolled), after a prefix of items.
  3. Allocate long[] (or boolean[]) of W+1. dp[0] = 0 (value) or 1 (ways) or true.
  4. For each item walk w in the correct direction.
  5. 0/1: for w = W; w >= wt; w-- : dp[w] = max(dp[w], dp[w-wt] + val).
  6. Unbounded: the same line with w++ from wt.
  7. Read dp[W] (or max over w, or dp[sum/2] for partition).

Java implementation

JavaKsRec.java
public class KsRec {
    
        static int rec(int[] wt, int[] val, int i, int left) {
            if (i == wt.length || left <= 0) {
                return 0;
            }
            int skip = rec(wt, val, i + 1, left);
            int take = 0;
            if (wt[i] <= left) {
                take = val[i] + rec(wt, val, i + 1, left - wt[i]);
            }
            return Math.max(skip, take);
        }
    
        public static void main(String[] args) {
            System.out.println(rec(new int[] {1, 2, 3}, new int[] {6, 10, 12}, 0, 5));
        }
        // Input : wt=[1,2,3] val=[6,10,12] W=5
        // Output: 22
    }
JavaKsMemo.java
import java.util.Arrays;
    
    public class KsMemo {
    
        static int rec(int[] wt, int[] val, int i, int left, int[][] memo) {
            if (i == wt.length || left <= 0) {
                return 0;
            }
            if (memo[i][left] != -1) {
                return memo[i][left];
            }
            int best = rec(wt, val, i + 1, left, memo);
            if (wt[i] <= left) {
                best = Math.max(best, val[i] + rec(wt, val, i + 1, left - wt[i], memo));
            }
            return memo[i][left] = best;
        }
    
        public static void main(String[] args) {
            int[] wt = {1, 2, 3}, val = {6, 10, 12};
            int W = 5;
            int[][] memo = new int[wt.length][W + 1];
            for (int[] row : memo) {
                Arrays.fill(row, -1);
            }
            System.out.println(rec(wt, val, 0, W, memo));
        }
        // Input : same
        // Output: 22
    }
JavaKsTab.java
public class KsTab {
    
        static int knapsack(int[] wt, int[] val, int W) {
            int n = wt.length;
            int[][] dp = new int[n + 1][W + 1];
            for (int i = 1; i <= n; i++) {
                for (int w = 0; w <= W; w++) {
                    dp[i][w] = dp[i - 1][w];
                    if (wt[i - 1] <= w) {
                        dp[i][w] = Math.max(dp[i][w], dp[i - 1][w - wt[i - 1]] + val[i - 1]);
                    }
                }
            }
            return dp[n][W];
        }
    
        public static void main(String[] args) {
            System.out.println(knapsack(new int[] {1, 2, 3}, new int[] {6, 10, 12}, 5));
        }
        // Input : same
        // Output: 22
    }
JavaKsRoll.java
public class KsRoll {
    
        static int knapsack(int[] wt, int[] val, int W) {
            int[] dp = new int[W + 1];
            for (int i = 0; i < wt.length; i++) {
                for (int w = W; w >= wt[i]; w--) {
                    dp[w] = Math.max(dp[w], dp[w - wt[i]] + val[i]);
                }
            }
            return dp[W];
        }
    
        public static void main(String[] args) {
            System.out.println(knapsack(new int[] {1, 2, 3}, new int[] {6, 10, 12}, 5));
        }
        // Input : same
        // Output: 22
    }

Edge cases and pitfalls

  • Ascending w on 0/1
    Item reused in one pass; knapsack becomes unbounded by accident.
    0/1: w--. Unbounded: w++. Say it out loud before the loop.
  • Ways vs permutations of coins
    Sum loop outside, coin inside counts 1+2 and 2+1 as two ways.
    Combinations: for each coin, for each w. Permutations: the opposite (usually not wanted).
  • dp[0] = 0 for ways
    Zero ways to make 0. Every cell stays 0.
    ways[0] = 1. value[0] = 0. possible[0] = true.
  • W = 1e9
    Allocating dp of size 1e9. MLE before TLE.
    If n ≤ 40, meet-in-the-middle. Otherwise the problem is not knapsack-DP.
  • int overflow on value * n
    n = 100, val = 1e9, sum does not fit in int.
    long[] dp.
  • Partition with odd sum
    Looking at dp[sum/2] when sum is odd. Integer division hides the impossibility.
    If sum is odd return false before allocating.

Interview follow-ups

Why is O(nW) called pseudo-polynomial?

W is a numeric magnitude, not a count of input tokens. Its bit length is log W, so the runtime is exponential in the input size of W. That is why knapsack is NP-hard and still easy when W is 1e4.

How do I reconstruct the items?

Full table: if dp[i][w] > dp[i-1][w] (or != for boolean after a take), item i was taken; set w -= wt[i-1] and i--. Otherwise i--. Rolling reconstruction needs an extra bit matrix or a second pass.

Two constraints (weight and volume)?

dp[w][v] or roll one axis. Time O(n W V). If both are large, it does not fit; look for a different state.

Meet-in-the-middle, briefly?

Split items into two halves, enumerate 2^{n/2} subsets each, store (weight, value) of the left, sort, and for each right subset binary-search the best left that still fits. n ≤ 40, W arbitrary.

Hint for AtCoder DP-E — invert the axes

W is 1e9, values sum to at most n*maxV = 1e5. So dp[v] = minimum weight to achieve value v, 0/1 on items, then the largest v with dp[v] ≤ W. Same family, state flipped. This is the move whenever one axis is huge and the other is not.

Hint for LC 494 Target Sum

Let P be the subset with + and N with -. P+N = sum, P-N = target, so P = (sum+target)/2. If that is not an integer or is negative, 0. Then count 0/1 ways to make P. Watch the +0 / ways[0]=1 base.

Recap

  • 0/1: w descending. Unbounded: w ascending.
  • dp[w] is the answer at capacity w after a prefix of items.
  • ways[0] = 1, value[0] = 0, possible[0] = true.
  • Combinations: coin loop outside.
  • O(nW) is pseudo-polynomial — refuse W = 1e9.
