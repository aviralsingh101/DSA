Digit DP

Count (or sum) the numbers ≤ R whose digits satisfy a local property by walking the decimal positions with a tight flag.

Hard 26 min read Prerequisites: DP Foundations digit DP tight counting P2

Why this exists

"How many numbers ≤ R have digit-sum S / no two adjacent equal / exactly K non-zero digits?" looks like a loop to R, which dies at R = 10^{18}. Digit DP walks the decimal representation left to right. At each position you choose a digit, remembering only a small state (position, tight, started, sum so far, last digit).

The tight flag is the whole trick. If the prefix so far matches R, the next digit may not exceed R's digit; otherwise 0..9 are free. A started flag avoids counting leading zeros as real digits when the property cares.

Range [L, R] is f(R) - f(L-1), with f(-1) = 0. That reduction is why every problem is "count ≤ R". P2 because the state design (what to remember so the property is Markov) is the contest, and tight/started bugs fail hidden tests.

A number ≤ R is a walk through digit positions where, as long as you have tied R, you are not allowed to step above its next digit. Dropping below frees you forever.

Recognise this pattern

Say yes when you see

  • Count / sum of integers in [L, R] with a digit property, R up to 10^18
  • Digit sum, last digit, adjacent difference, count of a certain digit
  • "Classy numbers", "numbers with no consecutive 1s in decimal"
  • The property depends on O(1) extra (sum ≤ 9*18, last digit, tight, started)
  • L and R given as strings of up to 18–100 digits

Not this pattern when

  • R ≤ 1e6 and the property is awkward → just loop
  • The property needs the whole number modulo a large coprime in a way that explodes the state
  • Prime in [L,R] → sieve / segmented sieve, not digit DP
  • Subsequence of digits matching a regex of length m → add m to the state (still digit DP if m is tiny)

Constraint tell: R ≤ 10^{18} (18 positions) or a 10^4-digit string. Extra state (sum, mod, last) must keep pos * extras * 2 * 2 under 1e7. Answers are long.

pos, tight, started, and the extras

Write the digits of R as d[0..len) most-significant first. rec(pos, sum, tight, started) = how many ways to fill positions pos..end. If pos == len, return 1 if the state is legal (and maybe started, if you do not count 0), else 0.

The next digit lo is 0; hi is tight ? d[pos] : 9. For each digit v in lo..hi, recurse with nsum = sum + (started || v>0 ? v : 0), ntight = tight && v==d[pos], nstarted = started || v>0. Memoize on those arguments. Dry-run: count numbers in 0..23 with digit sum 5. Length 2, d = [2,3]. The legal numbers are 5, 14, 23 — three of them. The table below walks the tight tree.

rec(pos, extra, tight, started) counts completions of the remaining suffix that stay ≤ R if tight, and that realise a legal extra-state at the end.

hi = tight ? d[pos] : 9    ntight = tight && v == d[pos]
Leading zeros

Until started is true, v = 0 does not add to the digit sum and does not set last-digit. The number 0 itself is the walk of all zeros; decide whether it satisfies the property (sum 0 usually yes if S=0).

f(R) - f(L-1)

Implement one function on a digit array. For L-1, handle L=0 as 0. String subtraction or parse L as long when it fits, then convert L-1 to digits.

The tight bit on n = 23

Algorithm

  1. Convert R to a digit array d[0..len) MSB first.
  2. State: pos, extra (sum / last / mod), tight, started.
  3. Base: pos == len → 1 if extra is legal (and handle 0).
  4. hi = tight ? d[pos] : 9. Loop v = 0..hi.
  5. Recurse with updated extra, ntight, nstarted. Add the results.
  6. Memoize on the tuple. Use long.
  7. [L,R] = f(R) - f(L-1).

Java implementation

JavaDigitRec.java
public class DigitRec {
    
        static int[] d;
        static int target;
    
        static long rec(int pos, int sum, boolean tight, boolean started) {
            if (pos == d.length) {
                return (started && sum == target) || (!started && target == 0) ? 1 : 0;
            }
            int hi = tight ? d[pos] : 9;
            long ans = 0;
            for (int v = 0; v <= hi; v++) {
                boolean nst = started || v > 0;
                int nsum = sum + (nst ? v : 0);
                if (nsum > target) {
                    continue;
                }
                ans += rec(pos + 1, nsum, tight && v == d[pos], nst);
            }
            return ans;
        }
    
        static long count(int n, int s) {
            d = String.valueOf(n).chars().map(c -> c - '0').toArray();
            target = s;
            return rec(0, 0, true, false);
        }
    
        public static void main(String[] args) {
            System.out.println(count(23, 5));
        }
        // Input : R=23, S=5
        // Output: 3
    }
JavaDigitMemo.java
import java.util.Arrays;
    
    public class DigitMemo {
    
        static int[] d;
        static int target;
        static long[][][][] memo;
    
        static long rec(int pos, int sum, int tight, int started) {
            if (pos == d.length) {
                return (started == 1 && sum == target) || (started == 0 && target == 0) ? 1 : 0;
            }
            if (memo[pos][sum][tight][started] != -1) {
                return memo[pos][sum][tight][started];
            }
            int hi = tight == 1 ? d[pos] : 9;
            long ans = 0;
            for (int v = 0; v <= hi; v++) {
                int nst = (started == 1 || v > 0) ? 1 : 0;
                int nsum = sum + (nst == 1 ? v : 0);
                if (nsum > target) {
                    continue;
                }
                ans += rec(pos + 1, nsum, (tight == 1 && v == d[pos]) ? 1 : 0, nst);
            }
            return memo[pos][sum][tight][started] = ans;
        }
    
        static long count(int n, int s) {
            d = String.valueOf(n).chars().map(c -> c - '0').toArray();
            target = s;
            memo = new long[d.length][s + 1][2][2];
            for (long[][][] a : memo) {
                for (long[][] b : a) {
                    for (long[] c : b) {
                        Arrays.fill(c, -1);
                    }
                }
            }
            return rec(0, 0, 1, 0);
        }
    
        public static void main(String[] args) {
            System.out.println(count(23, 5));
        }
        // Input : R=23, S=5
        // Output: 3
    }
JavaDigitTab.java
public class DigitTab {
    
        static long count(int n, int S) {
            int[] d = String.valueOf(n).chars().map(c -> c - '0').toArray();
            int len = d.length;
            // dp[pos][sum][tight][started] remaining from pos — fill pos = len down to 0
            long[][][][] dp = new long[len + 1][S + 1][2][2];
            for (int sum = 0; sum <= S; sum++) {
                dp[len][sum][0][1] = sum == S ? 1 : 0;
                dp[len][sum][1][1] = sum == S ? 1 : 0;
                dp[len][0][0][0] = S == 0 ? 1 : 0;
                dp[len][0][1][0] = S == 0 ? 1 : 0;
            }
            for (int pos = len - 1; pos >= 0; pos--) {
                for (int sum = 0; sum <= S; sum++) {
                    for (int tight = 0; tight < 2; tight++) {
                        for (int started = 0; started < 2; started++) {
                            int hi = tight == 1 ? d[pos] : 9;
                            long ans = 0;
                            for (int v = 0; v <= hi; v++) {
                                int nst = (started == 1 || v > 0) ? 1 : 0;
                                int nsum = sum + (nst == 1 ? v : 0);
                                if (nsum > S) {
                                    continue;
                                }
                                int nt = (tight == 1 && v == d[pos]) ? 1 : 0;
                                ans += dp[pos + 1][nsum][nt][nst];
                            }
                            dp[pos][sum][tight][started] = ans;
                        }
                    }
                }
            }
            return dp[0][0][1][0];
        }
    
        public static void main(String[] args) {
            System.out.println(count(23, 5));
        }
        // Input : R=23, S=5
        // Output: 3
    }

Edge cases and pitfalls

  • Forgetting tight
    Counting all len-digit strings, including those > R.
    hi depends on tight; ntight = tight && v==d[pos].
  • Leading zeros counted as digits
    Number 5 counted as tens=0, ones=5 with sum 0+5 but also as a 2-digit 05 with last-digit property treating 0 as last.
    started flag. Zeros before the first non-zero do not update extra.
  • f(R) - f(L) instead of f(L-1)
    Drops L or double-counts, depending on inclusivity.
    Closed range [L,R] = f(R) - f(L-1). L=0 → just f(R).
  • Memo key missing a flag
    Same pos and sum reused for tight and non-tight, mixing answers.
    Every argument of rec is part of the key, including tight and started.
  • int for the answer
    Count of 18-digit numbers is up to 1e18.
    long. Modulus if the statement asks.
  • target == 0 and the number 0
    started stays false all the way; you return 0 and miss the empty/zero case, or return 1 and overcount.
    Decide explicitly: !started && target==0 is the number 0.

Interview follow-ups

Why is dropping below R irreversible?

The remaining suffix of R is some number T. Once your prefix is already strictly smaller, any suffix of the right length is still ≤ R. So tight never turns back on. That is why one bit suffices.

Do I need started if I only care about digit sum?

Leading zeros add 0 to the sum, so for pure digit-sum you can skip started. You need it as soon as "count of digits", "last digit", or "no leading zero in the output number" matters. Keeping it always is cheaper than debugging.

How do I handle L and R as 1000-digit strings?

f on a char array. For L-1, decrement the digit string (borrow). Do not parse as long. Memo dimension pos ≤ 1000 is fine.

Is this related to automata?

Yes. The extra state is the automaton of the property; tight is the automaton of ≤ R. Digit DP is counting walks of length len on the product automaton.

Hint for CF 1036C Classy Numbers

A classy number has at most 3 non-zero digits. State = (pos, nonZeroCount, tight). started is implied by count>0. n ≤ 10^18, q ≤ 1e4, so memo per query (reset by a vis-stamp). [L,R] = f(R)-f(L-1).

Hint for AtCoder DP-S

K has up to 10000 digits, D ≤ 100. Count numbers ≤ K whose digit sum is 0 mod D. State (pos, sumMod, tight). Mod 1e9+7. Do not parse K as long. Subtract 0 if you excluded 0 and the problem includes it — read the statement; usually 0 is allowed and has sum 0.

Recap

  • Walk digits MSB first with tight (and usually started).
  • hi = tight ? d[pos] : 9. ntight = tight && v==d[pos].
  • Extra state holds the property (sum, last, mask, mod).
  • [L,R] = f(R) - f(L-1), long answers.
  • Memo every argument including the two flags.
