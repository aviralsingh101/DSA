Interval DP

The state is a subarray s[l..r], and the last cut (or last burst, or last merge) splits it into two smaller intervals.

Medium 26 min read Prerequisites: String DP interval DP MCM burst balloons P1

Why this exists

Interval DP is the family where the natural subproblem is a contiguous segment. Matrix-chain multiplication, bursting balloons, palindrome partitioning, merging stones, and "min cost to cut a stick" all ask: given [l, r], what is the best cost, and the last operation happens at some k in between.

The order is by interval length. Length 1 is the base; a length-L interval only reads strictly shorter pieces. That is a DAG on O(n²) states with an O(n) transition, hence O(n³) — the constraint tell n ≤ 400.

P1 because the modelling (what is the last action?) is the whole trick, and because you must pad sentinels for balloons / cuts. Once the recurrence is written, the loops are mechanical.

Name the last cut k inside [l, r]. Then dp[l][r] combines dp[l][k] and dp[k][r] with the cost of doing that last operation now.

Recognise this pattern

Say yes when you see

  • Min / max cost to process a subarray by repeatedly merging / bursting / cutting
  • Matrix-chain, burst balloons, min cost to cut a stick, merging stones
  • Palindrome partition min cuts, longest palindromic subsequence (already seen)
  • n ≤ 400, O(n³) fits; n ≤ 100 is even more comfortable
  • The statement talks about a last remaining element or a last cut

Not this pattern when

  • Non-contiguous subsets → knapsack / bitmask
  • n = 2000 with O(n³) → you need Knuth / D&C opt (later page) or a different state
  • The "interval" is a sliding window with a monotone property → two pointers
  • Only two strings' prefixes → string DP, not a third loop over k

Length, then left, then the cut

Burst balloons as the running example. Pad a with 1s on both ends. dp[l][r] = max coins from bursting everything strictly between l and r, with a[l] and a[r] still alive. The last balloon burst in (l, r) is k, scoring a[l]*a[k]*a[r] plus the two solved interiors.

Fill by increasing r-l. For length 1 interiors the answer is 0 (nothing to burst). The global answer is dp[0][n+1] after padding. MCM is the same loops: dp[i][j] min cost to multiply matrices i..j, last split k, cost = dp[i][k] + dp[k+1][j] + rows[i]*cols[k]*cols[j].

dp[l][r] is the best cost (or coins) to finish the open interval (l, r) while the boundaries stay alive.

dp[l][r] = max/min over k of dp[l][k] + dp[k][r] + cost(l,k,r)
Pad, then never burst the sentinels

Balloons and stick-cuts become uniform only after you add fake boundaries. Loops over k run from l+1 to r-1. Bursting a sentinel is a meaningless index error or a zero-score bug.

Why O(n³)

O(n²) pairs (l, r) and O(n) candidate k per pair. Nothing is O(n²) unless you can drop the k-loop (precomputed palindrome table, Knuth on the argmin).

Algorithm

  1. Pad sentinels if the cost of an operation uses outside neighbours.
  2. State: dp[l][r] = best on the open interval (l, r).
  3. Base: r = l+1 → 0 (empty interior).
  4. For len = 2 .. n+1, for l, r = l+len: try every k in (l, r).
  5. Transition: combine dp[l][k], dp[k][r], and cost(l,k,r).
  6. Take max or min over k.
  7. Answer is dp[0][padded n+1] (balloons) or dp[0][n-1] (MCM on dimensions).

Java implementation

JavaBurstRec.java
public class BurstRec {
    
        static int rec(int[] a, int l, int r) {
            int best = 0;
            for (int k = l + 1; k < r; k++) {
                best = Math.max(best, rec(a, l, k) + rec(a, k, r) + a[l] * a[k] * a[r]);
            }
            return best;
        }
    
        static int maxCoins(int[] nums) {
            int n = nums.length;
            int[] a = new int[n + 2];
            a[0] = 1;
            a[n + 1] = 1;
            System.arraycopy(nums, 0, a, 1, n);
            return rec(a, 0, n + 1);
        }
    
        public static void main(String[] args) {
            System.out.println(maxCoins(new int[] {3, 1, 5}));
        }
        // Input : [3, 1, 5]
        // Output: 35
    }
JavaBurstMemo.java
import java.util.Arrays;
    
    public class BurstMemo {
    
        static int rec(int[] a, int l, int r, int[][] memo) {
            if (r - l <= 1) {
                return 0;
            }
            if (memo[l][r] != -1) {
                return memo[l][r];
            }
            int best = 0;
            for (int k = l + 1; k < r; k++) {
                best = Math.max(best, rec(a, l, k, memo) + rec(a, k, r, memo) + a[l] * a[k] * a[r]);
            }
            return memo[l][r] = best;
        }
    
        public static void main(String[] args) {
            int[] nums = {3, 1, 5};
            int n = nums.length;
            int[] a = new int[n + 2];
            a[0] = a[n + 1] = 1;
            System.arraycopy(nums, 0, a, 1, n);
            int[][] memo = new int[n + 2][n + 2];
            for (int[] row : memo) {
                Arrays.fill(row, -1);
            }
            System.out.println(rec(a, 0, n + 1, memo));
        }
        // Input : [3, 1, 5]
        // Output: 35
    }
JavaBurstTab.java
public class BurstTab {
    
        static int maxCoins(int[] nums) {
            int n = nums.length;
            int[] a = new int[n + 2];
            a[0] = a[n + 1] = 1;
            System.arraycopy(nums, 0, a, 1, n);
            int[][] dp = new int[n + 2][n + 2];
            for (int gap = 2; gap <= n + 1; gap++) {
                for (int l = 0; l + gap <= n + 1; l++) {
                    int r = l + gap;
                    for (int k = l + 1; k < r; k++) {
                        dp[l][r] = Math.max(dp[l][r],
                                dp[l][k] + dp[k][r] + a[l] * a[k] * a[r]);
                    }
                }
            }
            return dp[0][n + 1];
        }
    
        public static void main(String[] args) {
            System.out.println(maxCoins(new int[] {3, 1, 5}));
        }
        // Input : [3, 1, 5]
        // Output: 35
    }

Edge cases and pitfalls

  • Filling by l, r increasing, not by length
    dp[l][k] is still 0 because that interval is longer in one index and not yet computed.
    Outer loop is gap / length. Then l. Then k.
  • Forgetting the pad
    Bursting the first balloon uses a missing left neighbour.
    a = [1] + nums + [1]. k runs in (l, r).
  • Using closed [l,r] including bursting l
    Then the neighbour formula double-counts or uses already-burst values.
    Open interval: l and r stay alive. Last burst is strictly inside.
  • int overflow on a[l]*a[k]*a[r]
    Values 100, n=300, the product and the sum of products can exceed int.
    long, or the problem's guaranteed bound.
  • Merging stones without the (len-1)%(K-1)==0 check
    You cannot merge an arbitrary pile count into one with K-way merges.
    A pile of p stones is mergeable iff (p-1) % (K-1) == 0.
  • n³ at n=2000
    8e9 operations.
    Knuth / D&C / a different model. See DP Optimisations.

Interview follow-ups

Why last, not first?

The first burst of a balloon would leave a new neighbour pair that is hard to name as two independent intervals. The last remaining balloon k splits the original range into two interiors that never interact except through k. Always try "last action" when first action fails to decompose.

When is the k-loop droppable?

When the extra cost does not depend on a free k, or when a boolean (is palindrome) can be precomputed. Knuth drops it down to amortised O(1) per interval when the quadrangle inequality holds.

How do I reconstruct the burst order?

Store bestK[l][r]. The last burst is that k; recurse on (l,k) and (k,r). The actual time order is interiors first, k last — reverse of the stored last-k.

Is LPS interval DP or string DP?

Both. LPS as LCS(s, rev(s)) is two-string DP. LPS as dp[i][j] on one string with a match using i+1,j-1 is interval DP of a simpler transition (no k-loop). Same answer.

Hint for CF 607B Zuma

dp[l][r] = min removals of a[l..r] as a Zuma interval. If a[l]==a[r], you may treat them as collapsing with the interior (dp[l+1][r-1]). Also try a split k. Fill by length. n ≤ 500, O(n³) is intended.

Hint for AtCoder DP-N Slimes

Cost to merge [l, r] is the sum of that range (prefix sums) plus the two child merges. dp[l][r] = pref[r]-pref[l-1] + min over k of dp[l][k]+dp[k+1][r]. Standard MCM with a prefix-sum cost.

Recap

  • State is an interval [l, r] (often open).
  • Last action at k splits into two strictly smaller intervals.
  • Fill by increasing length / gap.
  • Pad sentinels for balloons and stick cuts.
  • O(n³), n ≤ 400. Faster needs Knuth or a dropped k-loop.
