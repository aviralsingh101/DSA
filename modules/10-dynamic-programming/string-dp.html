String DP

Two indices into one or two strings: LCS, edit distance, palindrome partitions — the cell (i, j) is the answer for the two prefixes.

Medium 26 min read Prerequisites: Grid DP LCS edit distance palindrome P0

Why this exists

String DP is grid DP on the prefixes of one or two strings. dp[i][j] answers a question about s[0..i) and t[0..j) (or about s[i..j] for palindromes). The alphabet never appears in the state: only whether two characters match, and the three standard moves (drop s, drop t, or consume both).

LCS and edit distance are the same table with a different combine. Palindrome subsequence is LCS(s, reverse(s)). Palindrome substring / min-cut is a different axis: intervals of one string, which is the bridge to the next page.

n, m ≤ 1000 is the signature: O(nm) time, O(min(n,m)) space after rolling. Reconstruction of the LCS or the alignment walks the table back from (n, m).

If s[i-1] == t[j-1], the pair is free (or worth +1). If not, you must drop one side or substitute. Those three neighbours are the only from-cells.

Recognise this pattern

Say yes when you see

  • Longest common subsequence / substring of two strings
  • Edit / Levenshtein distance, insert-delete-replace
  • Distinct subsequences, wildcard matching, regex DP
  • Longest palindromic subsequence = LCS with the reverse
  • Interleaving string, wildcards, min ASCII delete sum

Not this pattern when

  • Longest common substring can also be DP, but sliding / suffix array is often intended
  • Anagrams / character counts only → hashing, not a 2D table
  • LIS in an array of numbers → previous page, even if you cast to a string
  • Interval palindrome cuts with n ≤ 400 and a third loop → interval DP

Prefixes (i, j) and three neighbours

LCS: if s[i-1]==t[j-1] then dp[i][j] = dp[i-1][j-1]+1, else max(dp[i-1][j], dp[i][j-1]). First row and col are 0 (empty prefix). This is the dry-run table.

Edit distance: match copies the diagonal; otherwise 1 + min(insert = left, delete = up, replace = diagonal). First row is 0..m (insert all), first col is 0..n (delete all). Rolling: keep the previous row, or even two cells if you walk carefully. Reconstruction: from (n,m), if match follow diagonal, else follow the neighbour that produced the value, emitting the operation.

dp[i][j] is the LCS length (or edit distance) of the prefixes s[0..i) and t[0..j).

match: diag + 1    mismatch: max(up, left)
Substring vs subsequence

Substring: on mismatch, dp[i][j] = 0, and the answer is the global max in the table, not dp[n][m]. Subsequence: on mismatch, you may still drop a character and keep a positive length. Mixing them is a common WA.

LPS without building the reverse

dp[i][j] = LPS of s[i..j]. If s[i]==s[j], 2+dp[i+1][j-1], else max(dp[i+1][j], dp[i][j-1]). That is interval DP on one string; fill by increasing length. Same answer as LCS(s, reverse(s)).

Which string table?

Algorithm

  1. Index prefixes as i = 0..n, j = 0..m with 0 = empty.
  2. Base: first row and col (0 for LCS, 0..n / 0..m for edit).
  3. For i = 1..n, j = 1..m: if s[i-1]==t[j-1] take the match branch, else the mismatch branch.
  4. LCS mismatch: max(up, left). Edit mismatch: 1+min(up,left,diag).
  5. Roll the previous row if you only need the number.
  6. Reconstruct from (n,m) following the neighbour that matches the recurrence.
  7. LPS: either LCS(s, reverse(s)) or interval dp on one string.

Java implementation

JavaLcsRec.java
public class LcsRec {
    
        static int lcs(String s, String t, int i, int j) {
            if (i == s.length() || j == t.length()) {
                return 0;
            }
            if (s.charAt(i) == t.charAt(j)) {
                return 1 + lcs(s, t, i + 1, j + 1);
            }
            return Math.max(lcs(s, t, i + 1, j), lcs(s, t, i, j + 1));
        }
    
        public static void main(String[] args) {
            System.out.println(lcs("abcde", "ace", 0, 0));
        }
        // Input : s=abcde t=ace
        // Output: 3
    }
JavaLcsMemo.java
import java.util.Arrays;
    
    public class LcsMemo {
    
        static int lcs(String s, String t, int i, int j, int[][] memo) {
            if (i == s.length() || j == t.length()) {
                return 0;
            }
            if (memo[i][j] != -1) {
                return memo[i][j];
            }
            if (s.charAt(i) == t.charAt(j)) {
                return memo[i][j] = 1 + lcs(s, t, i + 1, j + 1, memo);
            }
            return memo[i][j] = Math.max(lcs(s, t, i + 1, j, memo), lcs(s, t, i, j + 1, memo));
        }
    
        public static void main(String[] args) {
            String s = "abcde", t = "ace";
            int[][] memo = new int[s.length()][t.length()];
            for (int[] row : memo) {
                Arrays.fill(row, -1);
            }
            System.out.println(lcs(s, t, 0, 0, memo));
        }
        // Input : s=abcde t=ace
        // Output: 3
    }
JavaLcsTab.java
public class LcsTab {
    
        static int lcs(String s, String t) {
            int n = s.length(), m = t.length();
            int[][] dp = new int[n + 1][m + 1];
            for (int i = 1; i <= n; i++) {
                for (int j = 1; j <= m; j++) {
                    if (s.charAt(i - 1) == t.charAt(j - 1)) {
                        dp[i][j] = dp[i - 1][j - 1] + 1;
                    } else {
                        dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);
                    }
                }
            }
            return dp[n][m];
        }
    
        public static void main(String[] args) {
            System.out.println(lcs("abcde", "ace"));
        }
        // Input : s=abcde t=ace
        // Output: 3
    }
JavaLcsRoll.java
public class LcsRoll {
    
        static int lcs(String s, String t) {
            if (s.length() < t.length()) {
                String tmp = s; s = t; t = tmp;
            }
            int[] dp = new int[t.length() + 1];
            for (int i = 1; i <= s.length(); i++) {
                int prev = 0;
                for (int j = 1; j <= t.length(); j++) {
                    int tmp = dp[j];
                    if (s.charAt(i - 1) == t.charAt(j - 1)) {
                        dp[j] = prev + 1;
                    } else {
                        dp[j] = Math.max(dp[j], dp[j - 1]);
                    }
                    prev = tmp;
                }
            }
            return dp[t.length()];
        }
    
        public static void main(String[] args) {
            System.out.println(lcs("abcde", "ace"));
        }
        // Input : s=abcde t=ace
        // Output: 3
    }

Edge cases and pitfalls

  • Indexing charAt(i) against dp[i] without the empty row
    Off-by-one: s[i] vs prefix i+1. The table is n+1 by m+1 for a reason.
    dp[i][j] uses s.charAt(i-1) and t.charAt(j-1).
  • LCS recurrence for substring
    Keeping max(up,left) on a mismatch when the problem wants a contiguous block.
    Substring: mismatch → 0, answer = max over the table.
  • Rolling without saving the diagonal
    dp[j] is overwritten before you need it as dp[i-1][j-1].
    Stash prev = old dp[j] (which is up-right after you write, i.e. the old diagonal for the next j).
  • Edit distance first row = 0
    Inserting m characters into empty s costs m, not 0.
    dp[0][j] = j, dp[i][0] = i.
  • Modulo on LCS length
    Lengths do not wrap. Ways-of-LCS do.
    Only modulus counting problems. Lengths are int.
  • Wildcard '*' as a single char
    Treating '*' like '?' instead of "empty or eat one and stay".
    dp[i][j] |= dp[i][j-1] (eat empty) and dp[i-1][j] (eat s[i-1], star remains).

Interview follow-ups

How do I print one LCS?

From (n,m): if s[i-1]==t[j-1], prepend that char and go diag. Else go to the neighbour that equals dp[i][j] (prefer up or left, your choice). Reverse at the end. Need the full table.

Is LCS NP-hard?

For two strings it is O(nm). For an arbitrary number of strings it is NP-hard. That is why interviews stick to two.

Can I do better than O(nm)?

Slightly, with Four-Russians or bit-parallel tricks, and Hunt-Szymanski when the LCS is short. In contests, O(nm) at n=5000 with a rolled int[] is the expected work.

Wildcard vs regex DP?

'?' and '*' globbing is LC 44. Full regex with '*' meaning "previous char, 0 or more" is LC 10 and the star binds to the previous token, so the transition is slightly different. Both are boolean string DP.

Hint for AtCoder DP-F

n, m ≤ 3000, so O(nm) memory of 9e6 ints is tight but fine. Keep the full table (or prev-pointers) and walk back to emit the characters. Rolling only the values is not enough because you must reconstruct.

Hint for LC 72

dp[0][j]=j, dp[i][0]=i. Match: dp[i-1][j-1]. Else 1+min(insert dp[i][j-1], delete dp[i-1][j], replace dp[i-1][j-1]). That is the entire algorithm.

Recap

  • dp[i][j] is the answer for prefixes i and j.
  • LCS match: diag+1; mismatch: max(up, left).
  • Edit: match copies diag; else 1+min of three.
  • Substring resets to 0 on mismatch; subsequence does not.
  • Roll one row if you only need the number; keep the table to reconstruct.
