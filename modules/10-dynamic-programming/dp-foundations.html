Module 10 · Dynamic Programming

DP Foundations

DP is not a list of named tricks — it is a pipeline: name the state, write the transition, fix the base, pick an order (or memoize), then shave the space.

Easy 24 min read Prerequisites: Recurrences, Constraints → Complexity DP state memoization P0

Why this exists

Most interview DP failures are not arithmetic. They are a missing definition of what a state means, a transition that does not cover every way to form that state, or a loop that reads a cell before it has been written. The named problems (knapsack, LIS, LCS, digit DP) are the same pipeline with different state shapes.

The reason the pipeline is worth drilling is that it is mechanical. Once you can write "dp[i] = number of ways to climb i stairs" and "dp[i] = dp[i-1] + dp[i-2]" without blinking, every later page on this module is a change of coordinates, not a new subject.

Climbing stairs / Fibonacci is the smallest complete example: overlapping subproblems, an optimal-substructure recurrence, a base case, a linear order, and a rolling-array space optimisation. We run that example to the ground so the later families can assume the vocabulary.

A DP state is a question with a numeric answer. The transition is how that answer is assembled from strictly smaller questions. If you cannot say those two sentences out loud, you are not ready to code.

Recognise this pattern

Say yes when you see

  • "Number of ways" / "minimum cost" / "can you reach" on a structure with overlapping subproblems
  • A recurrence that would be exponential if you recurse without storing answers
  • The statement smells like recursion plus "do not recompute"
  • n is 40..1e4 and a 1D or 2D table of that size fits
  • You can name a suffix/prefix/subarray/subset whose answer depends only on smaller ones

Not this pattern when

  • Subproblems do not overlap (pure divide-and-conquer) → no table, just the recurrence
  • A greedy choice is provably safe → do not force DP
  • The graph of states has cycles with no decreasing rank → not a DAG of states; rethink
  • n = 1e5 and your first state is O(n²) → the state is wrong, not the idea of DP

Constraint tell: A table of size S and a transition of cost T must have S · T under about 10⁸. That single inequality is how you reject an over-large state before you write it. Answers that sum ways usually need long and a modulus.

The five-line pipeline

State. Write a sentence: dp[i] = number of ways to climb i stairs taking steps of 1 or 2. Until that sentence is unambiguous, do not open an editor.

Transition and base. The last step was 1 or 2, so dp[i] = dp[i-1] + dp[i-2]. Bases: dp[0] = 1 (one way to stand still) and dp[1] = 1. Every index the transition reads must be defined. Order or memo, then space. Recurse + hashmap of seen states, or fill i = 2 .. n left to right. Only the last two cells are live, so a pair of integers replaces the array. That is the whole subject, at this scale.

DP = DAG of questions. An edge A ← B means "A's answer uses B's answer". A valid order is any topological order of that DAG. Memoized recursion discovers the order for you; tabulation requires you to write it.

dp[i] = ways to climb i = dp[i-1] + dp[i-2]
Overlapping + optimal substructure

Overlapping: the same (i) is asked from many parents. Optimal substructure: a best/count answer for i is assembled from best/count answers for smaller i, not from some hidden extra that the state forgot. If the "how we got here" still matters, the state is incomplete (add a parameter).

Memo first in an interview

Write the recursive function that computes the state, add a cache keyed by the arguments, then — if time remains — invert it into loops. Interviewers score the recurrence. The loops are polish.

The pipeline you run on every later page

Algorithm

  1. Write the state sentence with every argument named.
  2. Write the transition as a formula that only reads strictly smaller states.
  3. Write the bases and check the first recursive index against them.
  4. Estimate S × T against the constraint. If it dies, shrink the state.
  5. Implement memoized recursion first, on the dry-run sample.
  6. Invert into a loop in a legal order (here, increasing i).
  7. Roll the array if only a constant window is live.
  8. Reconstruct if asked: store the argmax / parent of each transition.

Java implementation

JavaClimbRec.java
public class ClimbRec {
    
        static int ways(int n) {
            if (n < 0) {
                return 0;
            }
            if (n == 0) {
                return 1;
            }
            return ways(n - 1) + ways(n - 2);
        }
    
        public static void main(String[] args) {
            System.out.println(ways(6));
        }
        // Input : n = 6
        // Output: 13
    }
JavaClimbMemo.java
import java.util.Arrays;
    
    public class ClimbMemo {
    
        static int ways(int n, int[] memo) {
            if (n < 0) {
                return 0;
            }
            if (n == 0) {
                return 1;
            }
            if (memo[n] != -1) {
                return memo[n];
            }
            return memo[n] = ways(n - 1, memo) + ways(n - 2, memo);
        }
    
        public static void main(String[] args) {
            int n = 6;
            int[] memo = new int[n + 1];
            Arrays.fill(memo, -1);
            System.out.println(ways(n, memo));
        }
        // Input : n = 6
        // Output: 13
    }
JavaClimbTab.java
public class ClimbTab {
    
        static int ways(int n) {
            if (n == 0) {
                return 1;
            }
            int[] dp = new int[n + 1];
            dp[0] = 1;
            dp[1] = 1;
            for (int i = 2; i <= n; i++) {
                dp[i] = dp[i - 1] + dp[i - 2];
            }
            return dp[n];
        }
    
        public static void main(String[] args) {
            System.out.println(ways(6));
        }
        // Input : n = 6
        // Output: 13
    }
JavaClimbRoll.java
public class ClimbRoll {
    
        static int ways(int n) {
            int prev2 = 1, prev1 = 1;
            for (int i = 2; i <= n; i++) {
                int cur = prev1 + prev2;
                prev2 = prev1;
                prev1 = cur;
            }
            return prev1;
        }
    
        public static void main(String[] args) {
            System.out.println(ways(6));
        }
        // Input : n = 6
        // Output: 13
    }

Complexity

Time O(n) memo / tab / roll; O(φ^n) naked recursion Space O(n) memo/tab; O(1) roll; O(n) recursion depth

There are n + 1 states. Each transition reads two earlier cells in O(1):

T = Θ(n) once each state is stored

Naked recursion is the Fibonacci tree, Θ(φn). That gap is exactly what "overlapping subproblems" means, measured.

Edge cases and pitfalls

  • dp[0] = 0 for ways
    Zero ways to do nothing. Then every later cell is 0.
    Empty plan is one way for counting problems. Empty cost is 0 for min-cost.
  • Off-by-one on n vs n+1 allocation
    dp of length n, then write dp[n].
    If the state is "first i" or "value i", allocate n+1 and be explicit about whether i is 0-based size or 1-based value.
  • Reading a cell you have not written
    Looping i downwards when the transition reads i-1.
    Draw the dependency arrow; walk against it. Memo hides this; tabulation does not.
  • int overflow on ways
    Climbing stairs is tiny; knapsack-style counts are not.
    long, and the modulus in the addition if the statement gives one.
  • Forgetting the state still depends on a choice you discarded
    House-robber-style "take or skip" encoded as a 1D array that cannot tell whether i was taken.
    Either store two values (took / skipped) or define dp[i] as "best on prefix i with i decided" so the transition can refer to i-2.
  • Calling it DP when there is no overlap
    Memoizing a tree recursion whose every state is unique. You pay for a hashmap and gain nothing.
    If each state is hit once, it is just recursion (or a tree DP that still stores per-node answers, which is overlap across queries).

Interview follow-ups

Memo or tabulation, which do I write first?

Memo. It is the recurrence plus a cache, and it only computes reachable states. Tabulation needs an order and fills everything. After the memo is correct, inverting it is mechanical and often faster by a constant (no call stack, better locality).

What if the dependency graph is not obvious?

If every transition strictly decreases some rank (i, i+j, popcount, remaining capacity), an order exists. If you cannot name a rank, you probably have a cycle and the state is wrong (shortest-path-on-states, not DP).

How do I know the state is complete?

After writing the transition, ask: "is there any information about the past that I still need and did not put in the args?" If yes, add a parameter or change the meaning of the index. Completeness is the only hard part of DP.

Why is climb-stairs Fibonacci and not 2^n?

Sequences of 1s and 2s that sum to n, not every binary string. The recurrence counts compositions with parts in {1,2}, whose generating function is 1/(1-x-x^2), i.e. Fibonacci. 2^n would be if each stair independently had a yes/no decision.

Hint for CSES Dice Combinations

dp[x] = ways to sum to x with faces 1..6, order matters (compositions). dp[0]=1, dp[x] += dp[x-f] for f=1..6 if x-f ≥ 0, mod 1e9+7. That is climb-stairs with k = 6. If order did not matter it would be coin change unbounded, a different loop order — see knapsack.

Hint for CF 455A Boredom

Taking value v deletes v-1 and v+1. Compress to counts cnt[v], then house-robber on the value line: dp[v] = max(dp[v-1], dp[v-2] + v*cnt[v]). The state is the value, not the index. long for the answer.

Recap

  • State sentence, then transition, then base, then order.
  • Memo is the recurrence plus a cache; tabulation is the same DAG in loops.
  • S × T must fit the constraint before you code.
  • Roll the window when only the last few states are live.
  • Counting uses long / modulus; empty ways = 1, empty cost = 0.
