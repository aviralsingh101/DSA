Max Flow / Min Cut

Max flow equals min cut. Edmonds-Karp BFS-augments in O(V E²); Dinic layers + blocking flow is the contest default.

Hard 28 min read Prerequisites: BFS max flow min cut Dinic P2

Why this exists

You run a network of pipes from a source tank s to a sink tank t. Each pipe has a capacity, the most it can carry, and junctions other than s and t cannot store water: whatever flows in must flow out. A flow is an assignment of numbers to pipes that respects those two rules. The obvious greedy — pick a path, fill it, forget it — gets stuck. Push 2 along s → a → t on a network that also has a direct s → t of capacity 1 and you may block a combination that could have carried 3. Trying every subset of paths is exponential; you need a way to undo a greedy push when a better combination appears.

The undo is built into the residual graph. When you push f units along u → v, you reduce the leftover forward capacity by f and create (or increase) a backward residual edge v → u of capacity f. That backward edge is not a physical pipe; it is a permission slip that says "you may send flow backward, which is the same as cancelling previously forwarded flow". A later path that uses v → u is undoing the earlier decision so those units can be rerouted. Ford-Fulkerson finds any s-t residual path and pushes the bottleneck. Edmonds-Karp always takes a shortest residual path (a BFS) and is polynomial. Dinic builds a level graph and a blocking flow; on unit-capacity networks it is the contest default.

The same run answers a second question that looks physical. An s-t cut is a partition of the junctions into S containing the source and T containing the sink; its capacity is the total capacity of pipes that leave S for T — the pipes you would have to shut off to stop every drop. The max-flow min-cut theorem says the most you can push equals the cheapest such shutdown. In a problem statement the tell is "maximum throughput", "minimum capacity to disconnect", or a modelling sentence such as bipartite matching, project selection, or circulation with demands. The algorithm is twenty lines; the reduction is the interview.

A residual backward edge is an undo ticket for flow you already pushed. When no residual s-t path remains, the junctions still reachable from s are one side of a cheapest shutdown: every pipe leaving that set is full.

Recognise this pattern

Say yes when you see

  • Maximum throughput from s to t under capacities
  • Minimum capacity of an edge set whose removal disconnects s from t
  • Bipartite matching via unit flow (next page is the specialised view)
  • Project selection / closure — profit nodes to t, cost nodes from s
  • n a few hundred, m a few thousand — Dinic fits easily

Not this pattern when

  • Uncapacitated connectivity → DFS / bridges
  • Shortest path → Dijkstra; flow does not care about path length except inside Dinic levels
  • Min-cost flow when every unit has a price → MCMF, not this page
  • Undirected unweighted "min edges to disconnect" with unit capacities is flow, but also edge-connectivity via other theorems

Constraint tell: n ≤ 200 is Edmonds-Karp's comfortable window. n ≤ 2000 with unit capacities wants Dinic (or Hopcroft-Karp on a bipartite graph). Capacities up to 10⁵ need long for both the leftover residual and the answer. Every original pipe must be born with a reverse twin of capacity 0, otherwise a greedy first path cannot be undone and the algorithm stops below the true maximum.

Core idea and the invariant

Store the network as an edge list. For every original pipe u → v of capacity c, append a forward edge of residual c and a reverse twin of residual 0, and remember each twin's index so an update can touch both. After some flow f has been pushed on that pipe, the forward residual is c - f (room still left) and the backward residual is f (room to undo). An augmenting path is any s-t walk whose every residual is positive. The amount you push is the bottleneck, the smallest residual on that walk: subtract it along the walk and add it to every reverse twin. Adding to the reverse is the undo: a later walk that takes the twin is cancelling this push.

Edmonds-Karp finds the augmenting path with a BFS on residual > 0, so each augmentation is a shortest hop-path. Dinic first BFS-labels every junction with its residual distance from s, then DFS-pushes a blocking flow: it only walks edges with level[v] == level[u] + 1, and a current-edge pointer remembers that an exhausted edge will not come back inside this phase. When the DFS can no longer reach t, the level graph is blocked; rebuild levels and repeat until a BFS cannot reach t at all.

Walk the three-pipe sample in words. Capacities are s → a 3, a → t 2, s → t 1. The first BFS finds the one-hop path s-t and pushes 1; the forward residual s → t becomes 0 and a reverse t → s of 1 appears. The second BFS must go s-a-t, bottleneck min(3, 2) = 2, and the total becomes 3. The third BFS still reaches a (residual 1 remains on s → a) but cannot reach t, so the residual-reachable set is S = {s, a}. The pipes leaving S are a → t (capacity 2) and s → t (capacity 1), total 3, which equals the flow: that is the cheapest shutdown, physically the pipes you would have to close to isolate the sink.

Conservation: for every junction other than s and t, inflow equals outflow. Capacity: 0 ≤ f(e) ≤ c(e) on every pipe. When no residual s-t path exists, the residual-reachable set S is a min-cut and the flow value equals the total capacity of pipes leaving S.

In plain words, you keep pushing along leftover room (and along undo tickets) until the source side of the leftover network can no longer see the sink; the pipes that then sit on the boundary are all full, and that full boundary is the cheapest way to shut the network down.

Why a residual reverse edge lets flow be undone

Pushing f along u → v is a decision, not a law of physics. The reverse residual of capacity f is the ticket that lets a later path send f units back from v to u, which cancels those units on the original pipe and frees them to travel a different route. Without the twin, the first greedy path that used a scarce pipe would permanently block a better combination, and Ford-Fulkerson would stop below max flow. The reverse edge is not water flowing backward in the town; it is bookkeeping that says "this much of my earlier push may be reassigned".

What a min-cut means physically

An s-t cut is a fence: junctions on the source side S, junctions on the sink side T. Its capacity is the total size of the pipes that cross the fence from S to T — the pipes you would have to shut off (or the total capacity you would have to destroy) to stop every drop. The cheapest such fence is the min-cut. When the algorithm stops, residual-reachability from s names one cheapest fence: every pipe leaving that set is saturated, so no extra drop can sneak across, and the theorem says you cannot have been pushing more than that fence's capacity.

Algorithm

  1. Build the residual with a reverse twin of capacity 0. Every add(u, v, c) appends a forward edge and a reverse edge, each storing the other's index, because without the twin a greedy first path cannot be undone.
  2. Edmonds-Karp: BFS a residual path and push the bottleneck. Walk only residual > 0, take the shortest hop-path, subtract the bottleneck along it and add the same amount to every reverse twin so the push stays cancellable.
  3. Dinic: BFS levels, then DFS a blocking flow. Only walk edges with level[v] == level[u] + 1, and a current-edge pointer skips an exhausted residual inside the same phase; rebuild levels when the DFS can no longer reach t.
  4. Stop when a BFS cannot reach t at all. The value of the flow is the total leaving s (or entering t); that number will equal the capacity of the cut you read next.
  5. Read the min-cut from residual reachability. S is every junction a leftover-residual BFS from s can still see; the cut pipes are original edges u → v with u in S, v not in S, and they are all saturated.
  6. Store capacities and the answer in long. A pipe of capacity 10⁵ and a path of a few such pipes overflow an int residual and wrap into a fake leftover that looks like room to push.

Java implementation

JavaFordFulkerson.java
import java.util.*;
    public class FordFulkerson {
        static int bfs(int[][] cap, int s, int t, int[] par) {
            Arrays.fill(par, -1);
            par[s] = s;
            ArrayDeque<int[]> q = new ArrayDeque<>();
            q.add(new int[] {s, Integer.MAX_VALUE});
            while (!q.isEmpty()) {
                int[] cur = q.poll();
                int u = cur[0], f = cur[1];
                for (int v = 0; v < cap.length; v++) if (par[v] == -1 && cap[u][v] > 0) {
                    par[v] = u;
                    int nf = Math.min(f, cap[u][v]);
                    if (v == t) return nf;
                    q.add(new int[] {v, nf});
                }
            }
            return 0;
        }
        static int maxFlow(int[][] cap, int s, int t) {
            int[] par = new int[cap.length];
            int flow = 0, add;
            while ((add = bfs(cap, s, t, par)) > 0) {
                flow += add;
                for (int v = t; v != s; v = par[v]) { cap[par[v]][v] -= add; cap[v][par[v]] += add; }
            }
            return flow;
        }
        public static void main(String[] args) {
            int[][] c = new int[3][3];
            c[0][1] = 3; c[1][2] = 2; c[0][2] = 1;
            System.out.println(maxFlow(c, 0, 2));
        }
        // Input : s=0,a=1,t=2 caps 3,2,1
        // Output: 3
    }
JavaDinic.java
import java.util.*;
    public class Dinic {
        static class Edge { int to, rev; long cap; Edge(int to, int rev, long cap) { this.to = to; this.rev = rev; this.cap = cap; } }
        List<Edge>[] g;
        int[] lev, it;
        Dinic(int n) {
            g = new List[n];
            for (int i = 0; i < n; i++) g[i] = new ArrayList<>();
        }
        void add(int u, int v, long c) {
            g[u].add(new Edge(v, g[v].size(), c));
            g[v].add(new Edge(u, g[u].size() - 1, 0));
        }
        boolean bfs(int s, int t) {
            lev = new int[g.length];
            Arrays.fill(lev, -1);
            lev[s] = 0;
            ArrayDeque<Integer> q = new ArrayDeque<>();
            q.add(s);
            while (!q.isEmpty()) {
                int u = q.poll();
                for (Edge e : g[u]) if (e.cap > 0 && lev[e.to] < 0) { lev[e.to] = lev[u] + 1; q.add(e.to); }
            }
            return lev[t] >= 0;
        }
        long dfs(int u, int t, long f) {
            if (u == t) return f;
            for (; it[u] < g[u].size(); it[u]++) {
                Edge e = g[u].get(it[u]);
                if (e.cap <= 0 || lev[e.to] != lev[u] + 1) continue;
                long pushed = dfs(e.to, t, Math.min(f, e.cap));
                if (pushed > 0) { e.cap -= pushed; g[e.to].get(e.rev).cap += pushed; return pushed; }
            }
            return 0;
        }
        long maxFlow(int s, int t) {
            long flow = 0;
            while (bfs(s, t)) {
                it = new int[g.length];
                long add;
                while ((add = dfs(s, t, Long.MAX_VALUE / 4)) > 0) flow += add;
            }
            return flow;
        }
        public static void main(String[] args) {
            Dinic d = new Dinic(3);
            d.add(0, 1, 3); d.add(1, 2, 2); d.add(0, 2, 1);
            System.out.println(d.maxFlow(0, 2));
        }
        // Input : same network
        // Output: 3
    }
JavaMinCut.java
import java.util.*;
    public class MinCut {
        static List<Integer> sideS(List<int[]>[] residual, int s) {
            boolean[] vis = new boolean[residual.length];
            ArrayDeque<Integer> q = new ArrayDeque<>();
            q.add(s); vis[s] = true;
            while (!q.isEmpty()) {
                int u = q.poll();
                for (int[] e : residual[u]) if (e[1] > 0 && !vis[e[0]]) { vis[e[0]] = true; q.add(e[0]); }
            }
            List<Integer> S = new ArrayList<>();
            for (int i = 0; i < vis.length; i++) if (vis[i]) S.add(i);
            return S;
        }
        public static void main(String[] args) {
            List<int[]>[] r = new List[3];
            for (int i = 0; i < 3; i++) r[i] = new ArrayList<>();
            r[0].add(new int[] {1, 1});
            System.out.println(sideS(r, 0));
        }
        // Input : residual after a toy run, s can reach 0 and 1
        // Output: [0, 1]
    }

Complexity

Time EK O(V E^2), Dinic O(V^2 E) typical Space O(V + E)

Edmonds-Karp: each augmentation strictly increases the shortest residual distance of at least one junction, and that distance is at most V, so there are at most V E augmentations, each a BFS of the residual graph, which is O(V E²). At n = 200 and a few thousand pipes that is tens of millions of edge scans, comfortable. Ford-Fulkerson without the shortest-path rule can run for a number of augmentations equal to the max flow itself, which is unbounded when capacities are 10⁵.

Dinic rebuilds a level graph at most V times and each blocking-flow phase scans every residual edge a constant number of times thanks to the current-edge pointer, which is O(V² E) in the worst case. On unit-capacity networks the bound tightens to about O(E min(√E, V2/3)), which is why Dinic is the contest default at n = 2000 with unit caps. Store residuals in long: a handful of pipes of capacity 10⁵ overflow an int.

Edge cases and pitfalls

  • No reverse edges
    Without a reverse twin, a greedy first path that used a scarce pipe cannot be cancelled, so a later better combination is invisible and the algorithm stops below the true maximum, which looks correct on a sample with only one path.
    Every add(u, v, c) must also append a reverse edge of capacity 0, and the two must store each other's indices so a push updates both leftovers.
  • int overflow on cap sums
    A path of a few pipes each of capacity 10⁵ exceeds Integer.MAX_VALUE, so a residual wraps negative and looks like room to push (or like a full pipe), and the printed max flow is junk.
    Store capacities, residuals, bottlenecks and the answer as long. Test on two pipes of capacity 10⁵ in series and check the flow is 10⁵, not a wrapped int.
  • Using original caps to read the min cut
    Listing pipes that still have leftover original capacity includes pipes inside S and misses saturated pipes that actually cross the fence, so the "cut" does not disconnect s from t.
    After the flow run, BFS from s on residual > 0. The cut pipes are original edges from that reachable set to its complement; they are saturated and their residual is 0.
  • Multiple edges overwritten in a matrix
    An adjacency-matrix residual keeps one cell per pair, so a second pipe between the same junctions silently overwrites the first and the max flow drops.
    Use an edge list (the Dinic template) where parallel pipes are two pairs of twins, or add onto the matrix cell instead of assigning.
  • Bidirected input as two independent caps
    An undirected pipe of capacity c is one shared room both ways. Modelling it as a single directed edge lets flow travel only one way; omitting the reverse twin of capacity c is the other half of the same bug.
    For an undirected pipe of capacity c, call add(u, v, c) and add(v, u, c), each of which also creates its residual undo twin of 0.

Interview follow-ups

State the max-flow min-cut theorem.

In any flow network the value of a maximum s-t flow equals the capacity of a minimum s-t cut. Any flow is at most any cut, because every unit that leaves s and reaches t must cross the fence, and cannot exceed the fence's total pipe size. When the algorithm stops, the residual-reachable set S is a cut whose crossing pipes are all saturated, so its capacity equals the flow already pushed, and the two sides of the inequality meet.

How do you recover the cut edges?

After the last unsuccessful BFS, let S be every junction still reachable from s on residual > 0. The cut pipes are the original edges u → v with u in S and v not in S. Each of those has residual 0 — they are physically full — and shutting them off is a cheapest way to stop every drop. Do not list leftover-capacity pipes inside S; those never leave the source side.

Why Dinic's current-edge pointer?

Inside one blocking-flow phase an exhausted residual edge will not regain capacity, because the only pushes happening are further along the same level graph. The pointer remembers "I have already given up on this outgoing edge" so each phase scans every residual edge a constant number of times instead of restarting from the front of the adjacency list after every dead-end DFS.

Unit-capacity bipartite matching complexity?

Build s → L → R → t with every capacity 1 and run Dinic: the unit-network bound is O(E √V), which is the same bound Hopcroft-Karp quotes in matching language. Kuhn's DFS-augment is O(V E) and is often faster to type when both sides have a few hundred vertices. The next page is that specialised view without building the flow network.
