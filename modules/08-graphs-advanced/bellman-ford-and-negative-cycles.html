Bellman-Ford & Negative Cycles

Relax every edge n-1 times. A successful relaxation on the n-th pass is a negative cycle that can reach the target.

Medium 26 min read Prerequisites: Dijkstra's Algorithm Bellman-Ford negative cycle shortest path P1

Why this exists

You are pricing delivery routes across a handful of towns. Most roads cost money to drive, but a few of them pay you: one sponsor refunds 3 units if your van passes through their town, so that road carries a weight of −3. You want the cheapest cost from town 0 to every other town. The tool you would normally reach for, Dijkstra, works by repeatedly picking the unfinished town with the smallest known cost and declaring that cost final forever. With a refund in the graph that declaration is simply false: a town you settled at cost 7 can later be reached for 4 through a road that pays you back, and Dijkstra never reopens a settled town. There is no crash and no warning, just a wrong number in the output.

The algorithm on this page throws the clever ordering away and does something brutally simple instead. To relax an edge from u to v of weight w means one check: if dist[u] + w is smaller than the value currently stored in dist[v], overwrite dist[v] with it. Bellman-Ford relaxes every edge in the graph, then relaxes every edge again, and repeats that sweep n-1 times, where n is the number of towns. There is no priority queue and no such thing as a settled vertex, so a discovery made late is always allowed to improve a value written early. With n = 2000 towns and m = 5000 roads the whole run is 2000 × 5000 = 10⁶ edge checks, a few milliseconds.

Why exactly n-1 sweeps and not some other number? After the first sweep every distance reachable using a single road is correct; after the second, every distance reachable using two roads; and in general after sweep i the array is correct for every route of at most i roads. A route that never revisits a town touches at most n towns and therefore at most n-1 roads, so n-1 sweeps cover every sensible route. That bound also hands you a free detector. Run one extra sweep, and if some edge still improves a distance, the only possible explanation is a route that revisits a town and gets cheaper by doing so — a negative cycle, a loop whose weights sum to a negative number, which you could drive round forever to push the cost down without limit.

In a problem statement the tell is a sentence that explicitly allows negative weights, or a question phrased as "can you profit forever", sitting beside small limits such as n ≤ 2×10³ and m ≤ 5×10³. Two standard disguises are worth memorising. "Cheapest flight with at most k stops" is this algorithm stopped after k+1 sweeps instead of n-1, because the sweep counter is the edge budget. Currency arbitrage is the other: set each exchange edge to -log(rate) so that multiplying rates becomes adding weights, and a sequence of trades that multiplies your money by more than one becomes exactly a cycle of negative total weight.

After i full sweeps of the edge list, dist[v] is exactly the cost of the cheapest route from the source to v that spends at most i edges, so the sweep counter is really an edge budget. An honest route never needs more than n-1 edges, which is why anything that still improves on sweep n must be looping to save money rather than travelling somewhere new.

Recognise this pattern

Say yes when you see

  • Directed (or undirected) graph with negative weights, single source
  • Detect whether a negative cycle exists, or can reach a given node
  • "At most k edges / k stops" — stop after k relax passes
  • Arbitrage / exchange rates (negate the log of the rate)
  • n is a few thousand, m a few thousand — O(nm) fits

Not this pattern when

  • Non-negative weights and you need speed → Dijkstra
  • All-pairs on a dense graph of n <= 400 → Floyd-Warshall
  • 0-1 weights → 0-1 BFS
  • You only need a spanning tree → MST, not shortest paths

An undirected negative edge stored both ways is already a negative cycle of length 2, so confirm the statement is directed before you duplicate every road.

Core idea and the invariant

Keep the graph as a flat list of triples (u, v, w) rather than adjacency lists, because each sweep must look at every road anyway. Allocate dist[0..n-1] filled with a huge sentinel, set dist[src] = 0, and allocate par[v] = -1 so you can walk a route backwards later. To relax the edge u → v of weight w means: if dist[u] is already a real number and dist[u] + w is strictly smaller than dist[v], overwrite dist[v] and remember par[v] = u. Never relax from the sentinel: adding a negative weight to "infinity" fabricates a finite junk distance to a town the source cannot reach.

Repeat that sweep over the whole edge list exactly n-1 times. After sweep i the array holds the cheapest walk that uses at most i edges, so n-1 sweeps cover every walk that never revisits a town. Then run one extra sweep and collect every vertex whose distance still drops: each such victim sits on, or can be reached from, a negative cycle — a loop whose weights sum to a negative number. To print the loop, walk par exactly n steps from any victim (that walk is long enough to be forced onto the cycle) and then walk until a vertex repeats. To mark every town whose cheapest cost is unbounded, flood forwards from those victims, or flood on the reverse graph if the question is "can the source cheat its way to t".

Walk the four-town sample in words. Edges are 0 → 1 weight 5, 0 → 2 weight 4, 2 → 1 weight −2, 1 → 3 weight 1, 2 → 3 weight 3, source 0. After the first sweep dist is [0, 2, 4, 3] because the refund 2 → 1 improves town 1 from 5 down to 2 and then town 3 from 6 down to 3. The second sweep changes nothing, and neither does the extra detection sweep, so there is no negative cycle reachable from 0 and those four numbers are final.

After sweep i, dist[v] equals the minimum weight of a walk from the source to v that uses at most i edges, or INF if no such walk exists.

In plain words, the sweep counter is an edge budget, not a clock: each full pass of the edge list is allowed to grow every surviving route by exactly one more road, and a route that never loops cannot need more than n-1 roads. That is why a successful relax on sweep n cannot be travelling somewhere new — it must be looping to save money.

The extra sweep is the cycle detector

A walk that still improves after n-1 edges must repeat a vertex and get cheaper by doing so. That is the definition of a negative cycle reachable from the source. The extra sweep does not compute a new distance; it only raises a flag, and the parent pointers already stored during the first n-1 sweeps are what you walk to recover the loop.

Never relax from the sentinel

If dist[u] is still INF, the source has not reached u. Adding a negative w would write a finite number into dist[v] and pretend a path exists. Gate every relax on dist[u] being finite, and pick a sentinel such as Long.MAX_VALUE / 4 so even a legal finite add cannot overflow.

Structure

Algorithm

  1. Initialise distances and parents. Set dist[src] = 0, fill every other slot with a huge sentinel, and set par[v] = -1, so a town with no written route is visibly unreachable and a later walk has a place to start.
  2. Sweep the edge list n-1 times. For every triple (u, v, w), if dist[u] is finite and dist[u] + w beats dist[v], overwrite the distance and remember par[v] = u, because only a real route is allowed to improve another town.
  3. Stop a sweep early when nothing moves. If a full pass of the edge list changes no entry, later passes cannot change anything either, so you may break; the extra detection sweep is then guaranteed to be quiet as well.
  4. Run one more sweep as a detector. Collect every vertex whose distance still drops on sweep n: each of those victims is on, or reachable from, a negative cycle, and that is the only information this extra pass is meant to produce.
  5. Recover a cycle from the parent pointers. Starting at any victim, follow par exactly n times so the walk is forced onto the loop, then walk once more until a vertex repeats and emit that loop.
  6. Mark every town that can be driven to minus infinity. Flood forwards from the victims (or on the reverse graph, if the question is whether the source can cheat its way to a given target) so every node that inherits the unbounded improvement is flagged.

Java implementation

JavaBellmanFordBrute.java
import java.util.Arrays;
    public class BellmanFordBrute {
        static long[] bf(int n, int[][] edges, int src) {
            long[] d = new long[n];
            Arrays.fill(d, Long.MAX_VALUE / 4);
            d[src] = 0;
            for (int i = 0; i < n - 1; i++)
                for (int[] e : edges)
                    if (d[e[0]] + e[2] < d[e[1]]) d[e[1]] = d[e[0]] + e[2];
            return d;
        }
        public static void main(String[] args) {
            int[][] e = {{0,1,5},{0,2,4},{2,1,-2},{1,3,1},{2,3,3}};
            System.out.println(Arrays.toString(bf(4, e, 0)));
        }
        // Input : 4 nodes, edges as above, src 0
        // Output: [0, 2, 4, 3]
    }
JavaBellmanFord.java
import java.util.*;
    public class BellmanFord {
        static boolean hasNegCycle(int n, int[][] edges, int src) {
            long[] d = new long[n];
            Arrays.fill(d, Long.MAX_VALUE / 4);
            d[src] = 0;
            for (int i = 0; i < n - 1; i++)
                for (int[] e : edges)
                    if (d[e[0]] + (long) e[2] < d[e[1]]) d[e[1]] = d[e[0]] + e[2];
            for (int[] e : edges)
                if (d[e[0]] + (long) e[2] < d[e[1]]) return true;
            return false;
        }
        public static void main(String[] args) {
            int[][] e = {{0,1,5},{0,2,4},{2,1,-2},{1,3,1},{2,3,3}};
            System.out.println(hasNegCycle(4, e, 0));
            int[][] cyc = {{0,1,1},{1,2,-3},{2,0,1},{0,3,4}};
            System.out.println(hasNegCycle(4, cyc, 0));
        }
        // Input : first graph no cycle; second 0-1-2-0 weight -1
        // Output: false
        //         true
    }
JavaKStops.java
import java.util.Arrays;
    public class KStops {
        static int cheapest(int n, int[][] flights, int src, int dst, int k) {
            long[] d = new long[n];
            Arrays.fill(d, Long.MAX_VALUE / 4);
            d[src] = 0;
            for (int i = 0; i <= k; i++) {
                long[] nd = d.clone();
                for (int[] e : flights)
                    if (d[e[0]] + e[2] < nd[e[1]]) nd[e[1]] = d[e[0]] + e[2];
                d = nd;
            }
            return d[dst] >= Long.MAX_VALUE / 8 ? -1 : (int) d[dst];
        }
        public static void main(String[] args) {
            int[][] f = {{0,1,100},{1,2,100},{0,2,500}};
            System.out.println(cheapest(3, f, 0, 2, 1));
        }
        // Input : flights 0-1 100, 1-2 100, 0-2 500; k=1
        // Output: 200
    }

Complexity

Time O(n m) Space O(n + m)

Each of the n-1 sweeps looks at every one of the m edges, and the extra detection sweep does the same, so the work is (n) × m relax attempts. At the usual limits that is 2000 × 5000 = 10⁶ additions, a few milliseconds. The parent array and the distance array are both length n, and the edge list is length m, so the memory is linear in the input.

SPFA queues only the vertices that just improved and is faster on random graphs, but an adversary can force a vertex to re-enter the queue exponentially often. Do not ship SPFA on a contest that allows worst-case input unless you add a visit cutoff of about n and fall back to this O(nm) sweep when the cutoff fires.

Edge cases and pitfalls

  • Relaxing from INF
    INF + negative wraps into a finite junk distance, so a town the source cannot reach looks reachable and the extra sweep may even raise a false cycle flag.
    Gate every relax on dist[u] being finite, and pick a sentinel such as Long.MAX_VALUE / 4 so a legal add cannot overflow either.
  • int overflow
    A path of n edges each of size 10⁵ exceeds Integer.MAX_VALUE, so a real shortest path wraps negative and looks like a cycle the extra sweep will "detect".
    Store long[] dist and add with a long cast. Test on a three-edge path of weight 10⁵ each and check the printed sum is 3×10⁵.
  • Nth-pass victim is not on the cycle
    A victim is only reachable from the cycle, so walking par once can stop on a tree edge that leads into the loop rather than on the loop itself, and the printed walk is not closed.
    Walk parent exactly n times first so you are forced onto the cycle, then walk until a vertex repeats. Test on a cycle with a tail hanging off it.
  • Undirected negative edge
    Storing both orientations of a single negative undirected edge creates a two-cycle whose weights sum negative, so the detector fires on a graph that had no interesting loop.
    Undirected negatives are almost always a modelling error. Confirm the statement is directed before you duplicate every road, and if it is undirected then reject a negative weight immediately.
  • In-place relax for "at most k edges"
    Using one array lets a sweep read a distance written earlier in the same sweep, which is a walk of more than one extra edge, so "at most k stops" silently becomes "at most many stops".
    Clone dist at the start of each sweep and write improvements into the clone (LC 787). Test on a two-edge cheapest route that should be illegal when k = 0.

Interview follow-ups

Why n-1, not n?

A walk that never revisits a town uses at most n-1 roads, because it touches at most n towns. If a cheaper walk still uses n roads it must repeat a town, and the loop it closed must have negative total weight — otherwise dropping the loop would be cheaper. That is why sweep n is reserved for detection rather than for computing one more honest distance.

Does BF work on undirected graphs?

Yes, but only when every weight is non-negative, in which case you may store both orientations and the extra sweep will stay quiet. A single negative undirected edge stored both ways is already a negative two-cycle, so the detector fires immediately. If the statement really is undirected and allows a negative road, the cheapest cost is unbounded and you should reject the input rather than run this algorithm.

How do you list every node that can be driven to -INF?

After the extra sweep, the victims are the towns whose distance still improved. Flood forwards from those victims along the original edges to mark everyone who can inherit the unbounded improvement. If the question is "can the source cheat its way to t", you also need the victim to be reachable from the source, which the first n-1 sweeps already recorded as a finite dist.

Bellman-Ford vs Dijkstra with potentials?

Johnson's algorithm runs Bellman-Ford once from a dummy source that has a zero-weight edge into every vertex, reads the resulting distances as potentials, and rewrites every edge weight as w + pot[u] - pot[v]. Those reduced weights are non-negative when no negative cycle exists, so you may then run Dijkstra from every source. That is the all-pairs tool when n is too big for Floyd-Warshall but the graph is sparse and has no negative cycle.

Recap

  • Relax all edges n-1 times; dist is then exact for simple paths.
  • A success on pass n is a negative cycle.
  • Do not relax from INF.
  • k-stop problems use a cloned array per pass.
  • Walk parent n times before printing the cycle.
