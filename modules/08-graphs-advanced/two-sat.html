2-SAT

Each clause x ∨ y becomes implications ¬x → y and ¬y → x. Unsatisfiable iff x and ¬x sit in the same SCC.

Hard 22 min read Prerequisites: SCC: Tarjan & Kosaraju 2-SAT implication graph SCC P2

Why this exists

3-SAT is NP-complete. 2-SAT is linear. The trick is an implication graph on 2n vertices (x and ¬x for each variable): a clause of two literals forces two implications, and a valid assignment is a cut of the condensation that never puts x and ¬x together.

After SCCs, the condensation is a DAG. Assign x true if scc[x] > scc[¬x] (later in reverse-topo, i.e. we pick the sink side). That is the unique forced choice once you decide to make every implication-respecting assignment.

Recognition: "choose one of two options, with pairwise conflicts" — seating, assigning truth values, choosing an orientation. If a constraint involves three literals, it is not 2-SAT.

x ∨ y is (¬x → y) ∧ (¬y → x). A path x ⇒ ¬x ⇒ x is a contradiction. SCC is how you find those paths in linear time.

Recognise this pattern

Say yes when you see

  • Each constraint is a disjunction of at most two literals
  • "At least one of these two is true", "these two conflict"
  • Choose an orientation / a side / a colour with pairwise implications
  • n, m around 1e5 — need linear
  • You can write every rule as (a or b) after introducing x / not-x nodes

Not this pattern when

  • A clause with 3+ literals → NP-complete, not this page
  • XOR-SAT / linear equations over GF(2) → Gaussian elimination
  • You need the number of satisfying assignments modulo p → more than a yes/no SCC
  • Constraints are numeric inequalities, not booleans → 2-SAT only after a binary search on the answer, if at all

Core idea and the invariant

Map variable i to node 2i (false) and 2i+1 (true), or i and i+n — pick one and stick to it. For a clause (a ∨ b) add edges (~a o b) and (~b o a). For a forced literal a add (~a o a).

Run SCC. If any i has scc[i] == scc[~i], unsat. Otherwise set val[i] = scc[i] > scc[~i] (Kosaraju ids assigned in reverse-topo of G^R are already in the right order; Tarjan ids are assigned in reverse-topo of the condensation — same comparison).

If there is a path a ⇒ b in the implication graph, every satisfying assignment that sets a true must set b true. Therefore a path x ⇒ ¬x and ¬x ⇒ x (i.e. same SCC) is unsatisfiable. The DAG assignment picks, for each pair, the literal whose SCC is the sink-side one.

Structure

Algorithm

  1. Allocate 2n nodes. Fix a mapping pos(i)=2*i+1, neg(i)=2*i.
  2. For each clause (a ∨ b) add ~a o b and ~b o a.
  3. SCC the implication graph.
  4. If scc[pos(i)]==scc[neg(i)] return unsat.
  5. Else val[i] = scc[pos(i)] > scc[neg(i)].
  6. Verify on a tiny sample — mapping bugs are silent.

Java implementation

JavaTwoSatBrute.java
public class TwoSatBrute {
        static boolean sat(int n, int[][] clauses) {
            int lim = 1 << n;
            outer:
            for (int mask = 0; mask < lim; mask++) {
                for (int[] c : clauses) {
                    boolean a = c[0] > 0 ? ((mask >> (c[0] - 1)) & 1) == 1 : ((mask >> (-c[0] - 1)) & 1) == 0;
                    boolean b = c[1] > 0 ? ((mask >> (c[1] - 1)) & 1) == 1 : ((mask >> (-c[1] - 1)) & 1) == 0;
                    if (!a && !b) continue outer;
                }
                return true;
            }
            return false;
        }
        public static void main(String[] args) {
            System.out.println(sat(2, new int[][] {{1, 2}, {-1, 2}}));
            System.out.println(sat(1, new int[][] {{1, 1}, {-1, -1}}));
        }
        // Input : (x∨y)(~x∨y) ; then (x)(~x)
        // Output: true
        //         false
    }
JavaTwoSat.java
import java.util.*;
    public class TwoSat {
        int n;
        List<Integer>[] g;
        int[] tin, low, id;
        boolean[] on, val;
        int timer, cid;
        Deque<Integer> st = new ArrayDeque<>();
        TwoSat(int n) {
            this.n = n;
            g = new List[2 * n];
            for (int i = 0; i < 2 * n; i++) g[i] = new ArrayList<>();
            tin = new int[2 * n]; low = new int[2 * n]; id = new int[2 * n];
            on = new boolean[2 * n]; val = new boolean[n];
            Arrays.fill(tin, -1);
        }
        int pos(int x) { return x << 1 | 1; }
        int neg(int x) { return x << 1; }
        void implies(int a, int b) { g[a].add(b); }
        void or(int x, boolean xv, int y, boolean yv) {
            int a = xv ? pos(x) : neg(x);
            int b = yv ? pos(y) : neg(y);
            implies(a ^ 1, b);
            implies(b ^ 1, a);
        }
        void dfs(int u) {
            tin[u] = low[u] = timer++;
            st.push(u); on[u] = true;
            for (int v : g[u]) {
                if (tin[v] == -1) { dfs(v); low[u] = Math.min(low[u], low[v]); }
                else if (on[v]) low[u] = Math.min(low[u], tin[v]);
            }
            if (low[u] == tin[u]) {
                while (true) {
                    int x = st.pop(); on[x] = false; id[x] = cid;
                    if (x == u) break;
                }
                cid++;
            }
        }
        boolean solve() {
            for (int i = 0; i < 2 * n; i++) if (tin[i] == -1) dfs(i);
            for (int i = 0; i < n; i++) {
                if (id[pos(i)] == id[neg(i)]) return false;
                val[i] = id[pos(i)] > id[neg(i)];
            }
            return true;
        }
        public static void main(String[] args) {
            TwoSat s = new TwoSat(2);
            s.or(0, true, 1, true);
            s.or(0, false, 1, true);
            System.out.println(s.solve() + " " + s.val[0] + " " + s.val[1]);
        }
        // Input : (x∨y) (~x∨y)
        // Output: true false true
    }

public class TwoSatMap {
        static int v(int i, boolean pos, int n) { return pos ? i : i + n; }
        static int not(int x, int n) { return x < n ? x + n : x - n; }
        public static void main(String[] args) {
            int n = 2;
            System.out.println(v(0, true, n) + " " + not(v(0, true, n), n));
        }
        // Input : n=2, literal x0
        // Output: 0 2
    }

Edge cases and pitfalls

  • Swapping the assignment comparison
    scc[x] < scc[~x] flips every variable. Sample may still pass if both work.
    Tarjan / Kosaraju ids grow in reverse-topo; the larger id is the sink side → set that literal true. Verify on (x) alone.
  • Forgetting unit clauses
    A forced x needs (~x → x), not just a mental note.
    Encode (x ∨ x).
  • Odd mapping of ~x
    x^1 only works if you packed pos/neg as 2i / 2i+1.
    Pick one encoding. Write not() once and use it everywhere.
  • Adding only one implication per clause
    x ∨ y is two implications. One edge leaves a satisfying assignment that the graph does not force.
    Always add both (~a o b) and (~b o a).
  • Using undirected edges
    Implications are directed. An undirected edge merges too much.
    Directed SCC.

Interview follow-ups

Why scc[x] > scc[~x] means x is true?

Implication edges go from earlier (source) to later (sink) in the condensation. If ~x can reach x but not vice versa, x is forced true. The larger Tarjan id is later in reverse-topo, i.e. closer to sinks.

Can 2-SAT count solutions?

Yes in simple cases: each pair of complementary SCCs that are not forced is a free bit. Extra edges between pairs destroy the 2^{k} formula; then you need a more careful DAG DP.

How do you force x XOR y?

(x ∨ y) ∧ (~x ∨ ~y). Two clauses, four implications.

2-SAT vs 2-colouring?

Bipartite checking is 2-SAT with clauses "adjacent vertices differ". General 2-SAT allows arbitrary 2-clauses, including forcing two vertices equal, or forcing a single variable.
