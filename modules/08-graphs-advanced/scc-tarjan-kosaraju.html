SCC: Tarjan & Kosaraju

An SCC is a maximal set where every vertex can reach every other. Kosaraju is two DFS passes; Tarjan is one DFS with a low-link stack.

Medium 28 min read Prerequisites: DFS & Connected Components SCC Tarjan Kosaraju P1

Why this exists

You are given a one-way street map of a city, and you want to know which junctions can reach each other both ways. On an undirected map that question is just "are we in the same connected piece?", answered by one depth-first search. Directed streets break the symmetry: 0 can reach 3 along 0→1→3 while 3 has no way home, so they are not in the same group. A strongly connected component (SCC) is a maximal set of junctions where every member can reach every other member by following the arrows. Trying every pair with a fresh search is n searches of a graph with m streets, about 4×10¹⁰ steps at the usual limits, which no judge accepts.

The algorithms on this page find every SCC in one or two linear passes and then shrink each component to a single supernode. The graph of supernodes, the condensation, has no directed cycles left — it is a DAG — because a cycle would have merged those supernodes into one SCC. That DAG is the object every "eventual safe node", "2-SAT", and "fewest one-way streets to add so everyone can reach everyone" problem actually sits on. Kosaraju builds it with two searches and a reversed copy of the streets; Tarjan builds it with one search, a stack, and a number called low.

Write Kosaraju when you want the proof you can say out loud: finish times, reverse the arrows, search again. Write Tarjan when you already have discovery times and low-links from the bridges page and want a single pass. Both are O(n + m). In a problem statement the tell is a directed graph together with "mutual reachability", "condense into a DAG", or limits such as n, m ≤ 2×10⁵ that rule out pairwise searches.

In the reversed street map, yesterday's sinks become today's sources. A first search's finish order is a reverse topological order of the condensation, so searching the reversed map in reverse-finish order hits one source — one whole SCC — at a time and cannot leak into another.

Recognise this pattern

Say yes when you see

  • Partition a directed graph into strongly connected components
  • Condensation DAG: contract each SCC to a node
  • 2-SAT (x and not-x in the same SCC is unsat)
  • "Minimum edges so the graph is strongly connected" — count DAG sources and sinks
  • Eventual safe nodes — SCCs that cannot reach a cycle (or outdegree 0 in the condensation)

Not this pattern when

  • Undirected connected components → one DFS, no reverse graph
  • Bridges / articulation points → tin/low on an undirected graph
  • Weakly connected (ignore direction) → treat edges as undirected
  • You only need reachability from one source → one DFS / BFS

Core idea and the invariant

Kosaraju is two searches and a reversed copy of the streets. Pass 1 runs an ordinary DFS on the original graph and, as each vertex finishes (every outgoing street already explored), pushes it onto a list. Reverse every street to build GR. Pass 2 pops the finish list from the back and, whenever the popped vertex is still unvisited, starts a DFS on the reversed graph; every vertex that search reaches is one SCC. The reason it cannot leak: reverse-finish order on G is a topological order of the condensation of GR, so each second-pass root is a source of that DAG and owns exactly one component.

Tarjan is one search. tin[u] is the discovery time, a counter that ticks the first time you enter u. The vertex is pushed onto a stack and flagged onStack. low[u] measures something precise: the smallest discovery time of any vertex you can still reach from u by walking down tree edges inside u's subtree and then taking at most one back-edge to a vertex that is still on the stack (still being explored). A back-edge to a vertex that has already been popped is a cross edge into a finished SCC and must not update low. When the search at u returns and low[u] == tin[u], nothing in the subtree can climb to an ancestor of u, so u is the root of an SCC: pop the stack down to u and stamp that slice with a new component id.

Walk the four-junction sample in words. Streets are 0→1→2→0 and 1→3. Tarjan enters 0, then 1, then 2; the street 2→0 is a back-edge to an on-stack vertex, so low[2] becomes tin[0], that number climbs to 1 and then to 0, and low[0] == tin[0] pops 2, 1, 0 as SCC 0. Vertex 3 is entered next, has no back-edge, satisfies low[3] == tin[3], and pops as the singleton SCC 1. The condensation is one arrow SCC0→SCC1: one source, one sink. Kosaraju's first pass finishes 2, then 0, then 1, then 3; the reversed search starting at 3 takes only 3, and the next reversed search takes 0, 1, 2.

Kosaraju: reverse-finish order of G is a topological order of the condensation of GR, so each second-pass DFS tree is exactly one SCC. Tarjan: low[u] is the smallest tin reachable from u by tree edges going down plus at most one back-edge into a vertex still on the stack.

In plain words, low[u] == tin[u] means "nothing in my subtree can climb to an ancestor still being explored", so the vertices sitting above me on the stack down to me are a maximal mutually-reachable set and may be popped as one component.

What low[v] actually measures

low[v] is not "the parent" and not "the smallest neighbour". It is the earliest discovery time still reachable from v without leaving the current exploration path: walk down the DFS subtree, then take at most one back-edge to a vertex that is still on the stack. If that earliest time is v's own discovery time, the subtree is trapped — it cannot reach any ancestor — and v is an SCC root. Updating low from a vertex that has already been popped merges two components that are not mutually reachable.

Kosaraju if you want the proof, Tarjan if you already have tin/low

Kosaraju's two-pass story (finish order, reverse arrows, search sources of the reversed condensation) is the one you can say out loud in an interview. Tarjan is one pass and shares the same two arrays as the bridges page. Either is acceptable if you can point at the condensation and say it is a DAG.

Structure

Algorithm

  1. Kosaraju pass 1: search G and record finish order. Push a vertex onto the list only after every outgoing street has been explored, so the list is a reverse topological order of the condensation and the last vertex finished is a sink of the original DAG of components.
  2. Reverse every street to build GR. Yesterday's sinks become today's sources, which is the whole reason the second search can start at a source of the reversed condensation and stay inside one SCC.
  3. Kosaraju pass 2: search GR in reverse-finish order. Each time you pop an unvisited vertex, a new DFS tree is exactly one SCC; do not walk the original outgoing streets or you will glue extra vertices into the component.
  4. Tarjan: one search with tin, low, and a stack. Push on entry, update low from children and from back-edges to onStack vertices only, and when low[u] == tin[u] pop down to u — that slice cannot climb to any ancestor, so it is an SCC.
  5. Condense: one supernode per SCC id. Map every vertex to its id and add a condensation edge id[u] → id[v] only when the two ids differ, otherwise the DAG grows a self-loop and looks cyclic.
  6. Read sources and sinks of that DAG. A graph that is already one SCC needs 0 extra streets; otherwise the fewest streets that make it strongly connected is max(sources, sinks), by pairing sinks back to sources.

Dry run

Four junctions: a directed cycle 0→1→2→0 and a sink hanging off 1→3. Tarjan pops the cycle {0,1,2} first, then the singleton {3}.

Java implementation

JavaSccBrute.java
import java.util.*;
    public class SccBrute {
        static boolean reaches(List<Integer>[] g, int a, int b) {
            boolean[] vis = new boolean[g.length];
            ArrayDeque<Integer> q = new ArrayDeque<>();
            q.add(a); vis[a] = true;
            while (!q.isEmpty()) {
                int u = q.poll();
                if (u == b) return true;
                for (int v : g[u]) if (!vis[v]) { vis[v] = true; q.add(v); }
            }
            return false;
        }
        public static void main(String[] args) {
            List<Integer>[] g = new List[4];
            for (int i = 0; i < 4; i++) g[i] = new ArrayList<>();
            g[0].add(1); g[1].add(2); g[2].add(0); g[1].add(3);
            System.out.println(reaches(g, 0, 2) && reaches(g, 2, 0));
            System.out.println(reaches(g, 0, 3) && reaches(g, 3, 0));
        }
        // Input : 0	o1	o2	o0, 1	o3
        // Output: true
        //         false
    }
JavaKosaraju.java
import java.util.*;
    public class Kosaraju {
        List<Integer>[] g, rg;
        boolean[] vis;
        int[] id;
        List<Integer> order = new ArrayList<>();
        int cid;
        Kosaraju(int n) {
            g = new List[n]; rg = new List[n];
            for (int i = 0; i < n; i++) { g[i] = new ArrayList<>(); rg[i] = new ArrayList<>(); }
            vis = new boolean[n]; id = new int[n];
        }
        void add(int u, int v) { g[u].add(v); rg[v].add(u); }
        void dfs1(int u) {
            vis[u] = true;
            for (int v : g[u]) if (!vis[v]) dfs1(v);
            order.add(u);
        }
        void dfs2(int u) {
            id[u] = cid;
            for (int v : rg[u]) if (id[v] == 0 && vis[v]) { /* vis reused */ }
            for (int v : rg[u]) if (id[v] == -1) { id[v] = cid; dfs2(v); }
        }
        int[] scc() {
            int n = g.length;
            Arrays.fill(id, -1);
            for (int i = 0; i < n; i++) if (!vis[i]) dfs1(i);
            Arrays.fill(vis, false);
            cid = 0;
            for (int i = n - 1; i >= 0; i--) {
                int u = order.get(i);
                if (id[u] == -1) { dfs2(u); cid++; }
            }
            return id;
        }
        public static void main(String[] args) {
            Kosaraju k = new Kosaraju(4);
            k.add(0, 1); k.add(1, 2); k.add(2, 0); k.add(1, 3);
            System.out.println(Arrays.toString(k.scc()));
        }
        // Input : 0	o1	o2	o0, 1	o3
        // Output: [0, 0, 0, 1]
    }
JavaTarjanScc.java
import java.util.*;
    public class TarjanScc {
        List<Integer>[] g;
        int[] tin, low, id;
        boolean[] on;
        int timer, cid;
        Deque<Integer> st = new ArrayDeque<>();
        TarjanScc(int n) {
            g = new List[n];
            for (int i = 0; i < n; i++) g[i] = new ArrayList<>();
            tin = new int[n]; low = new int[n]; id = new int[n];
            on = new boolean[n]; Arrays.fill(tin, -1);
        }
        void add(int u, int v) { g[u].add(v); }
        void dfs(int u) {
            tin[u] = low[u] = timer++;
            st.push(u); on[u] = true;
            for (int v : g[u]) {
                if (tin[v] == -1) { dfs(v); low[u] = Math.min(low[u], low[v]); }
                else if (on[v]) low[u] = Math.min(low[u], tin[v]);
            }
            if (low[u] == tin[u]) {
                while (true) {
                    int x = st.pop(); on[x] = false; id[x] = cid;
                    if (x == u) break;
                }
                cid++;
            }
        }
        public static void main(String[] args) {
            TarjanScc t = new TarjanScc(4);
            t.add(0, 1); t.add(1, 2); t.add(2, 0); t.add(1, 3);
            for (int i = 0; i < 4; i++) if (t.tin[i] == -1) t.dfs(i);
            System.out.println(Arrays.toString(t.id));
        }
        // Input : same graph
        // Output: [0, 0, 0, 1]
    }

Complexity

Time O(n + m) Space O(n + m)

Kosaraju walks every vertex and every street once on G, once on GR, and spends linear time building the reversed adjacency lists, so the work is O(n + m). Tarjan walks every street once, pushes and pops each vertex once, and stores three arrays of length n plus a stack of size at most n, which is the same linear bound with a smaller constant and no reversed copy of the graph.

At n, m = 2×10⁵ that is a few hundred thousand array operations, a few milliseconds. The pairwise alternative — a search from every vertex — is about n × (n + m), near 8×10¹⁰ steps, which no judge accepts. Recursion depth can be n, so a chain overflows the default Java stack; the linear bound assumes an explicit stack or a raised -Xss.

Edge cases and pitfalls

  • Using a back-edge to a finished node in Tarjan
    A street into a vertex that has already been popped looks like a back-edge, so updating low from it pulls a finished SCC's discovery time into the current one and silently merges two components that are not mutually reachable.
    Update low[u] from v only when onStack[v] is still true. A popped neighbour is a cross edge into another SCC and must be ignored.
  • Kosaraju second pass on G, not G^R
    Walking the original outgoing streets on pass 2 follows arrows out of the component and glues extra vertices into the SCC, which looks correct on a single cycle and fails as soon as a sink hangs off it.
    Build the reversed adjacency lists in add and run pass 2 on those lists only. Test on 0→1→2→0 plus 1→3 and check that 3 is not in SCC 0.
  • Finish-order vs discovery-order
    Processing pass 2 in discovery (tin) order starts at sources of the original graph rather than sources of the reversed condensation, so a second-pass tree leaks across several SCCs.
    Push a vertex only after its recursive calls return, then iterate that list from the back. The last vertex finished is the first one you should start on GR.
  • Java recursion on a 2e5 path
    A directed chain of length n makes the recursive DFS n frames deep and throws StackOverflowError on the default Java stack, which looks like a wrong answer rather than a stack problem.
    Write the search with an explicit stack, or raise -Xss256m only for local tests. On Codeforces Java prefer the iterative version every time.
  • Condensing without skipping intra-SCC edges
    Copying every original street onto the supernode graph writes a self-loop on any SCC that contained a cycle, so the condensation looks cyclic and source/sink counts come out wrong.
    Add a condensation edge only when id[u] != id[v]. Test on a single directed cycle: the condensation must be one isolated supernode, not a loop of one.

Interview follow-ups

Why reverse finish order?

The finish times of a first DFS on G are a reverse topological order of the condensation: a sink component finishes before any component that can reach it. Reversing every street flips sinks into sources, so walking that list from the back starts at a source of GR's condensation. A search that starts at a source cannot leave its own SCC, which is why each second-pass tree is exactly one component.

Tarjan vs Kosaraju in an interview?

Kosaraju is the one whose proof you can say in two sentences (finish, reverse, search sources). Tarjan is one pass and reuses the same tin / low arrays as the bridges page, but the stack-and-onStack details are easier to get wrong. Either is acceptable if you can point at the condensation and say it is a DAG. Do not start implementing Tarjan from scratch unless the interviewer asks for one pass.

How many edges to make the graph strongly connected?

Contract every SCC to a supernode. If a single supernode remains, the answer is 0. Otherwise let A be the number of supernodes with in-degree 0 and B the number with out-degree 0; the fewest new streets is max(A, B). You can always realise that number by pairing sinks back to sources, because the condensation is a DAG and every supernode sits on some path from a source to a sink.

Can an SCC be a single node with no loop?

Yes: a trivial SCC. Vertex 3 on this page is one. It is still a supernode of the condensation. A self-loop on that vertex would make the singleton a cycle, which matters for "eventual safe nodes": a trivial SCC with no self-loop is safe only when it cannot reach a cycle elsewhere, i.e. when its out-degree in the condensation is 0 after you ignore other trivial sinks.
