Floyd-Warshall

The triple loop for k, for i, for j is "allow vertex k as an intermediate". After k = 0..n-1 every pair is optimal.

Medium 20 min read Prerequisites: Bellman-Ford & Negative Cycles Floyd-Warshall all-pairs APSP P1

Why this exists

n single-source Dijkstras are fine on sparse non-negative graphs. When n is a few hundred, the graph is dense, or you need the whole distance matrix (transitive closure, "best meeting city", "minimax path"), one O(n³) pass is simpler and faster.

The recurrence is shortest path whose intermediate vertices all lie in {0..k}. Fixing k as the newly allowed intermediate and trying it on every pair is exactly the update d[i][j] = min(d[i][j], d[i][k]+d[k][j]).

The same skeleton computes reachability (OR instead of min-plus), minimax (min of max-edge), and detects a negative cycle on the diagonal d[i][i] < 0.

k is not "the current source". k is the highest-index vertex you are now allowed to use as an intermediate. The loop order is k, then i, then j — always.

Recognise this pattern

Say yes when you see

  • All-pairs shortest paths, n <= 400
  • Transitive closure / reachability matrix
  • "Smallest max-edge on a path" (minimax) between every pair
  • Negative cycle anywhere in the graph (some d[i][i] < 0)
  • You need d[u][v] after adding vertices one by one (CF 295B)

Not this pattern when

  • Single source, sparse, non-negative → Dijkstra
  • n = 2000 → n Dijkstras or Johnson, not n^3
  • Only reachability on a DAG → DFS / topo
  • Negative cycle on an undirected graph with a negative edge — already yes, no algorithm needed

Constraint tell: n ≤ 400 is the Floyd signature (64 million operations). Use long and a sentinel that will not overflow when added.

Core idea and the invariant

Initialise d[i][i] = 0, d[u][v] = w for each edge (keep the minimum on parallel edges), rest INF. Then for (k) for (i) for (j) relax through k, skipping when d[i][k] or d[k][j] is INF.

After the loops, d[i][j] is the shortest-path distance, or INF if unreachable. d[i][i] < 0 means a negative cycle touches i. Parent pointers: whenever you relax, set nxt[i][j] = nxt[i][k].

After the outer iteration that has just processed k, d[i][j] is the shortest path from i to j whose internal vertices are a subset of {0,1,…,k}.

Structure

Algorithm

  1. Allocate long[n][n], fill INF, diagonal 0, write edges.
  2. for k in 0..n-1 — k is the new intermediate.
  3. for i, for j — if both halves are finite, relax d[i][j] through k.
  4. Skip the add when either half is INF (overflow / phantom paths).
  5. Read d[u][v]. Negative diagonal ⇒ negative cycle.
  6. Path recover with a nxt[i][j] table updated on every relax.

Java implementation

JavaAllPairsDijkstra.java
import java.util.*;
    public class AllPairsDijkstra {
        static long[][] run(int n, int[][] edges) {
            List<int[]>[] g = new List[n];
            for (int i = 0; i < n; i++) g[i] = new ArrayList<>();
            for (int[] e : edges) g[e[0]].add(new int[] {e[1], e[2]});
            long[][] d = new long[n][n];
            for (int s = 0; s < n; s++) {
                Arrays.fill(d[s], Long.MAX_VALUE / 4);
                d[s][s] = 0;
                PriorityQueue<long[]> pq = new PriorityQueue<>(Comparator.comparingLong(a -> a[0]));
                pq.add(new long[] {0, s});
                while (!pq.isEmpty()) {
                    long[] cur = pq.poll();
                    int u = (int) cur[1];
                    if (cur[0] != d[s][u]) continue;
                    for (int[] e : g[u])
                        if (d[s][u] + e[1] < d[s][e[0]]) {
                            d[s][e[0]] = d[s][u] + e[1];
                            pq.add(new long[] {d[s][e[0]], e[0]});
                        }
                }
            }
            return d;
        }
        public static void main(String[] args) {
            int[][] e = {{0,1,3},{0,2,8},{1,2,1},{2,3,1},{1,3,7}};
            System.out.println(Arrays.toString(run(4, e)[0]));
        }
        // Input : 4-node graph, row of source 0
        // Output: [0, 3, 4, 5]
    }
JavaFloydWarshall.java
import java.util.Arrays;
    public class FloydWarshall {
        static long[][] floyd(int n, int[][] edges) {
            long INF = Long.MAX_VALUE / 4;
            long[][] d = new long[n][n];
            for (int i = 0; i < n; i++) { Arrays.fill(d[i], INF); d[i][i] = 0; }
            for (int[] e : edges) d[e[0]][e[1]] = Math.min(d[e[0]][e[1]], e[2]);
            for (int k = 0; k < n; k++)
                for (int i = 0; i < n; i++)
                    for (int j = 0; j < n; j++)
                        if (d[i][k] + d[k][j] < d[i][j]) d[i][j] = d[i][k] + d[k][j];
            return d;
        }
        public static void main(String[] args) {
            int[][] e = {{0,1,3},{0,2,8},{1,2,1},{2,3,1},{1,3,7}};
            System.out.println(Arrays.toString(floyd(4, e)[0]));
        }
        // Input : same graph
        // Output: [0, 3, 4, 5]
    }
JavaTransitiveClosure.java
public class TransitiveClosure {
        static boolean[][] reach(int n, int[][] edges) {
            boolean[][] d = new boolean[n][n];
            for (int i = 0; i < n; i++) d[i][i] = true;
            for (int[] e : edges) d[e[0]][e[1]] = true;
            for (int k = 0; k < n; k++)
                for (int i = 0; i < n; i++)
                    if (d[i][k])
                        for (int j = 0; j < n; j++) d[i][j] |= d[k][j];
            return d;
        }
        public static void main(String[] args) {
            boolean[][] r = reach(3, new int[][] {{0,1},{1,2}});
            System.out.println(r[0][2]);
        }
        // Input : 0	o1	o2
        // Output: true
    }

Complexity

Time O(n^3) Space O(n^2)

Three nested n-loops, one add and one min each, is n³ operations. At n = 400 that is 64 million, comfortable. At n = 1000 it is a billion — too slow.

ApproachTimeSpaceWhen it is enough
n DijkstrasO(n m log n)O(n^2)Sparse, non-negative

n Bellman-FordsO(n^2 m)O(n^2)Almost never

Edge cases and pitfalls

  • Loop order i,j,k
    Using k last means you update with intermediates you have not finished allowing. The DP is wrong.
    k is the outer loop. Always.
  • INF + INF overflow
    Two unreachables add to a small negative and look like a path.
    Sentinel Long.MAX_VALUE/4, or skip when either half is INF.
  • Forgetting d[i][i] = 0
    The first pass through k=i writes junk, and the diagonal is no longer a cycle detector.
    Zero the diagonal before the loops.
  • Directed vs undirected write
    An undirected edge must set both d[u][v] and d[v][u].
    Write both, unless the statement is directed.
  • Reading d before all k finish
    Partial matrices are "intermediates ≤ k only", not true distances.
    That is a feature for "add vertices in reverse" problems — otherwise wait until the end.

Interview follow-ups

Why is k the outer loop?

The DP is by the set of allowed intermediates. You need every pair's answer for set {0..k-1} before you try k. That is exactly "k outermost".

How do you detect a negative cycle?

d[i][i] < 0 after the loops. Any pair that can reach such an i and be reached from it can be driven to -INF.

Floyd vs n Dijkstras?

Floyd wins on dense graphs and when you want the whole matrix plus extras (reachability, minimax). n Dijkstras win on sparse non-negative graphs, especially n = 2000, m = 5000.

Can Floyd handle negative edges?

Yes, the same way Bellman-Ford does. Negative cycles show up on the diagonal. It does not handle them as finite distances — they are a flag.

Recap

  • k is the new intermediate, and it is the outer loop.
  • d[i][j] = min(d[i][j], d[i][k]+d[k][j]).
  • n <= 400. Use long and a safe INF.
  • d[i][i] < 0 means a negative cycle.
  • The same triple loop does reachability and minimax.
