Bridges & Articulation Points

A bridge is an edge whose removal disconnects an undirected graph; an articulation point is a vertex with the same property. Both fall out of one tin/low DFS.

Medium 22 min read Prerequisites: DFS & Connected Components bridges articulation tin/low P1

Why this exists

"Critical connections", "edges we must repair", "nodes whose failure splits the network" are the same DFS. Discovery time tin[u] and low[u] — the earliest discovery you can reach from u without using the parent edge — classify every edge and every vertex in one pass.

Edge u-v (v a child) is a bridge iff low[v] > tin[u]: v cannot climb to u or above, so the only way out is that edge. Vertex u is articulation (non-root) iff some child has low[v] ≥ tin[u]. The root is articulation iff it has two or more DFS children.

The bridge-block tree (compress 2-edge-connected components) is a tree you can run reroot DP on. Same for the block-cut tree of articulation points.

low[v] > tin[u] means "v cannot reach u or above without this edge" — a bridge. low[v] >= tin[u] means "v cannot reach strictly above u" — u is a cut vertex for that child.

Recognise this pattern

Say yes when you see

  • Critical connections / bridges in an undirected graph
  • Articulation points / cut vertices
  • 2-edge-connected components, bridge-block tree
  • "Minimum edges to add so there is no bridge"
  • LC 1192 Critical Connections in a Network

Not this pattern when

  • Directed graphs → SCCs / bridges-in-directed (different, rarer)
  • Weighted "most critical" with capacities → min-cut / flow
  • You only need connected components → plain DFS, no tin/low
  • Finding a cycle → parent-coloured DFS, no low

Constraint tell: n, m ≤ 2×10⁵, undirected, possibly with parallel edges (a parallel pair is never a bridge). Multiedges need an edge id so the parent skip is exact.

Core idea and the invariant

DFS from every unvisited node. tin[u] = low[u] = timer++. For a neighbour v: if v is the parent, skip; if visited, low[u] = min(low[u], tin[v]) (back-edge); else recurse, low[u] = min(low[u], low[v]), then test the bridge / articulation predicates.

Parent must be an edge identity, not just a vertex, when parallel edges exist. The root's articulation test is "number of DFS children >= 2", independent of low.

low[u] is the smallest tin reachable from u by tree edges going down plus at most one back-edge, never using the parent edge. A child that cannot beat tin[u] is trapped in u's subtree.

Structure

Algorithm

  1. tin = low = -1, timer = 0. DFS every component.
  2. On a child: recurse, then low[u] = min(low[u], low[v]).
  3. Bridge: low[v] > tin[u]. Articulation: low[v] >= tin[u] (and u not a 1-child root).
  4. Back-edge to an already visited non-parent: low[u] = min(low[u], tin[v]).
  5. Root: articulation iff it has two or more DFS children.
  6. Multiedges: identify the parent by edge id, not by vertex.

Java implementation

JavaBridgeBrute.java
import java.util.*;
    public class BridgeBrute {
        static int comps(int n, List<int[]> edges, int skip) {
            int[] p = new int[n];
            for (int i = 0; i < n; i++) p[i] = i;
            java.util.function.IntUnaryOperator f = new java.util.function.IntUnaryOperator() {
                public int applyAsInt(int x) { return p[x] == x ? x : (p[x] = applyAsInt(p[x])); }
            };
            for (int i = 0; i < edges.size(); i++) if (i != skip) {
                int[] e = edges.get(i);
                p[f.applyAsInt(e[0])] = f.applyAsInt(e[1]);
            }
            int c = 0;
            for (int i = 0; i < n; i++) if (f.applyAsInt(i) == i) c++;
            return c;
        }
        public static void main(String[] args) {
            List<int[]> e = List.of(new int[]{0,1}, new int[]{1,2}, new int[]{2,0}, new int[]{1,3});
            int base = comps(4, e, -1);
            for (int i = 0; i < e.size(); i++)
                if (comps(4, e, i) > base) System.out.println(e.get(i)[0] + "-" + e.get(i)[1]);
        }
        // Input : triangle 0-1-2 plus 1-3
        // Output: 1-3
    }
JavaBridges.java
import java.util.*;
    public class Bridges {
        List<int[]>[] g;
        int[] tin, low;
        int timer;
        List<int[]> bridges = new ArrayList<>();
        boolean[] art;
        Bridges(int n) {
            g = new List[n];
            for (int i = 0; i < n; i++) g[i] = new ArrayList<>();
            tin = new int[n]; low = new int[n]; art = new boolean[n];
            Arrays.fill(tin, -1);
        }
        void add(int u, int v, int id) { g[u].add(new int[] {v, id}); g[v].add(new int[] {u, id}); }
        void dfs(int u, int pe) {
            tin[u] = low[u] = timer++;
            int kids = 0;
            for (int[] e : g[u]) {
                int v = e[0], id = e[1];
                if (id == pe) continue;
                if (tin[v] != -1) { low[u] = Math.min(low[u], tin[v]); continue; }
                kids++;
                dfs(v, id);
                low[u] = Math.min(low[u], low[v]);
                if (low[v] > tin[u]) bridges.add(new int[] {u, v});
                if (pe != -1 && low[v] >= tin[u]) art[u] = true;
            }
            if (pe == -1 && kids >= 2) art[u] = true;
        }
        public static void main(String[] args) {
            Bridges b = new Bridges(4);
            b.add(0, 1, 0); b.add(1, 2, 1); b.add(2, 0, 2); b.add(1, 3, 3);
            b.dfs(0, -1);
            System.out.println(b.bridges.get(0)[0] + "-" + b.bridges.get(0)[1]);
            System.out.println(Arrays.toString(b.art));
        }
        // Input : triangle + leaf
        // Output: 1-3
        //         [false, true, false, false]
    }
JavaLowLink.java
public class LowLink {
        static void rec(int u, int p, int[] tin, int[] low, int[] t, java.util.List<Integer>[] g) {
            tin[u] = low[u] = t[0]++;
            for (int v : g[u]) {
                if (v == p) continue;
                if (tin[v] != -1) { low[u] = Math.min(low[u], tin[v]); continue; }
                rec(v, u, tin, low, t, g);
                low[u] = Math.min(low[u], low[v]);
            }
        }
        public static void main(String[] args) {
            int n = 3;
            java.util.List<Integer>[] g = new java.util.List[n];
            for (int i = 0; i < n; i++) g[i] = new java.util.ArrayList<>();
            g[0].add(1); g[1].add(0); g[1].add(2); g[2].add(1);
            int[] tin = new int[n], low = new int[n];
            java.util.Arrays.fill(tin, -1);
            rec(0, -1, tin, low, new int[1], g);
            System.out.println(java.util.Arrays.toString(low));
        }
        // Input : path 0-1-2
        // Output: [0, 1, 2]
    }

Edge cases and pitfalls

  • Using the parent as a back-edge
    low[v] becomes tin[u] for every child, so you report zero bridges.
    Skip the parent edge (by edge id if the graph has multis).
  • Bridge test with >= instead of >
    A back-edge into u itself is not a bridge; >= falsely flags it.
    Bridge is strict >. Articulation is ≥.
  • Root tested with the non-root rule
    A root with one long child looks like an articulation under the low test and is not.
    Root: two or more DFS children. Never the low predicate.
  • Directed input treated as undirected
    You add only one direction and the DFS cannot climb back-edges.
    This page is undirected: store both directions, parent-skip one id.
  • Parallel edges
    Parent stored as a vertex: the second u-v is skipped as "parent" and a real non-bridge is reported as a bridge.
    Give every undirected edge an id; skip that id only.

Interview follow-ups

Why is the bridge test strict >?

If low[v] == tin[u], v can reach u via a back-edge (or via something that reaches u). Removing u-v, that back-edge still connects v's subtree to u. Not a bridge.

Why is articulation >=?

If low[v] == tin[u], v can reach u but not above u. Removing u disconnects v's subtree from the rest of the graph (the parent side of u).

Directed bridges?

A directed edge is a bridge if it is a bridge in the underlying undirected sense and it is the unique way to go between those SCCs — usually you just want "edges between SCCs" on the condensation.

How do you handle multiple components?

Run the DFS from every unvisited node. Each call has its own root test.

Recap

  • low[v] > tin[u] → edge u-v is a bridge.
  • low[v] >= tin[u] → u is articulation (not the 1-child root).
  • Root is articulation iff it has 2+ DFS children.
  • Never treat the parent edge as a back-edge.
  • Multiedges need an edge id.
