Bridges & Articulation Points

A bridge is an edge whose removal disconnects an undirected graph; an articulation point is a vertex with the same property. Both fall out of one tin/low DFS.

Medium 26 min read Prerequisites: DFS & Connected Components bridges articulation tin/low P1

Why this exists

You maintain a network of undirected cables, and you must name every cable whose single failure splits the network in two, and every junction whose single failure does the same. Those are bridges (critical edges) and articulation points (cut vertices). Trying every cable or every junction with a fresh connectivity search is m or n depth-first searches, about 4×10¹⁰ steps at the usual limits. One carefully instrumented search classifies every edge and every vertex in linear time.

The search records two numbers at each vertex. tin[u] is the discovery time, a counter that ticks the first time you enter u. low[u] is the earliest discovery time you can still reach from u by walking down the DFS subtree and then taking at most one back-edge, never using the parent edge you arrived on. If a child v has low[v] > tin[u], that subtree cannot climb back to u or anything earlier, so the only cable out is u-v and that cable is a bridge. If some child has low[v] ≥ tin[u], the subtree can reach u but not strictly above it, so removing u disconnects that child from the parent side: u is an articulation point. The root of the search is a special case: it is an articulation point exactly when it has two or more DFS children.

In a problem statement the tell is "critical connections", "edges we must repair", or "nodes whose failure splits the network" on an undirected graph with n, m ≤ 2×10⁵. After you have the bridges you can compress each 2-edge-connected piece into a supernode and obtain a tree, the bridge-block tree, which is the usual place to hang a reroot DP. The same idea with articulation points is the block-cut tree.

low[v] is the earliest discovery time the subtree of v can still climb to, without walking back over the parent edge. If it cannot even reach u, the edge u-v is a bridge; if it cannot reach strictly above u, then u is a cut vertex for that child.

Constraint tell: n, m ≤ 2×10⁵ on an undirected graph is the linear window: one DFS, each edge looked at twice. Parallel cables are allowed and a parallel pair is never a bridge, so the parent skip must use an edge id, not a vertex id. Recursion depth can be n; the same Java-stack warning as the SCC page applies. Trying every edge with a fresh search is about 4×10¹⁰ steps and will time out.

Core idea and the invariant

Start a DFS from every unvisited vertex so a disconnected graph is handled. On entry set tin[u] = low[u] = timer++, so both numbers begin as the discovery time. For each neighbour v, three cases. If the edge is the parent edge you arrived on, skip it — walking back over it would pretend the subtree can always climb to u and you would report zero bridges. If v is already visited, this is a back-edge: write low[u] = min(low[u], tin[v]). If v is new, recurse, then write low[u] = min(low[u], low[v]) and test the two predicates on that child.

The predicates are the whole classification. low[v] > tin[u] means the child cannot reach u or anything earlier without this edge, so u-v is a bridge (strict inequality: equality means a back-edge still ties the subtree to u). low[v] ≥ tin[u] means the child cannot reach strictly above u, so removing u splits that child off the parent side: a non-root u is then an articulation point. The root ignores low and is an articulation point exactly when it has two or more DFS children. When the graph has parallel edges, store an edge id on both orientations and skip by that id, otherwise the second u-v is mistaken for the parent and a real non-bridge is reported as a bridge.

Walk the four-vertex sample in words. The graph is the triangle 0-1-2 plus a pending leaf 1-3. The search walks 0-1-2; vertex 2 sees 0 as a back-edge and writes low[2] = tin[0] = 1. Returning to 1, low[1] becomes 1, which is not strictly greater than tin[0], so 0-1 is not a bridge. The child 3 is a leaf: low[3] = tin[3] = 4, which is greater than tin[1], so 1-3 is a bridge, and the same comparison ≥ marks 1 as an articulation point. Root 0 has only one DFS child, so it is not an articulation point even though the triangle hangs off it.

low[u] is the smallest tin reachable from u by tree edges going down plus at most one back-edge, never using the parent edge. A child v with low[v] > tin[u] cannot reach u or above; a child with low[v] ≥ tin[u] cannot reach strictly above u.

In plain words, low asks "how far back toward the ancestors can this subtree still climb without walking the cable I just used?", and the two inequalities decide whether that cable, or that junction, is the only way out.

low[v] on an undirected graph

Same measuring stick as Tarjan SCC, different graph: low[v] is the earliest discovery time the subtree can still climb to, walking down tree edges and then at most one back-edge, never using the parent cable. The bridge test is strict > because reaching u itself is enough to keep the graph connected after u-v is deleted. The articulation test is ≥ because reaching u but not above it means deleting u isolates that child from the parent side.

Structure

Algorithm

  1. Initialise tin and low to -1, then DFS every component. A disconnected graph has several roots; each root gets its own child-count test, and a vertex already discovered in an earlier call is skipped.
  2. On a new child, recurse first, then pull low[v] into low[u]. The child must finish so its own back-edges have already been written; only then is low[v] a trustworthy earliest-climb for the subtree.
  3. Test the two predicates on that child. low[v] > tin[u] flags the tree edge as a bridge; low[v] ≥ tin[u] flags a non-root u as an articulation point. The strictness difference is the whole distinction between "cannot reach u" and "cannot reach above u".
  4. On a back-edge to an already visited non-parent, write tin[v] into low[u]. That is the one allowed climb: a single back-edge to a vertex discovered earlier. Do not write low[v] here, and do not treat the parent edge as a back-edge.
  5. Treat the root as a special case. The root is an articulation point if and only if it has two or more DFS children, regardless of any low value; a single long child hanging off the root does not split the graph when the root is removed.
  6. Identify the parent by edge id when parallel cables exist. Skipping by vertex id treats the second u-v as the parent and a real non-bridge is reported as a bridge; give every undirected edge an id and skip that id only.

Java implementation

JavaBridgeBrute.java
import java.util.*;
    public class BridgeBrute {
        static int comps(int n, List<int[]> edges, int skip) {
            int[] p = new int[n];
            for (int i = 0; i < n; i++) p[i] = i;
            java.util.function.IntUnaryOperator f = new java.util.function.IntUnaryOperator() {
                public int applyAsInt(int x) { return p[x] == x ? x : (p[x] = applyAsInt(p[x])); }
            };
            for (int i = 0; i < edges.size(); i++) if (i != skip) {
                int[] e = edges.get(i);
                p[f.applyAsInt(e[0])] = f.applyAsInt(e[1]);
            }
            int c = 0;
            for (int i = 0; i < n; i++) if (f.applyAsInt(i) == i) c++;
            return c;
        }
        public static void main(String[] args) {
            List<int[]> e = List.of(new int[]{0,1}, new int[]{1,2}, new int[]{2,0}, new int[]{1,3});
            int base = comps(4, e, -1);
            for (int i = 0; i < e.size(); i++)
                if (comps(4, e, i) > base) System.out.println(e.get(i)[0] + "-" + e.get(i)[1]);
        }
        // Input : triangle 0-1-2 plus 1-3
        // Output: 1-3
    }
JavaBridges.java
import java.util.*;
    public class Bridges {
        List<int[]>[] g;
        int[] tin, low;
        int timer;
        List<int[]> bridges = new ArrayList<>();
        boolean[] art;
        Bridges(int n) {
            g = new List[n];
            for (int i = 0; i < n; i++) g[i] = new ArrayList<>();
            tin = new int[n]; low = new int[n]; art = new boolean[n];
            Arrays.fill(tin, -1);
        }
        void add(int u, int v, int id) { g[u].add(new int[] {v, id}); g[v].add(new int[] {u, id}); }
        void dfs(int u, int pe) {
            tin[u] = low[u] = timer++;
            int kids = 0;
            for (int[] e : g[u]) {
                int v = e[0], id = e[1];
                if (id == pe) continue;
                if (tin[v] != -1) { low[u] = Math.min(low[u], tin[v]); continue; }
                kids++;
                dfs(v, id);
                low[u] = Math.min(low[u], low[v]);
                if (low[v] > tin[u]) bridges.add(new int[] {u, v});
                if (pe != -1 && low[v] >= tin[u]) art[u] = true;
            }
            if (pe == -1 && kids >= 2) art[u] = true;
        }
        public static void main(String[] args) {
            Bridges b = new Bridges(4);
            b.add(0, 1, 0); b.add(1, 2, 1); b.add(2, 0, 2); b.add(1, 3, 3);
            b.dfs(0, -1);
            System.out.println(b.bridges.get(0)[0] + "-" + b.bridges.get(0)[1]);
            System.out.println(Arrays.toString(b.art));
        }
        // Input : triangle + leaf
        // Output: 1-3
        //         [false, true, false, false]
    }
JavaLowLink.java
public class LowLink {
        static void rec(int u, int p, int[] tin, int[] low, int[] t, java.util.List<Integer>[] g) {
            tin[u] = low[u] = t[0]++;
            for (int v : g[u]) {
                if (v == p) continue;
                if (tin[v] != -1) { low[u] = Math.min(low[u], tin[v]); continue; }
                rec(v, u, tin, low, t, g);
                low[u] = Math.min(low[u], low[v]);
            }
        }
        public static void main(String[] args) {
            int n = 3;
            java.util.List<Integer>[] g = new java.util.List[n];
            for (int i = 0; i < n; i++) g[i] = new java.util.ArrayList<>();
            g[0].add(1); g[1].add(0); g[1].add(2); g[2].add(1);
            int[] tin = new int[n], low = new int[n];
            java.util.Arrays.fill(tin, -1);
            rec(0, -1, tin, low, new int[1], g);
            System.out.println(java.util.Arrays.toString(low));
        }
        // Input : path 0-1-2
        // Output: [0, 1, 2]
    }

Complexity

Time O(n + m) Space O(n + m)

One DFS visits every vertex once and looks at every undirected edge twice (once from each end). The bridge and articulation tests are a constant amount of work per tree edge, so the whole run is O(n + m). At n, m = 2×10⁵ that is a few hundred thousand array operations, a few milliseconds.

The brute alternative — delete each edge and rerun a connectivity search — is O(m(n + m)), about 8×10¹⁰ steps at the same limits, which no judge accepts. Recursion depth can be n, so a path graph overflows the default Java stack; prefer an explicit stack on Codeforces Java.

Edge cases and pitfalls

  • Using the parent as a back-edge
    Walking back over the parent cable writes tin[u] into every child's low, so every child appears able to climb to u and you report zero bridges on a graph that has several.
    Skip the parent edge. When the graph may have parallel cables, skip by edge id, not by vertex id, so the second u-v is still examined.
  • Bridge test with >= instead of >
    A back-edge that reaches u itself makes low[v] == tin[u]. Using ≥ flags that tree edge as a bridge even though the back-edge still ties the subtree to u after the edge is deleted.
    The bridge test is strict >. The articulation test is ≥. Write the two comparisons on separate lines so a later edit cannot blur them.
  • Root tested with the non-root rule
    A root with one long child has low[child] ≥ tin[root] for the trivial reason that nothing sits above the root, so the low test marks a junction whose removal does not split the graph.
    The root is an articulation point if and only if it has two or more DFS children. Never apply the low predicate to the root.
  • Directed input treated as undirected
    Storing only one orientation means the search cannot climb a back-edge that the input listed the other way, so every tree edge looks like a bridge.
    This page is for undirected graphs: store both directions of every cable and skip one edge id as the parent. Directed "bridges" are edges between SCCs, a different page.
  • Parallel edges
    Parent stored as a vertex: the second cable between the same pair is skipped as "parent", the real back-edge is never seen, and a pair of parallel cables is reported as a bridge even though neither one disconnects the graph.
    Give every undirected edge an integer id, store (neighbour, id) in the adjacency lists, and skip that id only.

Interview follow-ups

Why is the bridge test strict >?

If low[v] == tin[u], the subtree of v can still reach u through a back-edge (or through something that itself reaches u). Delete the tree edge u-v and that back-edge still joins the subtree to u, so the graph stays connected. A bridge is an edge whose deletion really splits the graph, which is the stricter "cannot even reach u".

Why is articulation >=?

If low[v] == tin[u], the subtree can reach u but not any ancestor of u. Delete vertex u and the subtree has nowhere to go: it is cut off from the parent side of u. That is why a single child with low[v] ≥ tin[u] is enough to mark a non-root as an articulation point, and why the root needs a different test.

Directed bridges?

A directed edge whose deletion breaks reachability is usually just an edge between two SCCs of the condensation, not a tin/low fact on the underlying undirected graph. If the statement is directed, run the SCC page first and look at edges that leave one supernode for another. The algorithm on this page assumes undirected cables stored both ways.

How do you handle multiple components?

Run the DFS from every vertex that is still unvisited. Each call has its own root and its own child-count test. Bridges and articulation points are local to a component: a cable cannot be a bridge across two pieces that were never joined, and an isolated vertex is not an articulation point.

  • low[v] >= tin[u] → u is articulation (not the 1-child root).

  • Never treat the parent edge as a back-edge.
  • Multiedges need an edge id.
