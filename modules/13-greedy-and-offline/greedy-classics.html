Greedy Classics

A field guide to the greedy shapes you will actually be handed: intervals, jumps, gas, candies, Huffman-like merging, and scheduling.

Medium 24 min read Prerequisites: Greedy Foundations, Heaps & Priority Queue greedy intervals scheduling P0

Why this exists

Once the proof toolkit exists, recognition is the remaining skill. These patterns share a sort key and a one-pass decision; mixing the keys is the usual bug.

Intervals: finish time, or "min arrows / rooms" as a sweep. Jumps: farthest reach. Gas: prefix of gas-cost, start after the minimum prefix. Candies / ratings: two passes. Merging files: always merge two smallest (Huffman / heap).

Interviewers chain them: "now the weighted version" (DP), "now k rooms" (heap of end times). Know which upgrade kills the greedy.

Name the sort key in one phrase before you touch the keyboard. If you cannot, you do not yet know which classic it is.

Recognise this pattern

Say yes when you see

  • Intervals on a line: select, cover, or puncture
  • Jump game / jump game II
  • Circular gas / circular tour
  • Ratings with a neighbour constraint (candies)
  • Repeatedly combine two smallest costs

Not this pattern when

  • Weighted interval scheduling → DP
  • Must take fractions? wait, fractional knapsack IS greedy; 0/1 is DP
  • Need exact k-cover with costs → maybe min-cost flow
  • Graph shortest path → Dijkstra is greedy-with-a-proof, but it is its own page

Core idea and the invariant

Jump Game II: the current interval [L,R] was reachable in s jumps. Scan it for the farthest index, which becomes the next R. That is BFS-on-array without a queue.

Gas: if total gas < total cost, impossible. Otherwise the unique start is the index after the minimum prefix of (gas-cost). Proof: that prefix is the deepest deficit; starting just after it never goes negative.

Each classic has one invariant: activity — last-finish is minimal among k-sets; jumps — [0,R] is exactly the set reachable in ≤ s jumps; gas — prefix surplus is minimised at start-1.

Algorithm

  1. Classify the object: interval, jump, circular, rating, merge.
  2. Sort or heap with the matching key.
  3. One pass maintaining the invariant (last end, farthest, prefix, slope, heap pop).
  4. Handle impossible (gas total, jump that cannot grow R).
  5. Upgrade check: weights? k resources? → DP or a heap of k.
  6. Reconstruct if asked: store parent jumps / chosen indices.

Java implementation

Min jumps by DFS. Exponential.

JavaJumpBrute.java
public class JumpBrute {
        static int min(int[] a, int i) {
            if (i >= a.length - 1) return 0;
            int best = 1_000_000;
            for (int j = 1; j <= a[i]; j++) best = Math.min(best, 1 + min(a, i + j));
            return best;
        }
        public static void main(String[] args) {
            System.out.println(min(new int[] {2, 3, 1, 1, 4}, 0));
        }
        // Input : [2,3,1,1,4]
        // Output: 2
    }

Greedy window. O(n).

JavaJumpGameII.java
public class JumpGameII {
        static int jumps(int[] a) {
            int jumps = 0, r = 0, far = 0;
            for (int i = 0; i < a.length - 1; i++) {
                far = Math.max(far, i + a[i]);
                if (i == r) { jumps++; r = far; }
            }
            return jumps;
        }
        public static void main(String[] args) {
            System.out.println(jumps(new int[] {2, 3, 1, 1, 4}));
        }
        // Input : [2,3,1,1,4]
        // Output: 2
    }

Circular tour start index.

JavaGasStation.java
public class GasStation {
        static int start(int[] gas, int[] cost) {
            int n = gas.length, tank = 0, min = 0, idx = 0;
            for (int i = 0; i < n; i++) {
                tank += gas[i] - cost[i];
                if (tank < min) { min = tank; idx = i + 1; }
            }
            return tank < 0 ? -1 : idx % n;
        }
        public static void main(String[] args) {
            System.out.println(start(new int[] {1, 2, 3, 4, 5}, new int[] {3, 4, 5, 1, 2}));
        }
        // Input : gas 1..5, cost 3,4,5,1,2
        // Output: 3
    }

Complexity

Time O(n) or O(n log n) Space O(1) to O(n)

Jumps and gas are one pass. Interval problems sort. Huffman is n heap operations, O(n log n).

Edge cases and pitfalls

  • Jump Game II loop including last index
    You add an extra jump when i hits n-1.
    Loop to n-2 only.
  • Gas returning 0 when total is negative
    The min-prefix still exists but the tour is impossible.
    Check total < 0 first.
  • Meeting rooms without a heap
    Sorting by start and counting overlap naively is O(n^2), or wrong if you only look at the previous meeting.
    Min-heap of end times, or a sweep of +1/-1.
  • Candies one pass
    A decreasing then increasing valley needs both directions.
    Left-to-right enforce left neighbour, right-to-left enforce right, take max.
  • Huffman adding the new file once
    Cost is the sum of internal nodes, not just the final root. Push the merged size back.

Interview follow-ups

Why is Jump II not DP?

It can be DP (min jumps to i). The greedy window is BFS layers on the array, so the first time you reach n-1 is the shortest. That is the proof.

Two starting points for gas?

If total ≥ 0 there is exactly one start (modulo a stretch of zeros). The unique deepest prefix deficit pins it.

Can Huffman run on more than two-way merges?

Yes, k-way: always merge k lightest. Pad with zeros if n-1 is not divisible by k-1.

Interval covering from a point?

Sort by start, greedy take the interval that covers the current point and extends farthest. Jump Game in disguise.

Recap

  • Intervals: sort by end (or sweep).
  • Jumps: farthest in the current BFS layer.
  • Gas: start after the minimum prefix.
  • Candies: max of two slope passes.
  • Merges: always two smallest, push back.
