Mo's Algorithm

Reorder offline range queries into sqrt-blocks so adding/removing one endpoint is amortised O(n sqrt n) instead of O(nq).

Hard 24 min read Prerequisites: Coordinate Compression, Two Pointers Mo offline sqrt P2

Why this exists

n,q = 1e5 range queries that are not prefix-friendly (distinct count, mode, mex) cannot use Fenwick. If you can add and remove one index in O(1) or O(log n), Mo's algorithm orders the queries so the two pointers L,R move O(n sqrt n) times total.

Sort queries by (L / B, R) with B ≈ n/sqrt(q) or sqrt(n). Hilbert-order curves cut the constant further. Hilbert is optional; block sort is the interview version.

Mo on trees (Euler tour, two visits) and Mo with updates (time as a third coordinate, n^{5/3}) are the upgrades. If the add is already O(log n), total is O(n sqrt n log n), still often fine.

You pay for moving L and R, not for answering. Sort queries so consecutive ones are nearby on the number line, in blocks.

Recognise this pattern

Say yes when you see

  • Offline [L,R] queries, add/remove an index is O(1)/O(log)
  • Distinct values in a range (no updates)
  • Sum of frequencies^2, mode, mex with a frequency of frequencies
  • n,q ≤ 1e5 and you cannot think of a Fenwick identity
  • Tree-path queries via Euler tour (Mo on trees)

Not this pattern when

  • Online queries → you cannot reorder
  • Range sum / XOR → prefix, do not Mo
  • Updates + queries at 1e5 if add is O(n) → too slow even for Mo-with-time
  • n=1e6, q=1e6, add=O(1) → n sqrt n = 1e9, too slow; need a better structure

Core idea and the invariant

Maintain current [curL, curR] (init empty or [0,-1]). For each query in block order, while curL>L add --curL; while curR<R add ++curR; while curL<L rem curL++; while curR>R rem curR--. Then store ans[id].

Block id of L is L/B. Sort by block, then by R ascending (odd blocks descending R — Hilbert-lite, cuts moves in half).

After processing a query, [curL, curR] equals the query range and the frequency structure matches that range. Total |endpoint moves| = O((n+q) sqrt n) with B = sqrt(n).

Algorithm

  1. Compress values if they are 1e9 so freq[] is an array.
  2. Pack queries (L,R,id). Sort by (L/B, R) with odd-even R.
  3. add(i): freq[a[i]]++; if freq==1 distinct++.
  4. rem(i): if freq==1 distinct--; freq[--].
  5. Move the four while-loops in an order that never goes invalid (add before rem when expanding).
  6. Write ans[id]. Print in original order.

Java implementation

Rebuild a set per query.

JavaDistinctBrute.java
import java.util.*;
    public class DistinctBrute {
        static int dist(int[] a, int l, int r) {
            Set<Integer> s = new HashSet<>();
            for (int i = l; i <= r; i++) s.add(a[i]);
            return s.size();
        }
        public static void main(String[] args) {
            int[] a = {1, 2, 1, 3, 2};
            System.out.println(dist(a, 0, 2) + " " + dist(a, 1, 4));
        }
        // Input : [1,2,1,3,2], queries [0,2] [1,4]
        // Output: 2 3
    }

Classic Mo for distinct counts.

JavaMoDistinct.java
import java.util.*;
    public class MoDistinct {
        static int[] a, freq, ans;
        static int distinct;
        static void add(int i) { if (freq[a[i]]++ == 0) distinct++; }
        static void rem(int i) { if (--freq[a[i]] == 0) distinct--; }
        public static void main(String[] args) {
            a = new int[] {1, 2, 1, 3, 2};
            int[][] qs = {{0, 2, 0}, {1, 4, 1}};
            int n = a.length, B = (int) Math.sqrt(n);
            Arrays.sort(qs, (p, q) -> {
                int bp = p[0] / B, bq = q[0] / B;
                if (bp != bq) return bp - bq;
                return (bp & 1) == 0 ? p[1] - q[1] : q[1] - p[1];
            });
            freq = new int[4];
            ans = new int[2];
            int cl = 0, cr = -1;
            for (int[] q : qs) {
                while (cl > q[0]) add(--cl);
                while (cr < q[1]) add(++cr);
                while (cl < q[0]) rem(cl++);
                while (cr > q[1]) rem(cr--);
                ans[q[2]] = distinct;
            }
            System.out.println(ans[0] + " " + ans[1]);
        }
        // Input : same two queries
        // Output: 2 3
    }

The four while-loops, isolated. Plug any add/rem.

JavaMoAddRem.java
public class MoAddRem {
        static void dummy() {}
        static void run(int[][] qs) {
            int cl = 0, cr = -1;
            for (int[] q : qs) {
                while (cl > q[0]) { dummy(); cl--; }
                while (cr < q[1]) { dummy(); cr++; }
                while (cl < q[0]) { dummy(); cl++; }
                while (cr > q[1]) { dummy(); cr--; }
            }
        }
        public static void main(String[] args) {
            run(new int[][] {{0, 2, 0}});
            System.out.println("ok");
        }
        // Input : one query
        // Output: ok
    }

Complexity

Time O((n + q) sqrt n * T_add) Space O(n + q)

L moves: each block of L has size B, q queries, plus n resets: O(q B + n n/B). R moves O(n * n/B + q n/B wait): R is monotonic inside a block, so O((n/B)*n + q*something). Set B=sqrt(n), both are O(n sqrt n).

Edge cases and pitfalls

  • add/rem not inverses
    Removing twice, or freq going negative, then distinct drifts forever.
    rem is the exact inverse. Assert freq[x]>=0.
  • HashMap frequencies at 1e5
    T_add is huge; n sqrt n * hashmap blows the TL.
    Compress to 1..n, int[] freq.
  • Starting from [0,0] without adding 0
    You think the first index is in, but it is not, or you double-add it.
    Start [0,-1] empty, only add in the while loops.
  • Sorting by R only
    L jumps randomly, O(nq).
    Primary key is L-block.
  • Inclusive/exclusive mix
    Queries are [l,r] inclusive, you rem r when you meant r+1.
    Stick to inclusive and the four loops above.

Interview follow-ups

Why sqrt?

Balance L-moves (worse when B is large) against R-moves (worse when B is small / more blocks). B=n/sqrt(q) is slightly better than sqrt(n) when q differs from n.

Can Mo be online?

No. The sort needs all queries. If queries are online, you need a real data structure.

Distinct with updates, online?

Not Mo. Segment tree of Fenwicks, or a wavelet tree, or sqrt rebuild. Harder.

Hilbert order?

Map (L,R) to a position on a Hilbert curve so nearby queries in 2D are nearby in 1D. Faster constants, longer code. Block sort first.

Recap

  • Offline only. Sort by (L/B, R).
  • Four while-loops move [curL,curR].
  • add/rem inverse, array frequencies after compress.
  • Start empty [0,-1].
  • B ≈ sqrt(n); odd-even R helps.
