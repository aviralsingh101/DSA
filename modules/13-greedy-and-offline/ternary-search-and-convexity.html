Ternary Search & Convexity

On a unimodal function, two probes shrink the interval by a constant factor — ternary search, or a golden-section / integer-trinary loop.

Medium 22 min read Prerequisites: Binary Search on Answer, Greedy Foundations ternary search unimodal convex P2

Why this exists

Binary search needs a monotonic predicate. Many contest functions go down then up (or up then down): distance-sum to points on a line, a convex cost, a unimodal bitwise function. Ternary search finds the trough in O(log n) probes.

Convex DP (divide-and-conquer / Knuth / Li Chao / cht) is the data-structure upgrade of the same picture: the opt[i] as a function of i is unimodal or the cost is convex, so you can search or hull it.

On integers, a loop that keeps [lo, hi] and compares f(m1) and f(m2) is safer than floating ternary. Stop when hi-lo is a few units and brute the remainder.

If f decreases then increases, the minimum cannot lie in the worse third. Throw that third away. Convexity of f is a sufficient condition.

Recognise this pattern

Say yes when you see

  • Unimodal f on a line / on an index range
  • "Choose x to minimise sum |x-a_i| or sum (x-a_i)^2"
  • Ternary on the real line with a convex cost
  • Integer unimodal array, find the peak (also bitonic search)
  • Alphas of convex DP where you ternary an opt

Not this pattern when

  • Monotone predicate → binary search, one probe
  • Multiple local minima → ternary is wrong
  • Need the whole DP hull → Li Chao / CHT, not a one-shot ternary
  • Discrete not unimodal (random array) → linear scan

Constraint tell: O(log range) evaluations. If f is O(n), total O(n log X). On doubles, 80-100 iterations beat eps 1e-9. Integers: while hi-lo>3.

Core idea and the invariant

Integer: while hi-lo>2, m1 = lo+(hi-lo)/3, m2 = hi-(hi-lo)/3. If f(m1)<f(m2) the min is not right of m2, set hi=m2; else lo=m1. Then scan lo..hi.

Floats: same, or golden-section to reuse probes. Prove unimodality first: second differences of f ≥ 0 (discrete convex), or derivative changes sign once.

The minimum (maximum) of a unimodal f on [lo, hi] still lies in the shrunk interval after a third is discarded. When hi-lo is O(1), brute is exact.

Algorithm

  1. Prove unimodality (convex / one peak).
  2. Choose domain: indices, or a real x, or a discrete parameter.
  3. Loop with m1, m2 at 1/3 and 2/3 (or golden).
  4. Drop the third with the worse f.
  5. Stop when the interval is O(1) (ints) or width < eps (reals).
  6. Brute remaining integers. Return argmin.

Java implementation

Evaluate f everywhere. Correct, uses the unimodal array.

JavaMinScan.java
public class MinScan {
        static int argmin(int[] f) {
            int b = 0;
            for (int i = 1; i < f.length; i++) if (f[i] < f[b]) b = i;
            return b;
        }
        public static void main(String[] args) {
            System.out.println(argmin(new int[] {9, 7, 4, 2, 3, 8}));
        }
        // Input : [9,7,4,2,3,8]
        // Output: 3
    }

Integer ternary plus a finishing scan.

JavaTernaryInt.java
public class TernaryInt {
        static int argmin(int[] f) {
            int lo = 0, hi = f.length - 1;
            while (hi - lo > 3) {
                int m1 = lo + (hi - lo) / 3;
                int m2 = hi - (hi - lo) / 3;
                if (f[m1] < f[m2]) hi = m2;
                else lo = m1;
            }
            int b = lo;
            for (int i = lo + 1; i <= hi; i++) if (f[i] < f[b]) b = i;
            return b;
        }
        public static void main(String[] args) {
            System.out.println(argmin(new int[] {9, 7, 4, 2, 3, 8}));
        }
        // Input : [9,7,4,2,3,8]
        // Output: 3
    }

Minimise a convex f on [L,R] with 80 iterations.

JavaTernaryReal.java
public class TernaryReal {
        static double f(double x) { return (x - 3) * (x - 3) + 1; }
        static double minX(double lo, double hi) {
            for (int it = 0; it < 80; it++) {
                double m1 = lo + (hi - lo) / 3;
                double m2 = hi - (hi - lo) / 3;
                if (f(m1) < f(m2)) hi = m2;
                else lo = m1;
            }
            return (lo + hi) / 2;
        }
        public static void main(String[] args) {
            System.out.printf("%.4f%n", minX(0, 10));
        }
        // Input : (x-3)^2+1 on [0,10]
        // Output: 3.0000
    }

Complexity

Time O(log_{3/2} range) evaluations Space O(1)

Each step multiplies the interval by ≤ 2/3. Integer domain of size n dies in O(log n) steps; you still brute O(1) leftovers.

Edge cases and pitfalls

  • Plateaus
    f(m1)==f(m2) on a flat bottom: dropping either third can throw away the only index you needed if you don't brute the end.
    Stop early and scan; or treat == as a case that shrinks both sides carefully.
  • Not unimodal
    Two valleys. Ternary converges to a local min.
    Prove convexity. Plot f on a small test.
  • Floating ternary with too few iters
    eps 1e-9 on [0,1e9] needs ~ 2 log_{3/2}(1e18) ≈ 90 iterations, not 40.
    80-100 iterations, ignore eps.
  • Integer overflow in m1/m2
    lo + (hi-lo)/3 is safe; (2*lo+hi)/3 can overflow.
    The code above.
  • Ternary when binary on f(m)<=f(m+1) works
    Two probes per step instead of one. Slower and more error-prone.
    On integers, binary-search the first index with f[i]<=f[i+1] for a bitonic array.

Interview follow-ups

Why not always binary on f(m) vs f(m+1)?

On reals there is no m+1. On integers with a cheap neighbour test, binary is better. Ternary still works when you can only evaluate f, not compare adjacent discrete points easily (f is a heavy simulation).

Is every convex function unimodal?

Yes, a strictly convex f has a unique minimum. Weakly convex can have a flat bottom — brute the remainder.

Golden section vs 1/3-2/3?

Golden reuses one probe per step (one new evaluation). 1/3-2/3 is simpler and twice as many evals, still log. Use 1/3 in contests.

Connection to ternary search on trees?

Unrelated name. "Ternary search on the answer" vs a 3-ary search tree. Here we mean shrinking a numeric interval.

Recap

  • Unimodal f: discard the worse third.
  • Integers: stop at width 3 and scan.
  • Reals: 80 iterations.
  • Flat bottoms and multi-minima break it.
  • Neighbour compare → binary, fewer probes.
