DFS & Connected Components

Depth-first search is the graph's recursion: mark, recurse on unseen neighbours, and the vertices you touched in one call are a connected component.

Easy 24 min read Prerequisites: Graph Representations, BFS DFS components recursion P0

Why this exists

DFS answers a different question from BFS. It does not find shortest paths. It finds a spanning tree of each component, a parenthetical structure of enter/exit times, and the connected pieces of an undirected graph. Those three facts unlock cycle detection, topological sort, bridges, SCCs and most "paint the component" interview problems.

The practical reason to prefer DFS for components is that the code is a six-line recursion and the component id of every vertex is just "the start vertex of the DFS that first reached it". Number of islands, provinces, and "accounts merge" are this idea in costume.

The cost is the call stack. On a path of n = 10⁵, default JVM stack size will throw. The cure is an explicit ArrayDeque stack, not a hope that the graph is shallow. Learn both forms.

One DFS (or one explicit-stack walk) from an unvisited vertex paints exactly one connected component. Loop over vertices, start a new paint when you see a fresh one, and the number of paints is the number of components.

Recognise this pattern

Say yes when you see

  • "How many connected groups / islands / provinces?"
  • "Colour / list every vertex in the same component as X"
  • You need enter/exit times, a preorder, or a parent in a spanning tree
  • The next algorithm is cycle detection, topo sort, bridges or SCCs
  • A grid of land/water and 4-way adjacency

Not this pattern when

  • You need shortest unweighted distances → BFS
  • You need shortest weighted distances → Dijkstra
  • Directed "components" that should collapse cycles → SCC, not undirected DFS
  • The graph is a collection of pairs to unify and you only need the grouping → DSU is shorter

Constraint tell: n, m ≤ 2×10⁵. Recursive DFS needs -Xss or an explicit stack at this size. Time is O(n + m) either way. A grid is O(RC).

The recursion and the component loop

The recursive form is: mark u visited (and assign it the current component id), then for each unseen neighbour recurse. Because an undirected edge is stored both ways, the parent is already visited and is skipped; everything else you reach is in the same component.

The outer loop is the part people forget. A single dfs(0) only paints the component of 0. To count components, iterate s = 0 .. n-1 and start a new DFS (with a fresh id) whenever s is still unseen.

Timestamps tin[u] / tout[u] are incremented around the recursive calls. They turn ancestry into an interval test (tin[u] ≤ tin[v] ≤ tout[u]) and are the substrate for bridges, HLD and Euler tours. Record them even when the current problem does not ask; they cost two integers.

The invariant

During dfs(u), every vertex already marked with the current id is reachable from the component's start, and when dfs(u) returns, every vertex reachable from u through unseen vertices has been marked.

one start of dfs on an unvisited vertex = one connected component
Recursion depth is space, and it can be n

A path graph is a legal undirected graph. Recursive DFS is then n frames. In Java that is a StackOverflowError around a few thousand to tens of thousands of frames. The explicit-stack version in the Template tab is the contest default for n = 1e5.

Iterative DFS must simulate the neighbour iterator

Push (u, neighbour-index) pairs, not just u, or push neighbours in reverse and mark on push. A naive "push all neighbours" still works for components (you only need visited) but does not give correct tin/tout.

The array is the component id of each vertex, -1 unseen. The queue-like variable is the explicit stack (LIFO), so you can see DFS order versus the BFS queue on the previous page.

Algorithm

  1. Allocate int[] comp filled with -1, and a counter cid = 0.
  2. For s = 0 .. n-1, skip if comp[s] != -1.
  3. Otherwise start a component: call dfs(s, cid), then cid++.
  4. dfs(u, id): set comp[u] = id. For each neighbour v with comp[v] == -1, recurse (or push on an explicit stack).
  5. Do not recurse into the parent if you are also recording a DFS tree — pass p and skip v == p.
  6. Optional: record tin[u] before the loop and tout[u] after, incrementing a global timer.
  7. Answer is cid (count) and/or comp[] (labels).

Java implementation

Components via BFS from every unvisited vertex. Same answer, useful as a check.

JavaDfsBrute.java
import java.util.ArrayDeque;
    import java.util.ArrayList;
    import java.util.Arrays;
    import java.util.List;
    
    public class DfsBrute {
    
        static int[] componentsBfs(List<List<Integer>> g) {
            int n = g.size();
            int[] comp = new int[n];
            Arrays.fill(comp, -1);
            int cid = 0;
            for (int s = 0; s < n; s++) {
                if (comp[s] != -1) {
                    continue;
                }
                ArrayDeque<Integer> q = new ArrayDeque<>();
                comp[s] = cid;
                q.offer(s);
                while (!q.isEmpty()) {
                    int u = q.poll();
                    for (int v : g.get(u)) {
                        if (comp[v] == -1) {
                            comp[v] = cid;
                            q.offer(v);
                        }
                    }
                }
                cid++;
            }
            return comp;
        }
    
        public static void main(String[] args) {
            List<List<Integer>> g = demo();
            System.out.println(Arrays.toString(componentsBfs(g)));
        }
    
        static List<List<Integer>> demo() {
            List<List<Integer>> g = new ArrayList<>();
            for (int i = 0; i < 5; i++) {
                g.add(new ArrayList<>());
            }
            int[][] e = {{0, 1}, {0, 2}, {1, 2}, {1, 3}, {2, 3}};
            for (int[] x : e) {
                g.get(x[0]).add(x[1]);
                g.get(x[1]).add(x[0]);
            }
            return g;
        }
        // Input : components {0,1,2,3} and {4}
        // Output: [0, 0, 0, 0, 1]
    }

JavaDfsAndComponents.java
import java.util.ArrayList;
    import java.util.Arrays;
    import java.util.List;
    
    public class DfsAndComponents {
    
        static void dfs(List<List<Integer>> g, int u, int id, int[] comp) {
            comp[u] = id;
            for (int v : g.get(u)) {
                if (comp[v] == -1) {
                    dfs(g, v, id, comp);
                }
            }
        }
    
        static int[] components(List<List<Integer>> g) {
            int n = g.size();
            int[] comp = new int[n];
            Arrays.fill(comp, -1);
            int cid = 0;
            for (int s = 0; s < n; s++) {
                if (comp[s] == -1) {
                    dfs(g, s, cid++, comp);
                }
            }
            return comp;
        }
    
        public static void main(String[] args) {
            List<List<Integer>> g = new ArrayList<>();
            for (int i = 0; i < 5; i++) {
                g.add(new ArrayList<>());
            }
            int[][] e = {{0, 1}, {0, 2}, {1, 2}, {1, 3}, {2, 3}};
            for (int[] x : e) {
                g.get(x[0]).add(x[1]);
                g.get(x[1]).add(x[0]);
            }
            System.out.println(Arrays.toString(components(g)));
        }
        // Input : same graph as the dry run
        // Output: [0, 0, 0, 0, 1]
    }

Explicit stack, so a path of 1e5 cannot blow the JVM. Mark on push.

JavaDfsTemplate.java
import java.util.ArrayDeque;
    import java.util.ArrayList;
    import java.util.Arrays;
    import java.util.List;
    
    public class DfsTemplate {
    
        static int[] components(List<List<Integer>> g) {
            int n = g.size();
            int[] comp = new int[n];
            Arrays.fill(comp, -1);
            int cid = 0;
            ArrayDeque<Integer> st = new ArrayDeque<>();
            for (int s = 0; s < n; s++) {
                if (comp[s] != -1) {
                    continue;
                }
                comp[s] = cid;
                st.push(s);
                while (!st.isEmpty()) {
                    int u = st.pop();
                    for (int v : g.get(u)) {
                        if (comp[v] == -1) {
                            comp[v] = cid;
                            st.push(v);
                        }
                    }
                }
                cid++;
            }
            return comp;
        }
    
        public static void main(String[] args) {
            List<List<Integer>> g = new ArrayList<>();
            for (int i = 0; i < 5; i++) {
                g.add(new ArrayList<>());
            }
            int[][] e = {{0, 1}, {0, 2}, {1, 2}, {1, 3}, {2, 3}};
            for (int[] x : e) {
                g.get(x[0]).add(x[1]);
                g.get(x[1]).add(x[0]);
            }
            System.out.println(Arrays.toString(components(g)));
        }
        // Input : same graph
        // Output: [0, 0, 0, 0, 1]
    }

Complexity

Time O(n + m) Space O(n) for comp[] and the stack / recursion

Each vertex is marked once and then never re-entered. Each edge is examined a constant number of times from its endpoints:

T = Θ(n + m)

Recursive space is O(depth) extra, which is O(n) on a path. The explicit stack is the same bound but lives on the heap, which is what you want at n = 1e5.

Edge cases and pitfalls

  • One DFS from vertex 0
    Reporting a single component, or "the graph is connected", after dfs(0) on a graph whose other pieces were never started.
    The outer loop over unvisited starts is part of the algorithm, not optional glue.
  • StackOverflowError on a path
    Recursive DFS at n = 1e5 on a linked list of vertices. The judge returns RE, not WA.
    Explicit ArrayDeque stack, mark on push. Or raise -Xss if the platform allows it (most do not).
  • Treating directed reachability as undirected components
    Running this page's algorithm on a directed graph and calling the paints "components". A cycle of directed edges is one SCC, but a one-way edge does not merge the two ends.
    Undirected: this page. Directed mutual reachability: SCC. Directed one-way: just DFS/BFS from the source.
  • Mutating the grid without a visited array, then failing to restore
    Flood-fill that writes '0' over '1' is fine if you do not need the grid later. If you do, you have destroyed the input.
    Either copy, or keep a parallel boolean[][] seen, and only write if the problem asked you to mutate.
  • Skipping the parent incorrectly in an undirected graph
    Using a visited[] and also skipping parent, then missing a multi-edge cycle, or the opposite: not skipping parent and treating the back-edge to parent as a cycle.
    For components, visited is enough — parent is already visited. For cycle detection, skip the parent explicitly; see the next page.
  • Sharing one visited[] across independent queries without resetting
    Second query sees everything already painted.
    Reset, or stamp with a query id integer so you can avoid Arrays.fill.

Interview follow-ups

DFS or DSU for component count?

If the graph is already a list and you also want to walk it, DFS/BFS is natural. If the input is an edge list and you only need the grouping (or you will add edges online), DSU is shorter and does not build lists. Both are O(n + m).

How do I get the size of each component?

While painting id, increment cnt[id]. After the outer loop, cnt[comp[u]] is the size of u's piece. Alternatively return the size from recursive dfs as an int.

What does DFS order give me that BFS does not?

A parenthesis structure: every subtree is a contiguous segment of the Euler tour. That is why bridges, articulation points, SCCs (Tarjan), and subtree queries start from DFS, not BFS.

Can I DFS a directed graph to count "components"?

You can count weakly connected components by ignoring direction (add both ways). Strongly connected components need a second pass or Tarjan's lowlink. Do not mix the two words in an interview.

Hint for LC 130 — flood from the border

O's that touch the border cannot be captured. DFS/BFS from every border O, mark those as safe, then flip every remaining O. Interior-first search is the trap: you cannot know if a region is closed until you have seen the border.

Hint for CF 1167C — groups are cliques, not just edges

Each group of k friends is a clique. You do not need k choose 2 edges. Union everyone in the group to the first member (or DFS after adding those edges). The answer for i is the size of i's component.

Recap

  • One DFS from an unvisited vertex paints one component. Loop over starts.
  • Recursive DFS dies on a path of 1e5 — keep an explicit stack.
  • Time is O(n + m), same as BFS; the difference is the tree you build.
  • Directed "components" are SCCs, a different algorithm.
  • tin/tout turn ancestry into an interval and unlock every later DFS topic.
