Dijkstra's Algorithm

Non-negative weighted shortest paths: always expand the unsettled vertex with smallest dist, and the first time you settle it the distance is final.

Medium 26 min read Prerequisites: BFS, Heaps & Priority Queue Dijkstra heap shortest path P0

Why this exists

You are given 100000 junctions and 200000 one-way roads whose driving times are positive integers up to a billion, and you need the cheapest time from junction 0 to every other junction. BFS is the wrong tool the moment those times are not all equal: a single road of time 100 loses to a three-road walk of times 1+1+1, but BFS records the first arrival (one hop) and never looks at that junction again. Trying every walk is worse: at this size even listing the roads once is a few hundred thousand steps, and enumerating walks is exponential. You need a search that always expands the unfinished junction whose current best time is smallest.

That search is Dijkstra's algorithm. It keeps a dist array of best times found so far, and a min-heap of pairs (dist[u], u) so the next expansion is the closest unfinished vertex. Network delay time, path-with-minimum-effort, and almost every weighted maze are this heap plus the rule that the first time a vertex comes off the heap with a matching dist its time is final. The rule needs every weight to be non-negative. With a negative road, a vertex you have already frozen can still be cheapened by a detour you have not expanded yet, and the answer comes out too large.

A concrete three-node counterexample is enough to refuse negatives. Vertices 0, 1, 2, source 0, edges 0→1 of weight 2, 0→2 of weight 4, and 2→1 of weight -3. Dijkstra settles 1 at time 2 (the direct road) while 2 still sits at time 4, then freezes dist[1]. The true cheapest walk is 0-2-1 with total 4-3 = 1, which is never applied. Java's PriorityQueue also does not support decrease-key, so the contest pattern is "push a new pair when the time improves, skip a popped pair whose time no longer matches dist[u]". That is O(m log m), fine at m = 2×10⁵, and the signal in a statement is "minimum cost" on non-negative weights with those limits.

Always expand the unfinished vertex with the smallest dist. When every edge weight is non-negative, the first fresh heap pop is the true shortest-path distance and can be frozen. Skip heap pairs whose stored time no longer matches dist[u].

Recognise this pattern

Say yes when you see

  • Shortest path with non-negative edge weights
  • Grid with cell costs / effort / time to enter a cell
  • Network delay: max over dist[v] from a source
  • "Minimum cost" where cost adds along the path and never decreases by taking extra edges of negative weight
  • Implicit graphs whose edges you generate from a state with a non-negative cost

Not this pattern when

  • Unit weights → BFS, simpler and O(n+m)
  • Weights only 0 and 1 → 0-1 BFS
  • Negative edges, no negative cycle → Bellman-Ford / potential + Dijkstra (Johnson)
  • Negative cycle existence → Bellman-Ford, not this page

The duplicate-heap version is O(m log m), about 2×10⁵ times 18, which fits. A dense O(n²) scan of the closest unsettled vertex is better only when the graph is a matrix with n around 1000.

Core idea and the invariant

You need a long[] dist filled with a huge sentinel INF, dist[s] = 0, and a min-heap of pairs (d, u). To relax an edge u → v of weight w is to ask: is dist[u] + w smaller than the current dist[v]? If yes, overwrite dist[v] and push the new pair (dist[v], v) onto the heap. That is the same question BFS asked with w = 1, now asked with a real weight. The loop is: pop the pair with the smallest d; if d is not equal to dist[u] the pair is stale (an older, worse time) and you skip it; otherwise u is settled — its distance is frozen — and you relax every outgoing edge.

INF must be larger than any real path, so use Long.MAX_VALUE / 4, about 2×10¹⁰. Adding a weight to Integer.MAX_VALUE wraps negative and then "improves" every vertex. Never relax from a stale pop: that re-expands a settled vertex and can grow the heap without bound. A parent[v] = u write on a successful relaxation reconstructs the path. The non-negative hypothesis is what makes the first fresh pop final: every remaining unsettled vertex is at least as far as u, and an extra non-negative edge cannot jump in front of a closer vertex you have already frozen.

Walk the running weighted sample from 0: edges 0→1 of 4, 0→2 of 2, 2→1 of 1, 1→3 of 1, 2→4 of 7. Start with dist[0] = 0 and heap [(0, 0)]. Settle 0, relax 0→1 to 4 and 0→2 to 2. The next fresh pop is 2 at 2; relaxing 2→1 improves 1 from 4 to 3, and 2→4 writes 9. The next fresh pop is 1 at 3 (the leftover pair (4, 1) is stale and will be skipped). Relax 1→3 to 4, then settle 3 and 4. The finished array is [0, 3, 2, 4, 9], and every first settlement was final because every weight was non-negative.

When u is first popped with a pair whose time equals dist[u], that time is the true shortest-path distance from the source, and every remaining heap key is at least as large.

w ≥ 0 ⇒ settled set grows by true δ(s, u)

In plain words, you always freeze the closest unfinished junction, and because no road has a negative time, nobody you have not yet visited can sneak in with a cheaper total than a junction you already froze.

Three nodes are enough to break Dijkstra with a negative edge

Source 0, edges 0→1 weight 2, 0→2 weight 4, 2→1 weight -3. Dijkstra freezes vertex 1 at 2 before it expands 2. The walk 0-2-1 has total 1 and is never applied. Use Bellman-Ford (or Johnson) when any weight can be negative.

Relax means "is dist[u] + w a cheaper way to v?"

Overwrite dist[v] and push a new heap pair only when the answer is yes. The first time a popped pair matches the current dist[u], that value is final — but only while every w is at least 0.

Algorithm

  1. Fill a long[] dist with INF = Long.MAX_VALUE/4, set dist[s] = 0, and push (0, s). A 32-bit INF plus a positive weight wraps negative and then "improves" every vertex, which is why the array is long from the first line.
  2. Pop the pair (d, u) with the smallest time. If d != dist[u], skip it as stale. That pair is an older, worse time you pushed before a later relaxation improved u, and re-expanding it would grow the heap for no gain.
  3. Otherwise u is settled: relax each outgoing edge u → v of weight w. Relaxing means: if d + w is smaller than dist[v], overwrite dist[v] and push the new pair. That is the only write that can change an answer.
  4. Stop when the heap is empty, or return as soon as you settle t if you only need s-t. All-destinations must drain the heap; a single target can exit early because every later pop is at least as far as t.
  5. Leave unreachable vertices at INF, and never add a weight onto INF. Overflow of a sentinel is the usual way a distant vertex suddenly looks cheaper than the source.
  6. Refuse any negative weight; the freeze-on-first-pop proof needs w ≥ 0. The three-node graph 0→1 weight 2, 0→2 weight 4, 2→1 weight -3 freezes 1 at 2 and misses the true total 1.

Java implementation

JavaDenseDijkstra.java
import java.util.Arrays;
    public class DenseDijkstra {
        static long[] dijkstra(int[][] w, int s) {
            int n = w.length;
            long[] dist = new long[n];
            boolean[] used = new boolean[n];
            Arrays.fill(dist, Long.MAX_VALUE / 4);
            dist[s] = 0;
            for (int it = 0; it < n; it++) {
                int u = -1;
                for (int i = 0; i < n; i++)
                    if (!used[i] && (u < 0 || dist[i] < dist[u])) u = i;
                if (u < 0 || dist[u] >= Long.MAX_VALUE / 4) break;
                used[u] = true;
                for (int v = 0; v < n; v++)
                    if (w[u][v] < Integer.MAX_VALUE / 4)
                        dist[v] = Math.min(dist[v], dist[u] + w[u][v]);
            }
            return dist;
        }
        public static void main(String[] args) {
            int INF = Integer.MAX_VALUE / 4;
            int[][] w = new int[5][5];
            for (int[] row : w) Arrays.fill(row, INF);
            w[0][1] = 4; w[0][2] = 2; w[2][1] = 1; w[1][3] = 1; w[2][4] = 7;
            System.out.println(java.util.Arrays.toString(dijkstra(w, 0)));
        }
        // Input : dense matrix of the sample
        // Output: [0, 3, 2, 4, 9]
    }
JavaDijkstra.java
import java.util.ArrayList;
    import java.util.Arrays;
    import java.util.Comparator;
    import java.util.List;
    import java.util.PriorityQueue;
    
    public class Dijkstra {
        static long[] dijkstra(List<List<int[]>> g, int s) {
            int n = g.size();
            long[] dist = new long[n];
            Arrays.fill(dist, Long.MAX_VALUE / 4);
            PriorityQueue<long[]> pq = new PriorityQueue<>(Comparator.comparingLong(a -> a[0]));
            dist[s] = 0;
            pq.add(new long[] {0, s});
            while (!pq.isEmpty()) {
                long[] cur = pq.poll();
                int u = (int) cur[1];
                long d = cur[0];
                if (d != dist[u]) continue;
                for (int[] e : g.get(u)) {
                    int v = e[0], w = e[1];
                    if (d + w < dist[v]) {
                        dist[v] = d + w;
                        pq.add(new long[] {dist[v], v});
                    }
                }
            }
            return dist;
        }
        public static void main(String[] args) {
            List<List<int[]>> g = new ArrayList<>();
            for (int i = 0; i < 5; i++) g.add(new ArrayList<>());
            int[][] e = {{0,1,4},{0,2,2},{2,1,1},{1,3,1},{2,4,7}};
            for (int[] x : e) g.get(x[0]).add(new int[] {x[1], x[2]});
            System.out.println(Arrays.toString(dijkstra(g, 0)));
        }
        // Input : directed sample, source 0
        // Output: [0, 3, 2, 4, 9]
    }
JavaDijkstraUndirected.java
import java.util.*;
    public class DijkstraUndirected {
        static long to(List<List<int[]>> g, int s, int t) {
            int n = g.size();
            long[] dist = new long[n];
            Arrays.fill(dist, Long.MAX_VALUE / 4);
            PriorityQueue<long[]> pq = new PriorityQueue<>(Comparator.comparingLong(a -> a[0]));
            dist[s] = 0;
            pq.add(new long[]{0, s});
            while (!pq.isEmpty()) {
                long[] cur = pq.poll();
                int u = (int) cur[1];
                long d = cur[0];
                if (d != dist[u]) continue;
                if (u == t) return d;
                for (int[] e : g.get(u)) {
                    int v = e[0], w = e[1];
                    if (d + w < dist[v]) {
                        dist[v] = d + w;
                        pq.add(new long[]{dist[v], v});
                    }
                }
            }
            return -1;
        }
        public static void main(String[] args) {
            List<List<int[]>> g = new ArrayList<>();
            for (int i = 0; i < 5; i++) g.add(new ArrayList<>());
            int[][] e = {{0,1,4},{0,2,2},{2,1,1},{1,3,1},{2,4,7}};
            for (int[] x : e) {
                g.get(x[0]).add(new int[]{x[1], x[2]});
                g.get(x[1]).add(new int[]{x[0], x[2]});
            }
            System.out.println(to(g, 0, 4));
        }
        // Input : undirected sample, 0 to 4
        // Output: 9
    }

Complexity

Time O((n + m) log m) with a binary heap of duplicates Space O(n + m)

Each successful relaxation pushes one new pair, so the heap holds at most m entries in the duplicate-key version. Each push or pop on a binary heap costs O(log m), and each edge is examined once per settlement of its tail.

T = O(m log m), S = O(n + m)

At m = 2×10⁵ that is about 2×10⁵ times 18 heap operations, a few million steps, which fits in two seconds. A Fibonacci heap would be O(m + n log n) and nobody implements it in an interview. When the graph is a dense matrix with n around 1000, scanning the closest unsettled vertex in O(n²) is faster than paying a log on n² heap entries.

Edge cases and pitfalls

  • int overflow of dist
    INF = Integer.MAX_VALUE looks like a safe sentinel, then INF + w wraps to a negative number and every later comparison treats that overflow as a cheaper path.
    Use long[] dist and INF = Long.MAX_VALUE / 4. A path of n billion-weight edges then still sits well below the sentinel.
  • Not skipping stale pops
    You re-expand u with an old d, relax its edges again, and push even more leftover pairs. The heap grows and the algorithm can look like it is looping.
    Immediately after each pop, if (d != dist[u]) continue. Only a pair that still matches the current best time is allowed to settle and relax.
  • Negative weights
    A later cheaper walk through a negative edge never gets to improve a vertex you already froze, so the printed answer is too large. The three-node graph 0→1=2, 0→2=4, 2→1=-3 is the usual silent wrong answer.
    Refuse Dijkstra the moment any weight can be negative. Use Bellman-Ford, or Johnson's reweighting if you need many sources and there is no negative cycle.
  • Using TreeSet of vertices without updating
    A TreeSet of (d, u) used as decrease-key needs a remove of the old pair before the add of the new one; forgetting the remove leaves two keys for one vertex and the set order lies.
    The duplicate-heap pattern is simpler and is the contest default. TreeSet decrease-key is optional and only worth it if you already know you will not miss the remove.
  • Undirected input stored one way
    The statement says the roads are two-way but you inserted each pair once, so the shortest walk cannot use a road backwards and a reachable target looks unreachable.
    Insert both directions with the same weight unless the statement is directed. The reverse insert belongs in the same loop body as the forward one.

Interview follow-ups

Why non-negative is required?

The settled vertex u is the closest unfinished vertex, and freezing it is safe only if nobody you have not yet expanded can produce a smaller total. A negative edge can do exactly that. On vertices 0, 1, 2 with edges 0→1 weight 2, 0→2 weight 4, 2→1 weight -3, Dijkstra freezes 1 at 2; the walk 0-2-1 totals 1 and arrives too late. The heap order then describes a world that is no longer true.

Dijkstra vs Prim?

The loop shape is the same — a min-heap of vertices, grow a set one vertex at a time — but the key is different. Dijkstra's key is the best distance from the source. Prim's key is the cheapest edge that touches the tree so far. Mixing them is a common interview slip when you have just implemented one: you grow an MST when the question asked for shortest paths, or the other way around.

Early exit?

If you only need dist[t], return the moment you settle t. Every later fresh pop is at a distance at least as large, so it cannot improve t. The heap may still hold other vertices; that is fine. If you need distances to every vertex you must drain the heap. Do not exit on the first time t is pushed, only on the first time it is settled.

How do you print the path?

On each successful relaxation write parent[v] = u, the tail of the edge that just improved v. After the search, start at t and follow parent until you reach s, then reverse the list. If several walks tie, the first relaxation (or a ≤ versus < policy) picks one of the shortest paths, not all of them.

Recap

  • Min-heap of (dist, u), skip stale pops.
  • Settle once: first fresh pop is final iff w>=0.
  • long INF, never MAX_VALUE + w.
  • Unit weights → BFS; {0,1} → 0-1 BFS.
  • Not Prim — different key.
