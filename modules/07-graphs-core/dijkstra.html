Dijkstra's Algorithm

Non-negative weights turn shortest paths into "always expand the closest unfinished vertex" — a priority queue and a dist[] that only ever decreases.

Medium 26 min read Prerequisites: BFS, Graph Representations Dijkstra priority queue shortest path P0

Why this exists

BFS is Dijkstra with every weight equal to 1, and the queue is already sorted by distance. The moment weights differ, that free ordering disappears and you must always pull the unfinished vertex with the smallest tentative distance. A min-heap does that in O(log n) per push.

This is the default weighted shortest-path algorithm in interviews and contests. Network delay time, cheapest flights with no negative prices, path-with-minimum-effort (after you turn effort into an edge weight), and almost every "minimum cost to reach" with positive costs is Dijkstra. The two things it cannot do are negative edges and "longest path".

The implementation that wins in Java is the lazy one: push a new (dist, v) pair every time you improve v, and ignore stale heap entries when they pop with a worse key than dist[v]. Decrease-key is not in the standard library and you do not need it.

Because remaining edge weights are non-negative, the first time a vertex is popped from the heap with a key equal to dist[u], that distance is final. You may skip every later heap entry for u.

Recognise this pattern

Say yes when you see

  • "Shortest / cheapest path" and every edge weight is ≥ 0
  • A grid where moving to a neighbour costs a positive number (effort, time, fuel)
  • "Minimum time for a signal to reach all nodes"
  • You need distances from one source (or a few, run it several times) to every vertex
  • Unit weights would be BFS, but they are not unit

Not this pattern when

  • Any negative edge → Bellman-Ford (and a negative cycle is a different answer)
  • All weights in {0, 1} → 0-1 BFS is linear and simpler
  • All weights equal → BFS
  • Longest simple path → NP-hard; only legal on a DAG

Constraint tell: n ≤ 10⁵, m ≤ 2×10⁵ is the binary-heap range: O((n+m) log n) fits. Dense n = 1e4, m = n² needs a different plan (n² Dijkstra or Floyd if n is smaller). Distances are long if weights sum past 2e9.

Lazy heap Dijkstra

dist[s] = 0, every other dist[u] = +inf. Push (0, s). While the heap is not empty, pop (d, u). If d != dist[u] this entry is stale: skip. Otherwise u is final. For each edge u → v of weight w, if dist[u] + w < dist[v], write the new distance and push (dist[v], v).

Stale entries exist because we never decrease a key in the heap; we push a better pair instead. The check if (d != dist[u]) continue; makes each vertex finalise at most once. Edges are then relaxed only from a final distance, which is the proof that later pops cannot improve them given non-negative w.

On a grid, pack the cell id and use the four (or eight) implicit edges. On a graph with a second parameter (k stops, fuel left), the state is (vertex, extra) and the heap key is still the cost; that is Dijkstra on a product graph.

The invariant

After u is dequeued with d == dist[u], no remaining path to u can be shorter, because any other path would have to leave the finished set through a non-negative edge and would already have been at least as long.

first pop of u with d == dist[u] ⇒ dist[u] is optimal
Negative edges break the argument

A later cheap (even negative) edge could improve a finished vertex. The algorithm may then return a wrong distance without crashing. If the statement does not say weights are non-negative, do not use Dijkstra.

Java heap of int[]

PriorityQueue<int[]> with a comparator on a[0] - b[0] overflows. Compare with Integer.compare(a[0], b[0]), or pack (dist << 32) | v into a long if dist fits in 32 bits. Store dist as long in the array itself.

Algorithm

  1. Allocate long[] dist filled with a sentinel inf (Long.MAX_VALUE / 4 so additions cannot overflow).
  2. dist[s] = 0, push (0, s) into a min-heap.
  3. Pop (d, u). If d != dist[u] skip (stale).
  4. Otherwise u is final. Optionally break if u is the only target.
  5. For each edge u → v of weight w: nd = d + w. If nd < dist[v], set dist[v] = nd and push (nd, v).
  6. Do not mark visited before relaxing — a vertex may be improved several times before it is popped as final.
  7. Unreachable vertices stay inf. Convert to -1 if the problem asks.

Java implementation

Relax every edge n-1 times. Correct for non-negative weights, slower, and the right fallback if a negative edge appears.

JavaDijBrute.java
import java.util.Arrays;
    
    public class DijBrute {
    
        static long[] bf(int n, int[][] edges, int s) {
            long[] dist = new long[n];
            Arrays.fill(dist, Long.MAX_VALUE / 4);
            dist[s] = 0;
            for (int i = 0; i < n - 1; i++) {
                boolean any = false;
                for (int[] e : edges) {
                    int u = e[0], v = e[1], w = e[2];
                    if (dist[u] + w < dist[v]) {
                        dist[v] = dist[u] + w;
                        any = true;
                    }
                }
                if (!any) {
                    break;
                }
            }
            return dist;
        }
    
        public static void main(String[] args) {
            int[][] edges = {{0, 1, 2}, {0, 2, 5}, {1, 2, 1}, {1, 3, 4}, {2, 3, 1},
                    {1, 0, 2}, {2, 0, 5}, {2, 1, 1}, {3, 1, 4}, {3, 2, 1}};
            System.out.println(Arrays.toString(bf(4, edges, 0)));
        }
        // Input : undirected weighted graph as pairs both ways
        // Output: [0, 2, 3, 4]
    }

Lazy binary-heap Dijkstra. Stale pops are ignored. Distances are long.

JavaDijkstra.java
import java.util.ArrayList;
    import java.util.Arrays;
    import java.util.List;
    import java.util.PriorityQueue;
    
    public class Dijkstra {
    
        static long[] dijkstra(List<List<int[]>> g, int s) {
            int n = g.size();
            long[] dist = new long[n];
            Arrays.fill(dist, Long.MAX_VALUE / 4);
            PriorityQueue<long[]> pq = new PriorityQueue<>((a, b) -> Long.compare(a[0], b[0]));
            dist[s] = 0;
            pq.offer(new long[] {0, s});
            while (!pq.isEmpty()) {
                long[] cur = pq.poll();
                long d = cur[0];
                int u = (int) cur[1];
                if (d != dist[u]) {
                    continue;
                }
                for (int[] e : g.get(u)) {
                    int v = e[0], w = e[1];
                    long nd = d + w;
                    if (nd < dist[v]) {
                        dist[v] = nd;
                        pq.offer(new long[] {nd, v});
                    }
                }
            }
            return dist;
        }
    
        public static void main(String[] args) {
            List<List<int[]>> g = new ArrayList<>();
            for (int i = 0; i < 4; i++) {
                g.add(new ArrayList<>());
            }
            int[][] e = {{0, 1, 2}, {0, 2, 5}, {1, 2, 1}, {1, 3, 4}, {2, 3, 1}};
            for (int[] x : e) {
                g.get(x[0]).add(new int[] {x[1], x[2]});
                g.get(x[1]).add(new int[] {x[0], x[2]});
            }
            System.out.println(Arrays.toString(dijkstra(g, 0)));
        }
        // Input : undirected, weights as in the figure, source 0
        // Output: [0, 2, 3, 4]
    }

Same algorithm with parent[] for reconstruction. Stop early when the target is final.

JavaDijkstraTemplate.java
import java.util.ArrayList;
    import java.util.Arrays;
    import java.util.List;
    import java.util.PriorityQueue;
    
    public class DijkstraTemplate {
    
        static long[] dijkstra(List<List<int[]>> g, int s, int t, int[] parent) {
            int n = g.size();
            long[] dist = new long[n];
            Arrays.fill(dist, Long.MAX_VALUE / 4);
            Arrays.fill(parent, -1);
            PriorityQueue<long[]> pq = new PriorityQueue<>((a, b) -> Long.compare(a[0], b[0]));
            dist[s] = 0;
            pq.offer(new long[] {0, s});
            while (!pq.isEmpty()) {
                long[] cur = pq.poll();
                long d = cur[0];
                int u = (int) cur[1];
                if (d != dist[u]) {
                    continue;
                }
                if (u == t) {
                    break;
                }
                for (int[] e : g.get(u)) {
                    int v = e[0], w = e[1];
                    long nd = d + w;
                    if (nd < dist[v]) {
                        dist[v] = nd;
                        parent[v] = u;
                        pq.offer(new long[] {nd, v});
                    }
                }
            }
            return dist;
        }
    
        public static void main(String[] args) {
            List<List<int[]>> g = new ArrayList<>();
            for (int i = 0; i < 4; i++) {
                g.add(new ArrayList<>());
            }
            int[][] e = {{0, 1, 2}, {0, 2, 5}, {1, 2, 1}, {1, 3, 4}, {2, 3, 1}};
            for (int[] x : e) {
                g.get(x[0]).add(new int[] {x[1], x[2]});
                g.get(x[1]).add(new int[] {x[0], x[2]});
            }
            int[] parent = new int[4];
            long[] dist = dijkstra(g, 0, 3, parent);
            System.out.println(dist[3] + " parent[3]=" + parent[3]);
        }
        // Input : target 3
        // Output: 4 parent[3]=2
    }

Complexity

Time O((n + m) log n) lazy binary heap Space O(n + m) plus O(m) heap entries in the worst case

Each improving relaxation pushes one heap entry. A vertex can improve many times, but in the worst case the number of pushes is O(m). Each push/pop is O(log (heap)):

T = O((n + m) log m) = O((n + m) log n)

Fibonacci heaps with real decrease-key are O(m + n log n) and not worth it in Java. On a dense graph the O(n²) array-Dijkstra (pick the min unfinished with a scan) wins for n ≤ ~3000.

Edge cases and pitfalls

  • Marking visited when you push
    The first time you see v is via some path, not necessarily the shortest. Marking then freezes a wrong distance (BFS habit).
    A vertex becomes final only when it is popped with d == dist[u]. Relax freely until then.
  • int subtraction comparator
    (a, b) -> a[0] - b[0] overflows when keys differ by more than 2^31, silently breaking the heap.
    Long.compare / Integer.compare. Never subtract keys.
  • inf + w overflow
    dist[u] is Integer.MAX_VALUE, w is positive, the sum wraps negative and looks like a better path.
    Use long distances and inf = Long.MAX_VALUE / 4, or skip relaxation when dist[u] is still inf.
  • Negative weights
    The first-pop-is-final proof uses w ≥ 0. A negative edge can improve a finished vertex.
    Refuse Dijkstra. Bellman-Ford or potentials (Johnson) only after you know there is no negative cycle.
  • Using Dijkstra for longest path
    Negating weights invents negatives; flipping the heap to max does not work with cycles (you would walk forever).
    Longest simple path is NP-hard. Only do it on a DAG, in topo order.
  • Rebuilding the graph as undirected when it is directed
    Flights, one-way roads, and "from a to b with cost w" are directed. Adding the reverse invents paths.
    Read the statement. Add one directed edge unless it says bidirectional.

Interview follow-ups

Why can I skip stale heap entries?

When a better dist[u] is written, every older pair (d, u) has d > dist[u]. Popping it cannot be the first-final pop (that already happened or will happen with the current dist). Ignoring it is exactly as if we had deleted it.

Dijkstra vs Prim, in one sentence?

Both grow a tree with a min-heap. Dijkstra's key is distance from s; Prim's key is the cheapest edge out of the tree. Same skeleton, different relax, different problem.

When is O(n squared) Dijkstra better?

When the graph is dense (m ~ n^2) the heap version is O(n^2 log n) because there are O(n^2) pushes. Scanning for the closest unfinished vertex is O(n) per vertex, O(n^2) total, and has better constants. Use it for n around 2000 with a matrix.

How do I reconstruct the path?

Set parent[v] = u at every improving relaxation. Walk from t to s and reverse. If several equal-cost parents exist, the last improvement wins; that is still a shortest path.

Hint for LC 1631 — the cost is a bottleneck, not a sum

Effort of a path is the max absolute height-diff of a step. Dijkstra's key at a cell is the min achievable bottleneck to that cell: nd = max(d, |h[u]-h[v]|). Binary search on the effort plus BFS is the other solution; both are O(RC log).

Hint for CF 20C — reconstruct and watch 64-bit

n, m up to 1e5, weights up to 1e6, so dist up to 1e5 * 1e6 needs long. parent[v] = u on every improve. If dist[n] is still inf, -1. Else walk n back to 1 and reverse. Graph is undirected.

Recap

  • Non-negative weights only. First pop with d == dist[u] is final.
  • Lazy heap: push every improve, skip stale pops.
  • long distances, Long.compare — never subtract heap keys.
  • Unit weights → BFS; {0,1} → 0-1 BFS.
  • parent[] on improve reconstructs a shortest path.
pq min dist | skip d!=dist[u] | relax nd=d+w | long + Long.compare | no negative edges
