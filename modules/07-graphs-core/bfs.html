Breadth-First Search

The only shortest-path algorithm you need on an unweighted graph: a queue, a dist array, and the rule that the first time you see a vertex is the closest time.

Easy 24 min read Prerequisites: Graph Representations BFS queue shortest path P0

Why this exists

Breadth-first search visits vertices in order of unweighted distance from the source. That single fact is why it computes shortest paths on unit-weight graphs, why it colours bipartite graphs, why multi-source flood-fills work, and why "minimum operations to turn A into B" is a BFS on an implicit graph.

The reason it is an interview staple is that the code is short and the bugs are classic: marking visited at pop instead of push (the queue explodes), using a Stack by accident, forgetting disconnected components, and treating a weighted graph as unweighted. If you can write BFS without looking and name those four bugs, you have the foundation for Dijkstra and 0-1 BFS.

BFS is also the cleanest way to see a graph algorithm. The queue is the frontier, dist[u] is the level, and the invariant is visible in the array: processed vertices, the current layer, and the undiscovered rest.

The first time BFS reaches a vertex is via a shortest path. Mark it visited when you push, so each vertex enters the queue once. That is the whole correctness argument and the whole complexity proof.

Recognise this pattern

Say yes when you see

  • "Shortest path" on a graph whose edges all have the same weight (or weight 1)
  • "Minimum number of moves / operations" to reach a state
  • Multi-source flooding: rotting oranges, walls and gates, 01-matrix
  • Level-order traversal of a tree, or "nodes at distance k"
  • The implicit graph of a word ladder, a lock, or a grid with 4-way moves

Not this pattern when

  • Edges have different positive weights → Dijkstra
  • Weights are only 0 and 1 → 0-1 BFS, not plain BFS (treating 0-edges as 1 is wrong)
  • Negative weights → Bellman-Ford
  • You need any path, or connectivity only, and the graph is a tree → DFS is fine and uses less memory in practice

Constraint tell: n, m ≤ 2×10⁵ is the standard. BFS is O(n + m) and O(n) memory for the queue and dist. On a grid, n is the cell count. State-space BFS dies when the state does not fit in memory or in 10⁸ visits.

The invariant and the push-when-seen rule

Start with a queue holding the source (or every source), dist[s] = 0, and every other dist[u] = -1 meaning unseen. While the queue is not empty, pop u and relax every unseen neighbour v: set dist[v] = dist[u] + 1 and push v. Because vertices leave the queue in non-decreasing dist, the first time you see v is the closest time.

Visited-on-push is mandatory for correctness of the O(n) bound. If you mark at pop, two parents at the same level both push v, the queue can hold the same vertex many times, and a dense graph turns O(n + m) into something closer to O(n · m).

Multi-source BFS is the same algorithm with several zeros in the queue at the start. Each cell's distance is then the distance to the nearest source, which is exactly rotting oranges and 01-matrix.

The invariant

At every moment the queue holds a contiguous range of distances, and every vertex already popped has its final shortest-path distance. Equivalently:

the first time v is pushed, dist[v] is the unweighted distance from s

Never overwrite dist[v] after that. There is no second, shorter path in an unweighted graph.

Parent pointers reconstruct the path

Keep parent[v] = u at the moment you push v. Walk from the target back to the source and reverse. The path is unique in a tree and a shortest path in a general graph. Do not store the whole path on the queue — that copies O(n) per vertex.

ArrayDeque, not Stack, not a linked list used as a stack

BFS is a queue: offer at the back, poll at the front. java.util.Stack is a vector with a misleading name; ArrayDeque.pop is LIFO and gives you DFS. Write ArrayDeque<Integer> q and only use offer / poll.

Algorithm

  1. Allocate int[] dist of length n, fill with -1 (or a separate boolean[] seen).
  2. Seed the queue with every source. Set dist[s] = 0 and mark seen before the loop.
  3. While the queue is not empty, u = q.poll().
  4. For each neighbour v of u, skip if dist[v] != -1.
  5. Otherwise set dist[v] = dist[u] + 1, set parent[v] = u if you need the path, and q.offer(v).
  6. After the loop, dist[t] == -1 means unreachable; otherwise it is the shortest unweighted distance.
  7. If the graph may be disconnected and you need every component, wrap the above in for (s = 0; s < n; s++) if (dist[s] == -1) bfs(s).

Java implementation

Exploring every simple path and keeping the shortest works, and shows why BFS exists: this is exponential on a dense graph.

JavaBfsBrute.java
import java.util.ArrayList;
    import java.util.Arrays;
    import java.util.List;
    
    public class BfsBrute {
    
        static void dfs(List<List<Integer>> g, int u, int d, int[] best, boolean[] on) {
            if (d >= best[u]) {
                return;
            }
            best[u] = d;
            on[u] = true;
            for (int v : g.get(u)) {
                if (!on[v]) {
                    dfs(g, v, d + 1, best, on);
                }
            }
            on[u] = false;
        }
    
        public static void main(String[] args) {
            List<List<Integer>> g = new ArrayList<>();
            for (int i = 0; i < 4; i++) {
                g.add(new ArrayList<>());
            }
            int[][] e = {{0, 1}, {0, 2}, {1, 2}, {1, 3}, {2, 3}};
            for (int[] x : e) {
                g.get(x[0]).add(x[1]);
                g.get(x[1]).add(x[0]);
            }
            int[] best = new int[4];
            Arrays.fill(best, Integer.MAX_VALUE);
            dfs(g, 0, 0, best, new boolean[4]);
            System.out.println(Arrays.toString(best));
        }
        // Input : same four-node graph, source 0
        // Output: [0, 1, 1, 2]
    }

Mark on push. Returns dist; -1 means unreachable.

JavaBfs.java
import java.util.ArrayDeque;
    import java.util.ArrayList;
    import java.util.Arrays;
    import java.util.List;
    
    public class Bfs {
    
        static int[] bfs(List<List<Integer>> g, int s) {
            int n = g.size();
            int[] dist = new int[n];
            Arrays.fill(dist, -1);
            ArrayDeque<Integer> q = new ArrayDeque<>();
            dist[s] = 0;
            q.offer(s);
            while (!q.isEmpty()) {
                int u = q.poll();
                for (int v : g.get(u)) {
                    if (dist[v] == -1) {
                        dist[v] = dist[u] + 1;
                        q.offer(v);
                    }
                }
            }
            return dist;
        }
    
        public static void main(String[] args) {
            List<List<Integer>> g = new ArrayList<>();
            for (int i = 0; i < 4; i++) {
                g.add(new ArrayList<>());
            }
            int[][] e = {{0, 1}, {0, 2}, {1, 2}, {1, 3}, {2, 3}};
            for (int[] x : e) {
                g.get(x[0]).add(x[1]);
                g.get(x[1]).add(x[0]);
            }
            System.out.println(Arrays.toString(bfs(g, 0)));
        }
        // Input : n=4, undirected edges as above, source 0
        // Output: [0, 1, 1, 2]
    }

Multi-source plus parent pointers. Seed sources with every start cell; reconstruct with parent.

JavaBfsTemplate.java
import java.util.ArrayDeque;
    import java.util.ArrayList;
    import java.util.Arrays;
    import java.util.List;
    
    public class BfsTemplate {
    
        static int[] bfs(List<List<Integer>> g, int[] sources, int[] parent) {
            int n = g.size();
            int[] dist = new int[n];
            Arrays.fill(dist, -1);
            Arrays.fill(parent, -1);
            ArrayDeque<Integer> q = new ArrayDeque<>();
            for (int s : sources) {
                if (dist[s] == -1) {
                    dist[s] = 0;
                    q.offer(s);
                }
            }
            while (!q.isEmpty()) {
                int u = q.poll();
                for (int v : g.get(u)) {
                    if (dist[v] == -1) {
                        dist[v] = dist[u] + 1;
                        parent[v] = u;
                        q.offer(v);
                    }
                }
            }
            return dist;
        }
    
        public static void main(String[] args) {
            List<List<Integer>> g = new ArrayList<>();
            for (int i = 0; i < 4; i++) {
                g.add(new ArrayList<>());
            }
            int[][] e = {{0, 1}, {0, 2}, {1, 2}, {1, 3}, {2, 3}};
            for (int[] x : e) {
                g.get(x[0]).add(x[1]);
                g.get(x[1]).add(x[0]);
            }
            int[] parent = new int[4];
            int[] dist = bfs(g, new int[] {0}, parent);
            System.out.println(Arrays.toString(dist));
            System.out.println("parent[3]=" + parent[3]);
        }
        // Input : source 0
        // Output: [0, 1, 1, 2]
        //         parent[3]=1
    }

Complexity

Time O(n + m) Space O(n) for queue, dist, parent

Each vertex is pushed at most once (visited-on-push). Each edge is examined at most twice (once from each end if undirected):

T = Θ(n) + Θ(m) = Θ(n + m)

The queue holds at most n integers. On a grid, replace n with cells and m with 4 · cells. On an implicit state graph, n is the number of reachable states — that is the number you must be able to store.

Edge cases and pitfalls

  • Marking visited when you pop
    Two parents at distance d both push v. The queue grows with duplicates; on a complete graph this is catastrophic.
    Set dist[v] (or seen[v] = true) at the moment you offer v. The test if (dist[v] == -1) is the mark.
  • Using a stack
    ArrayDeque.push / pop or java.util.Stack gives DFS order. Distances are then wrong on any graph that is not a tree with a lucky shape.
    offer / poll only. If you need DFS, say so and use an explicit stack or recursion.
  • Treating weighted edges as unit
    Running BFS on a Dijkstra problem. The first path to v is the fewest-edges path, not the cheapest.
    BFS is legal iff every edge you traverse costs the same. Otherwise Dijkstra or 0-1 BFS.
  • Disconnected graphs and forgotten sources
    One BFS from vertex 0, then treating unvisited vertices as unreachable when the problem asked for components, or forgetting to seed every rotten orange.
    Match the seed set to the question. Connectivity of the whole graph: loop over unvisited starts. Nearest source: put every source in the queue at distance 0.
  • Storing the path on the queue
    Queue<List<Integer>> copying the path at every step. Memory becomes O(n²) and Java's allocator dies before the algorithm does.
    parent[v] = u, then walk back from the target. One integer per vertex.
  • Integer overflow on dist + 1 in weird state spaces
    Rare in plain graphs; common when dist is used as a map key mixed with other coordinates. Less often: using Integer.MAX_VALUE as unseen and adding 1.
    Unseen = -1, never MAX_VALUE + 1. On grids pack coordinates as r * cols + c in an int; n*m fits if you checked.

Interview follow-ups

Why is the first visit the shortest?

Edges cost 1. The queue is FIFO, so vertices leave in non-decreasing distance. When v is first reached it is from some u at distance d, and every unprocessed vertex has distance at least d. No later path can be shorter. This fails the moment edges can cost 0 or more than 1.

BFS vs DFS for connectivity?

Both are O(n + m) and both find components. BFS uses more memory on a long path (the queue holds a layer) and less on a star (the queue holds the leaves of one vertex). DFS risks StackOverflowError on a path of 10^5. Prefer BFS when you also want distances; prefer an explicit-stack DFS when you only want a component and depth can be huge.

How do I BFS a grid without building lists?

Encode a cell as id = r * cols + c. From (r, c) try the four deltas, skip out-of-bounds and blocked cells, and treat the neighbour id as v. visited / dist is a 2D array or a flat array of length rows*cols.

Can I early-exit when I pop the target?

Yes. Because distances are final at pop (they were already final at push), the moment you poll t you may return dist[t]. Do not exit at push if you still need something else from the same layer; for a single target, exiting at push is also correct.

Hint for LC 542 — multi-source, not per-cell BFS

BFS from every 1 is O(n² m²). Put every 0 in the queue at distance 0 and run one BFS. Each 1 receives the distance to the nearest 0. Transferable: "distance to the nearest X" is one multi-source BFS from all X.

Hint for LC 127 — generate neighbours without a full product

From a word, change each position to each letter and test membership in a HashSet of remaining words. That is 26 * L, not N² L. Bidirectional BFS from beginWord and endWord cuts the branching. Remove a word from the set when you push it (visited-on-push).

Recap

  • Mark on push, poll from an ArrayDeque. First visit = shortest unweighted path.
  • dist[v] = dist[u] + 1 once; never relax again.
  • Multi-source is the same loop with several zeros in the queue.
  • parent[] reconstructs; do not store paths on the queue.
  • Not for unequal weights — that is Dijkstra or 0-1 BFS.
