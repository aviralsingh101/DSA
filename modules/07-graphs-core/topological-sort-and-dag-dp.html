Topological Sort & DAG DP

A DAG has an order where every edge goes forward, and once you have that order every path DP is a single scan — no recursion, no memo table.

Medium 26 min read Prerequisites: DFS & Components, Cycle Detection & Bipartite topo sort Kahn DAG DP P0

Why this exists

Topological order is the reason DAGs are the friendliest graphs in the toolkit. If every edge u → v means "u before v", then a linear scan in that order processes every predecessor of v before v itself. Shortest paths, longest paths, counts of paths, and "minimum time to finish tasks" all collapse to for u in topo: for v in g[u]: relax.

Two constructions: Kahn peels vertices of indegree 0 and is the one you write in interviews (it also detects cycles). DFS post-order reversed is the one that falls out of the 3-colour cycle walk. Both are O(n + m).

DAG DP is the payoff. On a general graph, longest path is NP-hard. On a DAG it is the same relaxation as shortest path with min flipped to max, run in topo order. Course-schedule II, alien dictionary, and "number of ways to arrive" (on a DAG or after Dijkstra's DAG of shortest edges) are this pattern.

If the graph has a directed cycle, no topo order exists. If it does not, every path DP is legal in that order: when you reach v, every incoming edge has already been relaxed.

Recognise this pattern

Say yes when you see

  • Prerequisites, task order, compilation order, course schedule
  • "Longest / shortest / number of paths" on a directed graph that is acyclic (or a grid only moving down/right)
  • Alien dictionary: letters must respect a partial order
  • The constraint graph is a DAG of n le 1e5, so a general DP would be too slow without an order
  • You already have indegrees and a leftover after peeling would mean "impossible"

Not this pattern when

  • Undirected graphs — topo order is a directed idea. Use a tree order or BFS layers
  • Directed graphs that may have cycles and you need shortest paths with positive weights → Dijkstra, not topo
  • Negative weights with possible negative cycles → Bellman-Ford
  • You need a partial order over all pairs, not just a linear extension

Constraint tell: n, m ≤ 2×10⁵. Kahn uses an ArrayDeque of current zeros and an int[] indeg. DP values that count paths need long and often a modulus.

Kahn, DFS-topo, then one DP scan

Kahn: compute indegree of every vertex, push all zeros into a queue, pop u, append u to the order, decrement indegree of every out-neighbour, and push those that hit zero. If you emit fewer than n vertices, a cycle remains.

DFS-topo: run the 3-colour walk; on exit (paint BLACK) push u onto a stack. Reverse the stack. If you ever see a GREY neighbour, abort: no order exists. The two orders need not match; any linear extension is valid.

DAG DP: initialise dp[sources] from the problem (0 for longest-path length, 1 for path counts). Then for (u : topo) for (v : g[u]) dp[v] = combine(dp[v], dp[u] + w). Because every in-edge of v comes from an earlier topo index, the combine sees the final dp[u].

The invariant

In a topo order t[0..n), every directed edge u → v satisfies index(u) < index(v). Therefore a left-to-right scan has already finalised every predecessor.

dp[v] is complete the moment the scan reaches v
Prefer Kahn when the problem wants "impossible"

popped < n is a one-line cycle test and you already have the order. DFS-topo needs the extra GREY state. Interviewers almost always expect Kahn for course schedule.

Longest path on a DAG

Set dp[u] = 0 at vertices with indegree 0 (or -inf if you only want paths from a given s). Relax dp[v] = max(dp[v], dp[u] + w(u,v)) in topo order. The global max is the longest path length. Reconstruct via parent of the best relaxation.

Visual walkthrough

A small DAG

Edges 0→1, 0→2, 1→3, 2→3. Two valid orders: 0,1,2,3 and 0,2,1,3. Longest path 0 to 3 has length 2.

indeg[] and Kahn's queue

The array is remaining indegree. The queue holds current zeros. Each pop decrements neighbours; 3 hits zero last.

Algorithm

  1. Build a directed adjacency list and an int[] indeg.
  2. Push every vertex with indegree 0 into an ArrayDeque.
  3. While the queue is not empty: pop u, append u to order.
  4. For each out-neighbour v: decrement indeg[v]; if it hits 0, offer v.
  5. If order.size() < n return "cycle / impossible".
  6. Allocate dp[] and set the base (0 / 1 / -inf) on sources.
  7. Scan u in order and relax every out-edge into v with min, max, or +=.
  8. Read dp[target] or the global best, depending on the question.

Java implementation

Returns the order, or null if a cycle remains. This is the interview default.

JavaKahnTopo.java
import java.util.ArrayDeque;
    import java.util.ArrayList;
    import java.util.Arrays;
    import java.util.List;
    
    public class KahnTopo {
    
        static int[] topo(List<List<Integer>> g) {
            int n = g.size();
            int[] indeg = new int[n];
            for (int u = 0; u < n; u++) {
                for (int v : g.get(u)) {
                    indeg[v]++;
                }
            }
            ArrayDeque<Integer> q = new ArrayDeque<>();
            for (int u = 0; u < n; u++) {
                if (indeg[u] == 0) {
                    q.offer(u);
                }
            }
            int[] order = new int[n];
            int k = 0;
            while (!q.isEmpty()) {
                int u = q.poll();
                order[k++] = u;
                for (int v : g.get(u)) {
                    if (--indeg[v] == 0) {
                        q.offer(v);
                    }
                }
            }
            return k == n ? order : null;
        }
    
        public static void main(String[] args) {
            List<List<Integer>> g = new ArrayList<>();
            for (int i = 0; i < 4; i++) {
                g.add(new ArrayList<>());
            }
            g.get(0).add(1);
            g.get(0).add(2);
            g.get(1).add(3);
            g.get(2).add(3);
            System.out.println(Arrays.toString(topo(g)));
        }
        // Input : DAG 0->1, 0->2, 1->3, 2->3
        // Output: [0, 1, 2, 3]
    }

Longest path lengths from sources, using the Kahn order. Edge weight 1.

JavaDagDp.java
import java.util.ArrayList;
    import java.util.Arrays;
    import java.util.List;
    
    public class DagDp {
    
        static int[] longest(List<List<Integer>> g, int[] order) {
            int n = g.size();
            int[] dp = new int[n];
            Arrays.fill(dp, Integer.MIN_VALUE / 2);
            for (int u : order) {
                if (dp[u] < 0) {
                    dp[u] = 0;               // source (never relaxed)
                }
                for (int v : g.get(u)) {
                    dp[v] = Math.max(dp[v], dp[u] + 1);
                }
            }
            return dp;
        }
    
        public static void main(String[] args) {
            List<List<Integer>> g = new ArrayList<>();
            for (int i = 0; i < 4; i++) {
                g.add(new ArrayList<>());
            }
            g.get(0).add(1);
            g.get(0).add(2);
            g.get(1).add(3);
            g.get(2).add(3);
            int[] order = {0, 1, 2, 3};
            System.out.println(Arrays.toString(longest(g, order)));
        }
        // Input : same DAG, unit weights
        // Output: [0, 1, 1, 2]
    }

Self-contained Kahn plus path-count DP from vertex 0, modulo not needed on this size.

JavaTopoTemplate.java
import java.util.ArrayDeque;
    import java.util.ArrayList;
    import java.util.Arrays;
    import java.util.List;
    
    public class TopoTemplate {
    
        static long[] ways(List<List<Integer>> g, int s) {
            int n = g.size();
            int[] indeg = new int[n];
            for (int u = 0; u < n; u++) {
                for (int v : g.get(u)) {
                    indeg[v]++;
                }
            }
            ArrayDeque<Integer> q = new ArrayDeque<>();
            for (int u = 0; u < n; u++) {
                if (indeg[u] == 0) {
                    q.offer(u);
                }
            }
            int[] order = new int[n];
            int k = 0;
            while (!q.isEmpty()) {
                int u = q.poll();
                order[k++] = u;
                for (int v : g.get(u)) {
                    if (--indeg[v] == 0) {
                        q.offer(v);
                    }
                }
            }
            long[] dp = new long[n];
            dp[s] = 1;
            for (int i = 0; i < k; i++) {
                int u = order[i];
                for (int v : g.get(u)) {
                    dp[v] += dp[u];
                }
            }
            return dp;
        }
    
        public static void main(String[] args) {
            List<List<Integer>> g = new ArrayList<>();
            for (int i = 0; i < 4; i++) {
                g.add(new ArrayList<>());
            }
            g.get(0).add(1);
            g.get(0).add(2);
            g.get(1).add(3);
            g.get(2).add(3);
            System.out.println(Arrays.toString(ways(g, 0)));
        }
        // Input : same DAG, count paths from 0
        // Output: [1, 1, 1, 2]
    }

Complexity

Time O(n + m) Space O(n + m)

Kahn visits each vertex once and each edge once (the decrement). DFS-topo is the same bound. The DP scan is a third linear pass:

T = Θ(n + m)

That is why longest path is easy on a DAG and hopeless on a general graph: the order is what removes the need to try subsets of vertices.

Edge cases and pitfalls

  • Using the order of input vertices as topo order
    Relaxing in label order on a DAG that is not already sorted. dp[v] is read before its predecessors are final.
    Always compute an order (or prove the labels already are one, as in a grid).
  • Forgetting the cycle check
    Returning a partial order of length < n and then indexing it as if it were complete. DAG DP silently ignores the cyclic leftover.
    if (k != n) return impossible. Do this before allocating dp.
  • Building indegree from an undirected list
    Every edge increments both ends; every vertex with a neighbour has positive indegree and Kahn emits nothing.
    Topo is directed. If the problem is undirected, you want a different order.
  • Initialising path-count dp to 1 on every vertex
    Counts paths that start everywhere, not from s. Sources that are not s contribute phantom paths.
    dp[s] = 1, everyone else 0. Vertices not reachable from s stay 0.
  • int overflow on path counts
    A 40-vertex skinny DAG already exceeds Integer.MAX_VALUE.
    long, and apply the modulus in the relaxation if the statement asks.
  • PriorityQueue instead of ArrayDeque in Kahn
    Correct, and required when the problem wants the lexicographically smallest order. Otherwise it is a log factor and a surprise if you thought the order was unique.
    ArrayDeque for any valid order. PriorityQueue only when the statement asks for smallest labels first.

Interview follow-ups

Is the topo order unique?

Iff at every peel step exactly one vertex has indegree 0 (the remaining graph is a single chain of sources). If two zeros sit in the queue you may emit them in either order. Uniqueness is equivalent to a Hamiltonian path in the DAG that is forced by edges.

How is this related to DP on DAGs versus general DP?

General DP needs an explicit state partial order you invent. DAG DP uses the graph's own edges as that order. If your DP states are vertices of a DAG you already have, never recurse: topo-scan.

Can I topo-sort a graph with cycles after contracting SCCs?

Yes. The condensation of a directed graph is always a DAG. That is how you DP on "almost DAGs": Tarjan, then Kahn on the components. See SCC in the advanced graphs module.

Kahn vs DFS-topo for reconstruction of a cycle?

Kahn tells you a cycle exists (leftovers) but does not give the cycle. 3-colour DFS gives a back-edge. If you need the cycle itself, DFS; if you only need "impossible", Kahn.

Hint for CSES Longest Flight Route

Only vertices reachable from 1 can be on the answer. Run Kahn (or DFS-topo) on the whole graph, then longest-path DP from 1 (dp[1]=1 city, -inf elsewhere so you do not start in the middle). If dp[n] is still -inf, IMPOSSIBLE. Reconstruct via parent of the best relaxation.

Hint for LC 1976 — ways on the shortest-path DAG

First Dijkstra for dist[]. An edge u-v is a shortest-path edge iff dist[u] + w = dist[v]. Those edges form a DAG. Then path-count DP from src, or accumulate ways during Dijkstra when you hit equality. Mod 1e9+7, use long.

Recap

  • Kahn peels indegree 0; popped < n means a cycle.
  • Any linear extension is a valid topo order.
  • DAG DP is one scan of that order: min, max, or += on out-edges.
  • Longest path is easy on a DAG and NP-hard otherwise.
  • Path counts need long (and usually a modulus).
