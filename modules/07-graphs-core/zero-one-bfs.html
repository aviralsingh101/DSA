0-1 BFS

When every edge costs 0 or 1, a deque replaces the heap: 0-edges go to the front, 1-edges to the back, and you recover BFS-linear shortest paths.

Medium 24 min read Prerequisites: BFS, Dijkstra 0-1 BFS deque shortest path P1

Why this exists

0-1 BFS is the missing middle between BFS and Dijkstra. Edges cost only 0 or 1, so the next-closest vertex is either at the same distance (a 0-edge) or one further (a 1-edge). A deque maintains that: push-front on 0, push-back on 1. Distances come out sorted, and the whole run is O(n + m).

The pattern shows up more often than the name. "You may change a grid arrow for cost 1 or follow it for free", "close a door / use a special road", "minimum walls to break to reach the exit" (if breaking costs 1 and walking is free) are all 0-1 BFS. Writing Dijkstra is correct and a log slower; writing plain BFS that treats 0-edges as 1 is wrong.

P1 rather than P0 because you must see the reduction: invent the 0-edges and the 1-edges from the statement. The code afterwards is twenty lines you can reuse.

A 0-edge does not increase distance, so that neighbour belongs at the front of the frontier, just like the rest of the current BFS layer. A 1-edge is the next layer and belongs at the back.

Recognise this pattern

Say yes when you see

  • Every edge weight is in {0, 1}
  • "Follow the suggested move for free, any other move costs 1"
  • Minimum number of walls / obstacles to remove to reach a cell
  • Two kinds of roads, free and toll-1, and you want the fewest tolls
  • A grid whose cells push you in a direction (cost 0) or you override (cost 1)

Not this pattern when

  • Weights outside {0, 1} → Dijkstra (or Dial's algorithm if weights are tiny)
  • All weights 1 → plain BFS, the deque is pointless
  • Negative edges → Bellman-Ford
  • You need the number of 0-edges on a path rather than the cost — still 0-1 BFS if that is the cost; otherwise a different DP

Constraint tell: n, m ≤ 2×10⁵ like BFS. The deque holds each improving push; with visited-on-final-pop a vertex can enter twice (once via 1, then improved via 0). Still O(n + m). Distances fit in int when they count 1-edges.

Deque + the 0-front / 1-back rule

dist[s] = 0, others inf. Offer s at the back. While the deque is not empty, poll from the front (u). For each edge u → v of weight w in {0, 1}: if dist[u] + w < dist[v], write dist[v] and push v to the front if w == 0, else to the back.

Why this works: the deque stays sorted by dist. A 0-relax produces the same key as u, so v belongs with the current layer (front). A 1-relax produces key + 1, the next layer (back). That is Dijkstra's "extract-min" with only two possible next keys, implemented as a deque instead of a heap.

A vertex can be improved after it was first seen (first via a 1-edge, later via a 0-edge). That is why we compare distances rather than using a boolean visited-on-push. Each vertex is still improved O(1) times in a simple graph, so the bound stays linear.

The invariant

The deque holds vertices in non-decreasing dist, and the values present differ by at most 1. Therefore poll-first is extract-min, the same guarantee Dijkstra gets from a heap.

w = 0 → offerFirst(v); w = 1 → offerLast(v)
Do not mark visited on the first see

A 1-edge can reach v first at distance d+1, then a 0-edge from a sibling reaches it at distance d. If you froze v on first see, you keep the worse distance. Always relax with a strict < on dist[v].

This is also how you see "min changes to follow the grid"

From (r, c) the cell's arrow is a 0-edge; the other three directions are 1-edges. That single modelling step is LC 1368. After it, the code is the template on this page.

Algorithm

  1. Model the 0-edges and the 1-edges from the statement. This is the actual problem.
  2. Allocate dist[] with inf, set dist[s] = 0, offerLast(s).
  3. While the deque is not empty, u = pollFirst().
  4. For each edge u → v of weight w in {0,1}: nd = dist[u] + w.
  5. If nd < dist[v], write dist[v] = nd.
  6. If w == 0 offerFirst(v), else offerLast(v).
  7. Do not use a boolean visited-on-push unless you prove each vertex is improved only once (not true in general).
  8. Read dist[t]. Inf means unreachable.

Java implementation

Correct, a log slower. Use this only to check the deque version.

JavaZobBrute.java
import java.util.ArrayList;
    import java.util.Arrays;
    import java.util.List;
    import java.util.PriorityQueue;
    
    public class ZobBrute {
    
        static int[] dij(List<List<int[]>> g, int s) {
            int n = g.size();
            int[] dist = new int[n];
            Arrays.fill(dist, Integer.MAX_VALUE / 4);
            PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0]));
            dist[s] = 0;
            pq.offer(new int[] {0, s});
            while (!pq.isEmpty()) {
                int[] cur = pq.poll();
                if (cur[0] != dist[cur[1]]) {
                    continue;
                }
                for (int[] e : g.get(cur[1])) {
                    int nd = cur[0] + e[1];
                    if (nd < dist[e[0]]) {
                        dist[e[0]] = nd;
                        pq.offer(new int[] {nd, e[0]});
                    }
                }
            }
            return dist;
        }
    
        public static void main(String[] args) {
            List<List<int[]>> g = new ArrayList<>();
            for (int i = 0; i < 4; i++) {
                g.add(new ArrayList<>());
            }
            g.get(0).add(new int[] {1, 0});
            g.get(0).add(new int[] {2, 1});
            g.get(1).add(new int[] {3, 1});
            g.get(2).add(new int[] {3, 0});
            System.out.println(Arrays.toString(dij(g, 0)));
        }
        // Input : 0-1:0, 0-2:1, 1-3:1, 2-3:0
        // Output: [0, 0, 1, 1]
    }

ArrayDeque as a deque. offerFirst on 0, offerLast on 1.

JavaZeroOneBfs.java
import java.util.ArrayDeque;
    import java.util.ArrayList;
    import java.util.Arrays;
    import java.util.List;
    
    public class ZeroOneBfs {
    
        static int[] zeroOne(List<List<int[]>> g, int s) {
            int n = g.size();
            int[] dist = new int[n];
            Arrays.fill(dist, Integer.MAX_VALUE / 4);
            ArrayDeque<Integer> dq = new ArrayDeque<>();
            dist[s] = 0;
            dq.offerLast(s);
            while (!dq.isEmpty()) {
                int u = dq.pollFirst();
                for (int[] e : g.get(u)) {
                    int v = e[0], w = e[1];
                    int nd = dist[u] + w;
                    if (nd < dist[v]) {
                        dist[v] = nd;
                        if (w == 0) {
                            dq.offerFirst(v);
                        } else {
                            dq.offerLast(v);
                        }
                    }
                }
            }
            return dist;
        }
    
        public static void main(String[] args) {
            List<List<int[]>> g = new ArrayList<>();
            for (int i = 0; i < 4; i++) {
                g.add(new ArrayList<>());
            }
            g.get(0).add(new int[] {1, 0});
            g.get(0).add(new int[] {2, 1});
            g.get(1).add(new int[] {3, 1});
            g.get(2).add(new int[] {3, 0});
            System.out.println(Arrays.toString(zeroOne(g, 0)));
        }
        // Input : directed 0-1:0, 0-2:1, 1-3:1, 2-3:0
        // Output: [0, 0, 1, 1]
    }

Grid form: from each cell the suggested direction is a 0-step, the others are 1.

JavaZeroOneTemplate.java
import java.util.ArrayDeque;
    import java.util.Arrays;
    
    public class ZeroOneTemplate {
    
        static final int[] DR = {0, 1, 0, -1};
        static final int[] DC = {1, 0, -1, 0};
    
        /** grid[r][c] in {0,1,2,3} = suggested dir. Cost 0 to follow, 1 to override. */
        static int minChanges(int[][] grid) {
            int R = grid.length, C = grid[0].length;
            int[][] dist = new int[R][C];
            for (int[] row : dist) {
                Arrays.fill(row, Integer.MAX_VALUE / 4);
            }
            ArrayDeque<int[]> dq = new ArrayDeque<>();
            dist[0][0] = 0;
            dq.offerLast(new int[] {0, 0});
            while (!dq.isEmpty()) {
                int[] p = dq.pollFirst();
                int r = p[0], c = p[1];
                for (int k = 0; k < 4; k++) {
                    int nr = r + DR[k], nc = c + DC[k];
                    if (nr < 0 || nr >= R || nc < 0 || nc >= C) {
                        continue;
                    }
                    int w = (k == grid[r][c]) ? 0 : 1;
                    int nd = dist[r][c] + w;
                    if (nd < dist[nr][nc]) {
                        dist[nr][nc] = nd;
                        if (w == 0) {
                            dq.offerFirst(new int[] {nr, nc});
                        } else {
                            dq.offerLast(new int[] {nr, nc});
                        }
                    }
                }
            }
            return dist[R - 1][C - 1];
        }
    
        public static void main(String[] args) {
            int[][] grid = {{1, 1, 3}, {3, 2, 2}, {1, 1, 0}};
            System.out.println(minChanges(grid));
        }
        // Input : 3x3 arrow grid (dirs 0=R,1=D,2=L,3=U)
        // Output: 0
    }

Complexity

Time O(n + m) Space O(n)

Each improving relaxation pushes a vertex once more. In a simple 0-1 graph a vertex's distance takes at most two distinct values (first see, optional 0-improve), so pushes are O(n) and each edge is examined O(1) times:

T = Θ(n + m)

That is the same class as BFS and a log faster than Dijkstra, which is why you bother to notice that the weights are only 0 and 1.

Edge cases and pitfalls

  • Pushing 0-edges to the back
    The deque is then just a queue and 0-edges wait behind 1-edges. Distances can come out too large if you also freeze on first visit.
    offerFirst for w == 0, offerLast for w == 1. Always.
  • Visited-on-push like BFS
    First path to v may be a 1-edge; a later 0-edge is shorter and is ignored.
    Relax with nd < dist[v]. A vertex may enter the deque more than once.
  • Using a PriorityQueue "just in case"
    Correct, slower, and you lose the point of the pattern. Reviewers will ask why.
    If weights are only 0 and 1, write the deque. Mention Dijkstra as the fallback.
  • Treating "free then pay" as two BFS passes
    Running BFS on 0-edges then BFS on 1-edges in the wrong order misses mixed paths.
    One deque interleaves them. That is the algorithm.
  • Weights that are 0, 1 and 2
    The two-layer deque invariant dies. A 2-edge would need a third place to sit.
    Dial's algorithm (an array of deques indexed by distance) or Dijkstra.
  • pollLast by accident
    ArrayDeque has pollFirst and pollLast. The wrong one is DFS-ish and breaks order.
    Always pollFirst. The only choice is which end you offer onto.

Interview follow-ups

Why is the deque sorted?

Inductively it holds keys d and d+1 only, with all the d's at the front. A 0-push inserts another d at the front; a 1-push inserts a d+1 at the back. Polling the front always yields a smallest key. When the last d is gone the old d+1s become the new d.

Is 0-1 BFS just Dijkstra with a faster heap?

Yes. Extract-min is O(1) because the next key is only d or d+1. That is why the complexity drops the log. The modelling work is identical to Dijkstra: define states and edge weights, then run the right extractor.

Can I 0-1-BFS a graph with 0-cycles?

0-cycles do not change distances, but a careless implementation can loop forever if you push on ≤ instead of <. Strict improvement stops the walk. 0-cycles are otherwise harmless.

How is this different from 0-1 knapsack?

Only the name. 0-1 knapsack is a DP on items in-or-out. 0-1 BFS is a shortest-path algorithm on two weight values. Do not mix the phrases in an interview.

Hint for LC 2290 — the cost is the number of 1-cells you step on

Moving into a 0-cell costs 0; moving into a 1-cell costs 1. That is exactly 0-1 BFS on the grid graph. dist[R-1][C-1] is the minimum obstacles removed (you "remove" an obstacle by paying 1 to step on it). Do not binary-search the number of removals unless you want a slower solution.

Hint for LC 1368 — the arrow is a 0-edge

From (r, c) following grid[r][c] is weight 0; the other three directions are weight 1. Run the template. Dijkstra also passes; the intended solution is the deque. Start cell costs 0 even if you later leave it against its arrow.

Recap

  • Weights in {0, 1} only — otherwise Dijkstra or Dial.
  • offerFirst on 0, offerLast on 1, pollFirst always.
  • Relax with nd < dist[v]; do not freeze on first see.
  • The deque stays sorted with keys d and d+1 only.
  • Modelling is the hard part: name the 0-edges from the statement.
