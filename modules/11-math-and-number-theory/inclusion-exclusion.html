Inclusion-Exclusion

|A∪B|=|A|+|B|-|A∩B|. For n sets the sign is (-1)^{|S|+1}. The same sum counts surjections, derangements, and coprime lattice points.

Hard 28 min read Prerequisites: Combinatorics, Primes & Sieves inclusion-exclusion PIE Möbius P2

Why this exists

You are asked how many integers from 1 to 10 are divisible by 2 or by 3. Counting multiples of 2 gives 5, counting multiples of 3 gives 3, and adding them gives 8, which is too big because 6 was counted twice. Subtract the one number that is divisible by both and you get 7, which you can check by listing: 2, 3, 4, 6, 8, 9, 10. That is inclusion-exclusion on two sets: overcount, then correct.

Three sets is the same habit with one more correction. Multiples of 2, 3, or 5 up to 10: add the three single counts (5+3+2), subtract the three pairwise overlaps (multiples of 6, 10, and 15), then add back the triple overlap (multiples of 30) because the pairwise subtractions removed it too often. The running total is 5+3+2-1-1-0+0=8. Once you can see the overcount-and-correct on two and three sets, the k-set loop is just that pattern in a mask.

In code you loop every non-empty subset of k properties. The sign is plus when the subset size is odd (you are adding a single, or a triple, …) and minus when it is even (you are subtracting a pairwise overlap). The product 2k times the cost of counting one intersection must fit; k ≤ 20 is the usual comfort zone. The phrase “divisible by any of these primes” or “at least one property” next to a small k is the constraint that names this page.

The same overcount-and-correct counts derangements (permutations with no fixed point), surjections onto k labels, and pairs with gcd 1. Möbius inversion is the packaged form on the divisor lattice: leftover of a sum of mu[d] over divisors of n is 1 when n is 1 and 0 otherwise, which turns “coprime pairs up to n” into a single sum you can sieve.

You can count a union whenever you can count every intersection. Overcount by adding the singles, correct by subtracting the pairwise overlaps, and on three sets add the triple back. An element that sits in exactly r sets is then counted once, which is why the signed sum equals the size of the union.

Core idea and the invariant

Start with two sets and say the words out loud. Size of the union is size of A plus size of B minus size of the overlap: you overcounted every element that sat in both, so you subtract the overlap once and each element is counted once. Three sets: add the three singles, subtract the three pairwise overlaps (those elements were added twice too many times after the singles), then add the triple overlap back because the three pairwise subtractions removed it completely. That signed combination is the size of the union of A, B, and C.

The mask loop is the same overcount-and-correct for k properties. Skip mask 0, which would add the whole universe. For each non-empty mask, count the intersection of the chosen properties — for “divisible by these primes” that count is floor(n / product), the number of multiples of that product up to n. Add the term when the popcount is odd, subtract when it is even. If the product would exceed n, skip: there are no multiples, and a wrapped product would invent some.

Walk the sample. Up to 10, multiples of 2 or 3: singles 5+3, overlap 1, union 7. Add 5: singles 5+3+2, pairs 1, 1, 0, triple 0, union 8. Derangements of 3 items: start from 3! = 6 permutations, subtract those that fix at least one point by the same signed sum, and you get 2 (the two 3-cycles). Möbius of 1..6 is 1, -1, -1, 0, -1, 1, the precomputed signs for the divisor form of the same idea. Always verify the k = 2 mask loop against size A plus size B minus the overlap before you trust a larger k.

An element that belongs to exactly r ≥ 1 of the sets is added once for each singleton it sits in, subtracted once for each pair, added once for each triple, and so on. That signed combination of binomial coefficients equals 1, so the element contributes 1 to the union.

In plain words, you overcount, then you correct, and after the corrections every element that was in at least one set has been counted exactly once.

Interview sentence: “Add the singles, subtract the overlaps, add the triples back.”

Two sets, then three, then the mask

Size of A union B is size A plus size B minus the overlap. Size of A union B union C adds the third single, subtracts the three new pairwise overlaps, and adds the triple. The mask loop is that paragraph, not a different idea.

Mask 0 is the universe

Popcount 0 is even, so a sloppy sign rule subtracts or adds n and the answer is off by the size of the whole universe. Start the loop at mask 1.

Structure

Algorithm

  1. Name properties so every intersection is countable. “Divisible by this prime” and “fixes this position” work; a property whose overlap you cannot count is the wrong setup.
  2. Loop every non-empty mask. Masks from 1 through (1<<k)-1 are the singles, the pairs, the triples, and so on. Mask 0 is the universe and must not enter the sum.
  3. Sign by popcount. Add the intersection when the subset size is odd (overcount), subtract when it is even (correct). That is the two-set and three-set paragraph in a loop.
  4. Skip a product that exceeds n. There are then no multiples, and a 64-bit wrap would invent a fake floor(n / product).
  5. Reach for Möbius on divisor questions. The sieve writes the same plus-or-minus signs on the divisor lattice, so coprime-pair counts become one sum over d.
  6. Verify the k=2 case by hand. The mask loop must reproduce size A plus size B minus the overlap before you trust a larger k.

Java implementation

JavaUnionBrute.java
public class UnionBrute {
        static int count(int n, int[] p) {
            int c = 0;
            outer:
            for (int x = 1; x <= n; x++)
                for (int v : p) if (x % v == 0) { c++; continue outer; }
            return c;
        }
        public static void main(String[] args) {
            System.out.println(count(10, new int[] {2, 3}));
        }
        // Input : 1..10, div by 2 or 3
        // Output: 7
    }
JavaInclusionExclusion.java
public class InclusionExclusion {
        static long unionDiv(long n, int[] p) {
            int k = p.length;
            long ans = 0;
            for (int m = 1; m < (1 << k); m++) {
                long prod = 1;
                int bits = 0;
                boolean ov = false;
                for (int i = 0; i < k; i++) if (((m >> i) & 1) == 1) {
                    bits++;
                    if (prod > n / p[i]) { ov = true; break; }
                    prod *= p[i];
                }
                if (ov) continue;
                long term = n / prod;
                ans += (bits % 2 == 1) ? term : -term;
            }
            return ans;
        }
        public static void main(String[] args) {
            System.out.println(unionDiv(10, new int[] {2, 3}));
            System.out.println(unionDiv(10, new int[] {2, 3, 5}));
        }
        // Input : 10 with {2,3} and {2,3,5}
        // Output: 7
        //         8
    }
JavaMobiusGcd.java
import java.util.*;
    public class MobiusGcd {
        static int[] mu;
        static void sieve(int n) {
            mu = new int[n + 1];
            int[] spf = new int[n + 1];
            mu[1] = 1;
            List<Integer> pr = new ArrayList<>();
            for (int i = 2; i <= n; i++) {
                if (spf[i] == 0) { spf[i] = i; pr.add(i); mu[i] = -1; }
                for (int p : pr) {
                    long v = (long) i * p;
                    if (v > n) break;
                    spf[(int) v] = p;
                    mu[(int) v] = (i % p == 0) ? 0 : -mu[i];
                    if (i % p == 0) break;
                }
            }
        }
        static long coprimePairs(int n) {
            sieve(n);
            long ans = 0;
            for (int d = 1; d <= n; d++) ans += (long) mu[d] * (n / d) * (n / d);
            return ans;
        }
        public static void main(String[] args) {
            System.out.println(coprimePairs(3));
        }
        // Input : pairs in 1..3 with gcd 1
        // Output: 7
    }

Complexity

Time O(2^k T); Möbius O(n) + O(√n) floor sum Space O(n) for μ

The mask loop visits 2k - 1 non-empty subsets. If counting one intersection costs T (a product of k primes, or a stars-and-bars choose), the whole union is O(2k T). Möbius is one linear sieve, then a sum over d = 1..n. Grouping equal values of floor(n/d) collapses that sum to about 2 sqrt n blocks.

Putting real numbers in: k = 20 is a million subsets; if each intersection is a handful of arithmetic operations the batch finishes in tens of milliseconds. A universe scan at n = 1012 is impossible. Möbius to 107 is a few hundred milliseconds and 40 MB; the same sum at n = 1012 needs a Dirichlet prefix (Du-Jiao) or a promised smaller limit. Floor-block sums at n = 1012 are about two million iterations and are fine on their own.

Edge cases and pitfalls

  • Wrong sign / empty mask
    Mask 0 has popcount 0, so a sloppy sign rule adds or subtracts the whole universe. The answer is off by n and still looks like a plausible count.
    Start at mask 1. Add when popcount is odd, subtract when even. The two-set case must reproduce size A plus size B minus the overlap.
  • Product overflow
    The product of the chosen primes wraps a long, so n / prod becomes a huge fake count of multiples and the union is wildly too large.
    If the next prime would make prod > n, skip that mask. There are then no multiples of that product up to n.
  • mu of a square not zeroed
    Writing mu[i*p] = -mu[i] even when p already divides i leaves a non-zero Möbius value on a square. Later coprime-pair sums include extra terms and look only slightly off.
    If p divides i, set mu[i*p] = 0. After the sieve, mu[4], mu[9], and mu[12] must all be 0.
  • Derangement integer /
    Forming leftover of n! / k! with Java / truncates, so the signed sum is no longer the integer number of derangements.
    Keep a running multiply leftover M, or stay in exact integers with a running product that divides evenly at each step.
  • min(|A|,|B|) as intersection
    The smaller of the two set sizes is a cheap number and looks like an overlap bound, but it is not the size of the intersection, so the correction term is wrong.
    Count the overlap from the structure: multiples of the lcm, or elements that satisfy both constraints. For 2-or-3 up to 10 that overlap is 1, not min(5, 3)=3.

Interview follow-ups

Why is an r-set element counted once?

Picture an element that sits in exactly three of your sets. The singles add it three times. The pairwise overlaps subtract it three times, which removes it completely. The triple adds it back once. Net contribution: 1. In general the signed sum of “how many of its r memberships you pick” is 1 for every r ≥ 1, which is why overcount-and-correct equals the size of the union rather than some other combination.

Möbius vs raw IE?

Raw inclusion-exclusion loops subsets of a short list of properties. Möbius is the same signed sum, precomputed on the divisor lattice: mu[d] is the plus-or-minus (or zero on squares) you would have written by hand for the property “divisible by d”. Use the mask loop when k is tiny and the properties are arbitrary; use Möbius when the properties are “divisible by this integer” up to n.

n=1e12 in sum mu[d] floor(n/d)^2?

That sum computes the number of coprime pairs (i, j) with both at most n: for each d, leftover of mu[d] times the square of how many multiples of d sit in 1..n. You cannot sieve mu to 1012. Either the limit is actually 107, or you need a Dirichlet prefix (Du-Jiao / min_25). Floor-block grouping alone does not remove the need for mu[d].

Three-set formula?

Add the three single sizes (overcount), subtract the three pairwise overlaps (correct the double-counted elements), then add the triple overlap back because those last elements were subtracted too often. The result is the number of elements that sit in at least one of the three sets. It is the two-set rule with one extra correction, and the mask loop is that sentence for every subset size.
