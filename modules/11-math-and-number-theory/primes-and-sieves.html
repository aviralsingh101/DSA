Primes & Sieves

The linear sieve builds every prime ≤ n in O(n) and the smallest-prime-factor table factors any k ≤ n in O(log k).

Medium 22 min read Prerequisites: Modular Arithmetic, Complexity Analysis sieve SPF primes P1

Why this exists

Trial division to n is O(sqrt n) per number. A sieve pays O(n log log n) once (Eratosthenes) or O(n) (linear / Euler sieve) and then primality of every k ≤ n is an array read. The SPF table is the reason you sieve even when you only needed factorisation.

n = 1e7 is the Java comfort zone for a bool/int sieve. n = 1e12 needs segmented sieves or Miller-Rabin on single queries.

Multiplicative functions (phi, mu, tau, sigma) fill with the same linear sieve in one pass.

Every composite k ≤ n has a smallest prime factor p. Mark k=p*m exactly once, when p does not exceed SPF[m]. That is the linear sieve.

Recognise this pattern

Say yes when you see

  • All primes ≤ n, n ≤ 1e7
  • Factor many numbers ≤ n
  • phi/mu prefix on 1..n
  • Count primes in a range of length 1e6 inside [1,1e12] (segmented)
  • Smallest prime factor queries

Not this pattern when

  • One primality test of a 64-bit n → Miller-Rabin
  • Factor one 64-bit n → Pollard Rho
  • n=1e12 full sieve → memory dies
  • Need primes in a very sparse set → just test those

Core idea and the invariant

Eratosthenes: for i=2..n, if prime, mark i*i, i*i+i, ... composite. Optimise odds / wheel if needed.

Linear: for x=2..n, if spf[x]==0, spf[x]=x, push prime. Then for each prime p with ple spf[x] and p*xle n, spf[p*x]=p. Each composite is written once.

After the linear sieve, spf[x] is the smallest prime dividing x (and spf[p]=p). Factorisation pops spf until x=1, O(Ω(x)) ≤ O(log x).

Algorithm

  1. Allocate int[] spf = new int[n+1].
  2. For x=2..n: if spf[x]==0, spf[x]=x, primes.add(x).
  3. Inner: for each prime p, if p>spf[x] or p*x>n break; spf[p*x]=p.
  4. Factor k: while k>1, p=spf[k], divide out p.
  5. phi: same loop, phi[p*x] = phi[x]*p if p|x else phi[x]*(p-1).
  6. Segmented: sieve primes to sqrt(R), then a bool array of length R-L+1.

Java implementation

O(sqrt n) per test.

JavaTrialPrime.java
public class TrialPrime {
        static boolean isPrime(int n) {
            if (n < 2) return false;
            for (int i = 2; i * i <= n; i++) if (n % i == 0) return false;
            return true;
        }
        public static void main(String[] args) {
            int c = 0;
            for (int i = 2; i <= 10; i++) if (isPrime(i)) c++;
            System.out.println(c);
        }
        // Input : count primes ≤ 10
        // Output: 4
    }

SPF + primes list. Factor 84.

JavaLinearSieve.java
import java.util.*;
    public class LinearSieve {
        static int[] spf;
        static List<Integer> primes = new ArrayList<>();
        static void sieve(int n) {
            spf = new int[n + 1];
            for (int x = 2; x <= n; x++) {
                if (spf[x] == 0) { spf[x] = x; primes.add(x); }
                for (int p : primes) {
                    if (p > spf[x] || (long) p * x > n) break;
                    spf[p * x] = p;
                }
            }
        }
        static List<Integer> factor(int n) {
            List<Integer> f = new ArrayList<>();
            while (n > 1) { f.add(spf[n]); n /= spf[n]; }
            return f;
        }
        public static void main(String[] args) {
            sieve(100);
            System.out.println(primes.subList(0, 4));
            System.out.println(factor(84));
        }
        // Input : n=100, factor 84
        // Output: [2, 3, 5, 7]
        //         [2, 2, 3, 7]
    }

The simpler sieve if you only need a boolean prime[].

JavaEratosthenes.java
import java.util.Arrays;
    public class Eratosthenes {
        static boolean[] sieve(int n) {
            boolean[] p = new boolean[n + 1];
            Arrays.fill(p, true);
            p[0] = p[1] = false;
            for (int i = 2; i * i <= n; i++) if (p[i])
                for (int j = i * i; j <= n; j += i) p[j] = false;
            return p;
        }
        public static void main(String[] args) {
            boolean[] p = sieve(10);
            System.out.println(p[7] + " " + p[9]);
        }
        // Input : n=10
        // Output: true false
    }

Complexity

Time O(n) linear / O(n log log n) Eratosthenes Space O(n)

Linear: each composite is assigned its SPF once, each prime is pushed once. Eratosthenes: harmonic sum of n/p over primes is n log log n.

Edge cases and pitfalls

  • Inner loop from 2i instead of i*i
    Correct but slower; also i*i overflow for i~46341 in int.
    (long)i*i and start at i*i.
  • Linear sieve not breaking on p>spf[x]
    A number is marked by several primes, SPF is no longer smallest, and O(n log n).
    The break is the algorithm.
  • spf[1] and factor(1)
    Infinite loop while n>1 if spf[1] is 0 and you call factor(1).
    Special-case 1 as empty factor list.
  • n=1e8 boolean in Java
    Memory and time both tight; TLE on slow marking.
    Bitset, or n=1e7, or linear sieve.
  • Segmented sieve off-by-one on L=1
    1 is not prime; index 0 maps to L.
    Mark 0/1 explicitly if Lle1.

Interview follow-ups

Why is the linear sieve linear?

Every composite m has a unique writing m = p * x with p = spf[m] le spf[x]. The inner loop produces each m once.

Eratosthenes vs linear in practice?

Eratosthenes has better cache for prime[] only. Linear wins when you want SPF/phi/mu in the same pass.

How do you list primes in [1e12, 1e12+1e6]?

Sieve primes ≤ 1e6+eps, then segmented-mark the window. Do not allocate 1e12.

Goldbach / twin primes?

Sieve then a linear scan of the prime list. The sieve is the preprocess.
