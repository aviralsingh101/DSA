GCD & Extended Euclid

Euclid's algorithm is O(log min(a,b)). Extended Euclid also returns x,y with ax+by=gcd, which is the inverse of a mod m when gcd=1.

Medium 22 min read Prerequisites: Modular Arithmetic, Recursion Fundamentals gcd exgcd Bezout P1

Why this exists

gcd appears in fractions, lattice points, frog jumps (chicken nugget / Frobenius), and modular inverses when M is not prime. lcm(a,b)=a/gcd*b, carefully in long.

Bézout: there exist x,y with ax+by=gcd(a,b). Extended Euclid finds them. a has an inverse mod m iff gcd(a,m)=1, and that inverse is x normalised.

The subtractive version is slow (Fibonacci worst case is already logarithmic for modulo Euclid). Always %.

gcd(a,b)=gcd(b, a%b). Unrolling the remainders gives the inverse as a back-substitution — that is extended Euclid.

Recognise this pattern

Say yes when you see

  • Compute gcd / lcm, reduce fractions
  • Inverse of a modulo m when m is not prime
  • Integer solutions to ax+by=c
  • Lattice points on a segment (gcd of the delta)
  • When you can jump by a and b and want gcd-step

Not this pattern when

  • Polynomial GCD → different Euclid
  • Need all inverses 1..n-1 mod P → linear inverse sieve, not n exgcds
  • Real numbers → floating gcd is meaningless
  • Prime modulus and one inverse → Fermat is fine too

Core idea and the invariant

exgcd(a,b): if b==0, return (a,1,0) meaning a*1+b*0=a. Else (g,x1,y1)=exgcd(b,a%b); then x=y1, y=x1-(a/b)*y1.

Solve ax+by=c: if c%g !=0, no solution. Else multiply x,y by c/g. General solution x+=b/g*t, y-=a/g*t.

At every recursive call, the current pair still generates the same gcd. The returned (x,y) satisfy ax+by=g for the current (a,b).

Recurse on remainders, back-substitute

Algorithm

  1. gcd: while b!=0, (a,b)=(b,a%b). Return |a|.
  2. exgcd recursive as above, or iterative with x=1,y=0,x1=0,y1=1.
  3. Inverse: (g,x,y)=exgcd(a,m); if g!=1 fail; return (x%m+m)%m.
  4. ax+by=c: scale by c/g; parametrise by t.
  5. lcm: a/g*b with g=gcd, after confirming no overflow.
  6. n variables: iterate gcd, or lattice reduction — rare.

Java implementation

Subtract. Worst-case linear in a+b.

JavaGcdSub.java
public class GcdSub {
        static int gcd(int a, int b) {
            while (a != b) { if (a > b) a -= b; else b -= a; }
            return a;
        }
        public static void main(String[] args) {
            System.out.println(gcd(30, 18));
        }
        // Input : 30,18
        // Output: 6
    }

Iterative extended Euclid and modular inverse.

JavaExGcd.java
public class ExGcd {
        static long gcd(long a, long b) { return b == 0 ? a : gcd(b, a % b); }
        static long[] exgcd(long a, long b) {
            long x = 1, y = 0, x1 = 0, y1 = 1;
            while (b != 0) {
                long q = a / b;
                long nb = a % b; a = b; b = nb;
                long nx = x - q * x1; x = x1; x1 = nx;
                long ny = y - q * y1; y = y1; y1 = ny;
            }
            return new long[] {a, x, y};
        }
        static long inv(long a, long m) {
            long[] g = exgcd(a, m);
            if (g[0] != 1) return -1;
            long x = g[1] % m;
            return x < 0 ? x + m : x;
        }
        public static void main(String[] args) {
            System.out.println(gcd(30, 18));
            System.out.println(inv(7, 30));
        }
        // Input : gcd 30,18 and inv 7 mod 30
        // Output: 6
        //         13
    }

One particular solution of ax+by=c, or null.

JavaDiophantine.java
public class Diophantine {
        static long[] exgcd(long a, long b) {
            if (b == 0) return new long[] {a, 1, 0};
            long[] r = exgcd(b, a % b);
            return new long[] {r[0], r[2], r[1] - (a / b) * r[2]};
        }
        static long[] solve(long a, long b, long c) {
            long[] t = exgcd(a, b);
            if (c % t[0] != 0) return null;
            long k = c / t[0];
            return new long[] {t[1] * k, t[2] * k};
        }
        public static void main(String[] args) {
            long[] s = solve(30, 18, 12);
            System.out.println(s[0] + " " + s[1]);
        }
        // Input : 30x+18y=12
        // Output: -2 4
    }

Complexity

Time O(log min(a,b)) Space O(1) iterative / O(log) recursive

Each remainder is at most 2/3 of the previous (Lamé). Worst case consecutive Fibonacci numbers, O(log_phi a) steps.

Edge cases and pitfalls

  • lcm overflow
    a*b/gcd overflows before divide.
    a / gcd * b in long, gcd first.
  • Negative a,b
    Java % sign follows dividend; gcd may be negative.
    Work with abs, or normalise at the end.
  • Ignoring g!=1 for inverse
    You still return x, and a*x ≡ 0 or other junk.
    If g!=1, no inverse. For ax≡b, need g|b.
  • Recursive exgcd on Fibonacci 1e18
    Depth ~ 90, fine actually. Still prefer iterative.
    Iterative is clearer for the x,y updates.
  • General solution forgetting t step b/g
    You add b instead of b/g and skip solutions.
    x += (b/g)*t; y -= (a/g)*t.

Interview follow-ups

Why does Euclid terminate?

Remainders are non-negative and strictly decrease. gcd is preserved because a divisor of a,b divides a%b and conversely.

Binary GCD?

Stein: divide out 2, then subtract odds. Good on huge bit-integers. For 64-bit, % is faster in Java.

Frobenius coin problem?

For coprime a,b the largest impossible amount is ab-a-b. If gcd>1, all large enough multiples of the gcd are possible, but not all integers.

n-dimensional ax=c?

Gcd of all coefficients must divide c. Finding one solution uses iterative exgcd. The kernel is a lattice of rank n-1.

Recap

  • gcd(a,b)=gcd(b,a%b). Never subtract in a loop.
  • exgcd returns Bezout coefficients.
  • Inverse iff gcd(a,m)=1; normalise x.
  • lcm = a/gcd*b in long.
  • ax+by=c solvable iff gcd|c.
