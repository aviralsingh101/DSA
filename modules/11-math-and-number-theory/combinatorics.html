Combinatorics

nCr = n!/(r!(n-r)!) in a prime field is three factorials. Lucas handles n ≥ p. Stars-and-bars is C(n+k-1, k-1).

Medium 22 min read Prerequisites: Modular Arithmetic nCr Lucas Catalan P1

Why this exists

Counting problems collapse to choose, distribute, or Catalan. Mod a prime, a fact/invFact table makes every nCr O(1). That table is the primitive the rest of combinatorics sits on.

When n is huge and r is tiny, multiply the falling factorial. When n ≥ p, n! is 0 and you need Lucas: nCr of the base-p digits.

Stars-and-bars, "at least one", Catalan, and derangements are the four named shapes. The algebra is short once nCr is cheap.

nCr is a field element when M is prime and n < M. Precompute fact and invFact once. Lucas is the same formula on base-p digits when n ≥ M.

Recognise this pattern

Say yes when you see

  • Combinations / distributions modulo a prime
  • Stars-and-bars: n identical items, k labelled bins
  • Catalan: brackets, BSTs, monotone paths under the diagonal
  • n ≤ 1e18, r ≤ 1e6 — falling factorial
  • nCr mod p with n ≥ p — Lucas

Not this pattern when

  • Composite modulus that is not a prime power → CRT + per-prime fact
  • Exact huge integer, not a residue → BigInteger
  • Order matters and you used nCr instead of nPr
  • Subset DP is smaller than the closed form you are forcing

Core idea and the invariant

Build fact[0..n] and invFact (one inverse at n, then walk down). nCr = 0 if r<0 or r>n. Stars-and-bars: non-neg solutions of x_1+...+x_k=n is C(n+k-1, k-1).

Lucas: while n or r is nonzero, multiply nCr(n%p, r%p) (0 if a digit of r exceeds n), then n/=p, r/=p. Catalan = C(2n,n)*inv(n+1).

C(n,r)=C(n-1,r)+C(n-1,r-1) in Z and in a field. Lucas is that recurrence in base p via (1+x)^n ≡ ∏ (1+x)^{n_i p^i} (mod p).

Structure

Algorithm

  1. Pick the formula from n, r, M.
  2. fact / invFact if n < M and many queries.
  3. Falling if r is small: multiply (n-i)*inv(i+1).
  4. Lucas if n ≥ p: product of digit nCr.
  5. Stars-and-bars C(n+k-1, k-1); IE the caps.
  6. Catalan C(2n,n)*inv(n+1), or the difference form if p | n+1.

Java implementation

JavaNcrPascal.java
public class NcrPascal {
        static int nCr(int n, int r) {
            if (r < 0 || r > n) return 0;
            int[] dp = new int[r + 1];
            dp[0] = 1;
            for (int i = 1; i <= n; i++)
                for (int j = Math.min(i, r); j > 0; j--) dp[j] += dp[j - 1];
            return dp[r];
        }
        public static void main(String[] args) {
            System.out.println(nCr(5, 2));
        }
        // Input : 5 choose 2
        // Output: 10
    }
JavaNcrMod.java
public class NcrMod {
        static final int M = 1_000_000_007;
        static long[] fact, invF;
        static long modPow(long a, long e) {
            long r = 1;
            for (; e > 0; e >>= 1, a = a * a % M) if ((e & 1) == 1) r = r * a % M;
            return r;
        }
        static void build(int n) {
            fact = new long[n + 1]; invF = new long[n + 1];
            fact[0] = 1;
            for (int i = 1; i <= n; i++) fact[i] = fact[i - 1] * i % M;
            invF[n] = modPow(fact[n], M - 2);
            for (int i = n; i > 0; i--) invF[i - 1] = invF[i] * i % M;
        }
        static long nCr(int n, int r) {
            if (r < 0 || r > n) return 0;
            return fact[n] * invF[r] % M * invF[n - r] % M;
        }
        public static void main(String[] args) {
            build(20);
            System.out.println(nCr(10, 3));
            System.out.println(nCr(6, 3) * modPow(4, M - 2) % M);
        }
        // Input : C(10,3) ; Catalan_3
        // Output: 120
        //         5
    }
JavaLucas.java
public class Lucas {
        static long inv(long a, int p) {
            long r = 1, e = p - 2;
            for (a %= p; e > 0; e >>= 1, a = a * a % p) if ((e & 1) == 1) r = r * a % p;
            return r;
        }
        static long nCrSmall(int n, int r, int p) {
            if (r < 0 || r > n) return 0;
            long a = 1, b = 1;
            for (int i = 0; i < r; i++) { a = a * (n - i) % p; b = b * (i + 1) % p; }
            return a * inv(b, p) % p;
        }
        static long lucas(long n, long r, int p) {
            long ans = 1;
            while (n > 0 || r > 0) {
                ans = ans * nCrSmall((int) (n % p), (int) (r % p), p) % p;
                n /= p; r /= p;
            }
            return ans;
        }
        public static void main(String[] args) {
            System.out.println(lucas(10, 3, 7));
        }
        // Input : C(10,3) mod 7
        // Output: 1
    }

Complexity

Time O(n + log M) preprocess, O(1) nCr; Lucas O(log_p n) with a p-table Space O(n)

The factorial table is one pass. Lucas does O(log_p n) digits, each an nCr with args < p.

Edge cases and pitfalls

  • fact[n] when n >= M
    fact[n]=0, every choose looks like 0.
    Lucas.
  • Stars-and-bars off-by-one
    C(n+k-1, k) is not the number of solutions.
    C(n+k-1, k-1).
  • Catalan inv(n+1) when p | n+1
    Division fails.
    Use C(2n,n) - C(2n, n-1).
  • Integer / on the falling factorial
    Truncation in Z, not the field.
    Multiply by inv(i+1) mod M.
  • Order vs combination
    Arrangements are nPr.
    Ask whether order matters.

Interview follow-ups

Why Lucas?

Freshman's dream: (1+x)^p ≡ 1+x^p (mod p). The coefficient of x^r is the product of digit-wise nCr.

Each bin at least 1?

Give one first: C(n-1, k-1), n≥k.

Is Catalan an integer?

Always. Prefer the difference form mod p if p might divide n+1.

n=1e18, r=1e18, p=1e9+7?

Cannot sieve a 1e9 table. The problem will guarantee small r, or a different modulus.
