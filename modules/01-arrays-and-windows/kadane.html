Kadane's Algorithm

Find the maximum-sum contiguous subarray in one pass and constant memory, by asking only one question at each index: is it better to extend the current subarray, or to start a new one here?

Medium 20 min read Prerequisites: Complexity Analysis, Prefix Sums arrays dp in disguise single pass O(1) space

Why this exists

You are given an array that mixes positive and negative numbers, and you must pick a contiguous block whose sum is as large as possible. If every number were positive the answer would be the whole array, so the entire difficulty comes from deciding when a negative prefix is worth carrying and when it should be abandoned.

The obvious approach enumerates every pair (l, r) and sums the block. Even with a running sum that removes the innermost loop, you still evaluate n(n+1)/2 subarrays, which is Θ(n²). At the usual competitive constraint of n = 10⁵ that is about 5 × 10⁹ additions — comfortably a TLE in any language, and roughly a minute of CPU in Java. At n = 2 × 10⁵ it is hopeless.

The insight

You never need to know where the best subarray started. You only need the best sum of a subarray that ends at the current index. That single number can be updated from its own previous value in constant time, which collapses the quadratic search into one pass.

Recognise this pattern

Say yes when you see

  • "maximum sum contiguous subarray", "largest sum subarray", "best substring score"
  • The words subarray, substring or consecutive together with maximum or minimum, and no constraint on the length
  • The array contains negative values (otherwise the answer is trivially the whole array)
  • The quantity is additive along the array and you are free to choose where the block begins
  • "maximum profit from one buy then one sell" — that is Kadane on the difference array
  • "you may apply at most one operation to a contiguous segment" — Kadane with an extra state dimension

Not this pattern when

  • A non-contiguous subsequence is allowed → just add the positives, or it is an LIS-style DP
  • The block has a fixed length k → fixed sliding window
  • You must count subarrays with a property, not maximise → prefix sums + HashMap
  • The sum must equal, or stay under, a target → prefix sums with hashing or binary search
  • There is a length constraint such as "length at least k" → prefix sums plus a monotonic deque
  • The array is updated between queries → segment tree storing a 4-tuple per node

Constraint tell: n ≤ 10⁵ or larger with O(1) work per element → a single Θ(n) pass is intended. If instead n ≤ 2000, the setter is probably allowing the O(n²) double loop — take it, because it is far harder to get wrong under interview pressure.

Core idea and the invariant

Walk left to right and maintain one number, cur, meaning the best sum I can achieve with a subarray that finishes exactly here. When you step from index i-1 to i, there are only two possibilities for that best subarray: it is the single element a[i] on its own, or it is the best subarray ending at i-1 with a[i] glued onto its right end. Nothing else can be optimal, because any longer candidate ending at i has a prefix ending at i-1 which would then have to beat the best one — a contradiction.

The invariant

After the iteration for index i finishes:

  • cur = the maximum sum of a non-empty subarray ending exactly at i;
  • best = the maximum sum of a non-empty subarray ending at any index ≤ i.

Say this out loud in an interview: "Let cur be the best sum ending at i. A best subarray ending at i is either just a[i], or the best one ending at i−1 extended by a[i], so cur = max(a[i], cur + a[i]). The answer is the maximum of cur over all i."

It is a one-line DP

Kadane is not a special trick, it is the DP dp[i] = max(a[i], dp[i-1] + a[i]) with the answer maxi dp[i], rolled down to O(1) space because dp[i] depends only on dp[i-1]. Recognising that framing is what lets you extend it: every variant below is the same recurrence with more states.

The prefix-sum view (useful for variants)

With P[k] = a[0] + … + a[k-1], the sum of a[l..r] is P[r+1] − P[l]. So the answer is maxr (P[r+1] − minl≤r P[l]): sweep right, keep the minimum prefix seen so far. This is the same algorithm, and it is the version to reach for when a variant adds a length constraint, because "minimum prefix so far" generalises to "minimum prefix in a window".

What the brute force is actually doing

The quadratic solution fills a triangular table of every subarray sum. Seeing it makes two things obvious: the work is n(n+1)/2 cells, and each row is just the previous cell plus one element — which is the redundancy Kadane removes.

One iteration, as a decision

The dependency chain that makes it O(1) space

Algorithm

  1. Reject the empty array. With no elements there is no non-empty subarray, so throw rather than returning a silently wrong 0.
  2. Seed from the first element. cur = best = a[0], start = bestL = bestR = 0.
  3. For each i from 1 to n−1, compare cur + a[i] against a[i].
  4. If a[i] wins, restart: cur = a[i] and start = i. The carried prefix was negative, so drop it.
  5. Otherwise extend: cur = cur + a[i], leaving start where it is.
  6. Record a strict improvement: if cur > best then best = cur, bestL = start, bestR = i.
  7. Return best, with a[bestL..bestR] as the witness subarray.

Read row i = 2 again

At i = 2 the running sum cur is negative and we still extend. People "fix" this by resetting cur to 0 whenever it goes negative. That is correct only if the empty subarray is allowed — it silently returns 0 on an all-negative array. The comparison max(a[i], cur + a[i]) has no such hole.

Java implementation

Worth writing first in an interview: it is obviously correct, it gives you a reference to test against, and stating its complexity out loud is what motivates the optimisation.

JavaKadaneBrute.java
public class KadaneBrute {

    /** Every subarray [l..r], with a running sum so there is no third loop. */
    static long maxSubarrayBrute(int[] a) {
        if (a == null || a.length == 0) {
            throw new IllegalArgumentException("no non-empty subarray exists");
        }
        long best = Long.MIN_VALUE;
        for (int l = 0; l < a.length; l++) {
            long sum = 0;                       // long: n * max|a[i]| overflows int
            for (int r = l; r < a.length; r++) {
                sum += a[r];
                best = Math.max(best, sum);
            }
        }
        return best;
    }

    public static void main(String[] args) {
        int[] a = {-2, 1, -3, 4, -1, 2, 1, -5, 4};
        System.out.println(maxSubarrayBrute(a));
    }
    // Input : [-2,1,-3,4,-1,2,1,-5,4]
    // Output: 6
}

The two highlighted lines are the entire algorithm. Everything else is scaffolding.

JavaKadane.java
public class Kadane {

    /**
     * cur  = best sum of a subarray ending exactly at i
     * best = best sum of a subarray ending at any index <= i
     */
    static long maxSubarray(int[] a) {
        if (a == null || a.length == 0) {
            throw new IllegalArgumentException("no non-empty subarray exists");
        }
        long cur = a[0];
        long best = a[0];
        for (int i = 1; i < a.length; i++) {
            cur = Math.max(a[i], cur + a[i]);
            best = Math.max(best, cur);
        }
        return best;
    }

    public static void main(String[] args) {
        int[] a = {-2, 1, -3, 4, -1, 2, 1, -5, 4};
        System.out.println(maxSubarray(a));
    }
    // Input : [-2,1,-3,4,-1,2,1,-5,4]
    // Output: 6   (subarray [4,-1,2,1])
}

The version to memorise, because the follow-up "which subarray?" arrives about half the time. Note the strict > on the best update: it returns the leftmost and shortest optimal subarray, which is usually what a judge expects when ties exist.

JavaKadaneWithIndices.java
public class KadaneWithIndices {

    /** {bestSum, bestLeft, bestRight}; bestRight is inclusive. */
    static long[] maxSubarray(int[] a) {
        if (a == null || a.length == 0) {
            throw new IllegalArgumentException("no non-empty subarray exists");
        }
        long cur = a[0], best = a[0];
        int start = 0, bestL = 0, bestR = 0;
        for (int i = 1; i < a.length; i++) {
            if (cur + a[i] < a[i]) {        // restarting beats extending
                cur = a[i];
                start = i;
            } else {
                cur += a[i];
            }
            if (cur > best) {               // strict: keep the leftmost, shortest witness
                best = cur;
                bestL = start;
                bestR = i;
            }
        }
        return new long[] {best, bestL, bestR};
    }

    public static void main(String[] args) {
        int[] a = {-2, 1, -3, 4, -1, 2, 1, -5, 4};
        long[] r = maxSubarray(a);
        System.out.println(r[0] + " [" + r[1] + ".." + r[2] + "]");

        int[] allNeg = {-7, -3, -9, -4};
        System.out.println(maxSubarray(allNeg)[0]);
    }
    // Input : [-2,1,-3,4,-1,2,1,-5,4]  then  [-7,-3,-9,-4]
    // Output: 6 [3..6]
    //         -3
}

Complexity

Time Θ(n) Space Θ(1)

Brute force. The outer loop fixes l; the inner loop performs n − l additions. Summing over all l:

T(n) = Σl=0..n-1 (n − l) = n + (n−1) + … + 1 = n(n+1)/2 = Θ(n²)

That matches the 21 cells for n = 6 in the triangular table above.

Kadane. The loop body is a fixed number of comparisons and one addition, and it executes exactly n − 1 times, with no recursion and no nesting:

T(n) = (n − 1) · Θ(1) = Θ(n)

Space is four scalars regardless of n, so Θ(1). Note that Θ(n) is a lower bound too: any correct algorithm must read every element, since changing one unread value can change the answer.

Edge cases and pitfalls

  • Initialising best = 0
    long best = 0; long cur = 0; — returns 0 for [-7, -3, -9], because the empty subarray sneaks in as a candidate. This is the single most common Kadane bug.
    long best = a[0], cur = a[0]; and loop from i = 1. If the problem does allow an empty subarray, return Math.max(0, best) explicitly so the intent is visible.
  • int overflow on the running sum
    int cur, best; with n = 10⁵ and |a[i]| ≤ 10⁹ — the true sum reaches 10¹⁴, which silently wraps. You get a plausible-looking wrong answer, not an exception.
    Use long for cur and best whenever n × max|a[i]| can exceed 2³¹ − 1. Cheap insurance; do it by default.
  • Empty or null input
    long cur = a[0]; on an empty array throws ArrayIndexOutOfBoundsException from inside your algorithm, which looks like a logic error to the interviewer.
    Guard first and state the contract: "a non-empty subarray is required, so an empty input is invalid input". Handle it, then move on.
  • Resetting cur = 0 when it goes negative
    if (cur < 0) cur = 0; cur += a[i]; — equivalent to allowing the empty subarray, so it is wrong on all-negative input, and it also loses the start index you need for the "which subarray?" follow-up.
    Keep the comparison form cur = Math.max(a[i], cur + a[i]). It is the same number of operations and has no special case.
  • Using >= when recording the best
    if (cur >= best) — still returns the right sum, but reports the last and longest tied subarray. On [1, 0, 0] it answers [0..2] where most judges expect [0..0].
    Use strict > for the leftmost shortest witness. If the problem wants the longest, use >= deliberately and say so.
  • All-equal or single-element arrays
    Loops written as for (int i = 0; i < n; i++) while also seeding from a[0] double-count the first element, giving 2 × a[0] on a one-element array.
    Seed from index 0 and start the loop at i = 1. Test [5], [-5] and [2,2,2] before you say you are done.
  • Circular variant: forgetting the all-negative case
    return Math.max(kadaneMax, total - kadaneMin); — on [-3, -2, -5] the minimum subarray is the whole array, so total - kadaneMin = 0, which corresponds to the empty subarray.
    if (kadaneMax < 0) return kadaneMax; before combining. A negative maximum proves every element is negative.

At most one deletion Add a second state: best sum ending at i having already deleted one element. del = max(del + a[i], keep); keep = max(a[i], keep + a[i]); best = max(best, max(keep, del)); LC 1186
Maximum absolute sum The largest magnitude is either the maximum subarray sum or the negation of the minimum one, so run Kadane twice. return Math.max(kadaneMax(a), -kadaneMin(a)); LC 1749

Interview follow-ups

Now return the actual subarray, not just the sum.

Track start, the left end of the current candidate. It only moves when you restart. When cur beats best, snapshot bestL = start and bestR = i. That is the "Reusable template" tab above, and it costs three extra ints.

Prove it. Why is looking only at cur enough?

Induction on i. Assume cur is the maximum sum over subarrays ending at i-1. Any non-empty subarray ending at i is either [i, i] with sum a[i], or [l, i] with l < i, whose sum is sum(l..i-1) + a[i]. Maximising the second form over l maximises sum(l..i-1), which is exactly cur by hypothesis. So the new maximum is max(a[i], cur + a[i]), establishing the invariant at i. Every subarray ends at some index, so the maximum over all of them is the maximum of cur over all i, which best accumulates.

The data arrives as a stream and you cannot store it. Does anything break?

Nothing. Kadane is already a streaming algorithm: it touches each element once, in order, and keeps O(1) state. You can answer "best so far" after every element. The only thing you lose is the ability to replay the witness subarray, so if you need the values and not just the indices you must buffer a[bestL..bestR].

What if the empty subarray is allowed?

Then the answer is Math.max(0, best), and only then is the "reset to 0 when negative" formulation correct. Always ask this: it is the difference between -3 and 0 on an all-negative array, and it is the most common ambiguity in the problem statement.

Extend it to a 2D matrix: maximum-sum submatrix.

Choose the left and right columns (O(m²) pairs). For a fixed pair, collapse each row into a single number — the sum of that row between the two columns — maintained incrementally as the right column advances. Run 1D Kadane on that length-n array. Total O(m² n), so put the smaller dimension in the column role.

Elements get updated between queries. Now what?

Kadane's O(1) state is not mergeable, but a slightly bigger one is. Store per segment: total, best prefix sum, best suffix sum, and best inner sum. Merging two children takes the best of (left best, right best, left suffix + right prefix). That is a segment tree with O(log n) point update and O(log n) range query. This follow-up is the standard bridge from an easy array question to a hard data-structure question.

Can you parallelise it?

Yes, using the same 4-tuple. Split the array into p chunks, compute the tuple for each chunk independently, then reduce with the merge rule above. The reduction is associative, which is precisely why the segment tree works. Depth is O(log p) with O(n/p) work per chunk.

Hint for LC 363 — Max Sum of Rectangle No Larger Than K

Kadane maximises, but here you want the largest sum not exceeding k, and that objective is not built from local maxima. Compress column pairs as usual, then for the resulting 1D array walk prefix sums P[r] and ask for the smallest earlier prefix with P[l] ≥ P[r] − k. A TreeSet<Integer> answers that with ceiling in O(log n), giving O(m² n log n). The lesson to internalise: "at most k" kills greedy running maxima and calls for an ordered structure over prefixes.

Hint for LC 2272 — Substring With Largest Variance

Fix an ordered pair of letters (a, b) — only 26 × 25 pairs. Map a to +1, b to −1, ignore everything else, and you want the maximum subarray sum that contains at least one −1. Run Kadane while tracking a second value: the best sum of a window that has already consumed one b. When you would restart, remember that a b is available "for free" if one was just dropped. The reusable lesson: a "must include at least one X" constraint becomes an extra Kadane state, not a different algorithm.

Recap

  • The trigger is the word "contiguous" plus "maximum" with no length constraint. That is the recognition you are training, not the code.
  • The invariant is everything: cur is the best sum ending exactly at i. If you can say that sentence, you can rederive the algorithm and every variant on the spot.
  • Seed from a[0], never from 0, unless the empty subarray is explicitly allowed. Use long.
  • Variants add states, not algorithms. Deletion, multiplication, "at least one b", products — each is one more running value in the same single pass.
  • When updates appear, upgrade to the 4-tuple (total, prefix, suffix, best) and you have a segment tree. Kadane is the merge rule.
