K-th Element & Selection

Find the k-th smallest element in linear expected time, or the median of two sorted arrays in logarithmic time, by discarding half the remaining candidates each step.

Hard 22 min read Prerequisites: Binary Search Basics, Binary Search on the Answer quickselect median binary search P1

Why this exists

Sorting then indexing is always correct and almost always good enough: O(n log n) to read a[k]. Selection problems exist because some constraints are tighter, and because the median of two sorted arrays question is a Google classic that sorting would turn into a merge.

Quickselect is quicksort that only recurses into the side that contains rank k. Average O(n), worst-case O(n²) unless you add median-of-medians or a random pivot. The two-array median is a binary search on how many elements you take from the shorter array.

Both are discard-half arguments. Once you see them that way, k-th in a sorted matrix and k-th pair distance become the same idea with a different feasible.

You do not need full order to know rank k. You only need to know, for a candidate cut, how many items lie on each side — then throw one side away.

Recognise this pattern

Say yes when you see

  • "k-th smallest / largest" in an unsorted array, and n is large enough that n log n is tight
  • Median (k = n/2) of one array, or of two already-sorted arrays
  • k-th smallest in a row-and-column-sorted matrix
  • k-th smallest pair distance / pair sum — count-how-many-leq + binary search

Not this pattern when

  • You need the full sorted order afterwards → just sort
  • k is tiny (1, 2, 3) → a heap or a few comparisons, not quickselect
  • The array is already sorted → return a[k]
  • You must do it in-place and worst-case linear → median-of-medians, rarely asked

Core idea and the invariant

Quickselect: pick a pivot, partition so everything smaller is on the left. If the pivot lands at index k you are done. If it lands to the right, recurse left; otherwise recurse right. Expected linear because each step throws away a constant fraction on average.

Two-array median: imagine the merged array. A valid cut takes i elements from A and (half-i) from B such that every value on the left of the cut is ≤ every value on the right. Binary-search i. The conditions are A[i-1] ≤ B[j] and B[j-1] ≤ A[i] (with sentinels for empty sides).

After a partition at p, ranks [lo..p] live in a[lo..p] and ranks (p+1..hi] live in a[p+1..hi]. Rank k is in exactly one of those two pieces, so I can discard the other. For two arrays: I am searching the number of elements I take from the shorter array; the cut is valid iff the two crossing inequalities hold.

Algorithm

  1. Quickselect. Pick a pivot (random or last). Partition [lo, hi] so the pivot sits at p.
  2. If p == k return a[p]. If k < p set hi = p-1, else lo = p+1. Repeat.
  3. Two-array median. Ensure A is the shorter. Binary-search i = how many to take from A.
  4. j = half - i where half = (m+n+1)/2 (left side is the larger half when the total is odd).
  5. If Aleft > Bright i is too big; if Bleft > Aright, i is too small. Otherwise the cut is valid.
  6. Odd total: answer is max(Aleft, Bleft). Even: average of that and min(Aright, Bright).
  7. Use sentinels ±∞ when a side is empty so the comparisons stay uniform.

Java implementation

Always mention this first. For n ≤ 1e5 it is the right answer unless they ask for linear.

JavaKthSort.java
import java.util.Arrays;
    
    public class KthSort {
        static int kth(int[] a, int k) {
            int[] b = a.clone();
            Arrays.sort(b);
            return b[k];
        }
        public static void main(String[] args) {
            System.out.println(kth(new int[] {7, 2, 1, 6, 8, 5, 3}, 3));
        }
        // Input : [7,2,1,6,8,5,3], k = 3 (0-based)
        // Output: 5
    }
JavaQuickselect.java
import java.util.Random;
    
    public class Quickselect {
        static final Random R = new Random();
    
        static int kth(int[] a, int k) {
            int lo = 0, hi = a.length - 1;
            while (lo <= hi) {
                int p = partition(a, lo, hi, lo + R.nextInt(hi - lo + 1));
                if (p == k) return a[p];
                if (k < p) hi = p - 1;
                else lo = p + 1;
            }
            throw new IllegalArgumentException();
        }
    
        static int partition(int[] a, int lo, int hi, int pi) {
            int pivot = a[pi];
            swap(a, pi, hi);
            int store = lo;
            for (int i = lo; i < hi; i++) if (a[i] < pivot) swap(a, store++, i);
            swap(a, store, hi);
            return store;
        }
    
        static void swap(int[] a, int i, int j) { int t = a[i]; a[i] = a[j]; a[j] = t; }
    
        public static void main(String[] args) {
            System.out.println(kth(new int[] {7, 2, 1, 6, 8, 5, 3}, 3));
        }
        // Input : [7,2,1,6,8,5,3], k = 3
        // Output: 5
    }

The O(log(m+n)) cut search. Always binary-search the shorter array.

JavaMedianTwo.java
public class MedianTwo {
        static double findMedianSortedArrays(int[] A, int[] B) {
            if (A.length > B.length) return findMedianSortedArrays(B, A);
            int m = A.length, n = B.length;
            int lo = 0, hi = m, half = (m + n + 1) / 2;
            while (lo <= hi) {
                int i = lo + (hi - lo) / 2;
                int j = half - i;
                int Aleft  = (i == 0) ? Integer.MIN_VALUE : A[i - 1];
                int Aright = (i == m) ? Integer.MAX_VALUE : A[i];
                int Bleft  = (j == 0) ? Integer.MIN_VALUE : B[j - 1];
                int Bright = (j == n) ? Integer.MAX_VALUE : B[j];
                if (Aleft > Bright) hi = i - 1;
                else if (Bleft > Aright) lo = i + 1;
                else {
                    int leftMax = Math.max(Aleft, Bleft);
                    if (((m + n) & 1) == 1) return leftMax;
                    return (leftMax + Math.min(Aright, Bright)) / 2.0;
                }
            }
            throw new IllegalArgumentException();
        }
        public static void main(String[] args) {
            System.out.println(findMedianSortedArrays(new int[] {1, 3}, new int[] {2}));
            System.out.println(findMedianSortedArrays(new int[] {1, 2}, new int[] {3, 4}));
        }
        // Input : [1,3]+[2] then [1,2]+[3,4]
        // Output: 2.0
        //         2.5
    }

Complexity

Time Quickselect O(n) expected / O(n²) worst; two-array median O(log min(m,n)) Space O(1) iterative

Quickselect: a random pivot leaves expected half the work, so T(n) = T(n/2) + O(n) = O(n). Adversarial pivots give the full quicksort recurrence T(n) = T(n-1) + O(n) = O(n²). Randomise the pivot.

Two-array median: the search space is the shorter length, halved each step, and each step is O(1) comparisons, so O(log min(m,n)).

Edge cases and pitfalls

  • k is 1-based in the problem and 0-based in your code
    LC 215 asks for the k-th largest, which is rank n-k in 0-based ascending order.
    Convert once at the top: int rank = a.length - k; for k-th largest, and never touch k again.
  • Worst-case quadratic on sorted input
    Always pivoting on a[hi] of an already-sorted array degenerates.
    Swap a random index into the pivot slot. In an interview, say this out loud.
  • Off-by-one on empty sides of the two-array cut
    Accessing A[i-1] when i == 0.
    Sentinels: empty left is MIN_VALUE, empty right is MAX_VALUE.
  • Averaging two ints for the even case
    (leftMax + rightMin) / 2 truncates and can overflow.
    (leftMax + (double) rightMin) / 2.0 or / 2.0 with a long cast.
  • Mutating the caller's array
    In-place quickselect reorders a. Tests that reuse the array then fail.
    Clone if the caller still needs the original, or document the mutation.
  • Duplicate-heavy arrays and < vs ≤ in partition
    A partition that sends equals to one side unbalances on all-equal input.
    3-way partition (Dutch flag) around the pivot, then check whether k falls in the equal block.

Interview follow-ups

Why is the expected time linear?

A random pivot's rank is uniform. The expected remaining size is the average of 0,1,…,n-1 which is n/2, and T(n) = T(n/2)+O(n) solves to O(n). More carefully the constant is 4n or so, not n.

Can you make it worst-case linear?

Median-of-medians picks a pivot guaranteed to be in the 30th–70th percentile, so you discard at least 30% each time. The recurrence is T(n)=T(n/5)+T(7n/10)+O(n)=O(n). Nobody wants you to code it in an interview; naming it is enough.

Generalise LC 4 to the k-th of two sorted arrays.

The same cut search with half = k (1-based) instead of (m+n+1)/2. Return max(Aleft, Bleft). This is how you also solve "k-th of n sorted arrays" with a heap or a binary search on value.

The matrix is sorted by rows only, not columns.

You lose the staircase count. Heap the heads of each row (O(k log n)) or binary-search the value and binary-search each row (O(n log RANGE log n)).

Must not mutate the array and must be O(1) extra memory.

You cannot quickselect. Heap of size k uses O(k). For k-th of one array under these constraints you are stuck with sorting if you cannot overwrite, unless you are allowed O(n) extra to copy.

Hint for LC 4 — Median of two sorted arrays

Always binary-search the shorter array. i elements from A, j = half-i from B. The cut is valid when A[i-1] ≤ B[j] and B[j-1] ≤ A[i]. Empty sides are ±∞. Odd → max(lefts); even → average of max(lefts) and min(rights).

Hint for LC 378 — Kth in a sorted matrix

Binary-search the value, not an index. Count how many entries are ≤ mid by walking from the bottom-left (or top-right) in O(n). firstTrue for count ≥ k.

Recap

  • Full sort is the default. Reach for selection only when they ask for linear or the two-array log.
  • Quickselect = quicksort that discards one side. Randomise the pivot.
  • k-th largest is rank n-k in 0-based ascending order. Convert once.
  • Two-array median is a cut search on how many you take from the shorter array.
  • k-th in a matrix is binary search on the value plus a linear count.
