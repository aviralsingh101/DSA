Heavy-Light Decomposition

Split every root-path into O(log n) heavy chains so a segment tree on a flattened tree answers path queries in O(log² n).

Hard 28 min read Prerequisites: Binary Lifting & LCA, Segment Tree HLD trees segment tree P2

Why this exists

A path in a tree is not an array interval. Naive path-sum walks O(n) edges; a Fenwick tree on a DFS order answers subtree queries, not arbitrary paths. Heavy-light decomposition (HLD) is the standard way to turn a path into a handful of contiguous segments.

The trick is structural: from each node, the edge into its heaviest child (largest subtree) is heavy; every other child edge is light. Light edges at most halve the remaining size, so any root-path crosses O(log n) light edges and therefore lives on O(log n) heavy chains.

Lay each chain down as a contiguous segment of a global array (DFS that prefers the heavy child). A segment tree on that array answers a chain-range in O(log n), so a full path is O(log² n). Path updates with lazy propagation are the same skeleton.

A light edge halves the subtree, so a root-path uses O(log n) chains. Prefer the heavy child in DFS so each chain occupies a contiguous interval.

Recognise this pattern

Say yes when you see

  • Path aggregate or path update on a tree: sum, min, XOR, add-on-path
  • "Sum of node values from u to v" with point updates
  • Subtree queries and path queries on the same tree (HLD DFS order does both)
  • n, q ≤ 10⁵ on a tree, so O(log² n) per query is the intended budget
  • You already have LCA and a segment tree and the missing piece is "the path is not an interval"

Not this pattern when

  • Only subtree queries → Euler tour + Fenwick / segment tree, no HLD
  • Static path-min / path-max → binary lifting or a sparse table on the Euler tour
  • Distance-only queries → precompute depths and LCA, no values to aggregate
  • Centroid / small-to-large problems ("count pairs at distance k") → a different decomposition

Core idea and the invariant

Two DFS passes. First: compute sz, par, depth, and heavy[u] = child of maximum subtree. Second: assign each node a position pos[u] in a flat array, walking the heavy child first so a chain is contiguous. head[u] is the top of the chain containing u.

A path query lifts the deeper head up one chain at a time: while head[u] != head[v], query [pos[head[u]], pos[u]] and jump u = par[head[u]]. Finish with the remaining in-chain segment between u and v. Always query the deeper side first so the two pointers meet at the LCA chain.

Every root-path crosses O(log n) light edges, hence lives on O(log n) heavy chains. After a heavy-first DFS, each chain is a contiguous [pos[head], pos[node]] interval of the segment tree.

Algorithm

  1. DFS 1. Compute sz, par, depth, heavy[u].
  2. DFS 2. Assign pos and head, always recursing into the heavy child first.
  3. Build a segment tree on the pos-ordered values.
  4. pathQuery(u, v): while heads differ, query the deeper chain and jump to par[head].
  5. Same chain: query the closed interval between pos[u] and pos[v].
  6. Updates are the same walk, writing instead of reading. Subtree query is one interval [pos[u], pos[u]+sz[u]).

Java implementation

Walk parent pointers to the LCA. Correct, O(n) per query.

JavaPathSumBrute.java
public class PathSumBrute {
        static int[] par, val, depth;
        static int lca(int u, int v) {
            while (depth[u] > depth[v]) u = par[u];
            while (depth[v] > depth[u]) v = par[v];
            while (u != v) { u = par[u]; v = par[v]; }
            return u;
        }
        static int pathSum(int u, int v) {
            int a = lca(u, v), s = val[a];
            while (u != a) { s += val[u]; u = par[u]; }
            while (v != a) { s += val[v]; v = par[v]; }
            return s;
        }
        public static void main(String[] args) {
            par = new int[] {0, 0, 1, 1, 2, 2, 3, 3};
            val = new int[] {0, 1, 2, 3, 4, 5, 6, 7};
            depth = new int[] {0, 0, 1, 1, 2, 2, 2, 2};
            System.out.println(pathSum(5, 7));
        }
        // Input : tree 1-2-4/5, 1-3-6/7, values = ids
        // Output: 18
    }

Full HLD with a Fenwick tree for path sums and point updates.

JavaHldPathSum.java
import java.util.*;
    public class HldPathSum {
        int n, timer;
        List<Integer>[] g;
        int[] par, depth, sz, heavy, head, pos, val;
        long[] bit;
        HldPathSum(int n) {
            this.n = n;
            g = new List[n];
            for (int i = 0; i < n; i++) g[i] = new ArrayList<>();
            par = new int[n]; depth = new int[n]; sz = new int[n];
            heavy = new int[n]; Arrays.fill(heavy, -1);
            head = new int[n]; pos = new int[n]; val = new int[n];
            bit = new long[n + 2];
        }
        void add(int u, int v) { g[u].add(v); g[v].add(u); }
        void dfsSz(int u, int p) {
            par[u] = p; sz[u] = 1;
            int best = 0;
            for (int v : g[u]) if (v != p) {
                depth[v] = depth[u] + 1;
                dfsSz(v, u);
                sz[u] += sz[v];
                if (sz[v] > best) { best = sz[v]; heavy[u] = v; }
            }
        }
        void dfsHld(int u, int h) {
            head[u] = h; pos[u] = timer++;
            if (heavy[u] != -1) dfsHld(heavy[u], h);
            for (int v : g[u]) if (v != par[u] && v != heavy[u]) dfsHld(v, v);
        }
        void bitAdd(int i, long x) { for (i++; i <= n; i += i & -i) bit[i] += x; }
        long bitSum(int i) { long s = 0; for (i++; i > 0; i -= i & -i) s += bit[i]; return s; }
        long bitRange(int l, int r) { return bitSum(r) - bitSum(l - 1); }
        long pathSum(int u, int v) {
            long s = 0;
            while (head[u] != head[v]) {
                if (depth[head[u]] < depth[head[v]]) { int t = u; u = v; v = t; }
                s += bitRange(pos[head[u]], pos[u]);
                u = par[head[u]];
            }
            if (depth[u] > depth[v]) { int t = u; u = v; v = t; }
            s += bitRange(pos[u], pos[v]);
            return s;
        }
        public static void main(String[] args) {
            HldPathSum h = new HldPathSum(7);
            int[][] e = {{0,1},{0,2},{1,3},{1,4},{2,5},{2,6}};
            for (int[] x : e) h.add(x[0], x[1]);
            for (int i = 0; i < 7; i++) h.val[i] = i + 1;
            h.dfsSz(0, -1); h.dfsHld(0, 0);
            for (int i = 0; i < 7; i++) h.bitAdd(h.pos[i], h.val[i]);
            System.out.println(h.pathSum(4, 6));
        }
        // Input : same 7-node tree, values 1..7, query 5 to 7 (0-based 4,6)
        // Output: 18
    }

The query walk, isolated. Plug any range structure in for seg.query.

JavaHldTemplate.java
public class HldTemplate {
        static int[] head, par, depth, pos;
        static long queryRange(int l, int r) { return 0; } // segtree
        static long pathQuery(int u, int v) {
            long ans = 0;
            while (head[u] != head[v]) {
                if (depth[head[u]] < depth[head[v]]) { int t = u; u = v; v = t; }
                ans += queryRange(pos[head[u]], pos[u]);
                u = par[head[u]];
            }
            if (pos[u] > pos[v]) { int t = u; u = v; v = t; }
            ans += queryRange(pos[u], pos[v]);
            return ans;
        }
        public static void main(String[] args) {
            head = new int[] {0, 0, 2, 0, 4, 2, 6};
            par = new int[] {-1, 0, 0, 1, 1, 2, 2};
            depth = new int[] {0, 1, 1, 2, 2, 2, 2};
            pos = new int[] {0, 1, 4, 2, 3, 5, 6};
            System.out.println(pathQuery(4, 6));
        }
        // Input : heads/pos of the 7-node example
        // Output: 0
    }

Complexity

Time O(n) preprocess, O(log^2 n) per query Space O(n)

A light edge at least halves subtree size, so a node has O(log n) light ancestors. The query walk therefore processes O(log n) chains, each a segment-tree range of O(log n).

Tquery = O(log n) chains × O(log n) = O(log² n)

Edge cases and pitfalls

  • DFS does not prefer the heavy child
    Chains fragment; a "chain" is no longer a contiguous pos interval and every query is wrong.
    In the second DFS, recurse into heavy[u] before any light child, and pass the same head.
  • Forgetting to lift the deeper head
    Jumping the shallower pointer first walks off the LCA and double-counts or infinite-loops.
    Compare depth[head[u]] (not depth[u]) and always lift the deeper chain.
  • Off-by-one on the in-chain segment
    [pos[u], pos[v]) drops the LCA node, or includes it twice if both sides add it.
    After heads meet, query the closed interval between the two positions once.
  • 1-index vs 0-index mix
    Parent of the root becomes 0, Fenwick index 0 is unused, and bitAdd(pos[root], x) writes the wrong cell.
    Pick one convention. Fenwick wants 1-based indices: bitAdd(pos[u] + 1, x) if pos is 0-based.
  • Updating values after HLD without writing the tree
    You change val[u] but not the Fenwick / segment tree cell at pos[u].
    Point update is tree.update(pos[u], newValue). The original array is only the build source.

Interview follow-ups

Why is the bound O(log n) chains, not O(n)?

Each light edge moves to a subtree of size at most half. A walk toward the root therefore meets at most log n light edges, and each light edge is the only place a chain can change.

Can you get O(log n) instead of O(log^2 n)?

Yes for prefix-friendly operations (sum, XOR) with point updates: Fenwick on the HLD array is O(log n) per chain range, still O(log^2 n) total. True O(log n) path queries need a top tree or link-cut tree.

How do you handle edge weights?

Assign the edge (p, u) to node u. When the two pointers sit on the same chain, query (pos[lca], pos[deeper]] so the LCA node (which holds the parent edge) is excluded.

HLD versus centroid for "count pairs at distance k"?

HLD linearises paths; it does not enumerate pairs. Centroid decomposition solves through a separator in O(n log n). Use the tool that matches the query shape.

Recap

  • Heavy child = largest subtree; a light edge halves size.
  • Second DFS prefers the heavy child so a chain is contiguous.
  • Path query = O(log n) chain ranges, always lift the deeper head.
  • Subtree query is a single [pos, pos+sz) interval.
  • Edge weights live on the child; skip the LCA node.
