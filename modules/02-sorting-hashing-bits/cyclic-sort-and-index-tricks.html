Cyclic Sort & Index Tricks

When the array is a permutation of a known range, the value is the address: swap each number toward index value-1 until every cycle closes.

Medium 24 min read Prerequisites: Sorting & Comparators, Two Pointers cyclic sort permutation index as hash P1

Why this exists

You are given 100,000 seats labelled 1 through n, and each seat currently holds some ticket in that same range, possibly with one number missing and another duplicated. A hash set finds the hole in one pass but spends an extra 100,000 boxed integers of memory. A library sort plus a scan is about 1.7×10⁶ comparisons. You need neither: the number 7 belongs at index 6, so swap whatever sits at index 6 into its own home, and repeat. Every swap homes at least one value, so the whole cleanup is a few hundred thousand exchanges and constant extra memory.

Once the values sit at their addresses, the leftover mismatches are exactly the missing, duplicate, or disappeared numbers. That is why this is the native language of a whole interview cluster: missing number, first missing positive, find all duplicates, set mismatch. Interviewers like it because it looks like a magic trick until you say "the value is the index". The same idea without swaps is "index as a sign bit": negate a[|x|-1] to mark that x was seen, which still needs the array to be writable and the range to be 1..n.

When you cannot write the array at all, treat each index as a node with a single outgoing edge to a[i]. That picture is a functional graph — a graph where every node has out-degree one — and a duplicate value is a node with two incoming edges, which forces a cycle. Floyd's tortoise-and-hare walk finds the cycle entrance in linear time and constant extra memory. In a real statement the tell is n ≤ 10⁵ with values in a range of length n, plus "O(1) extra space" or "do not modify the input".

A permutation is a set of cycles on indices. Putting each value at its index is walking those cycles with swaps. What refuses to sit still is the duplicate already occupying a home, or the missing number whose slot is still holding leftover garbage.

Recognise this pattern

Say yes when you see

  • Array of length n, values in 1..n or 0..n, possibly with one duplicate / one missing
  • "Find all numbers that disappeared", "first missing positive"
  • "Find the duplicate without extra memory" (cycle in the functional graph)
  • You may mutate the array and O(1) extra space is required
  • "Place each number at index num-1" is a legal operation on the input

Not this pattern when

  • Arbitrary integers with a huge range → hash set or sort, not index placement
  • You must not mutate and you may use O(n) space → HashSet / boolean[]
  • The graph is a general directed graph, not a functional graph of outdegree 1 → DFS on a real graph, not cyclic sort
  • You need full sorted order of arbitrary keys → comparison sort

Constraint tell: n ≤ 10⁵ with values in a range of length n is the signature. First-missing-positive allows values outside 1..n: skip those, they cannot be placed. Floyd needs the array to encode a function on 1..n with no zeros.

Core idea and the invariant

Cyclic sort walks i from 0 to n-1. While a[i] is in range and is not already at home — home meaning a[i] == a[a[i]-1] would already hold, so the loop condition is the opposite — swap it into index a[i]-1. Each swap places at least one new value into its address, so the inner while runs at most n times across the whole array, not n times per index. Afterward, index i should hold i+1. Any break is the answer: the missing number is i+1, and the value sitting there may be the duplicate.

First missing positive uses the same placement after you treat anything ≤ 0 or > n as garbage that cannot occupy a slot. After the swaps, the first i with a[i] != i+1 is the answer; if every slot is home, the missing positive is n+1. When mutation is forbidden, interpret the array as next(i) = a[i] on values in 1..n, run Floyd's tortoise-and-hare until the two pointers meet, then reset one pointer to the start and walk both one step at a time: the meeting point is the cycle entrance, which is the duplicate.

Walk [3, 1, 4, 2, 5], a true permutation, to see the swaps. At i=0 the value 3 belongs at index 2, so swap: [4, 1, 3, 2, 5]. Still at i=0, 4 belongs at index 3: [2, 1, 3, 4, 5]. Then 2 belongs at index 1: [1, 2, 3, 4, 5]. Index 0 now holds 1, so the while stops, and the remaining slots are already home. On the broken input [3, 1, 3, 4, 2] the same process refuses to swap the first 3 because index 2 already holds 3; the later scan sees slot 0 still holding 3, so 1 is missing and 3 is the duplicate.

After the swaps, every in-range value x that appeared sits at index x-1, unless a duplicate already occupies that slot:

a[x-1] == x  for every x that could be placed uniquely

In plain words, the array has become its own address book: each number that has a unique home is sitting at that home, and anything still in the wrong seat is either garbage from outside 1..n or a second copy of a number whose seat was already taken.

Interview sentence: "The value is the address; I swap until every cycle of the permutation is rotated into place, then I read the holes."

Algorithm

  1. Confirm the range is length n (or 1..n after you ignore garbage). Cyclic sort is only legal when the value itself is a legal index, otherwise you are about to read off the end of the array.
  2. For each i, swap while the value is in range and not yet home. The test a[i] != a[a[i]-1] is what moves a number toward its address without needing a second array.
  3. Stop the while when home already holds this value. That is how you detect a duplicate: a second copy wants the same seat, and swapping again would loop forever.
  4. Scan i from 0 to n-1 after the swaps. If a[i] != i+1, then i+1 is missing and the value sitting there may be the duplicate.
  5. For first missing positive, skip anything ≤ 0 or > n. Those values cannot occupy a slot in 1..n; if every remaining slot is home, the answer is n+1.
  6. When you cannot mutate, run Floyd on f(x) = a[x]. Start at a[0] on a 1-based range stored in an array of length n+1, because index 0 is not a value in 1..n.
  7. Never index a[a[i]-1] without a range check. A 0 or a value past n turns that read into an out-of-bounds access, which is the most common crash on this page.

Java implementation

HashSet of seen values. Correct, O(n) extra, what cyclic sort avoids.

JavaCyclicBrute.java
import java.util.HashSet;
    import java.util.Set;
    
    public class CyclicBrute {
        static int firstMissingPositive(int[] a) {
            Set<Integer> s = new HashSet<>();
            for (int v : a) {
                if (v > 0) {
                    s.add(v);
                }
            }
            int x = 1;
            while (s.contains(x)) {
                x++;
            }
            return x;
        }
    
        public static void main(String[] args) {
            System.out.println(firstMissingPositive(new int[] {3, 4, -1, 1}));
            System.out.println(firstMissingPositive(new int[] {1, 2, 0}));
        }
        // Input : [3, 4, -1, 1] then [1, 2, 0]
        // Output: 2
        //         3
    }

Place each in-range value at index value-1, then read the first hole.

JavaCyclicSort.java
public class CyclicSort {
        static int firstMissingPositive(int[] a) {
            int n = a.length;
            for (int i = 0; i < n; i++) {
                while (a[i] >= 1 && a[i] <= n && a[a[i] - 1] != a[i]) {
                    swap(a, i, a[i] - 1);
                }
            }
            for (int i = 0; i < n; i++) {
                if (a[i] != i + 1) {
                    return i + 1;
                }
            }
            return n + 1;
        }
    
        static int findDuplicate(int[] a) {
            int n = a.length;
            for (int i = 0; i < n; i++) {
                while (a[i] >= 1 && a[i] <= n && a[a[i] - 1] != a[i]) {
                    swap(a, i, a[i] - 1);
                }
            }
            for (int i = 0; i < n; i++) {
                if (a[i] != i + 1) {
                    return a[i];
                }
            }
            return -1;
        }
    
        static void swap(int[] a, int i, int j) {
            int t = a[i];
            a[i] = a[j];
            a[j] = t;
        }
    
        public static void main(String[] args) {
            System.out.println(firstMissingPositive(new int[] {3, 4, -1, 1}));
            System.out.println(findDuplicate(new int[] {1, 3, 4, 2, 2}));
        }
        // Input : [3, 4, -1, 1] then [1, 3, 4, 2, 2]
        // Output: 2
        //         2
    }

Find the duplicate with Floyd when mutation is forbidden. Array is f(x)=a[x].

JavaFloydDup.java
public class FloydDup {
        static int findDuplicate(int[] a) {
            int slow = a[0];
            int fast = a[0];
            do {
                slow = a[slow];
                fast = a[a[fast]];
            } while (slow != fast);
            slow = a[0];
            while (slow != fast) {
                slow = a[slow];
                fast = a[fast];
            }
            return slow;
        }
    
        public static void main(String[] args) {
            System.out.println(findDuplicate(new int[] {1, 3, 4, 2, 2}));
            System.out.println(findDuplicate(new int[] {3, 1, 3, 4, 2}));
        }
        // Input : [1, 3, 4, 2, 2] then [3, 1, 3, 4, 2]
        // Output: 2
        //         3
    }

Complexity

Time O(n) amortised swaps + O(n) scan Space O(1) extra (Floyd also O(1); HashSet is O(n))

Each swap places at least one new value into its home, or proves a duplicate by finding that home already holds the same value. A value already home is never swapped again, so the inner while runs at most n times across the whole array: T(n) = Θ(n). At n = 10⁵ that is a few hundred thousand exchanges, versus 1.7×10⁶ comparisons for a full sort.

Floyd is the linked-list cycle proof on a functional graph of n+1 nodes and n+1 edges (index 0 unused as a value, values in 1..n). Two linear pointer walks find the meeting point and then the entrance, still O(n) time and O(1) extra memory, which is why it is the answer when mutation is forbidden and a hash set is not allowed.

Edge cases and pitfalls

  • Infinite swap on a duplicate
    while (a[i] != i+1) swap(i, a[i]-1) looks like it must make progress, but two copies of x both want index x-1 and the swap just exchanges them forever.
    Stop when a[a[i]-1] == a[i], i.e. home already holds this value. Test [3, 1, 3] and confirm the loop exits.
  • Placing 0 or n+1
    a[a[i]-1] with a[i] = 0 indexes -1, so first-missing-positive crashes on an input that is otherwise legal and well inside the time limit.
    Guard a[i] >= 1 && a[i] <= n before any home access, and treat everything outside that range as unplaceable garbage.
  • Floyd 0-based off-by-one
    Starting the tortoise at index 0 when 0 is not a node of f(x) = a[x] on a 1-based permutation follows a pointer that the graph does not contain.
    LC 287 stores values 1..n in an array of length n+1; start at a[0] and follow a[·], never treating 0 as a value.
  • Negate mark colliding with already-negative input
    LC 448 input is 1..n so negation is a safe seen-bit; LC 41 already contains negatives, so the same mark silently destroys real values.
    Cyclic-sort LC 41; do not negate unless you first sanitise every slot into 1..n or a known positive sentinel.
  • Returning n instead of n+1
    Array [1, 2, 3] as first missing positive has no hole inside, so returning n looks like "the scan found nothing" and is off by one.
    After a clean scan where every slot holds i+1, the missing positive is n+1. Include [1, 2, 3] → 4 as a unit test.

Interview follow-ups

Why is the inner while O(n) total, not O(n²)?

A swap that does not immediately home a[i] still homes the other slot, so each index becomes home at most once. Duplicates stop the loop via the a[home] == value guard, so there is no cycle of swaps among equals. Adding the outer n iterations of i still leaves a linear total.

Can you recover the original array after cyclic sort?

No, unless you stored the permutation yourself. The algorithm is in-place and destructive: after the swaps the original order is gone. If the caller needs the input, clone first — and then you already have O(n) extra memory, so a HashSet was the simpler honest answer.

Why does Floyd apply to finding a duplicate?

n+1 slots holding values in 1..n is a pigeonhole: the map x → a[x] has a node with two incoming edges (the duplicate). That node is the entrance of a cycle, exactly as in linked-list cycle II. The tortoise-and-hare meeting point is somewhere on that cycle; the second walk from the start finds the entrance.

First missing positive when n=1?

[1] returns 2 because the only slot is already home. [0] returns 1 because 0 is garbage and slot 0 is not 1. [2] also returns 1 because 2 is out of range for length 1. Always include these three unit tests; they catch both the n+1 fallback and the out-of-range skip.

Recap

  • Value is the address when the range is 1..n.
  • Guard the home index so duplicates do not infinite-loop.
  • Skip out-of-range values in first-missing-positive.
  • Floyd when you cannot mutate: cycle entrance is the duplicate.
  • After placement, scan holes: a[i] should equal i+1.
