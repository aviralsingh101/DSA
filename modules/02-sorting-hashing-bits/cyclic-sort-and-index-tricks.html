Cyclic Sort & Index Tricks

When the array is a permutation of a known range, the value is the address: swap each number toward index value-1 until every cycle closes.

Medium 20 min read Prerequisites: Sorting & Comparators, Two Pointers cyclic sort permutation index as hash P1

Why this exists

If every value lies in 1..n (or 0..n-1) and you are allowed to mutate, the array is its own hash table. The number x belongs at index x-1. Swapping along that rule sorts in linear time with O(1) extra memory, and the leftover mismatches are exactly the missing, duplicate, or disappeared numbers.

This is the native language of a whole LC cluster: missing number, first missing positive, find all duplicates, set mismatch, find the duplicate without modifying (Floyd on the functional graph). Interviewers like it because it looks like a magic trick until you say "the value is the index".

The same idea without swaps is "index as a sign bit": negate a[|x|-1] to mark that x was seen. It needs the array to be writable and the range to be 1..n. When you cannot write, the functional graph of i → a[i] still has a cycle you can find with Floyd.

A permutation is a set of cycles on indices. Putting each value at its index is walking those cycles with swaps. What refuses to sit still is the duplicate or the missing.

Recognise this pattern

Say yes when you see

  • Array of length n, values in 1..n or 0..n, possibly with one duplicate / one missing
  • "Find all numbers that disappeared", "first missing positive"
  • "Find the duplicate without extra memory" (cycle in the functional graph)
  • You may mutate the array and O(1) extra space is required
  • "Place each number at index num-1" is a legal operation on the input

Not this pattern when

  • Arbitrary integers with a huge range → hash set or sort, not index placement
  • You must not mutate and you may use O(n) space → HashSet / boolean[]
  • The graph is a general directed graph, not a functional graph of outdegree 1 → DFS on a real graph, not cyclic sort
  • You need full sorted order of arbitrary keys → comparison sort

Constraint tell: n ≤ 10⁵ with values in a range of length n is the signature. First-missing-positive allows values outside 1..n: skip those, they cannot be placed. Floyd needs the array to encode a function on 1..n with no zeros.

Core idea and the invariant

Cyclic sort: for i from 0 to n-1, while a[i] is in range and not already at home (a[i] != a[a[i]-1]), swap it there. Each swap homes at least one value, so the inner while is amortised O(n). Afterward, index i should hold i+1; any break is the answer.

First missing positive: treat anything ≤ 0 or > n as garbage that cannot occupy a slot. After placement, the first i with a[i] != i+1 is the answer; if none, the answer is n+1. Floyd for the duplicate: interpret the array as next(i) = a[i] (1-based), run tortoise and hare, then find the cycle entrance.

After the swaps, every in-range value x that appeared sits at index x-1, unless a duplicate already occupies that slot.

a[x-1] == x  for every x that could be placed uniquely

Interview sentence: "The value is the address; I swap until every cycle of the permutation is rotated into place, then I read the holes."

Algorithm

  1. Confirm the range is length n (or 1..n after ignoring garbage).
  2. For each i, while a[i] is in range and a[i] != a[a[i]-1], swap.
  3. Stop the while when a duplicate already sits at the home index, or the value is out of range.
  4. Scan i = 0..n-1. If a[i] != i+1, i+1 is missing and a[i] may be the duplicate.
  5. First missing positive: skip ≤ 0 and > n; if every slot is home, return n+1.
  6. No-mutate duplicate: Floyd tortoise/hare on f(x)=a[x] (careful with 0-based vs 1-based).
  7. Never use a[a[i]] without checking range, or you index out of bounds.

Java implementation

HashSet of seen values. Correct, O(n) extra, what cyclic sort avoids.

JavaCyclicBrute.java
import java.util.HashSet;
    import java.util.Set;
    
    public class CyclicBrute {
        static int firstMissingPositive(int[] a) {
            Set<Integer> s = new HashSet<>();
            for (int v : a) {
                if (v > 0) {
                    s.add(v);
                }
            }
            int x = 1;
            while (s.contains(x)) {
                x++;
            }
            return x;
        }
    
        public static void main(String[] args) {
            System.out.println(firstMissingPositive(new int[] {3, 4, -1, 1}));
            System.out.println(firstMissingPositive(new int[] {1, 2, 0}));
        }
        // Input : [3, 4, -1, 1] then [1, 2, 0]
        // Output: 2
        //         3
    }

Place each in-range value at index value-1, then read the first hole.

JavaCyclicSort.java
public class CyclicSort {
        static int firstMissingPositive(int[] a) {
            int n = a.length;
            for (int i = 0; i < n; i++) {
                while (a[i] >= 1 && a[i] <= n && a[a[i] - 1] != a[i]) {
                    swap(a, i, a[i] - 1);
                }
            }
            for (int i = 0; i < n; i++) {
                if (a[i] != i + 1) {
                    return i + 1;
                }
            }
            return n + 1;
        }
    
        static int findDuplicate(int[] a) {
            int n = a.length;
            for (int i = 0; i < n; i++) {
                while (a[i] >= 1 && a[i] <= n && a[a[i] - 1] != a[i]) {
                    swap(a, i, a[i] - 1);
                }
            }
            for (int i = 0; i < n; i++) {
                if (a[i] != i + 1) {
                    return a[i];
                }
            }
            return -1;
        }
    
        static void swap(int[] a, int i, int j) {
            int t = a[i];
            a[i] = a[j];
            a[j] = t;
        }
    
        public static void main(String[] args) {
            System.out.println(firstMissingPositive(new int[] {3, 4, -1, 1}));
            System.out.println(findDuplicate(new int[] {1, 3, 4, 2, 2}));
        }
        // Input : [3, 4, -1, 1] then [1, 3, 4, 2, 2]
        // Output: 2
        //         2
    }

Find the duplicate with Floyd when mutation is forbidden. Array is f(x)=a[x].

JavaFloydDup.java
public class FloydDup {
        static int findDuplicate(int[] a) {
            int slow = a[0];
            int fast = a[0];
            do {
                slow = a[slow];
                fast = a[a[fast]];
            } while (slow != fast);
            slow = a[0];
            while (slow != fast) {
                slow = a[slow];
                fast = a[fast];
            }
            return slow;
        }
    
        public static void main(String[] args) {
            System.out.println(findDuplicate(new int[] {1, 3, 4, 2, 2}));
            System.out.println(findDuplicate(new int[] {3, 1, 3, 4, 2}));
        }
        // Input : [1, 3, 4, 2, 2] then [3, 1, 3, 4, 2]
        // Output: 2
        //         3
    }

Complexity

Time O(n) amortised swaps + O(n) scan Space O(1) extra (Floyd also O(1); HashSet is O(n))

Each swap places at least one new value into its home (or proves a duplicate). A value already home is never swapped again, so the inner while runs ≤ n times across the whole array: T(n) = Θ(n).

Floyd is the linked-list cycle proof on a functional graph of n+1 nodes and n+1 edges (indices 0 unused, values 1..n). Two O(n) pointer walks.

Edge cases and pitfalls

  • Infinite swap on a duplicate
    while (a[i] != i+1) swap(i, a[i]-1) loops forever when two copies of x both want index x-1.
    Stop when a[a[i]-1] == a[i], i.e. home already holds this value.
  • Placing 0 or n+1
    a[a[i]-1] with a[i]=0 indexes -1. First missing positive must skip out-of-range values.
    Guard a[i] >= 1 && a[i] <= n before any home access.
  • Floyd 0-based off-by-one
    Starting at index 0 when 0 is not a node of f(x)=a[x] on a 1-based permutation.
    LC 287 stores values 1..n in an array of length n+1; start at a[0], follow a[·].
  • Negate mark colliding with already-negative input
    LC 448 input is 1..n so negation is safe; LC 41 has negatives already.
    Cyclic-sort LC 41; do not negate unless you first sanitise the range.
  • Returning n instead of n+1
    Array [1,2,3] as first missing positive should return 4, not a hole inside.
    After a clean scan, the missing is n+1.

Interview follow-ups

Why is the inner while O(n) total, not O(n²)?

A swap that does not immediately home a[i] still homes the other slot. Each index becomes home at most once. Duplicates stop the loop via the a[home]==value guard, so no cycle of swaps among equals.

Can you recover the original array after cyclic sort?

No, unless you stored the permutation. The algorithm is in-place destructive. If the caller needs the input, clone first (and then you have O(n) extra anyway, so a HashSet was simpler).

Why does Floyd apply to finding a duplicate?

n+1 slots holding values in 1..n is a pigeonhole: the map x → a[x] has a node with two incoming edges (the duplicate). That node is the entrance of a cycle. Same proof as linked-list cycle II.

First missing positive when n=1?

[1] → 2; [0] → 1; [2] → 1. The out-of-range 2 is ignored, slot 0 is not 1, answer 1. Always include these three unit tests.

Recap

  • Value is the address when the range is 1..n.
  • Guard the home index so duplicates do not infinite-loop.
  • Skip out-of-range values in first-missing-positive.
  • Floyd when you cannot mutate: cycle entrance is the duplicate.
  • After placement, scan holes: a[i] should equal i+1.
