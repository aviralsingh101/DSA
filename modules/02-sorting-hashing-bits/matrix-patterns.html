Matrix Patterns

A matrix is an array with 2D indexing: layers for rotate and spiral, in-place markers for set-zeroes, and a staircase walk when rows and columns are sorted.

Medium 24 min read Prerequisites: Two Pointers, Binary Search Basics matrix spiral rotate search 2D P0

Why this exists

You are handed a 400-by-400 grid of pixels and told to rotate it 90 degrees clockwise in place. Allocating a second 160,000-cell matrix and copying a[i][j] to b[j][n-1-i] is correct and costs 160,000 writes, but the statement forbids the extra memory. The in-place version does the same 160,000 writes without the second grid: swap across the diagonal (that is a transpose — rows become columns), then reverse each row. Four templates of that flavour — rotate, spiral, set-zeroes, staircase search — cover almost every interview matrix that is not a graph.

Index arithmetic is where people bleed time. Off-by-one on layers, walking off the right edge of a spiral, and using the first row as a marker then zeroing it too early are the classic bugs. Drawing the current layer and naming top, bottom, left, right removes them, because every index you write is then a function of those four numbers instead of a hard-coded n-1 inside a loop that also shrinks. A 400-by-400 spiral is 160,000 visits if you get the bounds right, and a handful of duplicates or misses if you do not.

When the matrix really is a graph — islands, unique paths with obstacles, word search — switch modules: BFS or DFS on the four neighbours. This page is the geometry of a dense grid you scan in a prescribed order, not the implicit graph. In a real statement the tell is n, m ≤ 400 plus "rotate in place", "spiral order", "set zeroes", or "search a sorted matrix". Those limits are permission to touch every cell a constant number of times and nothing heavier.

Name the bounds of the current layer, or the current staircase cell. Every index you write should be a function of those bounds, never a hard-coded n-1 inside a nested loop that also shrinks.

Core idea and the invariant

Rotate 90 degrees clockwise sends a[i][j] to a[j][n-1-i]. In place, first transpose by swapping a[i][j] with a[j][i] for every j > i, then reverse each row. Layers work too: cycle four cells around the current ring. Spiral uses the same rings without rotating: while top ≤ bottom and left ≤ right, walk right, down, left, up, and shrink the bound you just finished. After walking a side, check the bounds again so a single remaining middle row is not walked twice on the way back.

Set zeroes records which rows and columns contain a zero, then fills them. To stay in-place, row 0 and column 0 are the bitsets, plus one extra boolean because cell [0][0] belongs to both. The second pass zeroes the inner (n-1)×(m-1) first so those markers survive, then clears row 0 and column 0 last. Staircase search starts at the top-right of a matrix whose rows and columns are both sorted: if the cell is too big, move left; too small, move down. Each step discards a whole row or a whole column, so the walk is O(n + m).

Walk the 3-by-3 [[1,2,3],[4,5,6],[7,8,9]]. Transpose swaps 2 with 4, 3 with 7, and 6 with 8, leaving [[1,4,7],[2,5,8],[3,6,9]]. Reverse each row and you have [[7,4,1],[8,5,2],[9,6,3]], which is the 90-degree clockwise rotate. The same original, walked as a spiral, goes right 1,2,3, down 6,9, left 8,7, up 4, then the leftover centre 5. Searching for 6 in a row-and-column-sorted copy starts at the top-right 3, steps down to 6, and stops.

A layer with bounds top, bottom, left, right is processed exactly once, and the next layer is strictly inside:

top++, bottom--, left++, right--

In plain words, you walk the current rectangle's rim and then throw that rim away. The four numbers always describe a still-unvisited hole in the middle, so a cell is written or read once and never again.

Interview sentence: "I walk the current rectangle's perimeter, then I shrink all four bounds."

Which matrix template?

Algorithm

  1. Classify the question first. In-place geometry, search in a sorted grid, and a grid graph are three different templates; picking the wrong one wastes the whole attempt.
  2. Rotate clockwise by transposing, then reversing each row. The undo is the opposite pair (reverse rows, then transpose), which is how you check one cell by hand.
  3. Spiral keeps four bounds and shrinks after each side. Re-check top ≤ bottom before walking left, and left ≤ right before walking up, so a leftover middle row is not visited twice.
  4. Set zeroes in two passes. Mark on row 0 and column 0 first, zero the inner cells next, and only then clear the first row and column so the markers survive.
  5. For LC 74, treat the matrix as one sorted array of length n×m. Binary-search with mid = lo + (hi - lo) / 2 and map back to [mid / m][mid % m].
  6. For LC 240, start at the top-right cell. A value that is too big discards its column (move left); a value that is too small discards its row (move down).
  7. Border floods start from every border cell of the start state. Mark those cells safe with DFS or BFS, then flip the unmarked interior, which is why surrounded-regions is not a spiral walk.
  8. Never allocate an n-by-n extra grid if they said in-place. The first row and column, or a four-cell cycle, are the allowed extra memory.

Java implementation

Allocate a second matrix. Correct, O(n²) extra, the in-place version drops the copy.

JavaRotateBrute.java
import java.util.Arrays;
    
    public class RotateBrute {
        static int[][] rotate(int[][] a) {
            int n = a.length;
            int[][] b = new int[n][n];
            for (int i = 0; i < n; i++) {
                for (int j = 0; j < n; j++) {
                    b[j][n - 1 - i] = a[i][j];
                }
            }
            return b;
        }
    
        public static void main(String[] args) {
            int[][] a = {{1, 2, 3}, {4, 5, 6}, {7, 8, 9}};
            System.out.println(Arrays.deepToString(rotate(a)));
        }
        // Input : [[1,2,3],[4,5,6],[7,8,9]]
        // Output: [[7,4,1],[8,5,2],[9,6,3]]
    }

Rotate in place, spiral order, and staircase search.

JavaMatrixOps.java
import java.util.ArrayList;
    import java.util.Arrays;
    import java.util.List;
    
    public class MatrixOps {
        static void rotate(int[][] a) {
            int n = a.length;
            for (int i = 0; i < n; i++) {
                for (int j = i + 1; j < n; j++) {
                    int t = a[i][j];
                    a[i][j] = a[j][i];
                    a[j][i] = t;
                }
            }
            for (int i = 0; i < n; i++) {
                int l = 0, r = n - 1;
                while (l < r) {
                    int t = a[i][l];
                    a[i][l] = a[i][r];
                    a[i][r] = t;
                    l++;
                    r--;
                }
            }
        }
    
        static List<Integer> spiral(int[][] a) {
            int top = 0, bottom = a.length - 1;
            int left = 0, right = a[0].length - 1;
            List<Integer> out = new ArrayList<>();
            while (top <= bottom && left <= right) {
                for (int j = left; j <= right; j++) {
                    out.add(a[top][j]);
                }
                top++;
                for (int i = top; i <= bottom; i++) {
                    out.add(a[i][right]);
                }
                right--;
                if (top <= bottom) {
                    for (int j = right; j >= left; j--) {
                        out.add(a[bottom][j]);
                    }
                    bottom--;
                }
                if (left <= right) {
                    for (int i = bottom; i >= top; i--) {
                        out.add(a[i][left]);
                    }
                    left++;
                }
            }
            return out;
        }
    
        static boolean searchSorted(int[][] a, int t) {
            int i = 0, j = a[0].length - 1;
            while (i < a.length && j >= 0) {
                if (a[i][j] == t) {
                    return true;
                }
                if (a[i][j] > t) {
                    j--;
                } else {
                    i++;
                }
            }
            return false;
        }
    
        public static void main(String[] args) {
            int[][] a = {{1, 2, 3}, {4, 5, 6}, {7, 8, 9}};
            System.out.println(spiral(a));
            rotate(a);
            System.out.println(Arrays.deepToString(a));
            System.out.println(searchSorted(new int[][] {{1, 4, 7}, {2, 5, 8}, {3, 6, 9}}, 6));
        }
        // Input : spiral then rotate [[1,2,3],[4,5,6],[7,8,9]]; search 6
        // Output: [1, 2, 3, 6, 9, 8, 7, 4, 5]
        //         [[7, 4, 1], [8, 5, 2], [9, 6, 3]]
        //         true
    }

First row and first column as markers. Extra boolean for a[0][0].

JavaSetZeroes.java
import java.util.Arrays;
    
    public class SetZeroes {
        static void setZeroes(int[][] a) {
            int n = a.length, m = a[0].length;
            boolean firstCol = false;
            for (int i = 0; i < n; i++) {
                if (a[i][0] == 0) {
                    firstCol = true;
                }
                for (int j = 1; j < m; j++) {
                    if (a[i][j] == 0) {
                        a[i][0] = 0;
                        a[0][j] = 0;
                    }
                }
            }
            for (int i = 1; i < n; i++) {
                for (int j = 1; j < m; j++) {
                    if (a[i][0] == 0 || a[0][j] == 0) {
                        a[i][j] = 0;
                    }
                }
            }
            if (a[0][0] == 0) {
                Arrays.fill(a[0], 0);
            }
            if (firstCol) {
                for (int i = 0; i < n; i++) {
                    a[i][0] = 0;
                }
            }
        }
    
        public static void main(String[] args) {
            int[][] a = {{1, 1, 1}, {1, 0, 1}, {1, 1, 1}};
            setZeroes(a);
            System.out.println(Arrays.deepToString(a));
        }
        // Input : [[1,1,1],[1,0,1],[1,1,1]]
        // Output: [[1, 0, 1], [0, 0, 0], [1, 0, 1]]
    }

Complexity

Time O(n m) to touch every cell; staircase search O(n + m) Space O(1) extra for in-place rotate / set-zero; O(n m) for spiral output

Rotate, spiral, and set-zeroes each visit every cell a constant number of times: T = Θ(n m). At 400-by-400 that is 160,000 visits, comfortably under a second. Extra memory is the output list (spiral) or the O(1) markers (rotate, set-zeroes).

Staircase search discards a row or a column per step, so it takes at most n+m steps — 800 on a 400-by-400 grid, not 160,000. LC 74 binary search is O(log(n m)) comparisons on a virtual 1D array, about 18 probes when n and m are 400.

Edge cases and pitfalls

  • Spiral walking a row twice
    After shrinking top, the left-going pass re-reads the same single remaining row, so a 1-by-n matrix prints every cell twice and the answer looks almost right.
    Guard with if (top ≤ bottom) before walking left, and if (left ≤ right) before walking up.
  • Zeroing markers too early
    Clearing row 0 in the first inner pass wipes the column-marker bits, so later columns that should have stayed non-zero get cleared (or the reverse).
    Zero the inner (n-1)×(m-1) first, then row 0, then column 0, so the sentinels survive until they have been read.
  • mid overflow when flattening LC 74
    int mid = (lo + hi) / 2 looks like ordinary binary search, but lo + hi can overflow a 32-bit int when n×m is large.
    Always write int mid = lo + (hi - lo) / 2; and map back with mid / m and mid % m.
  • Staircase starting at bottom-right
    From the bottom-right both legal steps increase the value, so you cannot discard a row or a column and the walk has nowhere useful to go.
    Start at top-right or bottom-left, where one step decreases the value and the other increases it.
  • Transpose of a non-square
    In-place swap of a[i][j] with a[j][i] is only legal on a square; on an n-by-m rectangle those indices do not even exist.
    Allocate a fresh m-by-n array for a rectangular transpose, and treat rotate as square-only (LC 48 is square).

Interview follow-ups

Rotate anti-clockwise in place?

Transpose, then reverse each column (or reverse the rows first, then transpose). The mapping is a[i][j] → a[n-1-j][i]; check one corner cell by hand so you do not mix the clockwise and counter-clockwise pair. The four-cycle version just walks the opposite permutation of the same four cells.

Can staircase search be binary search?

You can binary-search each row in O(n log m). That is worse than O(n + m) when n and m are close, and better when one dimension is tiny (a 1-by-m row is just a binary search). LC 240 wants the staircase because both dimensions are large and only rows-and-columns-sorted, not concatenated.

Set zeroes without using the first row as a marker?

Two boolean arrays of size n and m are O(n+m) extra and much simpler to get right. The O(1) first-row / first-column version is only required when they insist on constant extra memory. Mention both in an interview and implement the one they ask for.

Spiral on a jagged / empty matrix?

Guard m = 0 before you read a[0].length. A 1-by-n row is only the rightward pass; the reverse passes must be skipped by the top ≤ bottom and left ≤ right checks, otherwise you walk the same row backwards and duplicate every single value.

Recap

  • Rotate = transpose + reverse rows.
  • Spiral = four bounds; re-check before reverse sides.
  • Set zero = first row/col as markers, inner first.
  • LC 74 is 1D binary search; LC 240 is a staircase.
  • Islands / surrounded flood from the border, then flip the rest.
