Non-Comparison Sorts

When keys live in a small universe, you can sort in linear time by counting, bucketing, or peeling digits — the Ω(n log n) barrier only applies to comparison sorts.

Medium 20 min read Prerequisites: Sorting & Comparators, Constraints → Complexity counting sort radix sort bucket sort P1

Why this exists

The information-theoretic lower bound of n log n assumes the only question you can ask is "is A less than B?". If you can index an array by the key itself, you can tally frequencies in O(n + R) and write the output in order. That is counting sort, and it is the right tool whenever R is on the order of n or a small constant (0/1/2, grades, ages, colours).

Radix sort is counting sort applied to one digit at a time, LSD or MSD. It turns a huge numeric range into w passes of a tiny range (base 10 or 2⁸). Bucket sort assumes a known distribution, scatters into n buckets, and sorts each; maximum-gap (LC 164) is the pigeonhole form of the same idea.

In interviews this family shows up as Dutch national flag (three colours), "sort an array of 0s and 1s", H-index with citations in 0..n, and maximum gap. Contests use counting as soon as values are coordinates you can compress, or as a histogram of a small alphabet.

Comparison sorts are optimal among comparison sorts. If the key is an integer in a small range, index by it. Linear time is then a histogram plus a prefix of counts.

Recognise this pattern

Say yes when you see

  • Keys are integers in 0..R with R = O(n) or a tiny constant
  • "Sort colours / 0s, 1s, 2s" — Dutch national flag, a 3-way partition
  • H-index, or any "how many values ≥ x" where x is in 0..n
  • Maximum gap after sorting, when n is large but a comparison sort is still allowed to feel too slow conceptually — bucket / pigeonhole
  • Fixed-width integers (32-bit) and you want guaranteed O(n) with a few passes

Not this pattern when

  • Arbitrary comparable objects with no integer key → comparison sort
  • Range is 10⁹ and you only have n = 10⁵ → sort the n values, or compress then count
  • You need the k-th element, not the full order → quickselect
  • Keys are floats with no distribution promise → comparison sort; buckets can be empty or overloaded

Core idea and the invariant

Counting sort: allocate cnt[R], increment cnt[a[i]], then either emit v repeated cnt[v] times (not stable in that form) or turn counts into starting positions with a prefix sum and scatter the original elements into an output array (stable). Stability matters when the payload is a pair and you are inside radix sort.

Dutch national flag is counting sort specialised to R = 3 in-place: pointers lo, mid, hi. a[mid] == 0 swaps with lo++; == 2 swaps with hi--; == 1 just mid++. Radix LSD applies stable counting to each digit from least significant, so the previous digit's order is preserved.

After counting, cnt[v] is how many keys equal v, and the prefix pos[v] = cnt[0]+…+cnt[v-1] is the first output index for v.

output[pos[a[i]]++] = a[i]

Interview sentence: "I index by the key instead of comparing keys, so the sort is a histogram plus a scatter."

Which linear sort?

Algorithm

  1. Read the range. If keys are not integers in a small universe, stop.
  2. R ≤ 3: Dutch national flag, in-place, one pass.
  3. R = O(n): int[] cnt = new int[R], tally, then emit or scatter.
  4. Stable scatter: prefix of counts → starting index; walk the input left-to-right or right-to-left as required.
  5. Radix LSD: for each digit from least significant, stable-count on that digit.
  6. Buckets / max gap: n-1 buckets over [min,max]; the max gap is not inside a bucket.
  7. Negatives: shift by min, or radix on unsigned bit patterns.

Java implementation

Library sort is correct and simpler. Use it unless R is tiny or they ask for linear.

JavaCountBrute.java
import java.util.Arrays;
    
    public class CountBrute {
        static int[] sort(int[] a) {
            int[] b = a.clone();
            Arrays.sort(b);
            return b;
        }
    
        public static void main(String[] args) {
            System.out.println(Arrays.toString(sort(new int[] {2, 0, 2, 1, 1, 0})));
        }
        // Input : [2, 0, 2, 1, 1, 0]
        // Output: [0, 0, 1, 1, 2, 2]
    }

Three-way partition and counting sort on a general small range.

JavaDutchFlag.java
import java.util.Arrays;
    
    public class DutchFlag {
        static void sortColors(int[] a) {
            int lo = 0, mid = 0, hi = a.length - 1;
            while (mid <= hi) {
                if (a[mid] == 0) {
                    swap(a, lo++, mid++);
                } else if (a[mid] == 2) {
                    swap(a, mid, hi--);
                } else {
                    mid++;
                }
            }
        }
    
        static int[] countingSort(int[] a, int r) {
            int[] cnt = new int[r];
            for (int v : a) {
                cnt[v]++;
            }
            int[] out = new int[a.length];
            int k = 0;
            for (int v = 0; v < r; v++) {
                for (int c = 0; c < cnt[v]; c++) {
                    out[k++] = v;
                }
            }
            return out;
        }
    
        static void swap(int[] a, int i, int j) {
            int t = a[i];
            a[i] = a[j];
            a[j] = t;
        }
    
        public static void main(String[] args) {
            int[] a = {2, 0, 2, 1, 1, 0};
            sortColors(a);
            System.out.println(Arrays.toString(a));
            System.out.println(Arrays.toString(countingSort(new int[] {2, 0, 2, 1, 1, 0}, 3)));
        }
        // Input : [2, 0, 2, 1, 1, 0]
        // Output: [0, 0, 1, 1, 2, 2]
        //         [0, 0, 1, 1, 2, 2]
    }

Stable LSD radix on non-negative ints, base 256, four passes.

JavaRadixLsd.java
import java.util.Arrays;
    
    public class RadixLsd {
        static void radixSort(int[] a) {
            int n = a.length;
            int[] tmp = new int[n];
            for (int shift = 0; shift < 32; shift += 8) {
                int[] cnt = new int[256];
                for (int v : a) {
                    cnt[(v >>> shift) & 255]++;
                }
                int[] pos = new int[256];
                for (int i = 1; i < 256; i++) {
                    pos[i] = pos[i - 1] + cnt[i - 1];
                }
                for (int v : a) {
                    int d = (v >>> shift) & 255;
                    tmp[pos[d]++] = v;
                }
                int[] swap = a;
                a = tmp;
                tmp = swap;
            }
        }
    
        public static void main(String[] args) {
            int[] a = {170, 45, 75, 90, 802, 24, 2, 66};
            radixSort(a);
            System.out.println(Arrays.toString(a));
        }
        // Input : [170, 45, 75, 90, 802, 24, 2, 66]
        // Output: [2, 24, 45, 66, 75, 90, 170, 802]
    }

Complexity

Time Counting O(n + R); radix O(n · w); DNF O(n) Space O(n + R) for stable counting; O(1) extra for DNF

Counting: one tally pass and one emit/scatter pass over n items plus R buckets: T(n,R) = Θ(n + R). Memory is the same order.

LSD radix with digit width w (e.g. 4 bytes): T(n) = Θ(w(n + B)) with B = 256. That is linear in n for fixed-width ints. DNF is one pass, three pointers, no extra histogram.

Edge cases and pitfalls

  • Indexing cnt[a[i]] on a negative key
    ArrayIndexOutOfBoundsException or a huge R if you shift wrong.
    Subtract min first, or radix on unsigned bits (>>>).
  • Incrementing mid after swapping a 2
    The value swapped in from hi has not been inspected. You skip a 0.
    On a 2: swap with hi and do not increment mid. On a 0: increment both.
  • Unstable counting inside radix
    Emitting by walking v = 0..R destroys the previous digit's order.
    Scatter via prefix positions, walking the input in a consistent direction.
  • R = 1e9 with n = 1e5
    new int[1_000_000_000] is a memory error, not a linear sort.
    Coordinate-compress, or comparison-sort the n values.
  • Max-gap putting n values into n buckets of width (max-min)/n
    The max adjacent gap in the sorted array can sit inside a bucket if you use n buckets carelessly, or you divide by zero when max==min.
    Use n-1 buckets over the exclusive range, handle max==min, scan adjacent non-empty buckets.

Interview follow-ups

Why does radix need a stable inner sort?

After sorting on digit k, items with the same digit k must keep their order from digits 0..k-1. An unstable inner sort reshuffles those, and the higher-digit pass cannot recover it. Counting-with-scatter is stable; dual-pivot quicksort is not.

Can counting sort be in-place?

The histogram is extra R memory. You can cycle-swap into place using the prefix positions, but it is not worth it in an interview. DNF is the in-place special case for R=3.

How do you handle 32-bit negatives in radix?

XOR with 1<<31 to flip the sign bit so negatives come first as unsigned, sort, then flip back. Or shift by subtracting Integer.MIN_VALUE as long.

When is counting slower than Arrays.sort?

When R is millions and n is thousands: you touch a huge cold array. Constants matter. Rule of thumb: counting wins when R is a small multiple of n and the array fits in cache.

Recap

  • Small integer range → histogram, not comparisons.
  • R=3 → Dutch flag, do not increment mid on a swap with hi.
  • Radix LSD needs a stable inner counting scatter.
  • R ≫ n → compress or comparison-sort; do not allocate R.
  • Max gap is pigeonhole: the big empty space is between buckets.
