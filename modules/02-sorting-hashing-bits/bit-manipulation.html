Bit Manipulation

Bits are a 32- or 64-slot boolean array that hardware already ANDs, ORs and XORs in one cycle — subset enumeration, parity, and "every bit independently" all live here.

Medium 26 min read Prerequisites: Complexity Analysis, Java for DSA bits XOR bitmask popcount P0

Why this exists

You are given 100,000 integers in which every value appears twice except one, and you must print the loner. A hash map of counts is correct and uses 100,000 extra boxed entries. XOR — the bit-wise exclusive-or, written ^, which is 1 exactly when the two bits differ — finishes the same job with one accumulator and 100,000 word operations. Take 13, which is 1101 in binary. 13 ^ 13 is 0000 because every bit cancelled; 13 ^ 0 is still 13; 13 ^ 6 (6 is 0110) is 1011, which is 11. Pairs cancel, the unique value remains.

The same 32 bits are also a tiny set. A shift slides those bits: 13 << 1 is 11010 = 26 (multiply by two); 13 >> 1 is 0110 = 6 (divide by two, rounding toward negative infinity on signed ints). A mask is a number you AND with to keep only some bits: 13 & (1 << 2) is 1101 & 0100 = 0100, so bit 2 of 13 is on. When n is at most 20, the integers 0 through (1 << n) - 1 are every subset of n items — about a million masks, each tested in a handful of bit operations, which is why "enumerate every subset" is legal at that limit and hopeless at n = 30.

Java stores negatives in two's complement: to negate 13, flip every bit of 00001101 to 11110010 and add one, getting 11110011, which is -13. That is why 13 & -13 equals 1, the lowest set bit, and why >> sign-extends (fills new bits with 1 on a negative) while >>> fills with 0. Shifting an int by 32 is masked to 5 bits, so 1 << 32 is 1, not 0. In a real statement the tell is "every element appears twice except one", "power of two", or n ≤ 20 plus "every subset".

Treat the integer as a set of bit positions. XOR toggles membership, AND keeps the intersection, OR takes the union, and mask ^ (1 << i) flips element i. Most bit problems are set problems wearing an integer costume.

Recognise this pattern

Say yes when you see

  • "Every number appears twice except one" / "appears three times except one"
  • "Count set bits", "power of two", "range AND / OR"
  • n ≤ 20 and "every subset" — iterate masks 0..(1<<n)-1
  • "Maximum XOR of two numbers", "XOR of a subarray" (prefix XOR)
  • Need to pack several flags into one int (visited subsets, Game of Life states)

Not this pattern when

  • Arbitrary-precision bitsets of size n=1e5 → BitSet or a long[], plus a Fenwick/seg-tree if you need prefixes
  • Maximum XOR of a subarray with n=1e5 → a binary XOR trie, not a nested mask loop
  • Subset sums with n=40 → meet in the middle, not 2^40
  • Just need popcount of one number once → Integer.bitCount, stop

Core idea and the invariant

An XOR fold is a running accumulator that starts at 0 and XORs every element in. Because x ^ x = 0 and XOR does not care about order, every pair vanishes and the unique value remains. For values that appear three times, count each of the 32 bits modulo 3 instead. A power of two has exactly one bit set, so x > 0 && (x & (x - 1)) == 0: subtracting one turns the trailing zeros of x into ones and the lowest one into a zero, and AND with x is then empty. The same identity, written x &= x - 1, turns off the lowest set bit and is the kernel of Kernighan's popcount (count how many times you can do that before x is 0).

A mask is an integer whose bit i is on exactly when element i is in the subset. The loop for (int m = 0; m < (1 << n); m++) therefore visits every subset when n is at most 20, and (m & (1 << i)) != 0 tests membership. Submasks of a particular m walk with s = (s - 1) & m. Prefix XOR is the same identity as prefix sums: the XOR of a[l..r] is px[r+1] ^ px[l]. In Java prefer Integer.bitCount, Integer.numberOfTrailingZeros and Integer.highestOneBit over a hand-rolled loop unless you are teaching the loop.

Walk the XOR fold on [4, 1, 2, 1, 2], writing bits of the accumulator. Start at 0. XOR 4 (100) gives 100. XOR 1 (001) gives 101 = 5. XOR 2 (010) gives 111 = 7. XOR the second 1: 111 ^ 001 = 110 = 6, and the first 1 has cancelled. XOR the second 2: 110 ^ 010 = 100 = 4, and both pairs are gone. The same 13 from the opening: 13 & -13 is 1 because two's complement -13 is ...11110011, AND keeps only the shared lowest one, and two iterations of x &= x - 1 on 12 (1100) walk 12 → 8 → 0, so popcount is 2.

XOR is its own inverse and is associative:

x ⊕ x = 0,  x ⊕ 0 = x,  (a⊕b⊕c) ⊕ b = a⊕c

In plain words, XOR is a toggle: hitting a bit twice turns it back off, so every even count of a value disappears and only the odd leftover remains. A mask is the same idea pointed at positions: bit i on means "i is in the set", and AND / OR / XOR become intersect / union / toggle on that set.

Interview sentence: "Pairs cancel under XOR; a mask is a subset of bit positions."

Which bit tool?

Algorithm

  1. XOR-fold when pairs, or any even count, should vanish. One accumulator replaces a hash map of counts because x ^ x = 0 cancels every repeat.
  2. Use x & (x - 1) to drop the lowest set bit. Looping that until x is 0 is Kernighan popcount, and one shot of it is the power-of-two test.
  3. Use x & -x to isolate the lowest set bit. Two's complement makes -x share only that one bit with x, which is also the Fenwick "next bucket" step.
  4. Enumerate masks with for (int m = 0; m < (1 << n); m++) when n is at most 20. Use 1L << i for i up to 62 so the shift does not wrap on an int.
  5. Walk submasks of m with s = (s - 1) & m. Each step turns off some bits of m without ever leaving the subset, which is why the inner SOS loop is 3^n rather than 4^n.
  6. Build a prefix XOR array for subarray queries. The range a[l..r] is then one operation, px[r+1] ^ px[l], the same identity as prefix sums with XOR in place of plus.
  7. In Java, use >>> for logical shifts and never 1 << 32 on an int. The shift count is masked to 5 bits, so that expression is 1, and arithmetic >> keeps the sign bit.

Java implementation

Count the unique element with a map. XOR drops the extra memory.

JavaBitBrute.java
import java.util.HashMap;
    import java.util.Map;
    
    public class BitBrute {
        static int singleNumber(int[] a) {
            Map<Integer, Integer> c = new HashMap<>();
            for (int v : a) {
                c.merge(v, 1, Integer::sum);
            }
            for (var e : c.entrySet()) {
                if (e.getValue() == 1) {
                    return e.getKey();
                }
            }
            return 0;
        }
    
        public static void main(String[] args) {
            System.out.println(singleNumber(new int[] {4, 1, 2, 1, 2}));
        }
        // Input : [4, 1, 2, 1, 2]
        // Output: 4
    }

XOR fold, power-of-two, Kernighan popcount, and prefix XOR.

JavaBitOps.java
import java.util.Arrays;
    
    public class BitOps {
        static int singleNumber(int[] a) {
            int x = 0;
            for (int v : a) {
                x ^= v;
            }
            return x;
        }
    
        static boolean isPowerOfTwo(int x) {
            return x > 0 && (x & (x - 1)) == 0;
        }
    
        static int popcount(int x) {
            int c = 0;
            while (x != 0) {
                x &= x - 1;
                c++;
            }
            return c;
        }
    
        static int[] prefixXor(int[] a) {
            int n = a.length;
            int[] p = new int[n + 1];
            for (int i = 0; i < n; i++) {
                p[i + 1] = p[i] ^ a[i];
            }
            return p;
        }
    
        public static void main(String[] args) {
            System.out.println(singleNumber(new int[] {4, 1, 2, 1, 2}));
            System.out.println(isPowerOfTwo(8) + " " + isPowerOfTwo(7));
            System.out.println(popcount(12));
            System.out.println(Arrays.toString(prefixXor(new int[] {1, 2, 3})));
        }
        // Input : [4,1,2,1,2]; 8 and 7; popcount 12; prefix XOR [1,2,3]
        // Output: 4
        //         true false
        //         2
        //         [0, 1, 3, 0]
    }

Enumerate subsets as masks. Sum of each subset stored in a long.

JavaBitmaskSubsets.java
import java.util.ArrayList;
    import java.util.List;
    
    public class BitmaskSubsets {
        static List<Long> subsetSums(int[] a) {
            int n = a.length;
            List<Long> out = new ArrayList<>();
            for (int mask = 0; mask < (1 << n); mask++) {
                long s = 0;
                for (int i = 0; i < n; i++) {
                    if ((mask & (1 << i)) != 0) {
                        s += a[i];
                    }
                }
                out.add(s);
            }
            return out;
        }
    
        /** Number of (mask, submask) pairs is 3^n. Includes the empty submask. */
        static long countSubmasks(int n) {
            long cnt = 0;
            for (int mask = 0; mask < (1 << n); mask++) {
                for (int sub = mask; ; sub = (sub - 1) & mask) {
                    cnt++;
                    if (sub == 0) break;
                }
            }
            return cnt;
        }
    
        public static void main(String[] args) {
            System.out.println(subsetSums(new int[] {1, 2, 4}));
            System.out.println(countSubmasks(3));
        }
        // Input : subset sums of [1, 2, 4]; submasks of n = 3
        // Output: [0, 1, 2, 3, 4, 5, 6, 7]
        //         27
    }

Complexity

Time XOR fold O(n); popcount O(set bits); subset enum O(2^n · n) Space O(1) for folds; O(2^n) if you store every subset sum

XOR, AND or OR of n integers is one pass: Θ(n) word operations. At n = 10⁵ that is 100,000 XORs, versus a hash map of 100,000 boxed counts. Kernighan popcount is proportional to the number of set bits, at most 32 per int, so it is constant for interview purposes.

Subset enumeration tries 2^n masks and n bit tests each: T(n) = Θ(n 2^n). At n=20 that is about 21 million bit tests, fine in Java; at n=25 it is 800 million and already tight. Submask enumeration of one mask with popcount p is 2^p, and summing over all masks is 3^n, which is why SOS inner loops stop around n=15.

Edge cases and pitfalls

  • 1 << 31 and 1 << 32 on int
    1 << 31 is Integer.MIN_VALUE (negative), and 1 << 32 is 1 because Java masks the shift count to 5 bits, so a loop bound you thought was 0 wraps back to 1.
    Write 1L << k for k up to 62, and never shift an int by 32 or more.
  • Arithmetic >> on a sign bit
    -1 >> 1 stays -1 because arithmetic shift copies the sign bit, so a bit-pattern you meant to halve stays all ones.
    Use >>> whenever you want zeros shifted in. Java has no unsigned int type, so the operator is the only unsigned shift you get.
  • x & (x-1) on x=0
    A power-of-two test without x > 0 accepts 0 (and any negative), because 0 & -1 is 0 and looks like "exactly one bit".
    Write x > 0 && (x & (x - 1)) == 0, and unit-test 0, 1, 2 and -8.
  • XOR of a subarray without a prefix
    Recomputing XOR(l..r) in O(r-l) per query looks like a one-liner and dies at n, q = 1e5, which is 5×10⁹ XORs in the worst case.
    Build a prefix XOR array once, then answer each query as p[r+1] ^ p[l] in one operation.
  • Mask loop with n=31 on int
    1 << n as the loop bound overflows a signed int: 2^31 is negative, so the loop either never runs or runs forever.
    Keep n at most 30 for int masks, or switch to 1L << n and a long loop variable.

Interview follow-ups

Two unique numbers, everything else twice?

XOR everything to get a^b. Those two numbers differ in at least one bit, and the lowest set bit of a^b names one such bit. Partition the array into "that bit on" and "that bit off" and XOR-fold each part: each part still has even counts of the paired values and exactly one unique, which is LC 260.

Why is n & -n the lowest set bit?

Two's complement defines -n as ~n+1. Adding one flips every trailing 1 of ~n into a 0 and the first 0 into a 1, which is exactly the lowest set bit of n. AND with n then keeps only that shared one. On 13 that is 1101 & ...0011 = 0001.

Enumerate only submasks of m, not all 2^n?

Write for (int s = m; s != 0; s = (s - 1) & m) and handle s=0 as a last step. Each iteration turns off some bits without ever leaving m, so you visit exactly the 2^{popcount(m)} submasks. Over all pairs (mask, submask) that is 3^n, the inner loop of SOS DP.

Maximum XOR pair in O(n)?

Not with a mask loop: n=1e5 cannot afford 2^32. Build a binary trie of the numbers (or of prefix XORs, if the question is a subarray) and, for each value, greedy-walk the opposite bit at every depth. That is O(32 n) and lives on the XOR trie page.

Recap

  • XOR cancels pairs; prefix XOR is the subarray identity.
  • x & (x-1) drops the lowest set bit; x & -x isolates it.
  • A mask is a subset; n ≤ 20 enumerates 2^n.
  • Use 1L << k and >>> for bit patterns.
  • Integer.bitCount exists; do not roll it unless teaching.
