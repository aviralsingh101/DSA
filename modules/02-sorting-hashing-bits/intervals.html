Intervals

Sort intervals by start (or by end), then a linear scan merges, punches holes, or counts how many overlap a point — the geometry is one-dimensional.

Medium 22 min read Prerequisites: Sorting & Comparators, Two Pointers intervals sweep merge greedy P0

Why this exists

An interval is a pair [l, r]. Naive "compare every pair" is O(n²) and dies at n = 10⁵. After sorting by start, overlaps are contiguous: if the current interval does not touch the previous merged end, nothing later with a larger start will touch it either. That single observation is merge intervals, insert interval, and coverage.

The other sort, by end, is the greedy for "how many can I keep if they must not overlap": always keep the one that finishes first. Meeting rooms, arrows bursting balloons, and non-overlapping removal are the same proof with a flipped sign.

Sweep-line is the same idea with an explicit event queue: +1 at l, −1 at r, walk left to right, and the running sum is how many intervals cover this point. That answers "maximum concurrent meetings" without building the merged list.

In one dimension, sorting turns geometry into adjacency. After the sort, every decision looks at the current interval and a single running endpoint (or a running count).

Recognise this pattern

Say yes when you see

  • "Merge overlapping intervals", "insert an interval into a sorted list"
  • "Minimum arrows / meetings / rooms" — concurrent overlap or greedy keep-by-end
  • "Employee free time", "covered points", "range module" as a list of disjoint intervals
  • A set of segments on a line; queries about union length or maximum overlap
  • "Can you attend all meetings?" — sort by start, check adjacent overlap

Not this pattern when

  • 2D rectangles with both axes mattering → sweep + a tree on the other axis, not this page
  • Intervals that you must update online as a balanced tree of ranges → TreeMap or a segment tree
  • Circular intervals on a clock without a cut → duplicate the array or pick a cut point
  • Graph intervals as edges of a constraint graph → 2-SAT / difference constraints

Constraint tell: n ≤ 10⁵ intervals forces O(n log n) sort plus a linear scan. Coordinates up to 10⁹ need long for union length. Inclusive vs exclusive ends is a spec question: check whether [1,2] and [2,3] overlap.

Core idea and the invariant

Merge: sort by start. Keep a running [curL, curR]. If the next start is ≤ curR (or < if ends are exclusive), extend curR = max(curR, nextR); else emit cur and start a new one. The sort is what makes "next" the only candidate that can overlap.

Non-overlap greedy: sort by end. Keep the interval that finishes first; skip anything that starts before that end. Proof: any kept set can replace its last interval with this earlier finish without losing feasibility, so the greedy stays ahead. Sweep for rooms: emit start events before end events at a tied time if a meeting can reuse a room that just freed (depends on the statement).

After sorting by start, a single running end curR satisfies:

every emitted interval is disjoint from the later ones, and curR is the max end of the open merge

Interview sentence: "I sort so overlaps become adjacent, then I only track one running endpoint."

Which interval sort?

Algorithm

  1. Decide inclusive vs exclusive ends. It changes ≤ vs <.
  2. Union / merge: sort by start, extend a running end, emit when a gap appears.
  3. Max non-overlapping: sort by end, take if start ≥ lastEnd.
  4. Rooms / concurrent: events +1/−1, sort by time, max the running sum.
  5. Two lists of disjoint intervals: two pointers; advance the earlier end.
  6. Insert: copy strictly-before, merge all that overlap the new one, copy after.
  7. Use long for union length: ends up to 1e9, n up to 1e5.

Java implementation

Pairwise overlap checks. Correct, quadratic, only for n ≤ 2000.

JavaIntervalBrute.java
public class IntervalBrute {
        static boolean anyOverlap(int[][] a) {
            int n = a.length;
            for (int i = 0; i < n; i++) {
                for (int j = i + 1; j < n; j++) {
                    if (a[i][0] <= a[j][1] && a[j][0] <= a[i][1]) {
                        return true;
                    }
                }
            }
            return false;
        }
    
        public static void main(String[] args) {
            int[][] a = {{1, 3}, {2, 6}, {8, 10}};
            System.out.println(anyOverlap(a));
        }
        // Input : [1,3], [2,6], [8,10]
        // Output: true
    }

Sort by start, merge in one pass. Also the min-arrows greedy (sort by end).

JavaMergeIntervals.java
import java.util.ArrayList;
    import java.util.Arrays;
    import java.util.List;
    
    public class MergeIntervals {
        static int[][] merge(int[][] a) {
            Arrays.sort(a, (u, v) -> Integer.compare(u[0], v[0]));
            List<int[]> out = new ArrayList<>();
            int curL = a[0][0], curR = a[0][1];
            for (int i = 1; i < a.length; i++) {
                if (a[i][0] <= curR) {
                    curR = Math.max(curR, a[i][1]);
                } else {
                    out.add(new int[] {curL, curR});
                    curL = a[i][0];
                    curR = a[i][1];
                }
            }
            out.add(new int[] {curL, curR});
            return out.toArray(new int[0][]);
        }
    
        static int minArrows(int[][] points) {
            Arrays.sort(points, (u, v) -> Integer.compare(u[1], v[1]));
            int arrows = 1;
            int end = points[0][1];
            for (int i = 1; i < points.length; i++) {
                if (points[i][0] > end) {
                    arrows++;
                    end = points[i][1];
                }
            }
            return arrows;
        }
    
        public static void main(String[] args) {
            int[][] m = merge(new int[][] {{1, 3}, {2, 6}, {8, 10}, {15, 18}});
            System.out.println(Arrays.deepToString(m));
            System.out.println(minArrows(new int[][] {{10, 16}, {2, 8}, {1, 6}, {7, 12}}));
        }
        // Input : merge [1,3][2,6][8,10][15,18]; arrows [10,16][2,8][1,6][7,12]
        // Output: [[1, 6], [8, 10], [15, 18]]
        //         2
    }

Sweep for maximum overlap (meeting rooms II) and two-list intersection.

JavaIntervalSweep.java
import java.util.ArrayList;
    import java.util.Arrays;
    import java.util.List;
    
    public class IntervalSweep {
        static int minRooms(int[][] meetings) {
            int n = meetings.length;
            int[] start = new int[n];
            int[] end = new int[n];
            for (int i = 0; i < n; i++) {
                start[i] = meetings[i][0];
                end[i] = meetings[i][1];
            }
            Arrays.sort(start);
            Arrays.sort(end);
            int i = 0, j = 0, cur = 0, best = 0;
            while (i < n) {
                if (start[i] < end[j]) {
                    cur++;
                    best = Math.max(best, cur);
                    i++;
                } else {
                    cur--;
                    j++;
                }
            }
            return best;
        }
    
        static int[][] intersect(int[][] a, int[][] b) {
            List<int[]> out = new ArrayList<>();
            int i = 0, j = 0;
            while (i < a.length && j < b.length) {
                int l = Math.max(a[i][0], b[j][0]);
                int r = Math.min(a[i][1], b[j][1]);
                if (l <= r) {
                    out.add(new int[] {l, r});
                }
                if (a[i][1] < b[j][1]) {
                    i++;
                } else {
                    j++;
                }
            }
            return out.toArray(new int[0][]);
        }
    
        public static void main(String[] args) {
            System.out.println(minRooms(new int[][] {{0, 30}, {5, 10}, {15, 20}}));
            int[][] x = intersect(new int[][] {{0, 2}, {5, 10}, {13, 23}},
                new int[][] {{1, 5}, {8, 12}, {15, 24}});
            System.out.println(Arrays.deepToString(x));
        }
        // Input : rooms [0,30][5,10][15,20]; intersect two disjoint lists
        // Output: 2
        //         [[1, 2], [5, 5], [8, 10], [15, 23]]
    }

Complexity

Time O(n log n) sort + O(n) scan Space O(n) for the output (and for event arrays)

The sort dominates: T(n) = Θ(n log n) + Θ(n). After sorting, each interval is inspected a constant number of times.

Sweep with 2n events is the same class. Two-pointer intersection of already-sorted disjoint lists is O(n + m) with no extra sort.

Edge cases and pitfalls

  • Inclusive ends treated as exclusive
    [1,2] and [2,3] should merge on LC 56 but a < test leaves a gap.
    Read the statement. LC 56 overlaps at a shared endpoint; LC 452 arrows too.
  • Sorting by the wrong coordinate
    Merging after sorting by end misses an overlap that starts late and stretches far.
    Union → sort by start. Greedy keep → sort by end. Do not mix.
  • int overflow on union length
    r - l + 1 with l, r up to 1e9 and n up to 1e5, summed in int.
    Accumulate in long. Subtract as long before adding one.
  • Forgetting to emit the last interval
    The loop only emits when a gap appears, so the final running merge is dropped.
    Always out.add(cur) after the loop.
  • Start and end events at the same time
    Processing a start before an end at time t counts an extra room that just freed.
    If a room can be reused at time t, process ends first. Match the problem's "touching is OK" rule.

Interview follow-ups

Why sort by end for "remove minimum overlapping"?

The interval that finishes first leaves the most room for the rest. If an optimal solution keeps a later-ending interval in that slot, swap it for the greedy choice: the end only moves left, so later intervals that fitted still fit.

How do you list points covered by exactly k intervals?

Sweep with +1 at l and −1 at r. Whenever the running count changes, close the previous segment at this x and open a new one. Group by the count value.

Intervals arrive online and you must merge on the fly?

A TreeMap from start to end, or a balanced tree of disjoint ranges. Lower-bound the start, walk neighbours that overlap, delete them, insert the union. See TreeMap patterns.

What changes on a circle?

Cut at 0, or duplicate the array shifted by the circumference so a wrap-around interval becomes a linear one. Take care not to double-count the cut point.

Recap

  • Sort by start to merge / take union.
  • Sort by end to keep the maximum non-overlapping set.
  • Sweep +1/−1 for maximum concurrent overlap.
  • Emit the last interval after the merge loop.
  • Inclusive vs exclusive ends change the comparison.
