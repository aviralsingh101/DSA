Suffix Array & LCP

A suffix array is the permutation of starting indices in lexicographic order; Kasai then fills the LCP array in O(n) and string problems become range-min on LCP.

Hard 28 min read Prerequisites: Sorting & Comparators, Sparse Table & RMQ suffix array LCP P2

Why this exists

Every substring is a prefix of some suffix. Sorting the suffixes therefore sorts all substrings, and the longest common prefix of two suffixes is the min LCP on the interval between them in the array. Distinct-substring count, longest repeated substring, and k-th substring fall out of that picture.

O(n log n) doubling (or SA-IS in O(n)) builds the array. Kasai's lemma: if suffix i has LCP h with its predecessor in the order, suffix i+1 has LCP at least h-1 with its predecessor. That one observation makes LCP linear.

Suffix automata / suffix trees are more powerful and more code. In Java contests the suffix array plus a sparse table on LCP is the structure you actually submit.

LCP of any two suffixes = RMQ of the LCP array between their ranks. Kasai fills that array by walking suffixes in text order, not sorted order.

Recognise this pattern

Say yes when you see

  • Number of distinct substrings = n(n+1)/2 - sum LCP
  • Longest repeated substring = max LCP
  • Longest common substring of two strings: SA of s+'#'+t, max LCP across the '#'
  • k-th lexicographic substring
  • O(1) LCP after O(n log n) preprocess

Not this pattern when

  • One pattern in one text → KMP, do not build an SA
  • You need online end-append of characters → suffix automaton
  • n = 1e5 and you only compare two whole strings → equals / hash
  • Mutable string with substring sorts → too heavy; hashes + segtree maybe

Constraint tell: n ≤ 4×10⁵ for O(n log n) doubling in Java; O(n log^2) with sort-of-pairs is tight at 4e5. Alphabet can be mapped to 1..n.

Core idea and the invariant

Doubling: rank by first 2^k characters. At step k you sort suffixes by (rank[i], rank[i+2^k]). After log n steps the order is full. Use a stable counting sort on ranks, not Timsort, if you need O(n log n).

Kasai: inv[sa[i]]=i. Walk i=0..n-1 in text order, keep k = current LCP. Compare sa[rank-1] starting at i. Then k = max(k-1, 0).

sa[i] is the start of the i-th smallest suffix. lcp[i] = LCP(suffix sa[i-1], suffix sa[i]). For any i < j, LCP(sa[i], sa[j]) = min(lcp[i+1], …, lcp[j]).

SA, then Kasai, then RMQ

Algorithm

  1. Map characters to ranks 1..sigma. Append a sentinel 0.
  2. Doubling: for k=0,1,2,... sort by (rank[i], rank[i+2^k]) and reassign ranks.
  3. Stop when all ranks are unique.
  4. Kasai: inv[sa[i]]=i; k=0; for i=0..n-1 compute lcp[inv[i]].
  5. Sparse table on lcp for range min.
  6. Answer the actual string problem (distinct, LCS, k-th, search).

Java implementation

Sort suffixes with String.compareTo. O(n^2 log n).

JavaSaBrute.java
import java.util.*;
    public class SaBrute {
        static int[] sa(String s) {
            Integer[] idx = new Integer[s.length()];
            for (int i = 0; i < idx.length; i++) idx[i] = i;
            Arrays.sort(idx, (a, b) -> s.substring(a).compareTo(s.substring(b)));
            int[] sa = new int[idx.length];
            for (int i = 0; i < idx.length; i++) sa[i] = idx[i];
            return sa;
        }
        public static void main(String[] args) {
            System.out.println(Arrays.toString(sa("banana")));
        }
        // Input : banana
        // Output: [5, 3, 1, 0, 4, 2]
    }

O(n log^2 n) doubling with Java sort. Fine for n ≤ 1e5.

JavaSuffixArray.java
import java.util.*;
    public class SuffixArray {
        static int[] sa(String s) {
            int n = s.length();
            Integer[] sa = new Integer[n];
            int[] r = new int[n], nr = new int[n];
            for (int i = 0; i < n; i++) { sa[i] = i; r[i] = s.charAt(i); }
            for (int k = 1; k < n; k <<= 1) {
                final int kk = k;
                Arrays.sort(sa, (a, b) -> {
                    if (r[a] != r[b]) return Integer.compare(r[a], r[b]);
                    int ra = a + kk < n ? r[a + kk] : -1;
                    int rb = b + kk < n ? r[b + kk] : -1;
                    return Integer.compare(ra, rb);
                });
                nr[sa[0]] = 0;
                for (int i = 1; i < n; i++) {
                    int a = sa[i - 1], b = sa[i];
                    boolean same = r[a] == r[b]
                        && (a + kk < n ? r[a + kk] : -1) == (b + kk < n ? r[b + kk] : -1);
                    nr[b] = nr[a] + (same ? 0 : 1);
                }
                int[] tmp = r; r = nr; nr = tmp;
                if (r[sa[n - 1]] == n - 1) break;
            }
            int[] out = new int[n];
            for (int i = 0; i < n; i++) out[i] = sa[i];
            return out;
        }
        static int[] lcp(String s, int[] sa) {
            int n = s.length();
            int[] inv = new int[n], lcp = new int[n];
            for (int i = 0; i < n; i++) inv[sa[i]] = i;
            int k = 0;
            for (int i = 0; i < n; i++) {
                if (inv[i] == 0) { k = 0; continue; }
                int j = sa[inv[i] - 1];
                while (i + k < n && j + k < n && s.charAt(i + k) == s.charAt(j + k)) k++;
                lcp[inv[i]] = k;
                if (k > 0) k--;
            }
            return lcp;
        }
        public static void main(String[] args) {
            String s = "banana";
            int[] sa = sa(s);
            System.out.println(Arrays.toString(sa));
            System.out.println(Arrays.toString(lcp(s, sa)));
        }
        // Input : banana
        // Output: [5, 3, 1, 0, 4, 2]
        //         [0, 1, 3, 0, 0, 2]
    }

n(n+1)/2 minus sum of adjacent LCPs.

JavaDistinctSubstrings.java
public class DistinctSubstrings {
        static long distinct(int n, int[] lcp) {
            long all = (long) n * (n + 1) / 2;
            for (int x : lcp) all -= x;
            return all;
        }
        public static void main(String[] args) {
            int[] lcp = {0, 1, 3, 0, 0, 2};
            System.out.println(distinct(6, lcp));
        }
        // Input : banana LCPs
        // Output: 15
    }

Complexity

Time O(n log^2 n) this code; O(n log n) with radix; O(n) SA-IS Space O(n)

log n doubling steps, each a sort of n pairs. Java Timsort is O(n log n) per step → O(n log^2 n). Kasai is strictly O(n) because k increases at most n times.

Edge cases and pitfalls

  • Kasai forgetting k--
    You re-compare from 0 every suffix and go quadratic.
    After writing lcp, if (k>0) k--; — the lemma.
  • No sentinel / ties
    Two suffixes with a common prefix to EOF compare equal and ranks collide forever.
    Treat out-of-range rank as -1, strictly smaller than any char.
  • lcp[0] meaning
    Some codes leave lcp[0]=0 unused; summing then subtracts an extra 0 (fine) but RMQ between ranks 0 and 1 must not read lcp[0] as a real LCP.
    lcp[i] = LCP(sa[i-1], sa[i]) for i≥1. RMQ on (i+1..j).
  • Building SA of s+t without a separator
    LCS of two strings: suffixes can cross the join.
    A char smaller than both alphabets between them.
  • Integer overflow on n(n+1)/2
    n=1e5 → 5e9. int dies.
    long.

Interview follow-ups

Prove Kasai's k--.

If suffix i shares h chars with its SA-predecessor, deleting the first character leaves h-1 as a lower bound on the LCP of suffix i+1 with whatever sits just before it in the SA (that predecessor is at least as large as the shifted previous predecessor).

SA vs suffix automaton for distinct substrings?

Both O(n). SA needs Kasai and a formula. SAM is one DAG whose endpos sizes sum to the answer. SAM is nicer online; SA is nicer for LCP/RMQ and k-th substring.

How do you get LCP of two arbitrary suffixes?

Rank them, RMQ-min the lcp array strictly between those ranks. Sparse table is O(1).

Why not always SA-IS?

It is O(n) and long. Doubling is 40 lines and passes n=1e5 in Java. Learn SA-IS later if constants bite.

Recap

  • sa = starting indices of suffixes in lex order.
  • lcp[i] = LCP of adjacent suffixes in that order.
  • Kasai: walk text order, k = max(k-1, 0).
  • Any LCP = RMQ on lcp between ranks.
  • Distinct = n(n+1)/2 - sum lcp.
