Rolling Hash

Map every substring to a polynomial s[l] b^{len-1} + … + s[r] modulo a prime so equality (and 2D / palindrome checks) become a few multiplies.

Medium 24 min read Prerequisites: Modular Arithmetic, Prefix Sums hashing polynomial hash P1

Why this exists

Substring equality, longest common substring, palindrome checks, and "does this pattern appear" are O(n) with KMP/Z for one pattern, but hashing stays O(1) per query after an O(n) prefix, and extends to 2D, trees, and sets of strings without a specialised automaton.

The polynomial hash is a prefix array in the ring Z/MZ: H[i] = s[0]b^{i-1} + s[1]b^{i-2} + … + s[i-1]. A substring is H[r]-H[l]*b^{r-l}, computed with a precomputed pow[]. Two 64-bit moduli (or one 2^64 unsigned plus one prime) make collisions a non-issue in contests.

The interview sentence is "compare hashes first, verify on a collision if the modulus is small". On Codeforces, anti-hash tests exist: use a randomised base, two moduli, or 2^61-1.

A substring hash is a prefix-hash difference scaled by a power of the base — the same identity as prefix sums, in a modular ring.

Recognise this pattern

Say yes when you see

  • O(1) substring equality after O(n) preprocess
  • Longest common prefix of two suffixes via binary search + hash
  • Palindrome check: hash(s[l..r]) == reverse-hash of that range
  • 2D grid matching (Rabin-Karp 2D)
  • You need to put substrings in a HashSet

Not this pattern when

  • You must be deterministic with no collision risk and one pattern → KMP
  • Need the suffix order, not equality → suffix array
  • Alphabet is huge and you need frequency maps → different tool
  • Single comparison of two whole strings → equals

Constraint tell: n, q ≤ 2×10⁵. Two 64-bit moduli, base random in [256, 1e9). Never use mod 1e9+7 alone on CF.

Core idea and the invariant

Fix base b and mod M. H[0]=0, H[i+1] = (H[i]*b + s[i]) % M. pow[0]=1, pow[i+1]=pow[i]*b % M. Substring [l, r) has hash (H[r] - H[l]*pow[r-l]) % M, add M if negative.

Collision probability for one comparison is about (length)/M with a random base. q comparisons → q/M. Two independent hashes make it q/M^2. Anti-hash: randomise b at startup, or use unsigned long overflow as a free 2^64 ring plus a prime.

H[i] = sum_{j=0}^{i-1} s[j] * b^{i-1-j} (mod M). Then hash[l, r) = H[r] - H[l] * b^{r-l} (mod M), the unique polynomial of that substring.

Algorithm

  1. Pick a random odd base > alphabet, and one or two moduli (2^61-1, 1e9+9, unsigned 2^64).
  2. Build H and pow of length n+1 in one pass.
  3. hash(l, r) half-open: h = H[r] - H[l]*pow[r-l]; if (h<0) h+=M;
  4. Compare two ranges by hash; optionally verify with char loop if M is small.
  5. Rabin-Karp slide: window := window*b - s[i-len]*pow[len] + s[i].
  6. Reverse hash on the reversed string (or a second prefix from the right) for palindromes.

Java implementation

substring equals. Correct, O(n) per query.

public class SubEqBrute {
        static boolean eq(String s, int l1, int r1, int l2, int r2) {
            return s.substring(l1, r1).equals(s.substring(l2, r2));
        }
        public static void main(String[] args) {
            String s = "abacaba";
            System.out.println(eq(s, 0, 3, 4, 7));
        }
        // Input : abacaba, [0,3) vs [4,7)
        // Output: true
    }

Single 64-bit unsigned ring via long overflow (mod 2^64). Fast and usually enough with a random base.

JavaRollingHash.java
import java.util.Random;
    public class RollingHash {
        long[] H, p;
        RollingHash(String s, long base) {
            int n = s.length();
            H = new long[n + 1];
            p = new long[n + 1];
            p[0] = 1;
            for (int i = 0; i < n; i++) {
                H[i + 1] = H[i] * base + s.charAt(i);
                p[i + 1] = p[i] * base;
            }
        }
        long hash(int l, int r) { return H[r] - H[l] * p[r - l]; }
        public static void main(String[] args) {
            long base = new Random().nextInt(1_000_000) + 257;
            RollingHash h = new RollingHash("abacaba", base);
            System.out.println(h.hash(0, 3) == h.hash(4, 7));
        }
        // Input : abacaba, [0,3) vs [4,7)  ("aba" vs "aba")
        // Output: true
    }

Two prime moduli. Safer on CF anti-hash.

JavaDoubleHash.java
public class DoubleHash {
        static final long M1 = 1_000_000_007L, M2 = 1_000_000_009L, B = 911382323L;
        long[] h1, h2, p1, p2;
        DoubleHash(String s) {
            int n = s.length();
            h1 = new long[n + 1]; h2 = new long[n + 1];
            p1 = new long[n + 1]; p2 = new long[n + 1];
            p1[0] = p2[0] = 1;
            for (int i = 0; i < n; i++) {
                h1[i + 1] = (h1[i] * B + s.charAt(i)) % M1;
                h2[i + 1] = (h2[i] * B + s.charAt(i)) % M2;
                p1[i + 1] = p1[i] * B % M1;
                p2[i + 1] = p2[i] * B % M2;
            }
        }
        long hash(int l, int r) {
            long x = (h1[r] - h1[l] * p1[r - l] % M1 + M1) % M1;
            long y = (h2[r] - h2[l] * p2[r - l] % M2 + M2) % M2;
            return (x << 32) ^ y;
        }
        public static void main(String[] args) {
            DoubleHash h = new DoubleHash("abacaba");
            System.out.println(h.hash(0, 3) == h.hash(4, 7));
        }
        // Input : same aba vs aba
        // Output: true
    }

Complexity

Time O(n) build, O(1) substring hash Space O(n)

Prefix and powers are one pass. Each query is a multiply and a subtract. Binary search on LCP is O(log n) hashes = O(log n).

Edge cases and pitfalls

  • Negative mod in Java
    (h[r] - h[l]*pow) % M can be negative, and HashSet treats -3 and M-3 as different.
    x %= M; if (x < 0) x += M;
  • Fixed base 31 and mod 1e9+7 on CF
    Anti-hash tests exist. Single small prime with a famous base will get WA.
    Random base per run, two moduli, or unsigned 64 + one prime.
  • Mapping letters to 0
    Leading zeros make "a" and "aa" collide when a maps to 0.
    Map 'a'.. to 1..26, or use the raw char code which is never 0.
  • pow overflow before mod
    p[i]*B overflows long if you meant a 1e18 modulus.
    Use a mul-mod, 2^61-1 trick, or stay in unsigned 2^64.
  • Half-open vs inclusive mix
    hash(l,r) as inclusive but multiplied by pow[r-l] instead of pow[r-l+1].
    Pick [l, r) everywhere, including the dry run.

Interview follow-ups

Why a random base?

For a fixed base, an adversary can build collisions (especially with small M). A random base unknown at test-generation time makes the polynomial random, and the Schwartz-Zippel bound applies.

Is 2^64 overflow OK?

It is a ring, not a field, so it has zero divisors. Thue-Morse / overflow attacks exist but are rarer. Pair it with a prime modulus if the contest is known-hostile.

LCP of two suffixes?

Binary search the length: hash equality is the predicate. O(log n) per LCP. Suffix arrays give all adjacent LCPs faster if you need them all.

Hash vs KMP in an interview?

Mention both. If they want worst-case linear, write KMP. If they want substring queries or a set of strings, write hashing and name the collision policy.
