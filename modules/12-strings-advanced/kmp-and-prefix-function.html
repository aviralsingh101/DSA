KMP & the Prefix Function

The prefix function π[i] is the longest proper prefix of s[0..i] that is also a suffix — KMP matching is one scan using those borders.

Medium 32 min read Prerequisites: Two Pointers, Hashing Patterns KMP prefix function string P1

Why this exists

You are given a long text and a shorter pattern, and you must find every place the pattern sits inside the text, including places that overlap. The obvious loop tries the pattern at index 0, then at index 1, and so on, and on each try it compares characters from the start of the pattern. That is perfectly correct, and on a text of length n and a pattern of length m it can do about n × m comparisons. At n = m = 105 that is 1010 steps, and the judge will cut you off long before you finish.

The array that saves those repeated comparisons is the prefix function. For a string s, the value π[i] is the length of the longest proper prefix of the piece s[0..i] that is also a suffix of that same piece. Proper means the piece itself does not count, so π[i] is always strictly smaller than i+1. People also call that shared piece a border. Once you know every border of the pattern, a mismatch no longer sends you back to the start of the text: it jumps the pattern to its next shorter border and you keep reading the text from the same character.

Those borders nest inside each other, which is why a single array is enough. If a candidate border of length q fails on the next character, every alignment that can still use some of the text you already matched must itself be a border of that failed border. The longest such leftover is exactly π[q-1], so the fallback q = π[q-1] never skips a viable shift and never invents one. The same array then answers "shortest period", counts overlapping hits, and builds the failure automaton you feed many texts through.

In a real statement the signal is a single pattern against a text of length about 106, or the phrase "shortest period" sitting next to a string that looks repetitive. Rolling hash is the randomised cousin and is faster to type; this page is the deterministic linear scan you write when the statement forbids false positives or when you need the border structure itself, not just equality.

A mismatch at a candidate border of length q does not rewind the text: the next candidate is π[q-1], the longest border of that border, and every surviving alignment is somewhere on that nested chain. Keep a current length q and you finish both the prefix array and the match in one pass.

Recognise this pattern

Say yes when you see

  • Shortest period of a string: n % (n - π[n-1]) == 0
  • Build a failure automaton and feed many texts
  • "String matching without hashing / without false positives"
  • Compress a string by its border structure

Not this pattern when

  • Many different patterns in one text → Aho-Corasick
  • You only need palindromes → Manacher
  • You need lexicographic suffix order → suffix array
  • One equality test of two whole strings → just compare, or a hash

Building π is strictly O(n) because the inner fallback loop cannot run more than n times in total. Recursion is not involved; if the statement also asks for many different patterns, this page is the wrong tool and you want Aho-Corasick instead.

Core idea and the invariant

You need one array pi of length n and one integer q. The slot pi[i] will hold the longest border of the prefix that ends at i, and q is that same length for the prefix you have just finished, so you can try to grow it onto the next character. Start with pi[0] = 0 and q = 0, because a single character has no proper prefix. Then for each later index i you do three things: while q is positive and s[i] disagrees with s[q], replace q by pi[q-1]; if the characters now agree, increment q; finally write pi[i] = q.

The fallback q = pi[q-1] looks like it might skip a match, so sit with why it cannot. After the previous character you already know that the last q characters of the processed prefix equal s[0..q). When s[i] is not s[q], a border of length q+1 is impossible. Any alignment that still uses some of those already-matched characters must start later, which means the leftover length k has to satisfy s[0..k) = s[q-k..q) — that is, k itself must be a border of the string of length q. The longest such k is stored at index q-1, so it is exactly pi[q-1]. If that also fails you walk to pi[pi[q-1]-1], and so on down to 0. Every possible surviving shift is a border of a border, so the chain visits them all and invents none.

The same walk is why the whole pass is linear, even though there is a while inside the for. Treat q as a potential: it starts at 0, each index increases it by at most 1, and every iteration of the inner loop drops it to a strictly smaller non-negative integer. The total of all those drops cannot exceed the total of all the increments, and the increments are at most n-1, so the body of the while runs at most n times across the whole string. Matching is the same arithmetic on a string of length |p| + |t| + 1.

Walk ababac character by character. At i = 0 the piece is a and there is no proper prefix, so pi[0] = 0. At i = 1 the piece is ab; the only proper prefix is a and the only proper suffix is b, they disagree, and pi[1] = 0. At i = 2 the piece is aba; the proper prefixes are a and ab, the proper suffixes are a and ba, and the longest string in both lists is a, so pi[2] = 1. At i = 3 you extend that border by b and get ab, so pi[3] = 2. At i = 4 you extend again and get aba, so pi[4] = 3. At i = 5 the next character is c against s[3] = b; the fallback walks q from 3 to pi[2] = 1 (try c against s[1] = b) and then to pi[0] = 0 (try c against s[0] = a), both fail, and pi[5] = 0. To match a pattern p inside a text t, build pi of p + '#' + t using a sentinel that appears in neither string; every index in the text half whose value equals |p| is an occurrence ending there.

The prefix function is the longest proper border of every prefix:

π[i] = max { k : 0 ≤ k < i+1 and s[0..k) = s[i-k+1..i] }, or 0 if no such k exists.

In plain words, after you finish index i the integer q is exactly that longest border, and the only shorter borders you will ever need are the borders of that border, which already live in π. Interview sentence: "On a mismatch I set q = π[q-1]; that is the next possible alignment, and the potential on q makes the whole scan linear."

The fallback is pi[q-1], never pi[q]

The string whose border you want has length q, so its last index is q-1. Writing q = pi[q] either reads an entry you have not filled yet or walks a different string, and the loop can spin or skip the alignment you needed. Test the fallback on ababac at the final c: the live length is 3, and the next try must be pi[2] = 1.

You do not have to concatenate

Build pi of the pattern alone. Scan the text with the same while-and-increment, and when q reaches |p| record a hit and set q = pi[q-1] so overlapping hits are not lost. The sentinel concatenation is the same idea with the bookkeeping already inside pi.

Why the inner loop cannot exceed n drops

Let q be a potential. Each of the n-1 values of i increases it by at most 1. Each while iteration replaces q by a strictly smaller non-negative integer. A non-negative integer cannot fall more times than it has risen, so the inner body runs at most n-1 times in total — about a million extra array reads at n = 106, not a quadratic blow-up.

Algorithm

  1. Allocate the array and the live length. Create int[] pi = new int[n] and set q = 0. Index 0 has no proper prefix, so pi[0] stays 0 and you never write it again.
  2. Walk every later index. For i from 1 to n-1 you will try to grow the current border onto s[i]. Starting at 1 is load-bearing: the fallback reads pi[q-1], which is only defined for prefixes you have already finished.
  3. Fall back while the next character disagrees. While q > 0 and s[i] != s[q], replace q by pi[q-1]. That is the longest border of the failed border, so you try the next possible alignment without moving i backwards.
  4. Grow the border when the characters agree. If s[i] == s[q] after the fallback (or because q was already 0 and they happen to match), increment q. You have just lengthened the live prefix by one character.
  5. Record the answer at this index. Write pi[i] = q. Later fallbacks will read this slot, so the value must be the true longest border, not a shorter one you happened to try along the way.
  6. Match a pattern by building pi of the concatenation. Compute the prefix function of p + '#' + t using a sentinel that appears in neither string, then report every index in the text half where pi[i] == p.length(). Those are the ends of occurrences, overlaps included.

import java.util.*;
    public class MatchBrute {
        static List<Integer> find(String t, String p) {
            List<Integer> ans = new ArrayList<>();
            for (int i = 0; i + p.length() <= t.length(); i++) {
                if (t.regionMatches(i, p, 0, p.length())) ans.add(i);
            }
            return ans;
        }
        public static void main(String[] args) {
            System.out.println(find("ababa", "aba"));
        }
        // Input : text ababa, pattern aba
        // Output: [0, 2]
    }

Prefix function, then match via the sentinel concatenation.

JavaKmp.java
import java.util.*;
    public class Kmp {
        static int[] prefix(String s) {
            int n = s.length();
            int[] pi = new int[n];
            for (int i = 1, q = 0; i < n; i++) {
                while (q > 0 && s.charAt(i) != s.charAt(q)) q = pi[q - 1];
                if (s.charAt(i) == s.charAt(q)) q++;
                pi[i] = q;
            }
            return pi;
        }
        static List<Integer> find(String t, String p) {
            int[] pi = prefix(p + "#" + t);
            List<Integer> ans = new ArrayList<>();
            int m = p.length();
            for (int i = 0; i < t.length(); i++) {
                if (pi[m + 1 + i] == m) ans.add(i - m + 1);
            }
            return ans;
        }
        public static void main(String[] args) {
            System.out.println(find("ababa", "aba"));
            System.out.println(Arrays.toString(prefix("ababac")));
        }
        // Input : ababa / aba, and pi of ababac
        // Output: [0, 2]
        //         [0, 0, 1, 2, 3, 0]
    }

Shortest period from the last prefix value.

JavaPeriod.java
public class Period {
        static int period(String s) {
            int n = s.length();
            int[] pi = new int[n];
            for (int i = 1, q = 0; i < n; i++) {
                while (q > 0 && s.charAt(i) != s.charAt(q)) q = pi[q - 1];
                if (s.charAt(i) == s.charAt(q)) q++;
                pi[i] = q;
            }
            int p = n - pi[n - 1];
            return n % p == 0 ? p : n;
        }
        public static void main(String[] args) {
            System.out.println(period("ababab"));
            System.out.println(period("abcab"));
        }
        // Input : ababab, then abcab
        // Output: 2
        //         5
    }

Complexity

Time O(n) Space O(n)

The outer loop visits each of the n-1 later indices once. The live length q starts at 0 and grows by at most 1 after each index, so it can rise at most n-1 times. Every iteration of the inner while replaces q by a strictly smaller non-negative integer, and a non-negative integer cannot fall more times than it has risen. Therefore the inner body runs at most n-1 times across the whole string, and the whole prefix-function pass is O(n) array reads.

Matching is one more prefix-function call on the concatenated string of length |p| + |t| + 1, which is the same bound. Putting real numbers in: at n = 106 you do a couple of million character comparisons, which is a few milliseconds. The naive aligner at the same size is n × m comparisons, about 1012 if both strings are long, and that is not a contest-legal runtime.

Edge cases and pitfalls

  • Missing the sentinel
    Computing π of p+t without a separator looks like a clever concatenation, and the array even fills. A border can cross the join and invent a fake occurrence that is half pattern and half text.
    Insert a character that appears in neither string, or scan the text with a separate automaton built from p alone. Test it on pattern ab and text ba: without a sentinel you can report a hit that is not there.
  • Off-by-one on occurrence index
    Seeing π[i] == |p| and treating i as a start index looks right because that is how Z-values work. For the prefix function the match ends at i in the concatenated string, so the start in t is a different arithmetic.
    Loop i over the text half as in the code, where the start is i - m + 1 after you have already offset into t. Check the sample ababa / aba, which must report starts 0 and 2, not 2 and 4.
  • Period formula without the divisibility check
    The string abcab has π[n-1] = 2, so n - π = 3 looks like a period, and the formula is sitting right there in every blog post. The string is not abc repeating.
    The candidate p = n - π[n-1] is the shortest period only when p divides n. Otherwise the string is not a whole number of copies and you should report n itself.
  • Using π[q] instead of π[q-1]
    Writing q = pi[q] looks symmetric with the live length, and on a lucky sample it even terminates. The border of a string of length q lives at index q-1, so the wrong index either loops or skips a nested border.
    The while body is always q = pi[q-1]. Walk ababac at the last character by hand: the live length is 3 and the next try must read pi[2], not pi[3].
  • A sentinel that already appears in the input
    Gluing with '#', a space, or '$' looks safe because those characters are punctuation. If the statement's alphabet includes them, a border can again cross the join and the match list is wrong.
    Pick a code that is outside the alphabet, or store the concatenation as an int[] with a sentinel integer such as -1. Print the pi array of p + sentinel + t and check that no value in the text half exceeds |p| except at real hits.

Interview follow-ups

Z-function vs prefix function?

The Z-value at i is the longest substring that starts at i and matches a prefix of s. The prefix-function value at i is the longest border that ends at i. They determine each other in linear time, so neither is more powerful. Matching a single pattern is more natural from π because the fallback q = π[q-1] is already the next automaton state; Z is more natural when the question is already "how much prefix starts here?".

Why is the inner loop amortised O(1)?

Amortised here means the expensive steps are rare enough that their total, divided by n, stays constant. The live length q is a potential: each index raises it by at most one, and each inner iteration drops it. The drops cannot outnumber the raises, so across the whole string the inner body runs at most n times. One index might walk a long border chain, but it spends credit that earlier matches deposited.

How do you match without concatenating?

Build π of the pattern alone. Scan the text with the same while-and-increment used to fill π, treating the text character as the next s[i] and the live length as the current state. When that state reaches |p| you have a hit ending at the current text index; set the state to π[|p|-1] so the next character can still start an overlapping hit.

Can KMP find the lexicographically smallest rotation?

Yes, that is Booth's algorithm: run the prefix-function idea on s+s and keep the smallest start that the border structure still allows. The other school is Duval's Lyndon factorisation, which also finds the least rotation in linear time. In an interview, say you would KMP on the doubled string and then mention Duval if they ask for the cleanest linear construction.
