Aho-Corasick

A trie of all patterns plus KMP-style failure links: feed the text once and report every pattern occurrence, overlapping included, in linear time.

Hard 32 min read Prerequisites: KMP & the Prefix Function, Trie Aho-Corasick automaton trie P2

Why this exists

You are given a dictionary of patterns and one long text, and you must report every place any of those patterns sits inside the text, overlaps included. Running KMP once per pattern is correct, and it costs about |t| times the number of patterns plus the total length of the dictionary. At a million-character text and a thousand patterns that is a billion steps, which some judges will still accept and some will not; at a million patterns it is not a contest-legal runtime. The naive nested loop that calls startsWith at every text index is worse still.

Aho-Corasick builds one automaton that knows the whole dictionary. The states are the nodes of a trie of every pattern. The extra ingredient is a failure link (also called a suffix link) on each node: from the string that node represents, jump to the longest proper suffix of that string that is still a prefix of some pattern in the dictionary. That is exactly KMP's π[q-1], just living on a tree of patterns instead of on one string. Feeding a text character is then: follow the trie edge if it exists, otherwise follow failure links until an edge exists, and never rewind the text pointer.

Those failure links are filled by a breadth-first walk from the root, parent before child, which is the same "shorter borders first" order that lets KMP read π[q-1] safely. Nested patterns such as ab sitting inside xab are easy to miss if you only look at the node you landed on; an output link (or an aggregated out[u] += out[fail[u]]) walks the failure chain and reports every dictionary word that ends here. The same automaton is the state space for "build a string that avoids these forbidden words".

In a real statement the signal is many patterns against one text, or a DP whose state is "where am I in the dictionary after reading i characters", with |t| + sum |p| around 106. One pattern is still KMP. A huge text and later "is this word in there?" questions is a suffix array or a suffix automaton of the text, not this page.

The failure link of a trie node is the KMP border of the string that node represents, taken inside the dictionary rather than inside one pattern: the longest proper suffix that is still a prefix of some word. Feeding a character follows an edge or walks those links, and because every surviving alignment is a suffix of a suffix you never skip a hit and never rewind the text.

Constraint tell: sum |p| + |t| ≤ 106 is the linear-automaton window. Alphabet 26 is a child array of 26 per node; a larger alphabet wants a map and a slower fail walk. If many patterns nest, compressing the failure chain into out[u] or an output link is mandatory: climbing fail raw at every text character can multiply the scan by the number of nested words.

Core idea and the invariant

You need a trie of every pattern, an array fail of one integer per node, and a number out[u] (or a list of pattern ids) on terminals. Insert each word from the root, creating a child for each new character, and mark the node where the word ends. The root represents the empty string and is state 0. After the trie exists, a breadth-first queue fills the links. Push every direct child of the root first, with fail = 0: a single-character word has no proper suffix that is still a prefix, so it falls back to the empty string. Then, while the queue is not empty, pop a node u and look at each letter c. If u has a child v on c, the failure of v is wherever fail[u] itself goes on c, because that is the longest suffix of u's string that can still accept c. If u has no child on c, you may fill nxt[u][c] = nxt[fail[u]][c] so the later scan is a single array read.

Why that failure cannot lose a match is the same nested-border argument as q = π[q-1], just on a tree. After reading some prefix of the text you sit at the node u whose string is the longest suffix of that prefix that is a prefix of some pattern. The next text character is c. If u has an edge on c, you take it and you have grown that dictionary prefix by one. If it does not, every alignment that can still use some of the text you already matched must start later, which means it is a proper suffix of u's string. The longest such suffix that is still a dictionary prefix is exactly fail[u], so you retry c from there. If that also fails you walk to fail[fail[u]], and so on down to the root. Every possible surviving alignment is a suffix of a suffix that the trie still knows about, so the chain visits them all and invents none. You never move the text pointer backwards.

BFS order is what makes the definition computable. The string at fail[u] is always strictly shorter than the string at u, so it is a node of smaller depth. A queue that pushes children after their parent has already been processed therefore finds fail[u] already filled, and nxt[fail[u]][c] already filled if you are precomputing missing edges. A depth-first walk can ask for a failure that has not been written yet and then store a wrong link that silently drops hits. Root children are the base: they fail to the root, which is how the empty string plays the role of π[0] = 0.

Nested words need one more line. Landing on the node for aba should also report ba and a if those are in the dictionary, because they are suffixes of what you just read. During the same BFS, add out[v] += out[fail[v]] (or set output[v] to v if v is terminal and to output[fail[v]] otherwise). Then a scan that does state = nxt[state][c]; ans += out[state] counts every word that ends at this text index, including the ones that only live on the failure chain. Walk the dictionary ab, ba, aba against the text abaca. After a you sit at the first-letter node; after ab you sit at the ab terminal and report one hit; after the next a you sit at aba and the aggregated out reports that word (and would report ba if the failure chain carried it). The letter c has no edge, so you fail to the root; the final a returns to the first-letter node. The text produced two hits, which is the sample.

After any prefix of the text, the current state is the longest suffix of that prefix that is still a trie prefix, and the failure chain lists every shorter leftover:

fail[u] = longest proper suffix of the string at u that is a prefix of some pattern,  and out[u] counts every dictionary word that is a suffix of that string.

In plain words, you never rewind the text, you never skip a dictionary word that ends here, and a missing letter is the same fallback KMP would take on a one-pattern trie. Interview sentence: "Failure is KMP's π[q-1] on the dictionary trie; BFS fills it parent-first; out[v] += out[fail[v]] is what reports nested hits."

Forgetting out[v] += out[fail[v]] drops nested words

Looking only at the node you landed on looks correct, because that node is the longest dictionary prefix you currently hold. A shorter pattern that is a suffix of that prefix lives on the failure chain, not on this node. The word ab inside xab is the classic miss. Aggregate during BFS, or walk an output-link chain at query time.

Fill missing edges or keep the while, not both halfway

Pre-filling nxt[u][c] = nxt[fail[u]][c] makes the scan one array read per character and is the listing on this page. The other school is a go(u, c) that walks fail until an edge exists, which is the same idea as KMP's inner while and is also linear by the same potential. Mixing a half-filled table with a while that assumes missing means 0 is how you loop at the root.

Why the scan is linear even with a while-fail

If you do not pre-fill edges, each text character may walk several failure links. Those walks drop to a strictly shorter string each time, and a later successful edge grows the current depth by one. Across the whole text the drops cannot outnumber the grows, so the extra hops total at most |t| plus the dictionary depth. That is KMP's potential on q, lifted to a trie.

Algorithm

  1. Insert every pattern into one trie. Start from the root for each word, create a child when the letter is new, and mark the terminal with a count or a pattern id. The trie nodes are the states of the automaton you are about to finish.
  2. BFS from the root to fill failure links. Push every child of the root with fail = 0. For each later child v reached by letter c from parent u, set fail[v] = nxt[fail[u]][c]. Parent-first order is what makes that read defined.
  3. Fill missing transitions, or keep an explicit while. On a missing letter, store nxt[u][c] = nxt[fail[u]][c] so the later scan is one array read. The other school is a go that walks fail until an edge exists, which is KMP's inner loop on the trie.
  4. Aggregate nested hits along the failure chain. During the same BFS write out[v] += out[fail[v]], or set an output link to the next terminal on that chain. Without this step a nested pattern that is only a suffix of the current node is silently dropped.
  5. Scan the text with one transition per character. Start at the root and do state = nxt[state][c] for each letter, then add out[state] (or walk output links) to record every dictionary word that ends here, overlaps included.
  6. Reuse the same states when the problem is a DP. "Build a string that avoids these words" is dp[i][state], taking automaton edges as transitions and treating terminals as forbidden (or as a sink). The automaton you just built is the state space.

Java implementation

For each pattern, indexOf / KMP separately.

JavaDictBrute.java
import java.util.*;
    public class DictBrute {
        static int hits(String t, String[] ps) {
            int c = 0;
            for (String p : ps) {
                for (int i = 0; i + p.length() <= t.length(); i++)
                    if (t.startsWith(p, i)) c++;
            }
            return c;
        }
        public static void main(String[] args) {
            System.out.println(hits("abaca", new String[] {"ab", "ba", "aba"}));
        }
        // Input : abaca vs ab, ba, aba
        // Output: 2
    }

JavaAhoCorasick.java
import java.util.*;
    public class AhoCorasick {
        static final int A = 26;
        int[][] nxt = new int[1][A];
        int[] fail, out;
        int sz = 1;
        void grow() {
            nxt = Arrays.copyOf(nxt, sz + 1);
            nxt[sz] = new int[A];
            sz++;
        }
        void add(String p) {
            int u = 0;
            for (int i = 0; i < p.length(); i++) {
                int c = p.charAt(i) - 'a';
                if (nxt[u][c] == 0) { grow(); nxt[u][c] = sz - 1; }
                u = nxt[u][c];
            }
            out = out == null ? new int[sz] : Arrays.copyOf(out, sz);
            out[u]++;
        }
        void build() {
            fail = new int[sz];
            out = Arrays.copyOf(out == null ? new int[sz] : out, sz);
            ArrayDeque<Integer> q = new ArrayDeque<>();
            for (int c = 0; c < A; c++) if (nxt[0][c] != 0) q.add(nxt[0][c]);
            while (!q.isEmpty()) {
                int u = q.poll();
                for (int c = 0; c < A; c++) {
                    int v = nxt[u][c];
                    if (v == 0) nxt[u][c] = nxt[fail[u]][c];
                    else {
                        fail[v] = nxt[fail[u]][c];
                        out[v] += out[fail[v]];
                        q.add(v);
                    }
                }
            }
        }
        long feed(String t) {
            int u = 0;
            long ans = 0;
            for (int i = 0; i < t.length(); i++) {
                u = nxt[u][t.charAt(i) - 'a'];
                ans += out[u];
            }
            return ans;
        }
        public static void main(String[] args) {
            AhoCorasick ac = new AhoCorasick();
            for (String p : new String[] {"ab", "ba", "aba"}) ac.add(p);
            ac.build();
            System.out.println(ac.feed("abaca"));
        }
        // Input : patterns ab, ba, aba; text abaca
        // Output: 2
    }

The go() fallback without pre-filling missing edges — same idea as KMP's while.

JavaAhoGo.java
public class AhoGo {
        static int go(int[][] nxt, int[] fail, int u, int c) {
            while (u > 0 && nxt[u][c] == 0) u = fail[u];
            return nxt[u][c];
        }
        public static void main(String[] args) {
            int[][] nxt = {{1, 0}, {0, 2}, {0, 0}};
            int[] fail = {0, 0, 0};
            System.out.println(go(nxt, fail, 2, 0));
        }
        // Input : tiny trie, from state 2 ask for 'a'
        // Output: 1
    }

Complexity

Time O((|t| + sum |p|) * alphabet) with filled transitions, or amortised O(|t|+sum|p|) with while-fail Space O(sum |p| * alphabet)

The trie has one new node per character of the dictionary in the worst case, so it holds O(sum |p|) nodes. The BFS visits each node and each of its σ letters once, which is O(sum |p| · σ) with filled transitions, or amortised linear in the dictionary size if you keep a while-fail instead. The text scan is then one transition per character. Aggregating out[u] += out[fail[u]] during BFS makes each text character cost a constant, not a walk down the failure chain.

Putting real numbers in: a million-character dictionary plus a million-character text, alphabet 26, is a few tens of millions of array writes to build and a million reads to scan, which is a few tens of milliseconds. Climbing fail raw at every character when many words nest can multiply that scan by the nesting depth and miss the limit. Running a separate KMP per pattern at m = 103 patterns is about a billion steps, which is the runtime this one automaton is designed to avoid.

Edge cases and pitfalls

  • Not copying out along fail
    Reporting only the terminal you landed on looks complete, because that node is the longest dictionary prefix of the text so far. A shorter pattern that is a suffix of that prefix lives on the failure chain, so ab inside xab is never counted.
    During BFS write out[v] += out[fail[v]], or store an output link to the next terminal on the chain and walk it at query time. Test a dictionary where one word is a suffix of another.
  • fail[child] using an unfilled parent fail
    A depth-first walk of the trie looks like it should fill links, because children are suffixes of their parents. Failure does not walk the trie parent; it walks a shorter string that may sit in a different branch, and a DFS can read fail[u] before BFS would have written it.
    Use a queue. Push the root's children first with fail = 0, and only process a node after its parent has been dequeued. That is the order that makes nxt[fail[u]][c] already defined.
  • nxt[0][c]==0 meaning missing vs meaning root
    Storing 0 for both "no child" and "the root" looks like a tidy default, and filling missing edges of the root to 0 is actually correct. Using 0 as a real child's index is not: you can no longer tell a missing edge from an edge back to the empty string, and the fail walk loops.
    Number nodes from 0 as the root. On a non-root, a stored 0 means "follow fail". On the root, a stored 0 means "stay", which is the empty-string self-loop for a letter the dictionary does not start with.
  • Alphabet not 'a'-'z'
    Subtracting 'a' from an uppercase letter, a digit, or a punctuation mark looks like the usual 26-way index. The result is negative or larger than 25, and the next array access throws.
    Map the real alphabet onto 0..sigma-1 at the input boundary, or store a HashMap per node if sigma is huge. The fail-fill is the same; only the child lookup changes.
  • Growing nxt incorrectly
    Allocating new int[sz+1][A] and copying the old table on every inserted character looks like the safe way to grow. Each copy walks the whole trie again, so a dictionary of length n costs O(n2) memory traffic before you even start the BFS.
    Preallocate a generous cap, or store nodes in an ArrayList and grow by doubling. The listing's grow() copies one row, not the whole table, which is the cheaper of the two honest options.

Interview follow-ups

Why BFS not DFS for failure links?

The node fail[u] represents a strictly shorter string than u, so it is an ancestor in the failure tree, not necessarily a trie-ancestor. A breadth-first walk by string length (which is trie depth) therefore finds every shorter state already filled, including nxt[fail[u]][c] if you pre-fill missing edges. A depth-first walk can ask for a failure in another branch that has not been written yet. The same reason KMP fills π from left to right: you only read borders of prefixes you have finished.

Aho vs suffix automaton?

Aho-Corasick is a dictionary matcher: the patterns are known up front and the text is a stream. A suffix automaton represents every slice of one text, and later "is this word in there?" questions walk that automaton. If the text is huge and the patterns arrive as queries, build a suffix automaton or a suffix array of the text. If the patterns are the dictionary and the text arrives online, build Aho-Corasick. They solve opposite sides of the same "many strings, one scan" feeling.

How do you reconstruct positions, not just counts?

Store pattern ids on terminals instead of (or as well as) a count. When the scan sits at text index i and the output chain reports a word of length L, that word ends at i and starts at i-L+1. Walk the output links for nested hits so a landing on aba also emits ba and a if those ids live on the chain. Aggregated out[u] is enough only when the statement asks for a total.

What is the output link?

It is the nearest terminal on the failure chain: from u, skip every non-terminal failure in one hop, then jump output[u] → output[output[u]] to visit the rest. That is the same information as walking fail, just without stopping at useless nodes. When you only need totals, folding those terminals into out[u] += out[fail[u]] during BFS is cheaper still, because the scan then never walks the chain at all.
