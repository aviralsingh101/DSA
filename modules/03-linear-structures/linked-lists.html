Linked Lists

Pointer surgery under a fixed extra-space budget: reverse a range, detect a cycle and its entry, merge two ordered lists, and clone a graph that happens to look like a list.

Medium 28 min read Prerequisites: Two Pointers linked list two pointers Floyd in-place P0

Why this exists

You are given the list 1 → 2 → 3 → 4 → 5 and asked to reverse it in place, returning the new head 5. You cannot jump to index 3 the way you would in an array; you can only follow a next pointer, and the moment you overwrite curr.next the rest of the list is gone unless you saved it. The whole family of interview questions is that constraint: rewrite pointers in O(1) extra memory on a structure you cannot index into.

They keep being asked because they punish sketchy pointer handling the way arrays punish off-by-ones, and the wrong version often looks correct on the sample. A missed save of curr.next drops the suffix and still reverses a one-node list. A cycle detector that returns the meeting point instead of the entry works whenever the stem length is a multiple of the cycle. A k-group reverse that does not first check that k nodes remain corrupts the leftover tail. On n = 10⁵ you also cannot recurse: a Java stack frame per node blows up around n = 10⁴.

Five famous problems share three moves — save the next, rewire, advance — plus one dummy node so replacing the head is the same code path as every other splice. Floyd's cycle algorithm is the one piece of theory: a pointer that walks one step and a pointer that walks two steps meet inside a cycle; reset one to the head and walk both at one step to land on the entry. Copy-list-with-random is the other classic: a HashMap is O(n) space; weaving a clone between each original, wiring randoms, then unweaving is the O(1)-space follow-up.

In a real statement the signal is a singly-linked input plus an in-place rearrangement, a cycle question, or a merge of ordered lists, usually with n ≤ 10⁵ and a constant extra-space budget. If you need random access by index, copy to an array. If you are merging k lists and k is large, that is a heap problem, not more pointer surgery.

Before you rewire curr.next, save it. After you rewire, the old successor is gone unless you held it. Every in-place list algorithm is that sentence plus a dummy node so replacing the head is not a special case.

Recognise this pattern

Say yes when you see

  • The input is a singly (or doubly) linked list and you must rearrange it in place
  • "Reverse the list" / "reverse nodes in k-group" / "reverse between left and right"
  • "Detect a cycle" or "return the node where the cycle begins"
  • "Merge two (or k) sorted lists"
  • "Copy a list that has an extra random pointer"
  • "Find the middle" / "delete the n-th from the end" — fast and slow pointers

Not this pattern when

  • You need order statistics or binary search on the values → copy to an array, or a tree
  • Random access by index is the hot path → ArrayList, not a list of nodes
  • The "list" is actually a graph with branching → BFS/DFS
  • k-list merge when k is large → the heap version on the heaps page

Constraint tell: n ≤ 10⁵ with an O(1) extra-space budget is the usual tell: you must rearrange pointers, not copy the list into an array. Recursion n frames deep blows the Java stack around n = 10⁴, so prefer the iterative reverse even when the recursive one looks shorter.

Core idea and the invariant

Iterative reverse uses three pointers. prev starts at null and will become the new head; curr starts at head and walks the still-untouched suffix. Each step first saves nxt = curr.next, then sets curr.next = prev, then advances prev = curr and curr = nxt. When curr is null, prev is the new head. Reverse-in-k-group is that same walk applied to successive slices, with a dummy node in front so the first group is not a special case. Walk k steps from the node before the group first; if you run out, leave the leftover tail in original order.

Floyd starts two pointers at the head. slow walks one step, fast walks two. If there is a cycle they eventually share a node, but that meeting point is somewhere on the cycle, not necessarily the entry. Set slow back to the head and walk both one step at a time; they meet at the entry because the stem length equals the remaining distance around the cycle. Merge of two sorted lists is a dummy plus a tail that always attaches the smaller current head. Copy-list-with-random is a HashMap from old node to new node first; weave a clone after each original only if they forbid the extra space.

Trace reverse on 1 → 2 → 3. Start with prev = null and curr on 1. Save nxt = 2, point 1 at null, then slide: prev is 1 and curr is 2. Save nxt = 3, point 2 at 1, slide onto 3. Save nxt = null, point 3 at 2, slide onto null. Return prev, which is 3, and the list is 3 → 2 → 1. Losing nxt on any of those three steps would have dropped the suffix forever.

Reverse: the chain from prev backwards is the already-reversed prefix; the chain from curr forwards is still untouched.

Floyd: after the first meeting, distance(head, entry) equals distance(meeting, entry) along the cycle. Walking both at speed 1 from those two starts collides at the entry.

In plain words, you have flipped every arrow you have already walked past, you have not yet touched anything still ahead of curr, and a dummy whose next is the real head makes "what if we replace the head?" the same four pointer writes as every other splice. If a reverse step ever overwrites curr.next without a saved nxt, the suffix is gone and the invariant is broken.

Floyd's meeting algebra

Stem length a, cycle c, meeting b into the cycle. Slow walked a+b, fast 2(a+b). The extra a+b is a whole number of laps: a+b = m c, so a = m c - b. From the meeting point, c-b more steps reach the entry, which is also a steps from the head. Resetting slow to head implements that.

Algorithm

  1. Draw the nodes and every next pointer, and put a dummy in front whenever the head might change. Without the picture, a splice that looks local silently drops a suffix.
  2. Reverse with three pointers: save nxt first, then point curr.next at prev, then slide both pointers forward. Return prev because that is the new head once curr walks off the end.
  3. For k-group, walk k nodes from groupPrev first. If you hit null, stop and leave the leftover tail alone; only then reverse that slice and stitch it back so the previous group still points at the new head.
  4. Detect a cycle with different speeds: while fast and fast.next are non-null, move slow one step and fast two. They meet inside the cycle if one exists, and the null guard is what proves the list is finite.
  5. Find the entry by resetting slow to the head after the first meeting, then walk both at one step. Returning the meeting point itself is only correct when the stem length happens to be a multiple of the cycle.
  6. Merge with a dummy and a tail so attaching the smaller current head is one assignment. When one list runs out, hang the rest on the tail and return dummy.next, not the old head.
  7. Copy random with a HashMap first, old node to new node, in two obvious passes. Mention the weave as the O(1)-space follow-up and write it only if they ask.

Java implementation

Three-pointer reverse, then k-group on top of it. The k-check before reversing is what fails on the leftover tail.

JavaListReverse.java
public class ListReverse {
        static class ListNode {
            int val;
            ListNode next;
            ListNode(int v) { val = v; }
            ListNode(int v, ListNode n) { val = v; next = n; }
        }
    
        static ListNode reverse(ListNode head) {
            ListNode prev = null, curr = head;
            while (curr != null) {
                ListNode nxt = curr.next;
                curr.next = prev;
                prev = curr;
                curr = nxt;
            }
            return prev;
        }
    
        static ListNode reverseKGroup(ListNode head, int k) {
            ListNode dummy = new ListNode(0, head);
            ListNode groupPrev = dummy;
            while (true) {
                ListNode kth = groupPrev;
                for (int i = 0; i < k && kth != null; i++) kth = kth.next;
                if (kth == null) break;
                ListNode groupNext = kth.next;
                ListNode prev = groupNext, curr = groupPrev.next;
                while (curr != groupNext) {
                    ListNode nxt = curr.next;
                    curr.next = prev;
                    prev = curr;
                    curr = nxt;
                }
                ListNode oldHead = groupPrev.next;
                groupPrev.next = kth;
                groupPrev = oldHead;
            }
            return dummy.next;
        }
    
        static String str(ListNode h) {
            StringBuilder sb = new StringBuilder();
            for (; h != null; h = h.next) {
                if (sb.length() > 0) sb.append("->");
                sb.append(h.val);
            }
            return sb.toString();
        }
    
        static ListNode build(int... a) {
            ListNode d = new ListNode(0), t = d;
            for (int v : a) { t.next = new ListNode(v); t = t.next; }
            return d.next;
        }
    
        public static void main(String[] args) {
            System.out.println(str(reverse(build(1, 2, 3, 4, 5))));
            System.out.println(str(reverseKGroup(build(1, 2, 3, 4, 5), 2)));
            System.out.println(str(reverseKGroup(build(1, 2, 3, 4, 5), 3)));
        }
        // Input : 1->2->3->4->5 ; k = 2 and k = 3
        // Output: 5->4->3->2->1
        //         2->1->4->3->5
        //         3->2->1->4->5
    }

Cycle detection, cycle entry, and merge of two sorted lists. Returning the meeting point as the entry is the bug this tab exists to prevent.

JavaListFloyd.java
public class ListFloyd {
        static class ListNode {
            int val;
            ListNode next;
            ListNode(int v) { val = v; }
            ListNode(int v, ListNode n) { val = v; next = n; }
        }
    
        static boolean hasCycle(ListNode head) {
            ListNode slow = head, fast = head;
            while (fast != null && fast.next != null) {
                slow = slow.next;
                fast = fast.next.next;
                if (slow == fast) return true;
            }
            return false;
        }
    
        static ListNode detectCycle(ListNode head) {
            ListNode slow = head, fast = head;
            boolean met = false;
            while (fast != null && fast.next != null) {
                slow = slow.next;
                fast = fast.next.next;
                if (slow == fast) { met = true; break; }
            }
            if (!met) return null;
            slow = head;
            while (slow != fast) {
                slow = slow.next;
                fast = fast.next;
            }
            return slow;
        }
    
        static ListNode mergeTwo(ListNode a, ListNode b) {
            ListNode dummy = new ListNode(0), tail = dummy;
            while (a != null && b != null) {
                if (a.val <= b.val) { tail.next = a; a = a.next; }
                else { tail.next = b; b = b.next; }
                tail = tail.next;
            }
            tail.next = (a != null) ? a : b;
            return dummy.next;
        }
    
        static String str(ListNode h) {
            StringBuilder sb = new StringBuilder();
            for (; h != null; h = h.next) {
                if (sb.length() > 0) sb.append("->");
                sb.append(h.val);
            }
            return sb.toString();
        }
    
        public static void main(String[] args) {
            ListNode n1 = new ListNode(3);
            ListNode n2 = new ListNode(2);
            ListNode n3 = new ListNode(0);
            ListNode n4 = new ListNode(-4);
            n1.next = n2; n2.next = n3; n3.next = n4; n4.next = n2;
            System.out.println(hasCycle(n1));
            System.out.println(detectCycle(n1).val);
            ListNode a = new ListNode(1, new ListNode(2, new ListNode(4)));
            ListNode b = new ListNode(1, new ListNode(3, new ListNode(4)));
            System.out.println(str(mergeTwo(a, b)));
        }
        // Input : cycle 3->2->0->-4->2... ; merge 1->2->4 and 1->3->4
        // Output: true
        //         2
        //         1->1->2->3->4->4
    }

O(n) space with a map first. The weave is the O(1)-space follow-up: clone after each original, wire randoms via orig.random.next, then split.

JavaCopyRandom.java
import java.util.HashMap;
    import java.util.Map;
    
    public class CopyRandom {
        static class Node {
            int val;
            Node next, random;
            Node(int v) { val = v; }
        }
    
        static Node copyMap(Node head) {
            if (head == null) return null;
            Map<Node, Node> map = new HashMap<>();
            for (Node p = head; p != null; p = p.next) map.put(p, new Node(p.val));
            for (Node p = head; p != null; p = p.next) {
                map.get(p).next = map.get(p.next);
                map.get(p).random = map.get(p.random);
            }
            return map.get(head);
        }
    
        static Node copyWeave(Node head) {
            if (head == null) return null;
            for (Node p = head; p != null; p = p.next.next) {
                Node cl = new Node(p.val);
                cl.next = p.next;
                p.next = cl;
            }
            for (Node p = head; p != null; p = p.next.next) {
                if (p.random != null) p.next.random = p.random.next;
            }
            Node dummy = new Node(0), tail = dummy;
            for (Node p = head; p != null; p = p.next) {
                tail.next = p.next;
                tail = tail.next;
                p.next = p.next.next;
            }
            return dummy.next;
        }
    
        public static void main(String[] args) {
            Node a = new Node(7), b = new Node(13), c = new Node(11);
            a.next = b; b.next = c;
            a.random = null; b.random = a; c.random = c;
            Node copied = copyWeave(a);
            System.out.println(copied.val + " " + copied.next.val + " " + copied.next.next.val);
            System.out.println(copied.random + " " + copied.next.random.val + " " + copied.next.next.random.val);
            System.out.println(copyMap(a).val);
        }
        // Input : 7->13->11 with randoms [null, 7, 11]
        // Output: 7 13 11
        //         null 7 11
        //         7
    }

Complexity

Time O(n) for reverse, Floyd, merge of two, copy Space O(1) extra for reverse / Floyd / merge / weave; O(n) for the HashMap copy

Reverse and k-group visit each node a constant number of times — save, rewire, advance, and at most one extra walk of k to test the group. Floyd: fast walks at most twice the stem plus one extra lap of the cycle, then both walk the stem:

T(n) = Θ(n) pointer assignments

Merge of two lists is Θ(n+m) splices. Merge of k lists by a heap is O(n log k) on the heaps page. Copy-random is two or three linear passes. At n = 10⁵ that is a few hundred thousand pointer writes, not a recursive stack of a hundred thousand frames.

Edge cases and pitfalls

  • Rewiring curr.next before saving it
    The suffix becomes unreachable the instant you overwrite curr.next. It still reverses a one-node list, which is why the sample can pass and everything longer fails.
    ListNode nxt = curr.next as the first line of the loop. Save, then rewire, then advance.
  • Returning Floyd's meeting point as the cycle entry
    LC 141 is done, LC 142 is not. The meeting point equals the entry only when the stem length happens to be a multiple of the cycle, so many samples look correct.
    Reset slow to head after they meet, walk both at one step, and return the second meeting.
  • Reversing a leftover tail in k-group
    A final group of size less than k is reversed because the loop did not check that k nodes remain. The spec says leave that tail in original order.
    Walk k steps from groupPrev first; if you hit null, break before reversing that incomplete slice.
  • Forgetting the dummy when the head can change
    Merge, delete-the-head, and the first k-group all return the old head, which now sits in the middle of the list. The rest of the splices looked local and correct.
    ListNode dummy = new ListNode(0, head); do every splice through the dummy; then return dummy.next as the real head.
  • Comparing node values instead of references in Floyd
    slow.val == fast.val on a list with duplicate values reports a false cycle, or misses a real one when two different nodes happen to share a value.
    Compare the node objects themselves: slow == fast. Values are irrelevant to the meeting test.
  • Breaking the original list in the weave copy
    clone.random is wired to an original node, or the caller's list is left interleaved with clones, because the split pass never restored orig.next.
    Set clone.random = orig.random.next so randoms stay on clones, then restore orig.next = clone.next in the same split pass.

Interview follow-ups

Why does resetting one pointer to the head find the entry?

After the first meeting, slow has walked a+b and that is a multiple of the cycle. So a more steps from the meeting point land on the entry, which is also a steps from the head. Walking both at speed 1 from those two starts implements the equality.

Can Floyd find a duplicate number in an array?

Yes, that is LC 287. An array a of n+1 values in 1..n is a functional graph i → a[i]: every index has outdegree one, so a duplicate value creates exactly one cycle. The cycle entry is the duplicate. The same code runs with slow = a[slow] and fast = a[a[fast]].

How do you reverse groups of k if k does not divide n?

Leave the leftover tail in original order, which is the LC 25 spec. From the node before the would-be group, try to walk k steps; if you cannot, stop and do not reverse. Test n=5, k=3 (answer starts 3,2,1 and ends 4,5), k=1 (identity), and k=5 (full reverse).

Map vs weave for copy-random in 25 minutes?

Write the map. Two obvious passes, old node to new node, O(n) extra memory, and you will finish. Mention the weave — clone after each original, wire randoms via orig.random.next, then split — as the O(1)-space follow-up, and write it only if they ask.

How do you merge k sorted lists?

Put the current head of each list into a min-heap and always splice the smallest, which is O(n log k) on n total nodes. Pairwise tournament merge has the same bound. Repeatedly merging into an accumulator is O(n k) and dies when k is large. Details sit on the heaps page.

Hint for LC 25 — reverse a slice with prev initialised to groupNext

Reverse in place between groupPrev.next and groupNext by running the standard reverse with prev initialised to groupNext (not null). Then every node's next already points at the correct successor, including the tail wiring to the next group. After the loop, the old group head is the new tail and the k-th node is the new head.

Hint for LC 138 weave — random of a clone is next of random of original

After the weave the list is A → A' → B → B'. The clone of X sits at X.next, so the clone of X.random sits at X.random.next. The split pass must restore A.next = B as well as collect A', otherwise you destroy the input.

Recap

  • Save, rewire, advance. Lose nxt and you lose the suffix.
  • Dummy node whenever the head might change (merge, k-group, delete).
  • Floyd detect is not Floyd entry. Reset slow to head, walk both at 1×.
  • k-group: walk k first; leftover tail stays in original order.
  • Copy random: HashMap first; weave if they forbid extra space.
