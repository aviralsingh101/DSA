Backtracking with Pruning

Backtracking is generation plus a veto: the moment a partial assignment cannot extend to a solution, you pop and try the next sibling instead of finishing the branch.

Hard 28 min read Prerequisites: Subsets, Permutations, Combinations, Bit Manipulation backtracking pruning N-Queens Sudoku bitmask P1

Why this exists

The previous page enumerates a Cartesian product. This page survives products that do not fit in memory by pruning: a constraint checked on the prefix that proves every completion is illegal. N-Queens without pruning is 16! board fillings; with column and diagonal bitmasks it is a few thousand leaves on n = 8 and a standard interview.

The same skeleton covers Sudoku (cell, row, column, box uniqueness), word search (grid DFS that unmarks on the way back), and palindrome partitioning (only cut when the piece is already a palindrome). The skill is not the skeleton — you already have it — it is choosing a cheap, complete veto.

Bitmasks turn the N-Queens veto into a few bitwise operations and make n = 14 solvable. That encoding is the one piece of this page that transfers to bitmask DP and to several Codeforces constructive searches.

A prune is a proof that the current path is dead. If the check can wait until the leaf, it is not a prune, it is a filter, and the tree will still explode.

Recognise this pattern

Say yes when you see

  • Place n non-attacking pieces, fill a grid under uniqueness constraints, or cut a string under a local predicate
  • "Restore" / "solve" / "find all valid boards / partitions"
  • The search space is a product (cells × choices) that is illegal for n without early rejection
  • You can name a constraint that depends only on the prefix: used columns, used characters, remaining unmatched opens
  • Word search / path-in-a-grid that must not reuse a cell

Not this pattern when

  • You need the count of configurations and n is large enough that DP over subsets or profile DP exists → do not backtrack
  • Any feasible solution is fine and a greedy choice property holds → greedy
  • The constraint is a numeric knapsack on n ≤ 40 → meet in the middle
  • You are searching a real graph for a shortest path → BFS, not backtracking

Constraint tell: n = 8 or 9 (N-Queens, Sudoku) is the interview signature. n = 14 N-Queens needs bitmasks. A 4×4 word-search board is fine; a 50×50 board with a long dictionary is a trie + pruning problem (LC 212), not a naive DFS.

Core idea: assign, veto, undo

The template is four lines of control flow. Pick the next decision (next row, next empty cell, next cut). Iterate the candidates. If a candidate fails the veto, skip it. Otherwise apply it, recurse, then undo. The undo is the difference between backtracking and "just recurse": the same used structure is shared across siblings, so it must be restored.

N-Queens bitmasks: row r tries every free bit of avail = all & ~(cols | d1 | d2). Placing bit b updates cols | b, (d1 | b) << 1, (d2 | b) >> 1. The shifts slide the diagonals as you move to the next row. No arrays, no O(n) attack scan.

Word search marks board[r][c] = '#' (or a used[][]) before the four recursive calls and restores the letter after. Palindrome partition precomputes isPal[i][j] in O(n²) so every cut is O(1) to validate; without that, you re-scan the piece at every node.

The interview sentence

A candidate is legal if and only if it does not violate a constraint with the prefix already chosen. Check that before the recursive call. Undo every mutation (cell, bitmask, mark) on the way back, including after a successful leaf if you are enumerating all solutions.

Pick the most constrained decision next

Sudoku is dramatically faster if you fill the cell with the fewest remaining digits, not "the next empty in row-major order". The same heuristic (minimum-remaining-values) applies to any filling problem. Interviewers love hearing the words even if they only wanted the row-major version.

Why bitmasks are enough for n <= 31

Columns and diagonals of an n-Queen board are n-bit sets. An int holds 32 bits; use a long for n up to 63. avail & -avail isolates the lowest set bit; avail -= bit (or avail &= avail-1) consumes it. That loop body is the entire branching.

Undo on every exit path

A successful leaf still shares the same board or bitmasks as its siblings. Restore every mutation after the recursive call, including after a true return if you are enumerating all solutions. The safe shape is apply, recurse, undo as three consecutive lines.

The assign / veto / undo loop

Algorithm

  1. Name the decision sequence. One queen per row; next empty Sudoku cell; next cut index; next grid step matching the next letter.
  2. Name the veto as a function of the prefix only. If you cannot check it yet, you do not have a prune.
  3. Encode the veto cheaply. Bitmasks for N-Queens; row/col/box bitsets for Sudoku; a mark on the cell for word search; isPal[i][j] for partitions.
  4. Apply, recurse, undo as three consecutive operations.
  5. For find-one, return a boolean and stop siblings on true. For find-all, collect and keep going.
  6. Precompute what you can — palindrome table, remaining digit counts.
  7. Prefer bitmasks at n ≤ 31 whenever the veto is a set of columns or used vertices.
  8. Count nodes on a 4-queen board by hand once so you believe the prune.

Java implementation

The version you can explain in sixty seconds. Each placement scans column and diagonals in O(n). Fine for n = 8; the bitmask rewrite is the follow-up.

JavaNQueensBrute.java
import java.util.ArrayList;
    import java.util.Arrays;
    import java.util.List;
    
    public class NQueensBrute {
    
        static List<List<String>> solveNQueens(int n) {
            char[][] b = new char[n][n];
            for (char[] row : b) {
                Arrays.fill(row, '.');
            }
            List<List<String>> ans = new ArrayList<>();
            go(0, b, ans);
            return ans;
        }
    
        static void go(int r, char[][] b, List<List<String>> ans) {
            int n = b.length;
            if (r == n) {
                List<String> pack = new ArrayList<>();
                for (char[] row : b) {
                    pack.add(new String(row));
                }
                ans.add(pack);
                return;
            }
            for (int c = 0; c < n; c++) {
                if (!safe(b, r, c)) {
                    continue;
                }
                b[r][c] = 'Q';
                go(r + 1, b, ans);
                b[r][c] = '.';
            }
        }
    
        static boolean safe(char[][] b, int r, int c) {
            for (int i = 0; i < r; i++) {
                if (b[i][c] == 'Q') {
                    return false;
                }
            }
            for (int i = r - 1, j = c - 1; i >= 0 && j >= 0; i--, j--) {
                if (b[i][j] == 'Q') {
                    return false;
                }
            }
            for (int i = r - 1, j = c + 1; i >= 0 && j < b.length; i--, j++) {
                if (b[i][j] == 'Q') {
                    return false;
                }
            }
            return true;
        }
    
        public static void main(String[] args) {
            System.out.println(solveNQueens(4).size());
        }
        // Input : n = 4
        // Output: 2
    }

Same tree, O(1) veto. avail & -avail peels the lowest free column. Shifts slide the diagonals to the next row.

JavaNQueensBitmask.java
public class NQueensBitmask {
    
        static int totalNQueens(int n) {
            return go(0, 0, 0, 0, n);
        }
    
        static int go(int row, int cols, int d1, int d2, int n) {
            if (row == n) {
                return 1;
            }
            int count = 0;
            int all = (1 << n) - 1;
            int avail = all & ~(cols | d1 | d2);
            while (avail != 0) {
                int bit = avail & -avail;
                avail -= bit;
                count += go(row + 1, cols | bit, (d1 | bit) << 1, (d2 | bit) >> 1, n);
            }
            return count;
        }
    
        public static void main(String[] args) {
            System.out.println(totalNQueens(4));
            System.out.println(totalNQueens(8));
        }
        // Input : 4, then 8
        // Output: 2
        //         92
    }

Two other vetoes on the same skeleton. Word search marks the cell; palindrome partition only recurses from a cut that is already a palindrome.

JavaBacktrackTemplate.java
import java.util.ArrayList;
    import java.util.List;
    
    public class BacktrackTemplate {
    
        static boolean exist(char[][] b, String word) {
            for (int r = 0; r < b.length; r++) {
                for (int c = 0; c < b[0].length; c++) {
                    if (dfs(b, r, c, 0, word)) {
                        return true;
                    }
                }
            }
            return false;
        }
    
        static boolean dfs(char[][] b, int r, int c, int k, String word) {
            if (k == word.length()) {
                return true;
            }
            if (r < 0 || c < 0 || r >= b.length || c >= b[0].length) {
                return false;
            }
            if (b[r][c] != word.charAt(k)) {
                return false;
            }
            char saved = b[r][c];
            b[r][c] = '#';
            boolean ok = dfs(b, r + 1, c, k + 1, word)
                    || dfs(b, r - 1, c, k + 1, word)
                    || dfs(b, r, c + 1, k + 1, word)
                    || dfs(b, r, c - 1, k + 1, word);
            b[r][c] = saved;
            return ok;
        }
    
        static List<List<String>> partition(String s) {
            int n = s.length();
            boolean[][] pal = new boolean[n][n];
            for (int i = n - 1; i >= 0; i--) {
                for (int j = i; j < n; j++) {
                    pal[i][j] = s.charAt(i) == s.charAt(j)
                            && (j - i < 2 || pal[i + 1][j - 1]);
                }
            }
            List<List<String>> ans = new ArrayList<>();
            cut(s, 0, pal, new ArrayList<>(), ans);
            return ans;
        }
    
        static void cut(String s, int start, boolean[][] pal, List<String> path,
                        List<List<String>> ans) {
            if (start == s.length()) {
                ans.add(new ArrayList<>(path));
                return;
            }
            for (int end = start; end < s.length(); end++) {
                if (!pal[start][end]) {
                    continue;
                }
                path.add(s.substring(start, end + 1));
                cut(s, end + 1, pal, path, ans);
                path.remove(path.size() - 1);
            }
        }
    
        public static void main(String[] args) {
            char[][] b = {
                {'A', 'B', 'C', 'E'},
                {'S', 'F', 'C', 'S'},
                {'A', 'D', 'E', 'E'},
            };
            System.out.println(exist(b, "ABCCED"));
            System.out.println(partition("aab"));
        }
        // Input : board + ABCCED; s = aab
        // Output: true
        //         [[a, a, b], [aa, b]]
    }

Complexity

Time pruned product Space O(depth)

Without a prune, N-Queens is at most n!. The diagonal veto removes a large constant; the tree is still super-exponential, which is why interviews stop at n = 9 and contests stop at n = 14 with bitmasks.

word search: O(RC · 4L) worst case

Palindrome partition is O(n · 2ⁿ) plus O(n²) to build isPal. Sudoku is a 981 product in theory and a few thousand nodes once row/col/box bitsets veto digits.

Edge cases and pitfalls

  • Checking the constraint only at the leaf
    Fill all n queens, then test the whole board. The tree is n^n, not n!.
    Veto as soon as a queen, digit or letter is placed.
  • Forgetting to unmark a cell
    Word search sets board[r][c] = '#' and returns without restoring.
    Restore after the four recursive calls, on every path.
  • Shifting diagonals the wrong way
    Illegal placements survive because attacks slide off the wrong side.
    Draw one queen at (0,1) and write the next row's bits by hand. n = 4 (answer 2) is the unit test.
  • Substring allocations inside the cut loop
    Calling s.substring before you know the piece is a palindrome.
    Test pal[start][end] first. Only then allocate.
  • Sudoku box index off by one
    r / 3 + c / 3 instead of (r / 3) * 3 + (c / 3).
    Box id is (r / 3) * 3 + (c / 3). Print it on a solved board once.

Interview follow-ups

Why do the diagonal shifts work?

A down-right diagonal has constant r - c. Moving to r+1 increases the occupied column on that diagonal by 1, which is a left shift if bit 0 is column 0. The other diagonal is constant r + c and slides the other way. Bits that shift off the ends have left the board.

Is word search BFS or DFS?

DFS with mark/unmark. BFS would need a used-set per path, and there is no shortest-path objective. LC 79 is existence, so backtracking DFS is the default.

When do I switch from backtracking to bitmask DP?

When you need a count or an optimum over subsets of n ≤ 20, and the same subset is reached by many orders. Filling under local constraints with n = 9 (Sudoku) stays backtracking.

Can I prune palindrome partition without the n^2 table?

Yes: scan the piece at each node. It is correct and slower. The table is the expected interview extra.

Hint for CF 377A — Maze

You must leave exactly k empty cells, still connected. DFS the empties from any start; the last s = empties - k cells you finish can become walls. A prefix of the same search stays connected. Do not place walls first.

Hint for LC 212 — Word Search II

A separate DFS per word dies. Insert every word into a trie. DFS each board cell once, walking the trie; prune when there is no child. Restore the board cell the same way as LC 79.

Recap

  • Assign, veto, recurse, undo. The veto is the prune.
  • N-Queens bitmasks: avail & -avail, then shift the diagonals.
  • Sudoku: next empty plus row/col/box sets.
  • Word search: mark, recurse four ways, unmark.
  • Palindrome partition: precompute isPal, cut only on true.
