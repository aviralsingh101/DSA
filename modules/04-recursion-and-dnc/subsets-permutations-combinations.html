Subsets, Permutations, Combinations

Every generation problem is include/exclude or "place the next choice", and almost every bug is a broken duplicate rule — the rules below are exact, not folklore.

Medium 28 min read Prerequisites: Recursion Fundamentals, Bit Manipulation backtracking subsets permutations bitmask dedup P0

Why this exists

"Return all subsets / permutations / combinations" is a single family. The search tree is always the same shape: at each position you either take an element or you do not, or you try every unused element as the next pick. The code is twenty lines. The reason this page is long is duplicates: the same multiset can be reached by many paths, and interviewers grade the skip rule, not the recursion.

There are two mechanical implementations and they are not interchangeable. Include/exclude (or the equivalent bitmask loop) builds subsets. Swap / used[] builds permutations. Combinations are subsets of a fixed size, generated with a start index so order does not explode into permutations. Combination-sum is the same tree with a remaining-target and a reuse policy.

Memorise the four skip predicates below as if they were an API. "Sort, then skip equals" is not a rule; it is four different rules that happen to start with a sort.

Duplicates are equal values at the same depth of the tree. Skip the second equal when its previous copy was not taken in this path; never skip across depths.

Recognise this pattern

Say yes when you see

  • "Return all subsets / all permutations / all combinations of size k"
  • "Combination sum": pick numbers that add to a target, with or without reuse
  • n ≤ 20 and you need every subset, or n ≤ 10 and you need every permutation
  • The statement says "unique" or the input contains duplicates
  • Letter combinations of a phone number, generate parentheses, restore IP addresses — the same tree with a different child-generation rule

Not this pattern when

  • You need the count of subsets with a property, not the list, and n is large → DP / knapsack
  • You need any one subset that works → you may still backtrack, but you return on the first success; or you use meet-in-the-middle / DP
  • n ≤ 40 subset-sum → meet in the middle, not 2ⁿ
  • The objects being chosen have a forced order (LIS, scheduling) → greedy or DP, not generation

Constraint tell: 2ⁿ is comfortable at n ≤ 20, tight at 22, dead at 30. n! is comfortable at n ≤ 9, optional at 10, dead at 12. If the output itself is exponential, the time lower bound is the output size — do not hunt for a polynomial.

Core idea and the exact dedup rules

Include/exclude walks indices left to right. From index i you either skip a[i] and go to i+1, or you append it, go to i+1, and pop on the way back. Every subset appears once. The bitmask form is the same tree flattened: bit j of mask m means "include a[j]".

Permutations fill positions. The swap implementation puts every remaining index into slot i by swapping a[i] with a[j] for j ≥ i, then recurses on i+1, then swaps back. The used[] implementation keeps the array intact and tracks which indices are already in the path. Both are O(n · n!) including output copies.

Dedup is a predicate on siblings, not on the whole path. Sort first so equals are adjacent. Then apply exactly one of the four rules below — mixing them is how you drop a valid subset or emit [1,2] twice.

The four skip predicates (memorise these)

Always Arrays.sort(a) first when the input can contain duplicates and the output must be unique.

  • Subsets II / combination sum II (start-index tree, each value at most once): at a fixed start, skip i when i > start && a[i] == a[i-1]. Same-depth equals share a parent; the first copy is allowed to be chosen or not, the rest must not start a new sibling.
  • Permutations II (used[] tree): skip index i when used[i], or when i > 0 && a[i] == a[i-1] && !used[i-1]. The previous equal must already be in the path; otherwise this pick is a sibling permutation of an earlier pick.
  • Combination sum (unlimited reuse): do not skip equals; recurse with start = i so you may pick a[i] again, and never pick an earlier index, so [2,3] and [3,2] cannot both appear.
  • Bitmask subsets: no skip rule. Each mask is a unique index-set. If values duplicate, two masks can have the same multiset — bitmask is the wrong tool for "unique value subsets".
Swap vs used[]

Swap mutates the array and needs no extra boolean array; the remaining suffix a[i..] is the unused set. Dedup with swap is awkward (you must skip a value already swapped into this slot). Prefer used[] the moment the input has duplicates. Prefer swap when the values are unique and you want cache-friendly in-place code.

Copy the path when you record it

ans.add(path) stores a reference. The next path.add mutates every previously stored answer. Always ans.add(new ArrayList<>(path)). This is the single most common backtracking bug in Java interviews.

Bitmasks when you do not need the lists

If you only need a count, a min, or an XOR of subsets, loop m = 0 .. (1<<n)-1 and walk set bits. No recursion, no allocation, and the inner loop is O(n) or O(popcount). This is the default at n ≤ 20 on Codeforces.

Algorithm

  1. Classify the tree. Subsets / combinations → start index. Permutations → swap or used[]. Target sum → add a remaining.
  2. Sort if the output must be unique and the input can contain duplicates.
  3. Write the skip predicate for that tree before any other line. Do not improvise a third rule.
  4. Record a copy of the path at the right moment: leaf for permutations and combinations of size k; every node (or the leaf of include/exclude) for subsets.
  5. Push, recurse, pop. The pop is mandatory even on early returns; a finally-shaped pair of lines, not a hope.
  6. For unlimited combination-sum, recurse with start = i and subtract a[i]. Guard remain < 0 as a prune.
  7. Prefer a bitmask loop when you need a numeric aggregate over subsets, not the lists themselves.
  8. Price the output. If you emit k arrays of length n, you have already paid O(kn); the recursion is not the cost.

Java implementation

The loop you write when values are unique and you want every subset. No stack, no path copies until you decide to materialise one.

JavaSubsetsBrute.java
import java.util.ArrayList;
    import java.util.List;
    
    public class SubsetsBrute {
    
        static List<List<Integer>> subsets(int[] a) {
            int n = a.length;
            List<List<Integer>> ans = new ArrayList<>();
            for (int m = 0; m < (1 << n); m++) {
                List<Integer> path = new ArrayList<>();
                for (int i = 0; i < n; i++) {
                    if ((m & (1 << i)) != 0) {
                        path.add(a[i]);
                    }
                }
                ans.add(path);
            }
            return ans;
        }
    
        public static void main(String[] args) {
            System.out.println(subsets(new int[] {1, 2, 3}));
        }
        // Input : [1, 2, 3]
        // Output: [[], [1], [2], [1, 2], [3], [1, 3], [2, 3], [1, 2, 3]]
    }

Subsets II and Permutations II with the exact skip predicates. Sort is not optional.

JavaSubsetsOptimal.java
import java.util.ArrayList;
    import java.util.Arrays;
    import java.util.List;
    
    public class SubsetsOptimal {
    
        static List<List<Integer>> subsetsWithDup(int[] a) {
            Arrays.sort(a);
            List<List<Integer>> ans = new ArrayList<>();
            goSub(a, 0, new ArrayList<>(), ans);
            return ans;
        }
    
        static void goSub(int[] a, int start, List<Integer> path, List<List<Integer>> ans) {
            ans.add(new ArrayList<>(path));
            for (int i = start; i < a.length; i++) {
                if (i > start && a[i] == a[i - 1]) {   // Subsets II skip
                    continue;
                }
                path.add(a[i]);
                goSub(a, i + 1, path, ans);
                path.remove(path.size() - 1);
            }
        }
    
        static List<List<Integer>> permuteUnique(int[] a) {
            Arrays.sort(a);
            List<List<Integer>> ans = new ArrayList<>();
            goPerm(a, new boolean[a.length], new ArrayList<>(), ans);
            return ans;
        }
    
        static void goPerm(int[] a, boolean[] used, List<Integer> path, List<List<Integer>> ans) {
            if (path.size() == a.length) {
                ans.add(new ArrayList<>(path));
                return;
            }
            for (int i = 0; i < a.length; i++) {
                if (used[i]) {
                    continue;
                }
                if (i > 0 && a[i] == a[i - 1] && !used[i - 1]) {  // Perm II skip
                    continue;
                }
                used[i] = true;
                path.add(a[i]);
                goPerm(a, used, path, ans);
                path.remove(path.size() - 1);
                used[i] = false;
            }
        }
    
        public static void main(String[] args) {
            System.out.println(subsetsWithDup(new int[] {1, 2, 2}));
            System.out.println(permuteUnique(new int[] {1, 1, 2}));
        }
        // Input : [1,2,2] and [1,1,2]
        // Output: [[], [1], [1, 2], [1, 2, 2], [2], [2, 2]]
        //         [[1, 1, 2], [1, 2, 1], [2, 1, 1]]
    }

Unlimited reuse versus 0/1. The only structural difference is i versus i+1 and whether equals are skipped.

JavaCombinationSum.java
import java.util.ArrayList;
    import java.util.Arrays;
    import java.util.List;
    
    public class CombinationSum {
    
        /** Reuse allowed. Candidates are usually unique. */
        static List<List<Integer>> combinationSum(int[] a, int target) {
            Arrays.sort(a);
            List<List<Integer>> ans = new ArrayList<>();
            go(a, 0, target, new ArrayList<>(), ans);
            return ans;
        }
    
        static void go(int[] a, int start, int remain, List<Integer> path, List<List<Integer>> ans) {
            if (remain == 0) {
                ans.add(new ArrayList<>(path));
                return;
            }
            for (int i = start; i < a.length && a[i] <= remain; i++) {
                path.add(a[i]);
                go(a, i, remain - a[i], path, ans);   // reuse: start stays i
                path.remove(path.size() - 1);
            }
        }
    
        /** Each index at most once; input may contain duplicates. */
        static List<List<Integer>> combinationSum2(int[] a, int target) {
            Arrays.sort(a);
            List<List<Integer>> ans = new ArrayList<>();
            go2(a, 0, target, new ArrayList<>(), ans);
            return ans;
        }
    
        static void go2(int[] a, int start, int remain, List<Integer> path, List<List<Integer>> ans) {
            if (remain == 0) {
                ans.add(new ArrayList<>(path));
                return;
            }
            for (int i = start; i < a.length && a[i] <= remain; i++) {
                if (i > start && a[i] == a[i - 1]) {
                    continue;
                }
                path.add(a[i]);
                go2(a, i + 1, remain - a[i], path, ans);
                path.remove(path.size() - 1);
            }
        }
    
        public static void main(String[] args) {
            System.out.println(combinationSum(new int[] {2, 3, 6, 7}, 7));
            System.out.println(combinationSum2(new int[] {2, 1, 2, 5}, 5));
        }
        // Input : candidates [2,3,6,7] target 7; [2,1,2,5] target 5
        // Output: [[2, 2, 3], [7]]
        //         [[1, 2, 2], [5]]
    }

Complexity

Time O(n * 2^n) / O(n * n!) Space O(n) plus output

Subsets: 2ⁿ nodes if you recurse include/exclude, or 2ⁿ masks. Materialising each subset of average size n/2 costs another O(n), hence O(n · 2ⁿ).

permutations = n! leaves, O(n) work to copy each ⇒ O(n · n!)

Combinations of size k produce C(n,k) leaves. Combination sum is output-sensitive and can be exponential in the target when 1 is a candidate.

The skip rules do not change the worst-case class; they only remove duplicate leaves. Sorting is O(n log n) and is dominated.

Edge cases and pitfalls

  • Storing the path by reference
    ans.add(path) then path.add(x). Every stored list mutates. The judge shows n copies of the last path.
    ans.add(new ArrayList<>(path)) at every record point.
  • The wrong skip predicate
    Using !used[i-1] on a start-index tree, or i > start && a[i]==a[i-1] on a permutation tree.
    Subsets II / Comb Sum II: same-depth skip via i > start. Permutations II: previous equal must already be used. Do not mix.
  • Forgetting to sort before skipping
    The skip looks at a[i-1], which is only the previous equal after a sort. Unsorted [2,1,2] will emit duplicate subsets.
    Arrays.sort(a) is part of the contract of every unique-output generator except pure bitmask-on-unique-indices.
  • Reuse going backwards
    Combination-sum with start = 0 on every call, so [2,3] and [3,2] both appear.
    Never decrease start. Unlimited reuse keeps start = i; 0/1 use advances to i+1.
  • Bitmask on duplicate values when uniqueness is required
    Looping 0 .. 2^n-1 on [1,2,2] and dumping every mask. [1,2] appears twice.
    Bitmasks identify index-sets. For unique value-subsets, use the start-index tree. For unique index-sets, bitmask is correct and simpler.

Interview follow-ups

Why is !used[i-1] the right permutation skip?

Equals are adjacent after sorting. If a[i-1] is unused, then this call is trying to pick the second equal before the first, at the same path prefix — a sibling of a permutation you already produced (or will produce) by picking the first equal first. Forcing used[i-1] linearises the equals: they may only be taken left-to-right.

Can I dedup by stuffing paths into a Set<List>?

Yes, and it is correct, and it is the wrong answer. It costs a hash of every path and hides a broken generator. The skip rules remove the duplicates at the source in O(1) per sibling. Interviewers ask you to write the rule.

Swap or used[] for unique permutations?

Swap. There is nothing to skip. used[] is extra memory and extra branches. Use swap until the input has duplicates, then switch — swap-plus-skip is easy to get wrong because the suffix is no longer a clean unused multiset after previous swaps.

When does combination sum become DP?

The moment they ask for the number of combinations (order irrelevant) and n or the target is large. That is unbounded knapsack. If they want the lists, you are stuck with output-sensitive backtracking no matter how large the target is.

Hint for LC 47 — why used[i-1] must be true

Take [1a, 1b, 2]. The permutations that start with 1 must all use 1a before 1b. If you allow a path to pick 1b while 1a is still free, you rebuild the same sequences the 1a-first branch already emitted. The predicate !used[i-1] is exactly "I am picking this equal while the previous equal is still free" — the sibling you must kill.

Hint for LC 40 — combination sum II

This is Subsets II plus a remaining-target prune. Sort, walk i from start, skip i > start && a[i]==a[i-1], recurse i+1, and bail when a[i] > remain (legal only because you sorted). Reuse is forbidden, so start must advance.

Recap

  • Subsets = include/exclude or bitmasks. Permutations = swap or used[].
  • Combinations keep a start index so order cannot explode.
  • Subsets II skip: i > start && a[i]==a[i-1].
  • Permutations II skip: a[i]==a[i-1] && !used[i-1].
  • Combination sum: reuse keeps start = i; 0/1 uses i+1 plus the Subsets II skip.
  • Always copy the path when you record it.
