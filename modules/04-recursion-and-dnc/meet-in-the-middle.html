Meet in the Middle

When n is 40, 2^n is dead and n/2 is 20: enumerate both halves, then match in the middle with a sort and a binary search.

Hard 24 min read Prerequisites: Subsets, Permutations, Combinations, Binary Search Basics meet in the middle subset sum 4-sum P2

Why this exists

You are given n = 40 integers and a target, and you must decide whether some subset adds to that target. Subset sum on n = 40 is the poster child. 240 is a trillion. 220 is a million. Split the array, enumerate every subset sum of each half, and ask whether a left sum plus a right sum hits the target. The ask is a sort plus a binary search, which is how 2n/2 becomes the running time.

The same split turns 4-sum into two 2-sums: all pairwise sums of the first half of the variables versus all pairwise sums of the second. You are given four arrays of length 400 and you must decide whether some a+b+c+d hits a target; n^3 is too slow, n^2 pairwise maps fit. It also solves closest subsequence sum (LC 1755) and the Codeforces problems whose constraint line is n ≤ 40.

Meet-in-the-middle is not a clever search. It is the observation that a Cartesian product A × B can be enumerated from both sides when each factor is about the square root of a product you cannot afford. Split, list every left sum, list every right sum, then ask whether some pair adds to the target. The listing is a bitmask loop you already know; the interview is the join, and forgetting the empty subset is the bug that hides a target sitting entirely in one half.

2n = 2n/2 × 2n/2. Enumerate each factor, then join with a sort and a binary search. The join, not the enumeration, is where the bugs live.

Recognise this pattern

Say yes when you see

  • n ≤ 40 (or 36, 42) and a subset / assignment whose naive cost is 2^n
  • 4-sum over four independent arrays when n^3 is too slow and n^2 is fine
  • "Closest subsequence sum to a target" with n ≤ 40
  • Two independent choices (left path / right path) that combine with XOR or addition
  • The statement offers n ≤ 20 as a special case and n ≤ 40 as the full constraint

Not this pattern when

  • n ≤ 20 → plain bitmask; MITM is extra code for no gain
  • n ≤ 80 with small sums → knapsack DP on the value
  • You need the subset reconstructed and have not planned how to store the witness
  • The combine is not a group operation and you cannot sort either half

Constraint tell: n ≤ 40 with a subset-sum flavour is the tell. 220 ≈ 1e6, times a log, fits in a second. 225 is the edge; 230 is a memory problem (an int[] of length 230 is 4 GB).

Core idea: enumerate halves, then join

Split a[0..n) into L = a[0..n/2) and R = a[n/2..n). Enumerate every subset sum of L with a bitmask loop, same for R, including mask 0 so the empty half is present. Sort the left sums. For each right sum y, binary-search target - y (exact) or the closest values (closest-sum). On [2, 4, 5 | 1, 3, 7] targeting 10, the right sum 10 pairs with left 0 and that is a real subset.

4-sum over four arrays is the same picture with pairwise sums in place of subset sums: build every a[i]+b[j], then probe with target-(c[k]+d[l]). 4-sum over one array of n numbers is n^3 after a sort; MITM is the right tool when you have four independent arrays of size n ≈ 400, where n^2 is a 160 000-entry map and n^3 would be tens of millions.

Memory is the silent constraint. Two arrays of 220 ints are 8 MB and fit comfortably; two arrays of boxed Long keys in a HashMap do not, because each entry carries object headers. Store witnesses (the mask next to the sum) only when the problem asks for the subset, and otherwise keep a sorted long[]. At n = 40 that array is a million entries, not a memory problem and not a reason to reach for a map.

Every subset of the whole array is a subset of the left half plus a subset of the right half, including the two empty ones. Enumerate both families and join a pair of sums in log time, and you have enumerated 2^n subsets in 2^{n/2} log time.

Two pointers for a range join

Sorted left sums, walk right sums, maintain a window of left values in [L - y, R - y]. Total join is linear after the sort. Use this when you count subsets with sum in a range.

Empty subsets are real

Mask 0 is sum 0 on each half. Forgetting it drops "the target lives entirely in one half" and the empty-empty case for target 0. Start the bitmask loop at 0, not 1.

Why not three-way split?

A 3-way split is 3 × 2^{n/3} plus a harder join. Two-way is the default; three-way shows up when 2^{n/2} does not fit and the join can be hashed.

The split-enumerate-join pipeline

Algorithm

  1. Confirm n is in the 30–42 window and naive 2^n is impossible, because 2^40 is a trillion loop iterations.
  2. Split at n/2. Uneven 20+21 is fine: one extra bit is still only about a million masks.
  3. Enumerate both halves with a bitmask loop. Include mask 0 so a target that lives in one half is not lost. Use long for sums.
  4. Sort one side, usually the left sums, so each right value is one binary search instead of a linear scan.
  5. Join. For each right sum y, search target - y in the sorted left array and treat a non-negative index as a hit.
  6. Keep the empty-empty case. Target 0 is true because both empty subsets sum to zero when taken together.
  7. If you need the subset, store the mask next to the sum, or re-enumerate the winning half.
  8. Mind memory: 2^{n/2} longs plus a sort. Boxed HashMap keys are optional only at n ≤ 36, where 2^18 entries still fit.

Java implementation

The oracle. Correct, and the reason n = 40 is impossible.

JavaMitmBrute.java
public class MitmBrute {
    
        static boolean subsetSum(int[] a, long target) {
            int n = a.length;
            for (int m = 0; m < (1 << n); m++) {
                long s = 0;
                for (int i = 0; i < n; i++) {
                    if ((m & (1 << i)) != 0) {
                        s += a[i];
                    }
                }
                if (s == target) {
                    return true;
                }
            }
            return false;
        }
    
        public static void main(String[] args) {
            System.out.println(subsetSum(new int[] {2, 4, 5, 1, 3, 7}, 10));
        }
        // Input : [2, 4, 5, 1, 3, 7], target 10
        // Output: true
    }

Enumerate halves, sort the left, binary-search each complement. Arrays.binarySearch returns a non-negative index on a hit.

JavaMitmOptimal.java
import java.util.Arrays;
    
    public class MitmOptimal {
    
        static boolean subsetSum(int[] a, long target) {
            int n = a.length;
            int mid = n / 2;
            long[] left = enumSums(a, 0, mid);
            long[] right = enumSums(a, mid, n);
            Arrays.sort(left);
            for (long y : right) {
                if (Arrays.binarySearch(left, target - y) >= 0) {
                    return true;
                }
            }
            return false;
        }
    
        static long[] enumSums(int[] a, int from, int to) {
            int m = to - from;
            long[] sums = new long[1 << m];
            for (int mask = 0; mask < (1 << m); mask++) {
                long s = 0;
                for (int i = 0; i < m; i++) {
                    if ((mask & (1 << i)) != 0) {
                        s += a[from + i];
                    }
                }
                sums[mask] = s;
            }
            return sums;
        }
    
        public static void main(String[] args) {
            System.out.println(subsetSum(new int[] {2, 4, 5, 1, 3, 7}, 10));
            System.out.println(subsetSum(new int[] {2, 4, 5, 1, 3, 7}, 8));
        }
        // Input : [2,4,5,1,3,7] targets 10 and 8
        // Output: true
        //         true
    }

Closest subsequence sum, and 4-sum over four arrays via pairwise halves.

JavaMitmTemplate.java
import java.util.Arrays;
    import java.util.HashMap;
    import java.util.Map;
    
    public class MitmTemplate {
    
        static int closestSum(int[] a, int target) {
            int n = a.length, mid = n / 2;
            long[] left = enumSums(a, 0, mid);
            long[] right = enumSums(a, mid, n);
            Arrays.sort(left);
            long best = Long.MAX_VALUE / 4;
            int ans = 0;
            for (long y : right) {
                int i = lowerBound(left, target - y);
                for (int k = i - 1; k <= i; k++) {
                    if (k < 0 || k >= left.length) {
                        continue;
                    }
                    long s = left[k] + y;
                    long d = Math.abs(s - target);
                    if (d < best) {
                        best = d;
                        ans = (int) s;
                    }
                }
            }
            return ans;
        }
    
        static int lowerBound(long[] a, long x) {
            int lo = 0, hi = a.length;
            while (lo < hi) {
                int mid = lo + (hi - lo) / 2;
                if (a[mid] < x) {
                    lo = mid + 1;
                } else {
                    hi = mid;
                }
            }
            return lo;
        }
    
        static long[] enumSums(int[] a, int from, int to) {
            int m = to - from;
            long[] sums = new long[1 << m];
            for (int mask = 0; mask < (1 << m); mask++) {
                long s = 0;
                for (int i = 0; i < m; i++) {
                    if ((mask & (1 << i)) != 0) {
                        s += a[from + i];
                    }
                }
                sums[mask] = s;
            }
            return sums;
        }
    
        /** Four independent arrays: exists a+b+c+d == target? */
        static boolean fourSumHalves(int[] A, int[] B, int[] C, int[] D, int target) {
            Map<Integer, Integer> left = new HashMap<>();
            for (int a : A) {
                for (int b : B) {
                    left.merge(a + b, 1, Integer::sum);
                }
            }
            for (int c : C) {
                for (int d : D) {
                    if (left.containsKey(target - c - d)) {
                        return true;
                    }
                }
            }
            return false;
        }
    
        public static void main(String[] args) {
            System.out.println(closestSum(new int[] {2, 4, 5, 1, 3, 7}, 10));
            System.out.println(fourSumHalves(
                    new int[] {1, 2}, new int[] {-2, -1},
                    new int[] {-1, 2}, new int[] {0, 2}, 0));
        }
        // Input : closest to 10; four arrays target 0
        // Output: 10
        //         true
    }

Complexity

Time O(2^{n/2} * n) Space O(2^{n/2})

Each half has size n/2, so each bitmask loop is O(2^{n/2} · n/2) if you walk bits, or O(2^{n/2}) if you use SOS / Gray-code incremental adds. At n = 40 that is about a million masks per side, not a trillion.

sort 2^{n/2} sums + 2^{n/2} binary searches = O(2^{n/2} n)

4-sum over four arrays of length m is O(m²) time and memory for the map of pairwise sums. That is why m ≤ 400 is the usual constraint: 160 000 map entries fit, while a four-nested loop does not.

Edge cases and pitfalls

  • Forgetting mask 0
    Looping mask = 1 .. 2^m-1, so sum 0 is missing. Target that lives in one half, or target 0, is reported absent.
    Start the bitmask loop at 0. The empty subset is a legitimate half and sum 0 must stay in the array.
  • int sums on large values
    n = 40, a[i] = 1e9, a subset sum is 4e10. Signed 32-bit wrap. Wrong misses that look like ordinary absent targets.
    long[] sums and a long target from the first line, before any addition can wrap.
  • binarySearch confusion
    Treating a negative Arrays.binarySearch return as a valid index, or using it as "closest" without decoding the insertion point. A miss still returns a number, so the code compiles and looks like a hit.
    Existence: >= 0 is a hit. Closest: write your own lower_bound and inspect both neighbours.
  • HashMap of 2^{20} boxed Longs
    A HashMap<Long, Integer> of 2^{20} keys makes memory and GC explode, even though the algorithm is otherwise right. A long[] plus a sort is smaller and faster.
    Prefer sorted primitive arrays. Hash only the pairwise 4-sum side, where m^2 is about 1e5 entries.
  • Splitting 4-sum on one array the MITM way without handling index reuse
    Pairwise sums from the same array can pick the same index twice, so a hit looks valid even though one element was spent on both halves.
    Either use four independent arrays (LC 454), or generate pairs as (i, j) with i < j and reject overlapping index pairs at join time.

Interview follow-ups

Why not just knapsack DP?

If the sums are bounded by S and nS fits in time and memory, knapsack DP is simpler and often faster. MITM wins when S is 40 * 1e9 and n is 40: the value dimension is unusable (a 4e10-long array), while the index dimension splits cleanly into two halves of twenty.

Can I recover the subset?

Store (sum, mask) pairs. On a hit, the two masks translate back to indices in each half. Or, once you know the two sums, re-enumerate the half (2^{20}) to find a mask that produces them. The second uses no extra memory and is the version you write when the judge only asked for existence first.

What is the 4-sum-over-halves trick on one array?

Generate all pair sums with i < j from the left n/2 indices, all pair sums from the right n/2 indices, and join. Pairs that need two left and two right indices are covered; pairs that sit entirely in one half must be counted inside that half. It is messier than four arrays, which is why LC 18 stays n^3.

Gray codes and incremental sums?

Walking masks in Gray-code order adds or removes one element per step, so each half is O(2^{n/2}) additions instead of O(n 2^{n/2}) bit walks. That factor of n/2 matters at n = 42, where you are already near the time limit; it is unnecessary at n = 36, where a plain bitmask loop already finishes.

Hint for CF 888E — Maximum Subsequence

Maximise a subset sum modulo m, n ≤ 35. Enumerate left and right sums already reduced modulo m, sort the left. For each right value y, the best left x is the largest x ≤ m-1-y (so x+y < m), or the largest x at all (wrap). Two binary searches per y, plus the two empty-half candidates.

Hint for LC 2035 — minimise partition difference

You must pick exactly n/2 elements into one side. Split the array in half; for each half enumerate sums grouped by how many items you picked. Join a left pick of k with a right pick of n/2-k. Closest total to sum/2 wins. This is MITM with an extra size coordinate.

Recap

  • n ≤ 40 subset-sum → split, enumerate, join.
  • Include mask 0 on both halves.
  • Sums are long. Sort one side; binary-search the complement.
  • 4-sum over four arrays is pairwise sums, same join.
  • This is not divide and conquer. No recurrence, one join.
