XOR Trie (Binary Trie)

A 2-child trie on bits, MSB first: to maximise XOR, greedily take the opposite bit whenever that child exists.

Hard 24 min read Prerequisites: Trie, Bit Manipulation XOR trie binary trie P1

Why this exists

Maximum XOR of two numbers in an array is not a sort+two-pointer problem in the usual way: XOR does not respect order. The greedy that works is bitwise, from bit 31 down: given a prefix of x, you want the other number to have the opposite bit. A binary trie of the inserted numbers tells you in O(1) whether that opposite child exists.

The same structure answers max XOR with a query value, max XOR of a subarray (insert prefix XORs), and CF 706D Vasiliy's Multiset (insert/delete + max XOR with x). It is the bit analogue of a BST on the numeric order of the 32-bit strings.

Insert is 32 steps of creating next[bit]. Query is 32 steps of preferring opposite. Counts on nodes support delete. Off-by-one on signed ints: treat bits as unsigned with >>> or a mask, or work in 30 bits if values are 1e9.

XOR is maximised by making each bit 1 from the MSB down, independently of lower bits in the greedy sense: at bit k, if the opposite child exists, take it. The trie is the existence oracle for those children.

Recognise this pattern

Say yes when you see

  • Maximum XOR of two numbers in an array (LC 421)
  • Max XOR of a subarray (prefix XOR + query)
  • Insert / delete / max XOR with x (CF 706D)
  • Two numbers from two arrays maximising XOR
  • Bitwise greedy that needs "does a number with this prefix exist?"

Not this pattern when

  • Maximum sum / min difference → sort, not XOR trie
  • 26-letter prefixes → ordinary trie
  • n=20, brute 2^n is enough
  • You need the k-th XOR, not the max → extra counts on nodes, still this trie

Constraint tell: n ≤ 1e5, values ≤ 1e9 so 30 bits (or 31). O(n * BITS) time and nodes. Use cnt if you delete. Java ints: bit 31 is the sign; for non-neg values loop b=30..0.

Core idea and the invariant

Node { Node[] ch = new Node[2]; int cnt; }. insert(x): from b=30..0, bit=(x>>b)&1, create child, cur=child, cnt++. queryMax(x): from b=30..0, want=1-bit, if child want exists and cnt>0 take it and set that bit in ans, else take bit.

For max pair: insert a[0], for i=1..n-1 ans=max(ans, queryMax(a[i])), insert a[i]. For subarray: same on prefix XOR array. Delete: walk and cnt-- (optionally drop cnt==0).

Each root-to-node path is a bit prefix of at least one stored number. queryMax walks a path that maximises XOR with x bit by bit.

at bit b: if opposite child exists, take it (that bit of XOR is 1)

Algorithm

  1. BITS=30 (or 31). Node with ch[2] and cnt.
  2. insert(x): for b=BITS-1..0, bit=(x>>b)&1, create, cur=ch[bit], cnt++.
  3. queryMax(x): want=bit^1; if ch[want]!=null take want and set ans|=(1<
  4. Max pair: insert as you go, or insert all then query all.
  5. Subarray: insert 0 first (empty prefix), then each prefix XOR.
  6. Delete: cnt-- along the path of x.

Java implementation

JavaXorPairBrute.java
public class XorPairBrute {
        static int maxXor(int[] a) {
            int best = 0;
            for (int i = 0; i < a.length; i++)
                for (int j = i + 1; j < a.length; j++)
                    best = Math.max(best, a[i] ^ a[j]);
            return best;
        }
        public static void main(String[] args) {
            System.out.println(maxXor(new int[]{3, 10, 5, 25, 2, 8}));
        }
        // Input : LC 421 sample
        // Output: 28
    }
JavaXorTrie.java
public class XorTrie {
        static class Node {
            Node[] ch = new Node[2];
            int cnt;
        }
        final Node root = new Node();
        static final int BITS = 30;
    
        void insert(int x) {
            Node cur = root;
            cur.cnt++;
            for (int b = BITS - 1; b >= 0; b--) {
                int bit = (x >> b) & 1;
                if (cur.ch[bit] == null) cur.ch[bit] = new Node();
                cur = cur.ch[bit];
                cur.cnt++;
            }
        }
        int queryMax(int x) {
            if (root.cnt == 0) return 0;
            Node cur = root;
            int ans = 0;
            for (int b = BITS - 1; b >= 0; b--) {
                int bit = (x >> b) & 1, want = bit ^ 1;
                if (cur.ch[want] != null && cur.ch[want].cnt > 0) {
                    ans |= 1 << b;
                    cur = cur.ch[want];
                } else {
                    cur = cur.ch[bit];
                }
            }
            return ans;
        }
        public static void main(String[] args) {
            int[] a = {3, 10, 5, 25, 2, 8};
            XorTrie t = new XorTrie();
            int best = 0;
            t.insert(a[0]);
            for (int i = 1; i < a.length; i++) {
                best = Math.max(best, t.queryMax(a[i]));
                t.insert(a[i]);
            }
            System.out.println(best);
        }
        // Input : 3 10 5 25 2 8
        // Output: 28
    }
JavaMaxXorSubarray.java
public class MaxXorSubarray {
        static class Node { Node[] ch = new Node[2]; }
        static Node root = new Node();
        static void insert(int x) {
            Node cur = root;
            for (int b = 30; b >= 0; b--) {
                int bit = (x >> b) & 1;
                if (cur.ch[bit] == null) cur.ch[bit] = new Node();
                cur = cur.ch[bit];
            }
        }
        static int queryMax(int x) {
            Node cur = root;
            int ans = 0;
            for (int b = 30; b >= 0; b--) {
                int bit = (x >> b) & 1, want = bit ^ 1;
                if (cur.ch[want] != null) { ans |= 1 << b; cur = cur.ch[want]; }
                else cur = cur.ch[bit];
            }
            return ans;
        }
        public static void main(String[] args) {
            int[] a = {1, 2, 3, 4};
            insert(0);
            int pref = 0, best = 0;
            for (int x : a) {
                pref ^= x;
                best = Math.max(best, queryMax(pref));
                insert(pref);
            }
            System.out.println(best);
        }
        // Input : [1,2,3,4] max subarray XOR
        // Output: 7
    }

Complexity

Time O(n * BITS) Space O(n * BITS) nodes worst case

Each insert/query walks BITS nodes, creating at most BITS new nodes. BITS=30, n=1e5 is 3e6 steps.

T = O(n B), S = O(n B), B ≈ 30

Brute pairs are O(n^2). Hashing does not help maximisation.

Edge cases and pitfalls

  • Signed shift on negative numbers
    >> sign-extends; bit 31 pollutes the walk if you use 32 bits on negatives.
    Non-neg constraints: loop 30..0. Else >>> or store as long.
  • Query on an empty trie
    NPE walking null children, or XOR with 0 pretending a number exists.
    cnt on root, or insert a dummy only when the problem allows 0.
  • Forgetting to insert 0 as empty prefix
    Max subarray XOR misses prefixes that start at index 0 (XOR of a prefix with 0).
    insert(0) before the loop.
  • Delete without cnt
    Removing a number that shared prefixes with another wipes the sibling's path.
    cnt++ on insert, cnt-- on delete, treat cnt==0 as missing.
  • Preferring the same bit for max XOR
    You minimise that bit of the XOR. Answer too small.
    want = bit ^ 1. Same bit is the fallback, and the rule for min XOR.

Interview follow-ups

Why is bit-greedy optimal?

Bit b is worth 2^b, more than 2^b-1+...+1. If you can set it, you always should, regardless of lower bits. The trie only tells you whether any stored number realises that opposite bit given the bits already chosen (which are a prefix constraint).

Max subarray XOR vs max pair XOR?

Subarray XOR is pref[r]^pref[l-1]. Insert prefix XORs into the trie, query the current prefix. That is max pair on the prefix array, including 0.

CF 706D operations?

Insert x, delete x (cnt), query max XOR with x. Same trie, watch cnt so two equal inserts need two deletes.

Persistent XOR trie?

On insert, copy the O(BITS) nodes on the path. Version i is the trie of the first i numbers. Query a range of versions for [L,R] problems.

Recap

  • Bits MSB first, two children 0/1.
  • Max XOR: prefer the opposite bit if that child exists.
  • O(n B) with B~30.
  • cnt for delete and empty checks.
  • Prefix XOR + trie for max subarray XOR; insert 0 first.
