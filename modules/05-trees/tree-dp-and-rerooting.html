Tree DP & Rerooting

One DFS computes every subtree answer; a second DFS reroots, combining "down" with "the rest of the tree" so every vertex can be treated as the root in O(n).

Hard 30 min read Prerequisites: Binary Tree Problem Patterns, DFS & Components tree DP rerooting P1

Why this exists

You are given a tree of 200000 vertices and asked, for every vertex, the sum of its distances to all the others. The obvious method roots the tree at vertex 0 and walks it, then roots it at vertex 1 and walks it again, and so on. Each walk costs a full pass, so two hundred thousand walks are about 4×10⁶ steps and the judge will not wait. The interview version of diameter hides the same trap: one global number needs one walk, but "the longest path starting at every vertex" is n separate questions and will not survive a naive restart.

Tree DP answers the rooted version first. A down DFS, starting at an arbitrary root, writes a summary of each subtree: its size, the sum of distances inside it, or the longest downward spine. That already answers the question at the chosen root. Rerooting is the second walk, and it is the whole point of this page: when the root slides from u to a child v, you do not recompute those subtree summaries. You recompute only the outside — everything that is not in v's subtree — and combine it with the down-summary you already have. For sums that combination is a closed formula; for maxima you keep the top two child contributions so the excluded child is not reused as its own outside.

In a statement the tell is "for every vertex" sitting next to n ≤ 2×10⁵ on an undirected tree of n - 1 edges. LC 834 (sum of distances), CF 219D (choose a capital), and "height if we root here" are the cluster. If the merge has no inverse, rerooting still works, but you must rebuild the outside from siblings instead of subtracting, which is why the top-two trick exists.

The down DFS answers the question as if one chosen vertex were the root. Rerooting reuses those subtree summaries and only recomputes the outside contribution when the root slides to a child, so every vertex's answer is constant extra work after one linear preprocess.

Core idea and the invariant

The first walk is ordinary subtree DP. dfs1(u, p) skips the parent, then for each child v folds v's summary into u. For sum of distances you store two arrays: sz[u] is the number of vertices in u's subtree, starting at 1 and adding each sz[v], and down[u] is the sum of distances from u to those vertices, built as down[u] += down[v] + sz[v] because every node in v's subtree is one edge farther from u than from v. After this pass, ans[root] = down[root] is the real answer at the chosen root, and every down[u] and sz[u] is finished. Those two arrays are not recomputed later.

When the root moves from u to a child v, the vertices that change distance are easy to name. Everyone in v's subtree, sz[v] of them, is now one closer. Everyone else, n - sz[v] vertices, is now one farther. The new answer is therefore the old answer plus (n - sz[v]) - sz[v], which is ans[u] + n - 2×sz[v]. That is the only number the second DFS writes: the outside contribution at v. It does not rebuild down[], and it does not recount subtree sizes. For a maximum instead of a sum there is no subtraction, so at u you keep the best and second-best child depths and give v whichever of those two is not v itself, plus the outside already known at u.

Take the five-node tree with edges 0-1, 1-2, 1-3, 0-4, rooted at 0. Leaves 2, 3 and 4 have sz = 1 and down = 0. Node 1 owns 2 and 3, so sz[1] = 3 and down[1] = 2. The root then has sz[0] = 5 and down[0] = (2+3) + (0+1) = 6, which is ans[0]. Sliding the root to 1 changes three distances by -1 and two (nodes 0 and 4) by +1, so ans[1] = 6 + 5 - 2×3 = 5. Sliding from 0 to 4 changes one distance by -1 and four by +1, so ans[4] = 6 + 5 - 2×1 = 9. Two walks, five answers, no fifth DFS.

After the down pass, down[u] is the answer on the subtree of u in the first rooting. After reroot, ans[u] is the answer on the whole tree as if rooted at u:

ans[v] = combine(ans[u] without v's subtree, down[v])

In plain words, moving the root to a child does not ask you to walk the tree again; it asks you to adjust the parent's already-known answer by the nodes that got closer and the nodes that got farther, then keep going.

Interview sentence: "I precompute every subtree, then I only recompute the outside when I slide the root."

Algorithm

  1. Build the undirected adjacency lists. A tree of n vertices has n - 1 edges stored both ways, so every loop must skip the parent; root the first pass at 0 so the down summaries have a direction.
  2. Down DFS writes subtree summaries only. From the children compute sz[u] and down[u] (or the top-two depths), because those numbers are the ones the second pass will reuse rather than recompute.
  3. Seed the answer at the chosen root. Set ans[root] = down[root], which is already the true whole-tree answer there and is the parent value the reroot step will adjust.
  4. Reroot by adjusting the outside. For each child, write ans[v] from ans[u] and sz[v] (or from the top-two depths), because sliding the root changes only who got closer and who got farther.
  5. Keep a top-two when the merge is a maximum. There is no inverse for max, so the excluded child's outside must come from the second-best sibling plus the parent's own outside, not from subtracting.
  6. Use long and prefer an iterative stack at n = 2×10⁵. A sum of distances overflows int, and a chain-shaped tree overflows the JVM stack long before the arithmetic does.

Java implementation

JavaNDfs.java
import java.util.*;
    public class NDfs {
        static List<List<Integer>> g;
        static int dfs(int u, int p) {
            int s = 0;
            for (int v : g.get(u)) if (v != p) s += dfs(v, u) + size(v, u);
            return s;
        }
        static int size(int u, int p) {
            int s = 1;
            for (int v : g.get(u)) if (v != p) s += size(v, u);
            return s;
        }
        public static void main(String[] args) {
            g = new ArrayList<>();
            for (int i = 0; i < 5; i++) g.add(new ArrayList<>());
            int[][] e = {{0,1},{1,2},{1,3},{0,4}};
            for (int[] x : e) { g.get(x[0]).add(x[1]); g.get(x[1]).add(x[0]); }
            System.out.println(dfs(0, -1));
        }
        // Input : 5-node sample, sum of distances from 0
        // Output: 6
    }
JavaRerootSum.java
import java.util.ArrayList;
    import java.util.Arrays;
    import java.util.List;
    
    public class RerootSum {
        static List<List<Integer>> g;
        static int n;
        static int[] sz;
        static long[] down, ans;
    
        static void dfs1(int u, int p) {
            sz[u] = 1;
            for (int v : g.get(u)) if (v != p) {
                dfs1(v, u);
                sz[u] += sz[v];
                down[u] += down[v] + sz[v];
            }
        }
        static void dfs2(int u, int p) {
            for (int v : g.get(u)) if (v != p) {
                ans[v] = ans[u] + n - 2L * sz[v];
                dfs2(v, u);
            }
        }
        public static void main(String[] args) {
            n = 5;
            g = new ArrayList<>();
            for (int i = 0; i < n; i++) g.add(new ArrayList<>());
            int[][] e = {{0,1},{1,2},{1,3},{0,4}};
            for (int[] x : e) { g.get(x[0]).add(x[1]); g.get(x[1]).add(x[0]); }
            sz = new int[n]; down = new long[n]; ans = new long[n];
            dfs1(0, -1);
            ans[0] = down[0];
            dfs2(0, -1);
            System.out.println(Arrays.toString(ans));
        }
        // Input : tree 0-1-2, 1-3, 0-4
        // Output: [6, 5, 8, 8, 9]
    }
JavaTopTwoHeight.java
import java.util.*;
    public class TopTwoHeight {
        static List<List<Integer>> g;
        static int[] down;
        static void dfs(int u, int p) {
            down[u] = 0;
            for (int v : g.get(u)) if (v != p) {
                dfs(v, u);
                down[u] = Math.max(down[u], down[v] + 1);
            }
        }
        public static void main(String[] args) {
            g = new ArrayList<>();
            for (int i = 0; i < 5; i++) g.add(new ArrayList<>());
            int[][] e = {{0,1},{1,2},{1,3},{0,4}};
            for (int[] x : e) { g.get(x[0]).add(x[1]); g.get(x[1]).add(x[0]); }
            down = new int[5];
            dfs(0, -1);
            System.out.println(Arrays.toString(down));
        }
        // Input : same tree, down-height from 0
        // Output: [2, 1, 0, 0, 0]
    }

Complexity

Time O(n) Space O(n)

Each of the n - 1 edges is walked a constant number of times across the two DFS passes. Combining a child is O(1) for a sum, and collecting the top two depths at a node is O(deg(u)), which still totals O(n) because the degrees of a tree sum to 2n - 2. The naive "root at each vertex and DFS" is Θ(n²).

T = Θ(n) versus naive Θ(n²)

At n = 2×10⁵ the two linear walks are a few million edge hops, comfortable; the naive version is about 4×10⁶ hops and will time out. If the merge really needs a full multiset of child answers you pay extra (small-to-large, or a heap), but the textbook reroot of a sum or a max does not.

Edge cases and pitfalls

  • Forgetting to skip the parent
    An undirected edge is stored both ways, so a loop that treats every neighbour as a child looks like the binary-tree recursion and then recurses forever along the same edge.
    Write if (v == p) continue; in every neighbour loop, both passes. A two-node tree is enough to expose the infinite walk.
  • int overflow of n*dist
    A sum of distances can reach about n×(n-1), so an int array wraps to a small wrong number that still looks like a plausible answer on the sample.
    Store down and ans as long[]. A star with a 200000-leaf count is the overflow test.
  • Reroot max without top-two
    Subtracting the child's own depth from a parent max that came from that same child looks like the sum-formula's inverse, then the child's outside becomes 0 even though a sibling spine is still there.
    Store the best and second-best child depths at u, and give v whichever of those two is not itself. A node with two long arms is the check.
  • sz[v] after rerooting used as if still rooted at 0
    The formula ans[u] + n - 2×sz[v] needs sz[v] to stay the down-subtree size from the first rooting; recomputing sizes during the second pass looks tidy and then uses the wrong closer-count.
    Leave sz[] alone in dfs2 unless you have a separate reason to rebuild it. Check that ans[1] on the five-node sample is 5, not 6.
  • Stack overflow
    A path of 2×10⁵ is a legal tree, so the recursive pair of walks is correct on paper and then dies with StackOverflowError on the anti-recursion test.
    Write an iterative DFS, or raise the stack, whenever the statement does not promise a bushy tree. Contests like this chain.

Interview follow-ups

Why n - 2*sz[v]?

When the root slides from u to child v, every node in v's subtree is one hop closer and every node outside that subtree is one hop farther. The closer count is sz[v], the farther count is n - sz[v], and the change in the sum is (n - sz[v]) - sz[v], which is n - 2×sz[v]. You add that delta to ans[u]; you do not walk either side again.

When is rerooting impossible in O(n)?

When you cannot recover "the parent's answer without this child" in constant time or in time proportional to the degree. A merge that needs a full multiset of sibling answers forces small-to-large, a heap, or an honest O(n²). Sums and maxima with a top-two are the cases that stay linear.

Diameter via rerooting?

The height of the tree after rerooting at v is the eccentricity of v, the farthest distance from that vertex. The diameter is the maximum eccentricity, which is also max(down[v] + up[v]) over vertices. If you only need the diameter value, two BFS (or two DFS) from a farthest vertex is shorter and does not reroot.

Weighted edges?

Replace each +1 with the edge weight w(u, v) in the down pass. The reroot delta becomes "minus twice the total weight of v's subtree, plus the total weight of every edge", so you track a subtree weight-sum alongside sz. The picture is the same: closer side loses w, farther side gains w.
