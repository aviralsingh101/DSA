Binary Search Trees

Left < node < right on every subtree: inorder is sorted, k-th smallest is an inorder walk, and validate is a range (lo, hi) passed down, not a local comparison.

Easy 22 min read Prerequisites: Binary Tree Basics & Traversals, Binary Search Basics BST inorder validate P0

Why this exists

A BST is a binary tree plus an invariant, and almost every BST bug is a local check that is not the invariant. "Left child < me < right child" is necessary and not sufficient: a right grandchild can still violate the ancestor. The real invariant is a range: every node sits in (lo, hi) inherited from its ancestors.

Because inorder is sorted, k-th smallest is "walk inorder, stop at k", and "two-sum in a BST" is a two-pointer on the iterator, not a hash set you needed for an unsorted tree. Delete is the one structural operation people fumble (two children: splice the inorder successor).

Balanced BSTs (TreeMap) are a later Java page. This page is the interview BST: validate, search, insert, delete, k-th, LCA using values, convert sorted array to BST.

Validate with a range, not a local compare. Inorder of a BST is strictly increasing (if unique keys). k-th smallest is inorder that stops early.

Recognise this pattern

Say yes when you see

  • Validate binary search tree
  • k-th smallest / k-th largest in a BST
  • Insert / delete / search
  • LCA in a BST (walk from the root using values)
  • Convert a sorted array to a height-balanced BST

Not this pattern when

  • The tree is not ordered → general binary-tree patterns
  • You need O(1) extra k-th after many inserts → store subtree sizes (order-statistic tree)
  • String prefixes → trie
  • n=1e5 and you need log queries on a static tree of un-ordered values → not a BST

Core idea and the invariant

Validate: ok(node, lo, hi) with long sentinels (or null bounds). Fail if val ≤ lo or val ≥ hi. Recurse left with hi=val, right with lo=val. Inorder alternative: prev pointer, fail if node.val ≤ prev.

Insert: empty slot is the new node; go left if val < cur, else right. Delete: 0 children drop; 1 child replace; 2 children copy successor.val then delete successor (which has no left). LCA: while node is not between p and q, step left or right.

For every node, all keys in its left subtree are < node.val and all keys in its right subtree are > node.val (unique keys).

lo < node.val < hi, inherited from ancestors

Algorithm

  1. Validate: dfs(n, lo, hi), fail unless lo < n.val < hi; rec left (lo,val), right (val,hi).
  2. Or inorder: prev, fail if n.val ≤ prev.
  3. Search / insert: compare and step, like binary search.
  4. Delete two-children: successor = min of right; copy; delete successor.
  5. k-th: inorder until count==k, or sizes on nodes for O(h).
  6. LCA: from root, step until p and q are on different sides (or one equals the node).

Java implementation

JavaBstLocalCheck.java
public class BstLocalCheck {
        static class Node {
            int val; Node left, right;
            Node(int v) { val = v; }
        }
        static boolean local(Node n) {
            if (n == null) return true;
            if (n.left != null && n.left.val >= n.val) return false;
            if (n.right != null && n.right.val <= n.val) return false;
            return local(n.left) && local(n.right);
        }
        public static void main(String[] args) {
            Node r = new Node(4);
            r.left = new Node(2); r.right = new Node(5);
            r.left.left = new Node(1); r.left.right = new Node(6);
            System.out.println(local(r));
        }
        // Input : invalid BST (6 in left of 4) that local-check misses
        // Output: true
    }
JavaValidateBst.java
public class ValidateBst {
        static class Node {
            int val; Node left, right;
            Node(int v) { val = v; }
        }
        static boolean ok(Node n, long lo, long hi) {
            if (n == null) return true;
            if (n.val <= lo || n.val >= hi) return false;
            return ok(n.left, lo, n.val) && ok(n.right, n.val, hi);
        }
        static int kth(Node n, int[] k) {
            if (n == null) return -1;
            int L = kth(n.left, k);
            if (k[0] == 0) return L;
            if (--k[0] == 0) return n.val;
            return kth(n.right, k);
        }
        public static void main(String[] args) {
            Node r = new Node(4);
            r.left = new Node(2); r.right = new Node(5);
            r.left.left = new Node(1); r.left.right = new Node(3);
            System.out.println(ok(r, Long.MIN_VALUE, Long.MAX_VALUE));
            System.out.println(kth(r, new int[]{3}));
        }
        // Input : BST 4 / 2 5 / 1 3 , k=3
        // Output: true
        //         3
    }
JavaLcaBst.java
public class LcaBst {
        static class Node {
            int val; Node left, right;
            Node(int v) { val = v; }
        }
        static Node lca(Node n, int p, int q) {
            while (n != null) {
                if (p < n.val && q < n.val) n = n.left;
                else if (p > n.val && q > n.val) n = n.right;
                else return n;
            }
            return null;
        }
        public static void main(String[] args) {
            Node r = new Node(6);
            r.left = new Node(2); r.right = new Node(8);
            r.left.left = new Node(0); r.left.right = new Node(4);
            System.out.println(lca(r, 2, 8).val);
            System.out.println(lca(r, 2, 4).val);
        }
        // Input : LC 235 sample
        // Output: 6
        //         2
    }

Complexity

Time O(h) search/insert/delete/LCA; O(n) validate / k-th naive Space O(h)

h is log n on a balanced tree and n on a skew tree. Validate must see every node, O(n).

T_search = O(h), T_validate = Θ(n)

Order-statistic trees store sz[] so k-th is O(h) after each insert.

Edge cases and pitfalls

  • Local left < me < right only
    A 6 sitting in the left subtree of 4 passes the local check at 2.
    Pass (lo, hi). Use long so Integer.MIN_VALUE is a legal node value.
  • int overflow sentinels
    lo = Integer.MIN_VALUE, node.val is also MIN_VALUE, lo < val fails or you use <= wrong.
    long lo, hi with Long.MIN/MAX, or Integer bounds as objects.
  • Delete successor incorrectly
    You delete the successor's value from the wrong parent, or forget it has no left child only.
    successor = min(right); node.val = s.val; node.right = delete(node.right, s.val).
  • Duplicates
    <= on both sides, or a validate that uses < both ways, rejects a legal duplicate policy.
    Pick a side for equals (usually right) and match validate to it.
  • k-th by converting to an array always
    Fine for one query; wasteful if the follow-up is many k-th with inserts.
    Subtree sizes, or a persistent inorder iterator.

Interview follow-ups

Why long bounds?

The node type is int, so MIN_VALUE and MAX_VALUE are legal keys. If you pass those as the initial lo/hi with int, a root equal to MIN_VALUE is rejected. long sentinels sit strictly outside.

Is every inorder-sorted tree a BST?

Yes for unique keys: the BST invariant is equivalent to inorder being strictly increasing. Building a tree from an increasing inorder still needs a structure (balanced mid split) if you also want height log n.

Delete complexity?

O(h) to find, O(h) to find the successor, O(h) to splice. Still O(h). Hibbard deletion unbalances over time; interviews ignore that.

LCA in BST vs general tree?

BST: walk from the root using values, no extra memory. General: postorder both-sides (previous page) or binary lifting (later).
