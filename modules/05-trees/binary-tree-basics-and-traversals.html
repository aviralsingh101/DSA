Binary Tree Basics & Traversals

A binary tree is a recursive pair of subtrees. Every classic walk — preorder, inorder, postorder, level order — is the same recursion with the visit moved.

Easy 22 min read Prerequisites: Recursion Fundamentals, Complexity Analysis binary tree DFS BFS traversal P0

Why this exists

Almost every binary-tree question is a traversal wearing a costume. Diameter, path sum, symmetry, serialisation, construction from two orders — each is "walk every node exactly once and combine the children's answers". If you cannot write the four walks without looking them up, the later pages in this module feel like magic.

The recursive definition is the whole data structure: a node holds a value and two optional children. Height, size, and "is this a leaf" fall out of that definition in three lines. Interviewers ask for both recursive and iterative forms because a linked-list-shaped degenerate of n = 1e5 overflows the JVM stack.

The four orders are not four algorithms. They are one DFS with the visit placed before, between, or after the two recursive calls, plus one BFS that swaps the implicit stack for an ArrayDeque.

Preorder / inorder / postorder are the same DFS with the visit moved. Level order is the same walk with a queue instead of a stack. Learn one walk, then move the visit.

Recognise this pattern

Say yes when you see

  • Return the preorder / inorder / postorder / level-order list of values
  • Height, depth, number of nodes, or is this a leaf / full / complete tree
  • A problem that is "do something at every node, using answers from children"
  • Reconstruct a tree from two of the three DFS orders
  • Iterative traversal is requested, or n is large enough that recursion may overflow

Not this pattern when

  • The input is a general graph with cycles → BFS/DFS on graphs, not a tree walk
  • You need ancestor queries or path aggregates on a static tree → LCA or Euler tour
  • The tree is a BST and the question uses the search-tree invariant → BST page
  • You are counting strings or XOR pairs → trie / XOR trie

Constraint tell: n ≤ 1e5 is fine for an iterative walk. Recursive DFS on a skew tree of that size overflows the Java stack (typically a few thousand frames). Prefer iterative whenever the statement does not promise a balanced tree.

Core idea and the invariant

A binary tree node is (val, left, right). The recursive walk is: optionally visit, walk left, optionally visit, walk right, optionally visit. Preorder visits first, inorder between the children, postorder last. Height = 1 + max(hL, hR) with null contributing 0 (nodes) or -1 (edges).

Iterative preorder: stack, pop, visit, push right then left. Iterative inorder: walk cur left while pushing, then pop-visit and step right. Level order: queue, snapshot size to group by depth. Use ArrayDeque, never java.util.Stack.

Every node is entered once and left once. The three DFS orders are the same walk; only the moment of recording node.val changes:

pre = visit, L, R  |  in = L, visit, R  |  post = L, R, visit

Interview sentence: "I walk every node once; the order is where I put the visit."

Algorithm

  1. Represent Node(val, left, right). Missing child is null.
  2. Recursive DFS: base-case on null, place out.add before, between, or after the two rec calls.
  3. Iterative preorder: stack starts with root; pop, visit, push right then left. ArrayDeque.
  4. Iterative inorder: walk cur left while pushing, pop-visit, cur = popped.right.
  5. Level order: queue root; drain sz = q.size() each layer.
  6. Height / size are postorder combines; if n can be a skew chain, prefer iterative.

Java implementation

JavaHeightOnly.java
public class HeightOnly {
        static class Node {
            int val; Node left, right;
            Node(int v) { val = v; }
        }
        static int height(Node n) {
            if (n == null) return 0;
            return 1 + Math.max(height(n.left), height(n.right));
        }
        public static void main(String[] args) {
            Node r = new Node(1);
            r.left = new Node(2); r.right = new Node(3);
            r.left.left = new Node(4); r.left.right = new Node(5);
            System.out.println(height(r));
        }
        // Input : tree 1 / 2 3 / 4 5
        // Output: 3
    }
JavaTreeTraversals.java
import java.util.ArrayList;
    import java.util.List;
    
    public class TreeTraversals {
        static class Node {
            int val; Node left, right;
            Node(int v) { val = v; }
        }
        static void preorder(Node n, List<Integer> out) {
            if (n == null) return;
            out.add(n.val);
            preorder(n.left, out);
            preorder(n.right, out);
        }
        static void inorder(Node n, List<Integer> out) {
            if (n == null) return;
            inorder(n.left, out);
            out.add(n.val);
            inorder(n.right, out);
        }
        static void postorder(Node n, List<Integer> out) {
            if (n == null) return;
            postorder(n.left, out);
            postorder(n.right, out);
            out.add(n.val);
        }
        public static void main(String[] args) {
            Node r = new Node(1);
            r.left = new Node(2); r.right = new Node(3);
            r.left.left = new Node(4); r.left.right = new Node(5);
            List<Integer> pre = new ArrayList<>(), in = new ArrayList<>(), post = new ArrayList<>();
            preorder(r, pre); inorder(r, in); postorder(r, post);
            System.out.println(pre);
            System.out.println(in);
            System.out.println(post);
        }
        // Input : tree 1 / 2 3 / 4 5
        // Output: [1, 2, 4, 5, 3]
        //         [4, 2, 5, 1, 3]
        //         [4, 5, 2, 3, 1]
    }
JavaLevelOrder.java
import java.util.ArrayDeque;
    import java.util.ArrayList;
    import java.util.List;
    
    public class LevelOrder {
        static class Node {
            int val; Node left, right;
            Node(int v) { val = v; }
        }
        static List<List<Integer>> levelOrder(Node root) {
            List<List<Integer>> out = new ArrayList<>();
            if (root == null) return out;
            ArrayDeque<Node> q = new ArrayDeque<>();
            q.add(root);
            while (!q.isEmpty()) {
                int sz = q.size();
                List<Integer> row = new ArrayList<>();
                for (int i = 0; i < sz; i++) {
                    Node u = q.poll();
                    row.add(u.val);
                    if (u.left != null) q.add(u.left);
                    if (u.right != null) q.add(u.right);
                }
                out.add(row);
            }
            return out;
        }
        public static void main(String[] args) {
            Node r = new Node(1);
            r.left = new Node(2); r.right = new Node(3);
            r.left.left = new Node(4); r.left.right = new Node(5);
            System.out.println(levelOrder(r));
        }
        // Input : tree 1 / 2 3 / 4 5
        // Output: [[1], [2, 3], [4, 5]]
    }

Complexity

Time O(n) Space O(h) recursion / stack, O(w) for BFS

Each node is pushed and popped a constant number of times, so every walk is linear in the number of nodes.

T(n) = T(n_L) + T(n_R) + Θ(1) = Θ(n)

Auxiliary space is the height h (skew = n) or the BFS width w (complete last level = n/2).

ApproachTimeSpaceWhen it is enough
Recursive DFSO(n)O(h) stackDefault; fine when balanced

Level-order BFSO(n)O(w)Anything that needs depth grouping
Morris traversalO(n)O(1)Rare; temporarily threads the tree

Edge cases and pitfalls

  • Using java.util.Stack
    Synchronised Vector subclass, wrong methods, slower.
    ArrayDeque: push/pop/peek for DFS, add/poll for BFS.
  • Forgetting the null base case
    NPE on a missing child; only shows up on trees that are not perfectly full.
    First line: if (node == null) return (or the identity of the combine).
  • Height off-by-one (nodes vs edges)
    LC 104 wants 1 for a single node; LC 543 diameter is in edges.
    State the convention in a comment. Edge-height: null returns -1.
  • Level-order without snapshotting queue size
    Cannot tell where one level ends. Flat list is still correct; grouped list is not.
    int sz = q.size(); then a for of that many polls.
  • Recursive walk on a linked-list-shaped tree
    n=1e5 right spine, StackOverflowError.
    Write the iterative version.

Interview follow-ups

How do you reconstruct from preorder and inorder?

First preorder value is the root. Find it in inorder: left of it is the left subtree. Map values to indices for O(1) splits, total O(n). Preorder+postorder is ambiguous unless the tree is full.

Why is inorder of a BST sorted?

Left < root < right, and inorder is L, root, R. See the BST page.

O(1) extra space with parent pointers?

Walk to parent and decide whether you arrived from the left child. Same three-colour state machine as iterative postorder, stored in the current position.

What changes for an n-ary tree?

DFS becomes visit then loop children. Level order is unchanged except the enqueue loop. There is no unique inorder.

Recap

  • One DFS, three visit placements give preorder, inorder, postorder.
  • Level order is BFS with sz = q.size().
  • Height and size are postorder combines with a null identity of 0.
  • Iterative forms are required on skew trees.
  • ArrayDeque, never java.util.Stack.
