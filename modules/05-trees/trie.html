Trie

A tree of prefixes: each edge is a character, insert/search/startsWith are O(|s|), and the same walk powers word-search II and autocomplete.

Medium 22 min read Prerequisites: Binary Tree Basics & Traversals trie prefix tree P0

Why this exists

HashSet.contains is O(|s|) expected for exact strings and cannot answer "is there a stored word that starts with this prefix" without scanning everything. A trie shares prefixes: n words of length L use O(total characters) nodes, and a prefix query walks one path of length |prefix|.

LC 208 is the API. Word Search II is "DFS the board, walk the trie in lockstep, prune when the node is null". Autocomplete, replace-words, and longest-word-in-dictionary are the same walk with a different payload on terminal nodes.

The implementation choice is next[26] vs HashMap<Character,Node>. Interviews want the array for lowercase English. Count how many words share a node if you must delete.

A trie node is the set of strings with a given prefix. Child c is that prefix extended by c. Terminal flag (or count) marks a complete word.

Recognise this pattern

Say yes when you see

  • implement-trie: insert, search, startsWith
  • Search a board for many words (Word Search II)
  • Replace words with the shortest dictionary prefix / root
  • Count words with a given prefix, autocomplete
  • XOR of numbers → next page (binary trie), not this 26-way trie

Not this pattern when

  • Exact lookup of a few strings, no prefixes → HashSet
  • Suffix queries / longest palindrome → suffix array, Manacher, not a prefix trie
  • Maximum XOR pair → XOR trie
  • n*L too big to store every node and you only need equality → hashing

Core idea and the invariant

Node { Node[] next = new Node[26]; boolean term; int cnt; }. insert: cur = root, for ch in s: i=ch-'a'; if next[i]==null next[i]=new Node(); cur=next[i]; cur.cnt++. Then cur.term=true. search: walk, fail on null, then term. startsWith: walk, fail on null.

Word Search II: build a trie of the word list. DFS the board; if next[cell]==null return; if term, emit word and optionally unmark term (dedup). Restore the cell after DFS. Delete dead leaves to prune (optional speed).

The path from the root to a node spells a prefix of at least one inserted word. term (or cntEnd) is true iff that prefix is a complete word.

search(s) = walk(s) lands on a node with term=true

Algorithm

  1. Node: next[26], term, optional cnt.
  2. insert: create missing children, mark term at the end, bump cnt.
  3. search: walk, null → false, else return term.
  4. startsWith: walk, null → false, else true.
  5. Board search: DFS 4-way, trie pointer, emit on term, restore cell.
  6. Do not store the whole string on every node unless you need it for output.

JavaTrie.java
public class Trie {
        static class Node {
            Node[] next = new Node[26];
            boolean term;
        }
        final Node root = new Node();
    
        void insert(String w) {
            Node cur = root;
            for (int i = 0; i < w.length(); i++) {
                int c = w.charAt(i) - 'a';
                if (cur.next[c] == null) cur.next[c] = new Node();
                cur = cur.next[c];
            }
            cur.term = true;
        }
        boolean walk(String w, boolean needTerm) {
            Node cur = root;
            for (int i = 0; i < w.length(); i++) {
                int c = w.charAt(i) - 'a';
                if (cur.next[c] == null) return false;
                cur = cur.next[c];
            }
            return needTerm ? cur.term : true;
        }
        public static void main(String[] args) {
            Trie t = new Trie();
            t.insert("app");
            t.insert("ape");
            System.out.println(t.walk("ape", true));
            System.out.println(t.walk("ap", true) + " " + t.walk("ap", false));
        }
        // Input : insert app, ape; search ape, search ap, startsWith ap
        // Output: true
        //         false true
    }
JavaReplaceWords.java
public class ReplaceWords {
        static class Node {
            Node[] next = new Node[26];
            String word;
        }
        static String replace(String[] dict, String sentence) {
            Node root = new Node();
            for (String w : dict) {
                Node cur = root;
                for (int i = 0; i < w.length(); i++) {
                    int c = w.charAt(i) - 'a';
                    if (cur.next[c] == null) cur.next[c] = new Node();
                    cur = cur.next[c];
                }
                cur.word = w;
            }
            StringBuilder sb = new StringBuilder();
            for (String tok : sentence.split(" ")) {
                Node cur = root;
                String use = tok;
                for (int i = 0; i < tok.length(); i++) {
                    int c = tok.charAt(i) - 'a';
                    if (cur.next[c] == null) break;
                    cur = cur.next[c];
                    if (cur.word != null) { use = cur.word; break; }
                }
                if (sb.length() > 0) sb.append(' ');
                sb.append(use);
            }
            return sb.toString();
        }
        public static void main(String[] args) {
            System.out.println(replace(new String[]{"cat", "bat", "rat"}, "the cattle was rattled by the battery"));
        }
        // Input : LC 648 sample
        // Output: the cat was rat by the bat
    }

Complexity

Time O(L) per insert/search/startsWith Space O(total characters * σ) worst, typically O(total chars)

Each character of each word creates at most one new node. Shared prefixes share nodes.

T(insert) = O(|s|), S = O(Σ |s_i|)

HashSet search is also O(|s|) but startsWith is O(n |s|) over the set. Trie makes prefix O(|s|).

Edge cases and pitfalls

  • Forgetting term vs prefix
    search("ap") true after inserting apple. startsWith and search mixed up.
    search requires term; startsWith does not.
  • Not creating nodes on insert
    NPE on next[c].field, or silent drop of the suffix.
    if (cur.next[c]==null) cur.next[c]=new Node();
  • Word Search II without marking the cell
    The same cell is reused in one word (loop).
    board[r][c]='#'; rec; restore.
  • 26 vs 'A'
    Uppercase or extra characters, negative index.
    Normalise, or a map. Guard c in 0..25.
  • Storing List<String> on every node
    Memory explodes; copying lists is O(n) per insert.
    term + reconstruct the word, or store one String at terminals only.

Interview follow-ups

Why not a HashMap of all prefixes?

You can: insert every prefix of every word into a HashSet for startsWith, and a set of words for search. Memory is worse (every prefix stored as a String) and Word Search II still wants a walk that can prune. The trie is the compressed form of that map.

Aho-Corasick vs trie DFS on a text?

Aho adds failure links so you scan the text once for all patterns. If the "text" is a 2-D board with 4-way moves, board DFS + trie is the right shape (LC 212). If the text is a string, Aho is linear.

Autocomplete top-k?

At the prefix node, the subtree holds candidates. Precompute a small heap of best words at each node, or DFS the subtree (fine if small).

Unicode?

HashMap<Character,Node> or a UTF-8 byte trie (256). Do not allocate next[Character.MAX_VALUE].

Recap

  • next[26] + term is the whole node.
  • insert creates, search needs term, startsWith does not.
  • Share prefixes — that is the memory win.
  • Word Search II: board DFS locked to the trie pointer.
  • XOR is a 2-child trie on the next page.
