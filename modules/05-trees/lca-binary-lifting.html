LCA & Binary Lifting

Precompute the 2^k-th ancestor of every node in O(n log n), then LCA and k-th ancestor queries become O(log n) jumps.

Hard 24 min read Prerequisites: Tree DP & Rerooting, Bit Manipulation LCA binary lifting P1

Why this exists

The interview LCA on a binary tree is one DFS. The contest LCA is n,q = 1e5 queries on a static tree: distance(u,v), k-th node on a path, max edge on a path. Binary lifting stores up[k][v] = the 2^k-th parent of v, built from up[k][v]=up[k-1][up[k-1][v]]. Lift the deeper node to the same depth, then lift both until their parents match.

The same table answers "k-th ancestor" by jumping bits of k, and with extra payload on edges (max, gcd, sum) you merge along the jumps. Euler-tour RMQ is the other LCA; lifting is easier to extend with path aggregates.

depth[] from a DFS, parent[0][v] from the same DFS, then the doubling loop. Queries are then a short bit loop. Off-by-one on "lift to depth of LCA+1" is the classic bug.

Any ancestor distance d is a sum of distinct powers of two. Jump those bits. LCA is: equalise depth, then jump both while the 2^k parents still differ, then take the parent.

Recognise this pattern

Say yes when you see

  • Many LCA queries on a static tree
  • Distance = depth[u]+depth[v]-2*depth[lca]
  • k-th ancestor, or k-th node on the path u-v
  • Path min/max/gcd by storing a payload next to up[k][v]
  • n,q = 1e5, so O(log n) per query after O(n log n) prep

Not this pattern when

  • One or two LCA queries on a binary tree in an interview → the postorder trick
  • The tree changes (link/cut) → LCT, not lifting
  • Subtree queries, not path-to-root → Euler tour + Fenwick
  • n=1e9 implicit → different

Constraint tell: n,q ≤ 2e5, LOG=18 or 20. up is int[LOG][n] (or [n][LOG]). Root's parent is the root or -1; jumping past the root must be defined (stay at root, or -1).

Core idea and the invariant

DFS from the root: depth[v], up[0][v]=parent. Then for k=1..LOG-1, for all v, up[k][v]=up[k-1][up[k-1][v]] (if parent is -1, keep -1).

LCA: if depth[u]<depth[v] swap. Lift u by depth[u]-depth[v] using bits. If u==v return u. Then for k=LOG-1..0, if up[k][u]!=up[k][v] jump both. Return up[0][u].

up[k][v] is the ancestor of v exactly 2^k steps toward the root (or the root / -1 if you run out).

lca(u,v) = first common ancestor; dist = d[u]+d[v]-2 d[lca]

Algorithm

  1. DFS from root: depth[], up[0][v]=parent (root parent = -1 or itself).
  2. Double: for k=1..LOG-1, up[k][v] = up[k-1][up[k-1][v]] (guard -1).
  3. Equalise depth by lifting the deeper node.
  4. If equal, that is the LCA.
  5. From high bit to 0: if up[k][u]!=up[k][v] jump both.
  6. Return up[0][u] (the parent of the nodes just below the LCA).

Java implementation

JavaLcaWalk.java
import java.util.*;
    public class LcaWalk {
        static int[] p, d;
        static int lca(int u, int v) {
            while (d[u] > d[v]) u = p[u];
            while (d[v] > d[u]) v = p[v];
            while (u != v) { u = p[u]; v = p[v]; }
            return u;
        }
        public static void main(String[] args) {
            p = new int[]{-1, 0, 1, 1, 0};
            d = new int[]{0, 1, 2, 2, 1};
            System.out.println(lca(2, 3) + " " + lca(2, 4));
        }
        // Input : sample parents
        // Output: 1 0
    }
JavaBinaryLifting.java
import java.util.ArrayList;
    import java.util.List;
    
    public class BinaryLifting {
        static final int LOG = 20;
        static int[][] up;
        static int[] depth;
        static List<List<Integer>> g;
    
        static void dfs(int u, int p) {
            up[0][u] = p;
            for (int k = 1; k < LOG; k++) {
                int mid = up[k - 1][u];
                up[k][u] = mid < 0 ? -1 : up[k - 1][mid];
            }
            for (int v : g.get(u)) if (v != p) {
                depth[v] = depth[u] + 1;
                dfs(v, u);
            }
        }
        static int lift(int u, int h) {
            for (int k = 0; k < LOG; k++) if (((h >> k) & 1) == 1) {
                u = up[k][u];
                if (u < 0) return u;
            }
            return u;
        }
        static int lca(int u, int v) {
            if (depth[u] < depth[v]) { int t = u; u = v; v = t; }
            u = lift(u, depth[u] - depth[v]);
            if (u == v) return u;
            for (int k = LOG - 1; k >= 0; k--)
                if (up[k][u] != up[k][v]) { u = up[k][u]; v = up[k][v]; }
            return up[0][u];
        }
        public static void main(String[] args) {
            int n = 5;
            g = new ArrayList<>();
            for (int i = 0; i < n; i++) g.add(new ArrayList<>());
            int[][] e = {{0,1},{1,2},{1,3},{0,4}};
            for (int[] x : e) { g.get(x[0]).add(x[1]); g.get(x[1]).add(x[0]); }
            up = new int[LOG][n];
            depth = new int[n];
            for (int[] row : up) java.util.Arrays.fill(row, -1);
            dfs(0, -1);
            System.out.println(lca(2, 3) + " " + lca(2, 4));
            System.out.println(depth[2] + depth[4] - 2 * depth[lca(2, 4)]);
        }
        // Input : sample tree, queries (2,3) (2,4)
        // Output: 1 0
        //         3
    }
JavaKthAncestor.java
public class KthAncestor {
        static int[][] up;
        static int kth(int u, int k) {
            for (int i = 0; i < 20; i++) if (((k >> i) & 1) == 1) {
                u = up[i][u];
                if (u < 0) return -1;
            }
            return u;
        }
        public static void main(String[] args) {
            up = new int[20][5];
            for (int[] row : up) java.util.Arrays.fill(row, -1);
            up[0][1] = 0; up[0][2] = 1; up[0][3] = 1; up[0][4] = 0;
            for (int k = 1; k < 20; k++)
                for (int v = 0; v < 5; v++)
                    if (up[k - 1][v] >= 0) up[k][v] = up[k - 1][up[k - 1][v]];
            System.out.println(kth(2, 2));
            System.out.println(kth(2, 3));
        }
        // Input : 2's 2nd ancestor and 3rd
        // Output: 0
        //         -1
    }

Complexity

Time O(n log n) build, O(log n) per LCA / k-th ancestor Space O(n log n)

LOG = ceil(log2 n) ~ 18. Filling up[k][v] is n * LOG. A query equalises with at most LOG jumps then at most LOG more.

T_build = O(n log n), T_q = O(log n)

Euler+RMQ is O(n log n) / O(1) with a sparse table, slightly heavier constants, worse at path payloads.

Edge cases and pitfalls

  • Lifting past the root without a guard
    up[k][-1] or up[k][parent of root] indexes garbage.
    Store -1, skip when mid<0. Or parent[root]=root and jumps stay put.
  • Returning u after the loop instead of up[0][u]
    You stopped at the children of the LCA, not the LCA.
    After equalise, if u==v return u; else jump while parents differ; return parent.
  • Filling up[k] inside DFS before children set up[k-1]
    up[k][v] depends only on v's ancestors, so filling at v during DFS is actually OK if you fill all k for v after up[0][v] is set, before children. Filling a global k-loop after the whole DFS is simpler.
    Either fill all k for u at dfs entry, or a nested loop after DFS.
  • depth not set when lifting
    Forgot DFS, all depths 0, LCA is nonsense.
    One DFS from the true root (problem's 1, or 0).
  • 1-based nodes, 0-based table
    n=5 nodes 1..5, array of 5, index 5 dies.
    n+1 arrays, ignore 0, or decrement labels.

Interview follow-ups

Why jump from high bits down when equalising is low bits up?

Equalising a known height h uses the bits of h, any order. The LCA's "while parents differ" must go from high to low: a low-bit jump first could overshoot the LCA and land on different ancestors that later cannot resync.

Virtual trees?

Sort a subset of nodes by tin, LCA consecutive pairs, stack-build the compressed tree. Binary lifting (or RMQ) supplies those LCAs. Used in DP on a few important vertices.

Weighted distance?

Store distRoot[v] = distance to root during DFS. dist(u,v)=distRoot[u]+distRoot[v]-2*distRoot[lca]. No extra lifting payload needed for sums.

LOG = 20 vs 18?

2^18 = 262144. n=2e5 needs 18. 20 is a safe default. 31 is a waste of memory (n*31 ints).

  • k-th ancestor is jumping the bits of k.
