How to use this course

  1. Read the recognition card before the algorithm. Every topic page opens with "Recognise this pattern" — the trigger phrases, the constraint tells, and what this pattern is commonly confused with. That section is the part you actually lost.
  2. Run the visual walkthrough. Press Play on the trace player and watch the indices move. Do not skip it because you "know" the algorithm; recognising the shape of the state is what makes it recallable under pressure.
  3. Cover the code and re-derive it from the stepper. The numbered algorithm steps use exactly the same variable names as the Java, so you can write the implementation yourself and then diff.
  4. Do the practice table top to bottom. It is ordered easy to hard on purpose. Stop when you can do the medium tier without hints.
  5. Then do Mock Drills. Those problems are deliberately unlabelled, which is the only honest test of pattern recognition.

What every topic page contains

The structure never changes, so you always know where to look:

Recognition and intuition

  • Why the technique exists, and what the naive approach costs
  • Trigger phrases, constraint tells, and lookalike patterns
  • The precise loop invariant or recurrence, stated the way you would say it out loud

Mechanics

  • An animated trace over a concrete small input, plus a structural diagram
  • Numbered algorithm steps that mirror the code's variable names
  • A full dry-run table showing every iteration

Code and cost

  • Brute force, optimal, and a reusable template — all compilable Java 17
  • A real complexity derivation, not just the final Big-O
  • Edge cases and the specific bugs people ship

Interview transfer

  • Variants and exactly which lines change for each
  • The follow-up questions an interviewer asks next
  • 8–12 curated problems, easy to hard, with links
